The UTC date is checked before each bot dispatch. If it changes, STOP, run
Cleanup and start again with a fresh DATE.

Every push of a commit goes through this helper: the repository push gate
refuses a commit other than the checked-out HEAD. The helper creates a scratch
worktree detached at exactly that commit, pushes its HEAD and removes it. The
gate runs the repository gates there; allow several minutes while uv builds its
environment. The hook and gate are never bypassed; deletions are not gated.
push_exact() { wt=$(mktemp -d) && git worktree add --detach "$wt" "$1" && (cd "$wt" && git push origin "HEAD:$2"); rc=$?; git worktree remove --force "$wt" 2>/dev/null || rm -rf "$wt"; return $rc; }

== What this writes to the remote

WRITE: bot run on the default branch | created by owner dispatch | removed in nowhere; history stays
WRITE: bot/registry-$DATE | created by the bot | removed in Cleanup
WRITE: proof/target-$DATE and temporary protection | owner push and OWNER APPROVAL REQUIRED API write | removed in Cleanup
WRITE: landing/registry-$DATE | owner push | removed in Cleanup
WRITE: registry-bot label and tracking issue | created by the bot | removed in Cleanup (issue closed; reusable label may stay)
WRITE: dispatched ci.yml runs and check runs | created by the bot | removed in nowhere; history stays, run deletion is optional
WRITE: push-event CI runs on proof/target-* and landing/* | Option A first push starts full two-OS CI; later pushes also start CI | history stays
WRITE: Actions cache entries | created by the bot run | removed in automatic expiration

== Part 3: the BOT-02 question

GitHub documents that dispatched checks on a pull request head do not satisfy a
branch ruleset. The default branch uses classic protection and this flow has no
pull request, so only this proof answers whether those checks allow a fast-forward.
Record Part 2's RUN_ID, job results, check runs and protection read BEFORE any Option A push: that push starts ordinary push-event CI and would confound the evidence.
Re-read the fetched final head and STOP unless it equals SHA_FIRST.
SHA=$(git rev-parse "refs/remotes/origin/bot/registry-$DATE")
[ "$SHA" = "$SHA_FIRST" ] || echo "STOP: head changed; Cleanup and restart"
gh run -R "$REPO" list --workflow ci.yml --commit "$SHA" --json event,conclusion,headSha,status
Expect every run for SHA to be completed with success and workflow_dispatch; STOP otherwise.

Option A (recommended): create a throwaway target at BASE. Obtain explicit owner
approval for the protection write; STOP if approval is not given.
Read the entire classic protection and STOP if any enabled setting cannot map.
The following jq check accepts only the known settings and refuses reviews,
restrictions, app-pinned checks, and any unknown enabled protection. Inspect the
whole response and STOP if GitHub adds a setting whose meaning is unclear.
MAIN_PROTECTION=$(gh api repos/$REPO/branches/main/protection)
printf '%s\n' "$MAIN_PROTECTION" | jq .
printf '%s\n' "$MAIN_PROTECTION" | jq -e '
  (keys - ["url", "required_status_checks", "enforce_admins", "required_pull_request_reviews", "restrictions", "required_signatures", "required_linear_history", "allow_force_pushes", "allow_deletions", "required_conversation_resolution", "block_creations", "required_bypass_pull_request_allowances", "lock_branch", "allow_fork_syncing"]) as $unknown |
  ($unknown | length == 0) and
  (.required_pull_request_reviews == null) and (.restrictions == null) and
  (all(.required_status_checks.checks[]?; .app_id == null)) and
  (all([.block_creations, .lock_branch, .allow_fork_syncing, .required_bypass_pull_request_allowances][]; . == null or .enabled == false))
' || echo "STOP: main enables a setting this proof cannot map"
Construct the PUT from main, not a handwritten approximation. Required signatures use their separate endpoint.
PROTECTION=$(printf '%s\n' "$MAIN_PROTECTION" | jq '{required_status_checks: (if .required_status_checks == null then null else {strict: .required_status_checks.strict, contexts: .required_status_checks.contexts} end), enforce_admins: .enforce_admins.enabled, required_pull_request_reviews: null, restrictions: null, required_linear_history: (.required_linear_history.enabled // false), allow_force_pushes: (.allow_force_pushes.enabled // false), allow_deletions: (.allow_deletions.enabled // false), required_conversation_resolution: (.required_conversation_resolution.enabled // false)}')

== Cleanup

Before cleanup, verify each proof dispatch by its recorded run id; STOP until all
are completed, including a failed or interrupted run. If a dispatch did not appear,
identify its run id in Actions and wait for it to complete before cleanup.
gh run -R "$REPO" view "$BOT_RUN" --json status --jq .status
If BOT_RUN2 was dispatched, check it too:
gh run -R "$REPO" view "$BOT_RUN2" --json status --jq .status
STOP unless every dispatched bot run reports completed; do not clean up while
any other bot run is queued or in progress. Recheck both preflight run lists.
Here the preflight proved the namespace empty: no bot/registry-*, proof/* or
landing/* ref and no open registry-bot issue. Everything there now was created
by this proof, including a branch created under a date rollover and an issue
left by a failed publish; cleanup therefore needs no recorded names. If anyone
else legitimately created work there meanwhile, stop and handle it by hand.

If Option A ran and protection was created, remove it before deleting the branch:
WRITE   gh api -X DELETE repos/$REPO/branches/proof%2Ftarget-$DATE/protection
gh api repos/$REPO/branches/proof%2Ftarget-$DATE/protection
Expect HTTP 404 (Branch not protected). STOP if it is not 404; repeat the delete
and read-back before deleting the branch. Never touch default branch protection.

WRITE   delete every ref now in that namespace, each with an expected-SHA lease:
(
set -o pipefail
listing=$(git ls-remote --heads origin "refs/heads/bot/registry-*" "refs/heads/proof/*" "refs/heads/landing/*")
while read -r sha ref; do
  case "$ref" in
    refs/heads/bot/registry-*|refs/heads/proof/*|refs/heads/landing/*) git push --force-with-lease="$ref:$sha" --delete origin "$ref" ;;
  esac
done <<< "$listing"
)
The pipefail setting is confined to this bash subshell.
The full-ref case is necessary because remote listing patterns match ref tails.
If GitHub refuses to delete proof/target-$DATE, its protection may still be there:
repeat the protection delete and 404 read-back first; never touch default branch protection.
WRITE   close every open proof issue:
open=$(gh issue -R "$REPO" list --label registry-bot --state open --json number --jq '.[].number')
while IFS= read -r n; do
  [ -n "$n" ] || continue
  gh issue -R "$REPO" close "$n" --comment "Closing: registry bot proof run."
done <<< "$open"
