<objective>
Wire D-04's consolidation into the one seam every PATH-wiring route already goes through, make
the new path constant test-safe everywhere, and record this phase's invariants in
`.claude/architecture.md` so they survive as doctrine.

Purpose: D-04 — the consolidation has to actually RUN, on the same trigger D-01 names ("the next
time `apply`/`fix` runs on Doctor, or `make fix`"). D-01 — the migration of the managed block and
the consolidation of the generic file are triggered by the same four call sites, so wiring them
together keeps one user action from producing half a fix.

Output: a `shellrc_path` parameter on `installer/app.py::configure_path`, a `_SHELLRC` constant
and four updated call sites in `setup.py`, the test-isolation updates that make the new constant
safe, and a new `.claude/architecture.md` section.

**Why the consolidation runs BEFORE the PATH block is written.** The copy-forward must land while
the file's block layout is still whatever the previous run left; writing the managed PATH block
first would mean two consecutive read-modify-write cycles on `~/.myshellrc` in one call, with the
foreign content arriving second and the block order flipping depending on which ran first.
Consolidate, then write the managed block: the managed block ends up last, which is also the
order that makes the guarded exports the final word on PATH.

**Why split mode is skipped.** In split mode this project writes the managed block directly into
each rc file and deliberately maintains no `~/.myshellrc` indirection (`installer/app.py:207-212`).
Consolidating a foreign file into a file nothing sources would move the user's content somewhere
less reachable while reporting success. Skip it, silently, and record the reason in a comment —
this is a deliberate scope decision, not an oversight for a reviewer to flag.

**Host-safety rule, and why this plan carries the most of it.** This is the plan that introduces
a module-level constant derived from the REAL `Path.home()`. `~/.shellrc` does not exist on this
machine, so the production path is a no-op here — but that is luck, not isolation. Every test
that redirects `setup._MYSHELLRC` must redirect `setup._SHELLRC` in the same place, and Task 2
finds them all rather than assuming `_sandbox` is the only one. No task in this plan runs
`make setup`, `make fix` or `make uninstall` against this machine. `make doctor` is a read-only
report and is allowed.

`No tests collected` line on a green run. Re-run as `rtk proxy uv run pytest <args>` or
`.venv/bin/pytest <args>` to read the real result.
</objective>
