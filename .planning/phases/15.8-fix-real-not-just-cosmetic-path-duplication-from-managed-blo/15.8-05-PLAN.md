<objective>
Decide, precisely and conservatively, what consolidation does about a line inside `~/.shellrc`
that sources `~/.myshellrc` — and prove in real shells that the result cannot loop.

Plan 15.8-04 built the preconditions, the backup and the happy path. This plan adds the content
inspection that sits between them, plus the two public helpers plan 15.8-06 consumes.

Purpose: D-04. A `~/.shellrc` that sources `~/.myshellrc` is the case that turns consolidation
into a self-sourcing file: after the stub is written, `~/.shellrc` sources `~/.myshellrc`, which
now contains the copied-forward line sourcing `~/.myshellrc`. Research marks it `[ASSUMED]` (A1)
— unverifiable on this host, since `~/.shellrc` does not exist here — which makes it a case to
BUILD and TEST against synthetic fixtures, never one to acknowledge and skip.

Output: the line classifier, `consolidation_refusal`, `consolidated_body`, the public
`sources_file` predicate and `remove_source_block`, in `installer/shellrc.py`; unit and
real-shell tests in `tests/test_shellrc.py`.

**The rule, stated before any code: rewrite only what is unambiguous, refuse the rest.**

An earlier revision of this plan tried to detect source lines with one regex (command position at
line start or after `;`/`&&`/`||`/`|`) and comment out whatever it found, whole line. Cross-AI
review (HIGH-04) showed that rule failing in both directions at once:

- It MISSED `if . "$HOME/.myshellrc"; then`, `! source ...`, backslash-continued commands, and
  indirection through a variable (`target="$HOME/.myshellrc"; . "$target"`). Every missed line
  becomes a self-source after migration — the exact failure this handling exists to prevent.
- It OVER-REACHED on a compound line: `export A=1; . "$HOME/.myshellrc"; export B=1` would have
  been replaced wholesale by a comment, silently killing two exports the user relies on.

So: exactly one shape is rewritten — a simple logical line that consists SOLELY of a `.` or
`source` command whose argument statically resolves to the target. Everything else that looks
like a live source of the target ends the operation with a reason. Refusing is cheap, visible,
and leaves the user exactly where they were; guessing is none of those things.

**What that costs, said plainly.** The guarded `[ -f "…" ] && . "…"` shape — the one this
project's own `ensure_source` writes — is a compound line and is therefore REFUSED, not
rewritten. That is deliberate. Teaching the rewriter to handle a specific safe compound form is a
designed decision with its own fixtures, not something to slip in while implementing this one.
A user who hits it gets a reason naming the file and the line.

**The documented residual, kept honest and now tested.** Foreign content copied forward verbatim
may itself contain plain, non-self-deduping PATH exports. They keep their existing behavior:
sourced twice, they add two copies. Rewriting a user's own lines would break D-04's verbatim
copy-forward promise, and this project already has a separate, user-facing mechanism for other
tools' plain exports (`installer/rcclean.py::find_duplicate_path_lines`). Task 2 pins that
residual with its own test and its own directory, so it is a stated contract rather than a
surprise — and so a later phase that decides to change it has to change a test to do so.

- `target="$HOME/.myshellrc"` followed on a later line by `. "$target"` — indirection: the source

**One private classifier, three verdicts.** Implement a single function that takes the file's
lines and the target path and returns, per line, one of three verdicts: not a source of the
target, a rewritable simple source, or an ambiguous source. Both public helpers below call it, so
detection and rewriting cannot drift apart. Structure it as:

- Skip a line whose stripped form starts with `#`.
- DETECT: the line contains a `.` or `source` command in COMMAND POSITION — at the start of the
  stripped line, or immediately after any of `;` `&&` `||` `|` `(` `{`, or after one of the
  reserved words `if` `then` `elif` `else` `while` `until` `do` `!` — whose argument statically
  resolves to the target file. "Statically resolves" means: after stripping one layer of matching
  double or single quotes, the argument is the target's absolute path, or `~`/`$HOME`/`${HOME}`
  followed by the remainder of the target's path relative to the injected home. Compare on the
  full resolved path, NOT on the basename alone — `~/.myshellrc` and `~/.shellrc` differ by one
  character and a basename-substring rule would confuse them in one direction.
- REWRITABLE only when the ENTIRE stripped line, ignoring leading indentation and trailing
  whitespace, is exactly that one source command and its argument, and the line does not end with
  a backslash continuation and the previous line does not either. Anything else that DETECTED is
  AMBIGUOUS.
- INDIRECTION is a separate ambiguous case the per-line rule cannot see, so add it at file level:
  when the text contains a live assignment whose value statically resolves to the target AND a
  live source command anywhere in the file whose argument is a variable expansion other than
  `$HOME`/`${HOME}`, treat the file as ambiguous, attributing the reason to the assignment's line.
  Over-approximating here refuses; under-approximating here ships a self-sourcing file.

Put the reasoning in a comment above the classifier, both directions named: under-detection
creates a sourcing loop, over-reach on a compound line would silently delete the other commands
sharing that line, and the only move that is wrong in neither direction is to rewrite one
unambiguous shape and refuse the rest.

**`consolidation_refusal(shellrc_text: str, myshellrc_text: str, *, shellrc_path: Path,
myshellrc_path: Path) -> str | None`** returns a human-readable reason, or None when the merge is
safe. Refuse when:
- any line of `shellrc_text`, stripped, begins with this project's marker prefix in either
  direction — merging content that carries marker-shaped lines could corrupt `apply_block`'s
  boundary pairing on a later re-apply;
- `sources_file(myshellrc_text, shellrc_path)` is True — the stub would close the loop, and the
  only alternative is editing the user's own unmanaged content in `~/.myshellrc`, which this
  project does not do;
- the classifier reports ANY ambiguous verdict over `shellrc_text` — name the file and the line
  number in the reason.
Each reason must name the file and say what the user should do, because plan 15.8-06 prints it
verbatim AND raises it as a `ShellrcRefusal`.

**`consolidated_body(shellrc_text: str, myshellrc_path: Path) -> str`** returns the text with
every REWRITABLE line replaced by a single commented line carrying a short reason followed by the
original line's exact text. Nothing else in the text is altered: same line count, same order,
same trailing whitespace on untouched lines. It assumes `consolidation_refusal` already returned
None, so it never has to decide what to do with an ambiguous line — state that in its docstring,
and make it a precondition rather than a defensive branch.

**`sources_file(text: str, target: Path) -> bool`** — the one public predicate for "does this
text live-source that file". True for a rewritable OR an ambiguous verdict; False otherwise.
Docstring must say it is deliberately BROADER than the rewriter and why: its caller

reaching the file.

**`remove_source_block(path: Path) -> None`** — mirror `remove_managed_block` exactly: a missing
