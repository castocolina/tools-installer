  <behavior>
**The property this test creates, stated precisely before any code.** The defect this phase
exists to kill is not "a PATH assignment appears in our source". It is "our source emits, into a
file a shell re-sources, a PATH assignment that PREPENDS to the existing PATH without checking
first" — a self-referential assignment whose value contains `$PATH`. That shape accumulates one
extra copy per evaluation, which is the bug. A TOTAL assignment, whose value does not reference
`$PATH`, replaces PATH outright and is idempotent by construction no matter how often it runs;
it cannot produce a duplicate and is not the defect. The needle targets the accumulating shape,
and that narrowing is the invariant's definition, not a concession to make a test pass.

Write the test first and watch it pass for the right reason. Then confirm it can actually fail:
copy the scan over a temporary directory built under `tmp_path` that contains a throwaway `.py`
file carrying an unguarded accumulating line, and assert the checker reports it. Never seed a
violation into a committed source file. A source-scanning invariant that has never been seen to
fail is not an invariant.

Factor the scan into one small module-level helper in the test file — something like
`_accumulating_path_lines(root: Path) -> list[tuple[Path, int, str]]` — so the real scan and the
seeded-violation proof run the SAME code against different roots. A second, test-only copy of the
scan logic would let the two drift, and the copy that guards the repo is the one that would rot.

`test_no_unguarded_path_prepend_under_installer`:
- Walk every `*.py` file under the `installer/` package directory, resolved relative to the test
  file (`Path(__file__).resolve().parent.parent / "installer"`), recursively, sorted so a failure
  message is stable run to run.
- A line is a HIT when both hold: (a) a regex finds an assignment to the PATH name, allowing an
  optional `export` prefix, with a negative lookbehind on a word character so a longer variable
  name ending in `PATH` is not a false hit; and (b) the remainder of the line, AFTER that match,
  references the PATH variable expansion. Both conditions together are what identify a prepend.
- A hit is EXEMPT when either: (1) the case-guard opening appears on the hit line, or on either
  of the two source lines immediately above it — a two-line lookback, because the emitter's line
  is a single f-string today but the formatter may wrap it, and nothing resembling that opening
  ever sits near an unguarded rc-writing prepend; or (2) its file is `installer/rcclean.py`.
- Assert the list of NON-exempt hits is empty.
- LIVENESS, asserted in the same test and load-bearing: assert the scan found at least one hit
  inside `installer/shellrc.py`. That hit is the emitter's own guard line. This is what stops the
  failure mode where someone answers a red test by shrinking the needle until it matches nothing
  — that move now fails here instead of silently deleting the invariant. State that reason in a
  comment directly above the assertion.
- Write the failure message to name the offending file and line number, so a future violation
  reads as an instruction rather than a puzzle.
- Document in the test's docstring, in this order: what the accumulating shape is and why only it
  is the defect; that `installer/executors.py:31-38` (an `sh -c` command prefix built from a
  complete `shell_path()` value) and `installer/systemd_daemon.py:253-265` (a systemd unit
  `Environment=` line) are total assignments that fall outside the needle by that property, write
  no rc file, and are never re-sourced — named explicitly so a reader can tell a reasoned
  exclusion from an oversight; and exactly what the `rcclean.py` allowance is and why it is
  narrow — that module classifies and strips OTHER tools' lines and writes no PATH line of its
  own, so the allowance covers its documentation of the shapes it recognizes, never a second
  emitter.

`test_managed_block_output_contains_no_bare_assignment_line`:
- Assert that no line of `managed_block([dir_a, dir_b])` STARTS with a PATH assignment (with or
  without an `export` prefix) — the exact structural property `installer/rcclean.py:16`'s regex
  keys on. This is the emitted-output twin of plan 15.8-02's scanner-side test: one asserts the
  scanner ignores us, this one asserts we never produce the shape it looks for.
  </behavior>
