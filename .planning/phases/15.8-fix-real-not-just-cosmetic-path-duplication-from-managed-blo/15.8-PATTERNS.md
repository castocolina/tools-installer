## Pattern Assignments

### 1. The new reusable emitter — where it lives and what to copy

**Architecture split (`.claude/architecture.md` rule 4 + the file's own module docstring):** `installer/shellrc.py` is already the pure-string-building layer — every function in it (`managed_block`, `apply_block`, `strip_block`, `write_pnpm_home`'s block-assembly half) takes plain data (`list[Path]`, `str`) and returns a `str`; IO (`.read_text()`/`.write_text()`) is confined to a handful of thin functions at the bottom (`write_myshellrc`, `write_managed_path`, `ensure_source`, `write_pnpm_home`) that call the pure builders and then touch disk. `setup.py` never appears in this module at all — wiring stays out per rule 4. **The new emitter belongs in `installer/shellrc.py` itself, as a new pure function beside `managed_block`**, exactly as CONTEXT's "Claude's Discretion" section already resolves it (no new module needed — both call sites, `managed_block()` and `write_pnpm_home()`, already live in this file).

**Closest existing function to copy shape from:** `managed_block()` itself (`installer/shellrc.py:101-111`):
```python
def managed_block(bin_dirs: list[Path]) -> str:
    """Marker-delimited block exporting each bin dir onto PATH.

    Paths are double-quoted but not otherwise escaped: they come only from the
    trusted registry and Path.home(), never from user input. Do not feed
    user-supplied paths here without shell-quoting first.
    """
    lines = [_PATH_BEGIN]
    lines.extend(f'export PATH="{directory}:$PATH"' for directory in bin_dirs)
    lines.append(_PATH_END)
    return "\n".join(lines)
```
Copy: the docstring's trust/quoting caveat (still true — paths come from the registry/`Path.home()`, never user input), the plain `list[Path] -> str` signature shape, and the fact that it returns a *fragment* (one line, or the whole block) rather than writing anything.

**What to deliberately differ on:** the per-directory line itself changes from `export PATH="{dir}:$PATH"` to the case-guarded form `installer/rcclean.py:61-70`'s docstring already names as the reference idiom:
```
case ":$PATH:" in
  *":{dir}:"*) ;;
  *) export PATH="{dir}:$PATH" ;;
esac
```
`rcclean.py`'s comment ("pnpm's own... form is self-deduping... nothing safe or necessary to strip") is the exact citation to anchor the new shape against — it documents that this codebase already trusts this idiom as safe to leave alone, which is also why `find_duplicate_path_lines` must keep NOT flagging it (see item 3).

A small pure helper (e.g. `_path_guard(directory: Path) -> str`, or inlined directly in `managed_block()`) is the natural granularity: it takes one `Path`, returns the multi-line case-guard fragment, and both `managed_block()` (loop over `bin_dirs`) and `write_pnpm_home()` (single dir) call it. This mirrors how `managed_block()` already loops a per-directory string-builder (today: an f-string; tomorrow: this helper) — no new architectural seam, just a new pure function beside an existing one.

### 2. Block writing/reading contract the new emitter must fit into

Three existing functions in `installer/shellrc.py` form the contract:

- **`apply_block(content, block, begin=_PATH_BEGIN, end=_PATH_END)`** (`installer/shellrc.py:114-131`) — the idempotent replace-or-append mechanism D-01's automatic migration relies on. Confirmed by reading in full: it finds the *last* `begin` marker, pairs it with the following `end`, and replaces that whole span with the new `block` text — so simply changing what `managed_block()` returns is sufficient; no separate migration code is needed. This is the load-bearing read for D-01 and needs no change.
- **`existing_managed_bin_dirs(path, exists=...)`** (`installer/shellrc.py:72-98`) — the reader that must change in lockstep. Today it does exact-string matching:
  ```python
  prefix = 'export PATH="'
  suffix = ':$PATH"'
  ...
  for line in lines[start + 1 : stop]:
      if not (line.startswith(prefix) and line.endswith(suffix)):
          continue
      candidate = Path(line[len(prefix) : -len(suffix)])
  ```
  Once `managed_block()` emits a multi-line `case`/`esac` fragment per directory instead of one `export PATH=...` line, this prefix/suffix match will silently return `[]` for freshly-written files (and will also still parse OLD pre-migration files that still use the plain form during the window before `apply` regenerates them — both shapes may legitimately appear on disk at different times, so the reader likely needs to recognize both, or the pure fragment builder should expose the directory list in a form this reader can re-derive without re-parsing shell syntax). This is a P0 lockstep edit, explicitly flagged by CONTEXT's canonical refs.
- **`write_pnpm_home(rc_path, pnpm_home)`** (`installer/shellrc.py:200-219`) — D-02's second target. Currently builds its own inline block:
  ```python
  block = "\n".join((
      _PNPM_BEGIN,
      f'export PNPM_HOME="{pnpm_home}"',
      f'export PATH="{pnpm_home}:$PATH"',
      _PNPM_END,
  ))
  ```
  Copy its `apply_block(...)`-then-`updated == existing`-changed-check-then-write structure verbatim; only the PATH line (not the `PNPM_HOME=` line, which is a plain assignment, not a PATH mutation) is replaced with the new case-guard emitter.

### 3. File-level migration/consolidation (D-04)

No exact precedent exists for "migrate file A's content into file B and leave one canonical file" — CONTEXT's own research note confirms this ("No existing code has any awareness of a generic `.shellrc` today"). Three partial analogs, each contributing a different half of the needed discipline:

- **`installer/omz.py::write_plugins`** (`installer/omz.py:432-478`) — closest for the *content-merge-with-provenance* half. Pattern to copy: read existing content (`_read_rc`), compute what needs to move/change, write a **transactional record before the mutating write** (`_record_owned` is called before `_atomic_write`), and roll the record back on a failed write (`except OSError: ... restore ...; raise`). For D-04, this shape maps to: record (in a comment block or state file) that `~/.shellrc`'s content was consolidated, THEN perform the write, with rollback on failure — never silently lose provenance of what was merged.
- **`installer/daemon.py::_is_our_wrapper` / `install_wrapper`** (`installer/daemon.py:294-321`) — the ownership-sentinel discipline: *never touch a same-named artifact this project did not create.* Direct quote of the rule to carry into D-04: "Refuses to overwrite a same-named file it does not own (no sentinel present) rather than clobbering an unrelated file a user or another tool placed there." `~/.shellrc` is, by construction, a file this project never wrote (no `_PATH_BEGIN`/`_SOURCE_BEGIN` markers in it) — so the correct application of this rule is the *inverse* of `install_wrapper`'s check: `~/.shellrc` is presumptively foreign content that must be preserved verbatim (copied forward), never silently deleted or overwritten, and `~/.myshellrc` (the file this project DOES own and already writes marker blocks into) is the only file the consolidation should mutate.
- **`installer/env_redirect.py::competing_conf_paths`** (`installer/env_redirect.py:265-291`) — the closest match for *detecting a competing file this project doesn't own* (Phase 15.7 precedent). Pattern to copy: a pure, read-only scan function that returns the list of "other" paths carrying the same responsibility (there: other `.conf` files assigning the same systemd variable; here: `~/.shellrc` existing alongside `~/.myshellrc`), returned as data for the caller to act on or merely report — it does not itself delete or merge anything, keeping the pure/IO split rule 4 requires.

**Ownership rule the consolidation must respect (synthesized from all three):** `~/.shellrc`'s content is foreign and must never be deleted without first being copied forward (D-04's own "reversibility: reversible... not a deletion of anything without first copying it forward"); `~/.myshellrc` is the only file this project treats as owned and may freely edit via `apply_block`; the merge should either preserve `~/.shellrc`'s content verbatim above `~/.myshellrc`'s own managed markers (CONTEXT's own discretion note's first option) or record what was migrated the way `omz.py` records owned plugin names — but must not silently overwrite `~/.myshellrc`'s existing managed block area with unmanaged foreign content, since `apply_block` would then corrupt on the next re-apply if the foreign content itself happened to contain marker-like lines. No sentinel/ownership check on `~/.shellrc` itself is needed (unlike `daemon.py`'s wrapper case) — its mere existence is the sole trigger, since this project never owns it.

### 4. Tests — location, tmp_path HOME pattern, and real-shell invocation precedent

**Location:** `tests/test_shellrc.py` — existing tests already use `tmp_path` directly as file targets (`tmp_path / ".myshellrc"`), never monkeypatching `Path.home()` for pure-function tests since `managed_block`/`apply_block`/`write_myshellrc` all take explicit `Path` arguments (`tests/test_shellrc.py:114-133`). New unit tests for the emitter's fragment shape and `existing_managed_bin_dirs`'s round-trip follow this exact shape — no `monkeypatch` needed unless testing `collect_bin_dirs`'s `home` injection param (`test_collect_bin_dirs_expands_user`, `tests/test_shellrc.py:48-53`, which does use `Path.home()` comparison, not monkeypatch — the function takes `home:` as an explicit keyword instead).

**Real-shell invocation precedent — exact helper shape to follow.** `tests/test_prune_tmp_linux_sh.py:36-47`:
```python
ROOT = Path(__file__).resolve().parent.parent
SCRIPT = ROOT / "scripts" / "prune-tmp-linux.sh"
pytestmark = pytest.mark.skipif(shutil.which("bash") is None, reason="bash not on PATH")

def _run(*args: str, home: Path, cwd: Path | None = None) -> "subprocess.CompletedProcess[str]":
    env = {"PATH": os.environ.get("PATH", "/usr/bin:/bin"), "HOME": str(home)}
    return subprocess.run(
        ["bash", str(SCRIPT), *args],
        env=env,
        cwd=None if cwd is None else str(cwd),
        capture_output=True,
        text=True,
        check=False,
    )
```
and `tests/test_prune_user_tmpdir_sh.py:101-141`'s equivalent `_run` for the macOS wrapper script. Both share: (a) a module-level `pytestmark = pytest.mark.skipif(shutil.which("bash") is None, ...)` guard so the suite degrades gracefully on a bash-less CI image, (b) a minimal, explicit `env={"PATH": ..., "HOME": str(tmp_path-derived-home)}` — never `os.environ` passed wholesale, so the test is hermetic and deterministic per `.claude/testing.md`'s "mock filesystem/HOME via tmp_path" rule, (c) `capture_output=True, text=True, check=False` so assertions run against `stdout`/`returncode` rather than relying on an exception.

**For the new "source this block N times, assert PATH has one copy" test:** write the emitted block (via `managed_block([...])`, the real production function — not a hand-copied fixture) into a `tmp_path` file, then invoke `bash -c 'source "<file>" && source "<file>" && source "<file>" && echo "$PATH"'` with `env={"PATH": "<seed>", "HOME": str(tmp_path)}` following the `_run` shape above, and assert the directory appears exactly once in the resulting `$PATH` split on `:`. This is a genuinely new test (no existing shellrc test currently sources anything through a real shell — all current `test_shellrc.py` tests assert on the *string* `managed_block()` returns, never on shell RUNTIME behavior), which is precisely the gap this phase's whole premise is about (file-content idempotency already proven; runtime-effect idempotency was not). Use the `prune-tmp-linux.sh` tests' `pytestmark`/`env=` shape, not their `SCRIPT` constant (there is no script file here — the "script" is the string `managed_block()` returns, written to a tmp file by the test itself).

### 5. Doctor/status integration

**Code path:** `installer/doctor.py::audit_path` (`installer/doctor.py:15-27`) computes `duplicated` by counting `PATH.split(":")` entries per declared bin dir; `installer/guidance.py:78-86` turns each duplicate into a `Guidance` object with the exact copy `"{directory} duplicated on PATH"` / `"Harmless — transient duplicates clear when you open a new shell."`. This module is a pure `PATH`-string classifier with **zero knowledge of shellrc.py's block shape** — it reads the live `$PATH` environment variable, not any rc file — so it needs **no code change** for D-01/D-02/D-03 to land; its findings should simply stop firing (for a freshly-sourced shell) once the case-guard form prevents real accumulation, exactly as CONTEXT's Integration Points section states.

**Any test pinning current (buggy) behavior?** No. Searched `tests/` for `audit_path`/`DoctorReport(duplicated=` callers constructing a scenario with an already-duplicated `$PATH` string — the existing doctor tests construct `path_value` strings directly (synthetic PATH values passed as plain data), so they test the counting logic in isolation, not the *cause* of duplication. None of them assert or depend on shellrc.py's plain-export emission shape, so no doctor/status test needs updating as part of this phase — only the new shellrc-level tests (item 4) need to exist to prove the root cause is fixed. The already-honest "Harmless — transient duplicates clear when you open a new shell" guidance text (`installer/guidance.py:83`) also needs no wording change: it was already correctly describing session-scoped staleness, D-01's note explicitly says this messaging pattern is not a gap this phase needs to close further.

## Shared Patterns

### Pure/IO split (rule 4)
**Source:** `installer/shellrc.py` module docstring + existing `managed_block`/`apply_block` vs. `write_myshellrc`/`write_pnpm_home` split.
**Apply to:** the new emitter function — must be a pure `Path -> str` (or `list[Path] -> str`) builder with no `.read_text()`/`.write_text()` inside it, called from the existing thin IO wrappers.

### Marker-delimited idempotent block replacement
**Source:** `installer/shellrc.py:114-131` (`apply_block`).
**Apply to:** every call site that writes a block (`managed_block()`'s caller, `write_pnpm_home`, and D-04's `~/.myshellrc` consolidation write) — always go through `apply_block`, never a bespoke string-splice.

### Self-deduping shape must stay recognized by rcclean.py
**Source:** `installer/rcclean.py:61-70` (`find_duplicate_path_lines` docstring + its `_PATH_EXPORT` regex, which only matches a *plain* `export PATH=...` / `PATH=...` line, not a `case`/`esac` block).
**Apply to:** the new emitter's output. Because `_PATH_EXPORT` structurally cannot match a multi-line `case ... esac` block (it operates line-by-line against a single-assignment regex), the new shape is automatically NOT flagged by `find_duplicate_path_lines` without any change to `rcclean.py` — confirmed by reading the regex and the per-line loop in full. If a future variant of the emitter ever collapses the guard onto a single line matching `_PATH_EXPORT`'s shape, `rcclean.py` would need a compatibility update; the multi-line `case`/`esac` form does not need one. Verify this with a direct unit test (`find_duplicate_path_lines` fed the new `managed_block()` output, asserting an empty result) rather than assuming from static regex reading alone.

### Ownership/foreign-file discipline
**Source:** `installer/daemon.py:294-321` (`_is_our_wrapper`), `installer/env_redirect.py:265-291` (`competing_conf_paths`).
**Apply to:** D-04's `~/.shellrc` detection — treat it as always-foreign (no sentinel check needed, since this project never writes that filename), never delete without copying forward, and only ever mutate `~/.myshellrc` (the file this project owns).
