# 15.8-04 — D-04 `~/.shellrc` consolidation

## What shipped

`consolidate_shellrc(shellrc_path, myshellrc_path)` plus two precondition
helpers (`consolidation_precondition` for hazards, `backup_precondition` for an
existing backup) and a `ShellrcConsolidation` result carrying a status and a
refusal reason.

On the happy path it copies the original's content forward into `~/.myshellrc`,
backs the original up to `~/.shellrc.tools-installer.old` via the project's
existing `staged_sibling` / `OLD_SUFFIX` convention, and replaces `~/.shellrc`
with a marked stub that sources the canonical file — so exactly one file carries
configuration and the user can undo the whole thing with a single `mv`.

**Step order (load-bearing, pinned by tests):** absence → hazards → identity-bound
snapshot and UTF-8 decode → owned-stub check returning `already` → backup
validation against a snapshot guaranteed not to be a stub. Validating the backup
before the stub check would make every repeat run refuse, because after a
successful run the backup holds the original while `~/.shellrc` holds the stub,
so a bytes comparison always differs. This contradiction was found by cross-AI
review cycle 3 and fixed in planning.

**Write order:** copy-forward → backup → stub. The stub is written last, so
every intermediate crash state leaves the content in at least two places.

## Refusals (nothing is written in any of these)

| Case | Why |
|---|---|
| Either path is a symlink | `atomic_write_text` deliberately follows symlinks (`installer/atomic.py:42`), so `~/.shellrc -> ~/.myshellrc` would write the stub INTO the canonical file and leave it sourcing itself |
| Both paths resolve to one file | Same destruction, reached by hard link or alias instead |
| Original is not valid UTF-8 | A typed refusal with an actionable message, rather than a `UnicodeDecodeError` escaping the UI's `OSError` handling |
| Existing backup differs in bytes or mode | It may be another tool's, or an older version; accepting it would make "reversible with one `mv`" false |

## Verification

Beyond the plan's own tests, the orchestrator re-verified the five
safety-critical behaviors directly against real files in a scratch HOME before
committing:

1. Normal run consolidates, content lands in `~/.myshellrc`, backup is
   byte-identical to the original; **second run returns `already` and writes
   nothing**.
2. `~/.shellrc -> ~/.myshellrc` symlink: **refused**, `~/.myshellrc` byte-identical.
3. `~/.myshellrc -> ~/.shellrc` symlink (other direction): **refused**, original
   byte-identical.
4. Non-UTF-8 original: **refused**, file untouched, no backup created.
5. Stale backup with different bytes: **refused**, both files untouched.
