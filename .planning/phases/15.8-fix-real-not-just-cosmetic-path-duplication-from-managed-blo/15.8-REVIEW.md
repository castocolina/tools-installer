## Summary

The PATH emitter (`path_export_guard`) is solid: the `${PATH:+:$PATH}` /
`${PATH-}` pair, the dual-spelling guard, the declared-spelling write, and the
`rcclean` non-interference are all correct and genuinely proven live. I found
nothing wrong with priority 2 *as it applies to the PATH block itself*, and
priority 4 is clean in the one place the prompt asked about: `sources_file`'s
`unprovable` is never folded into `yes` by any caller (`installer/app.py:242`
and `:246` branch on it explicitly and correctly).

The `~/.shellrc` consolidation is where this phase breaks. I reproduced **three
independent paths that end in a `SIGSEGV`-on-startup shell or in silent
corruption of the user's own content**, all verified end-to-end by running the
real production functions and then sourcing the files they produced in real
bash. The most serious one (CR-01) needs no classifier hole at all: the
single-route wiring in `configure_path` creates a brand-new mutual-source loop
between `~/.bashrc` and `~/.myshellrc` out of two files that had no loop before
the run. The others (CR-02, CR-03, CR-04) are classifier/heredoc-detector holes
where a shape all three shells execute is classified `none` — the exact
direction the architecture doc claims is impossible ("Every other live mention
in command position ... refuses the operation", "A file containing any
here-document ... is left untouched"). Both claims are provably false.

## Critical Issues

### CR-01: `configure_path` creates a fresh `.bashrc` ⇄ `.myshellrc` source loop — verified SIGSEGV

**Severity:** CRITICAL (BLOCKER)
**File:** `installer/app.py:216-251`, with the incomplete loop check at `installer/shellrc.py:654-659`

**Issue.** `consolidation_refusal` checks exactly one loop arm: does
`~/.myshellrc` already source `~/.shellrc` (shellrc.py:654). It never asks the
other, equally reachable question: does the content being **copied forward into
`~/.myshellrc`** source one of the rc files that `configure_path` is about to
wire back to `~/.myshellrc` at `app.py:251`. When `~/.shellrc` sources
`~/.bashrc`, consolidation copies `. ~/.bashrc` into `~/.myshellrc`, then
`sources_file(bashrc_text, ~/.shellrc)` correctly answers `no` (the `.bashrc`
does not source `.shellrc`), so `ensure_source` adds `. ~/.myshellrc` to
`.bashrc`. The result is `.bashrc → .myshellrc → .bashrc → …`.

**Reproduction (run, not hypothesised).** Pre-state — no loop exists:

```
~/.bashrc    : export KEEP=1
~/.shellrc   : . "$HOME/.bashrc"
~/.myshellrc : (absent)
```

Call `configure_path(..., shellrc_path=~/.shellrc, rc_paths=[~/.bashrc])`.
Returned outcome: `ShellrcConsolidation(status='consolidated')` — a reported
success. Post-state:

```
~/.bashrc    : export KEEP=1
               # >>> tools-installer source >>>
               [ -f ".../.myshellrc" ] && . ".../.myshellrc"
               # <<< tools-installer source <<<
~/.myshellrc : # >>> tools-installer consolidated shellrc >>>
               . "/…/.bashrc"
               # <<< tools-installer consolidated shellrc <<<
               # >>> tools-installer path >>> …
```

`bash -c '. ~/.bashrc'` on that tree: **`Segmentation fault`, exit 139.** The
user's login shell no longer starts. A realistic trigger is the common
shell-dispatch idiom inside a shared `~/.shellrc`:
`[ -n "$BASH_VERSION" ] && [ -f ~/.bashrc ] && . ~/.bashrc` — that line
classifies `none` (it does not mention `~/.myshellrc`), is copied forward
verbatim, and produces the same loop.

**Fix.** Before `ensure_source` runs, refuse (or skip the rc) when the
consolidated body live-sources that rc. `sources_file` already answers this
question — it just is never asked in this direction. In `consolidate_shellrc`,
take the rc paths as a parameter and add to `consolidation_refusal`:

```python
for rc_path in rc_paths:                       # the paths configure_path will wire
    reaches_rc, number, _ = _text_sources_target(shellrc_text, rc_path)
    if reaches_rc and number is not None:
        return (
            f"{shellrc_path} line {number} sources {rc_path}; consolidating it "
            f"and then wiring {rc_path} to {myshellrc_path} would create a "
            f"sourcing loop. Consolidate by hand."
        )
```

### CR-02: a leading redirection hides a live `source` from the classifier — verified SIGSEGV

**Severity:** CRITICAL (BLOCKER)
**File:** `installer/shellrc.py:336-360` (`_command_head`), `:441-453` (`_inspect_source_line`)

**Issue.** POSIX allows redirections to precede the command word. `_command_head`
only strips reserved words, assignment words and `command`/`builtin` wrappers;
a leading `>/dev/null` or `2>/dev/null` becomes `words[0]`, is neither a source
command nor dynamic, and `_inspect_source_line:452` `continue`s. The line is
classified **`none`** — not `ambiguous` — so `consolidation_refusal` returns
`None` and the line is copied forward verbatim.

**Verified in all three shells.** With `~/.myshellrc` containing `MARK=hit`:

```
$ cat t1.sh
>/dev/null . /…/.myshellrc
echo "MARK=$MARK"
$ bash t1.sh   →  MARK=hit
$ sh   t1.sh   →  MARK=hit
$ zsh  t1.sh   →  MARK=hit
```

**End-to-end reproduction.** `~/.shellrc` = `export FOO=1\n2>/dev/null . ~/.myshellrc\n`.
`consolidate_shellrc` returns `status='consolidated'` and writes a
`~/.myshellrc` whose consolidated block contains the untouched line
`2>/dev/null . ~/.myshellrc`. Sourcing the produced `~/.myshellrc` in bash:
**`Segmentation fault`, exit 139.**

**Fix.** Treat any word before the command word that is not a recognised prefix
as *unknown*, not as the command. In `_command_head`, detect a leading
redirection token (`re.match(r"^\d*[<>]", word)`) and either strip it while
setting `had_prefix = True` (so the line can still be seen as a source and can
only ever be `ambiguous`), or flag the segment as unparsable so
`_inspect_source_line` returns `has_unresolvable_source=True`.

### CR-03: `<<\EOF` and `cmd>f<<EOF` are not recognised as here-documents — verified content corruption

**Severity:** CRITICAL (BLOCKER)
**File:** `installer/shellrc.py:521-528` (`_has_here_document_opener`)

**Issue.** The regex requires the delimiter to be `'…'`, `"…"`, or
`[A-Za-z_][A-Za-z0-9_-]*` immediately after `<<-?\s*`. The standard
backslash-quoted delimiter form `<<\EOF` (the exact equivalent of `<<'EOF'`)
starts with `\` and is not matched. The `(?:^|[\s;|&({])` prefix also misses
`cat >file<<EOF`. When the opener is missed, the here-document **body is scanned
as ordinary shell lines**, and `consolidated_body:596-599` will comment out a
body line — the precise "wholesale comment-out silently destroys content"
outcome the refusal exists to prevent.

**Reproduction.** `~/.shellrc`:

```
cat <<\EOF > ~/notes.txt
To load the env by hand run:
. ~/.myshellrc
EOF
```

`_has_here_document_opener("cat <<\\EOF > ~/notes.txt")` → `False`.
`consolidation_refusal(...)` → `None`. `consolidate_shellrc` → `consolidated`.
The block written into `~/.myshellrc`:

```
cat <<\EOF > ~/notes.txt
To load the env by hand run:
# tools-installer disabled this line; /…/.myshellrc is now the file it was sourcing: . ~/.myshellrc
EOF
```

The user's document text has been silently rewritten. (Recoverable from the
`.tools-installer.old` backup — which is why this is CRITICAL, not
unrecoverable.)

**Fix.** Extend the delimiter alternation and drop the restrictive prefix class:

```python
re.search(r"<<-?\s*(?:'[^']*'|\"[^\"]*\"|\\?[A-Za-z_0-9][A-Za-z0-9_.-]*)", line)
```

and exclude the here-string `<<<` explicitly (`(?!<)` after `<<`) so it is not
newly false-positived.

### CR-04: a backslash line continuation inside the path hides the source entirely

**Severity:** HIGH (BLOCKER)
**File:** `installer/shellrc.py:497-507` (`_classify_source_lines`), `:472-482`

**Issue.** `_classify_source_lines` tracks `continued_before` but never *joins*
continued lines. A continuation that splits the **argument** therefore yields
two lines that each classify `none`:

```
. ~/.mysh\
ellrc
```

`classify_source_line(". ~/.mysh\\", target)` → `verdict='none'` (the argument
resolves to `~/.mysh\`, a different file); `classify_source_line("ellrc")` →
`verdict='none'`. `consolidation_refusal` → `None`; `sources_file` → `"no"`.
Bash removes the `\<newline>` pair and executes `. ~/.myshellrc` — a
self-sourcing `~/.myshellrc` after consolidation, same SIGSEGV outcome as CR-02.

Note the asymmetry that shows the gap is real: the *safe* continuation shapes
(`. ~/.myshellrc \` and `. \` + newline) are both correctly refused; only the
shape that splits mid-argument escapes.

**Fix.** Join physical lines on a trailing unescaped `\` into one logical line
before classifying, or — cheaper and consistent with house doctrine — refuse
the whole file whenever any line ends in an unescaped backslash *and* the joined
logical line mentions the target's basename.

### CR-05: a non-regular `~/.shellrc` (FIFO) hangs the installer forever

**Severity:** HIGH (BLOCKER)
**File:** `installer/shellrc.py:749-760` (`_snapshot`), `:703-725` (`consolidation_precondition`)

**Issue.** `consolidation_precondition` checks symlink-ness and same-file
identity but never that `~/.shellrc` is a **regular file** — even though
`backup_precondition:791-795` makes exactly that check for the backup and
documents why. `_snapshot` then does `os.open(path, O_RDONLY | O_NOFOLLOW)`. On
a FIFO with no writer, that call **blocks indefinitely**, inside the
`try/except OSError` that was supposed to make an unreadable file a typed
refusal.

**Reproduction.** `mkfifo ~/.shellrc; consolidate_shellrc(...)` under
`timeout 8` → exit 124 (hung). In the TUI this freezes the apply worker with no
recovery; on the CLI it hangs `make fix` / `make setup`.

**Fix.** Add to `consolidation_precondition`, before any open:

```python
try:
    st = os.lstat(shellrc_path)
except OSError:
    return f"{shellrc_path} could not be inspected; refusing rather than guessing what it is."
if not stat.S_ISREG(st.st_mode):
    return f"{shellrc_path} is not a plain file; refusing to consolidate it."
```

(and/or pass `os.O_NONBLOCK` in `_snapshot`'s open).

### CR-06: a non-UTF-8 `~/.myshellrc` raises an uncaught `UnicodeDecodeError`

**Severity:** HIGH (BLOCKER)
**File:** `installer/shellrc.py:894` and `installer/shellrc.py:906`

**Issue.** A non-UTF-8 `~/.shellrc` is handled as a typed refusal
(`shellrc.py:878-887`), but the two reads of `~/.myshellrc` — `read_text()` at
:894 and `pre_myshellrc_bytes.decode("utf-8")` at :906 — are unguarded.
`UnicodeDecodeError` is a `ValueError`, so `installer/ui_common.py:54`
(`except (OSError, CommandError, ShellrcRefusal)`) does **not** catch it: the
TUI crashes instead of showing an error, and `main`/`_run_fix` print a
traceback.

**Reproduction.**

```
~/.shellrc   : export A=1
~/.myshellrc : \xff\xfe bad
```

```
UnicodeDecodeError: 'utf-8' codec can't decode byte 0xff in position 0
  at installer/shellrc.py:894 in consolidate_shellrc
```

**Fix.** Read `~/.myshellrc` as bytes once and decode inside a
`try/except UnicodeDecodeError` that returns the same shape of typed refusal
already used for `~/.shellrc`; reuse the single `pre_myshellrc_bytes` read for
both the refusal check and the rollback snapshot instead of reading twice.

## Warnings

### WR-01: `consolidated_body` is not line-preserving — CRLF is normalised and `\x0c`/`\x85`/` ` split a real line in two

**Severity:** MEDIUM (WARNING)
**File:** `installer/shellrc.py:581-593`

The docstring promises "same line count, same order, same trailing whitespace on
every untouched line", and the architecture doc promises a verbatim
copy-forward. `str.splitlines()` + `"\n".join()` breaks both: it consumes `\r`
and also treats `\x0b`, `\x0c`, `\x1c-\x1e`, `\x85`, ` `, ` ` as line
breaks — characters a shell treats as **ordinary characters inside a line**.

Verified:

```
in : 'export A=1\r\nexport B=2\r\n'   out: 'export A=1\nexport B=2\n'      # CRLF silently dropped
in : 'export A=1\x0cexport B=2\n'     out: 'export A=1\nexport B=2\n'      # one shell line became two
in : 'export MSG="a b"\n'        out: 'export MSG="a\nb"\n'           # string content changed
```

`test_a_crlf_original_is_backed_up_byte_for_byte` pins the **backup**, which
hides this: the live copy in `~/.myshellrc` is the one that changed.

**Fix.** Split with `re.split(r"(?<=\n)", text)` (or `text.split("\n")`) so only
`\n` is a separator, and re-join with `""`/`"\n"` accordingly. Same change is
needed in `consolidation_refusal:604,646` and `_classify_source_lines:501` so
the three line indexings stay aligned.

### WR-02: refusing when `~/.myshellrc` is a symlink is over-refusal, and contradicts what the module does one call later

**Severity:** MEDIUM (WARNING)
**File:** `installer/shellrc.py:712-718`

The stated reason — "writing the consolidated content through it would replace
its target" — is what `atomic_write_bytes` does **by design** for every
project-owned file (`installer/atomic.py:42`, documented there as the correct
behaviour for a dotfile-manager setup), and is exactly what
`write_myshellrc`/`apply_block` do to that same symlinked `~/.myshellrc`
milliseconds later at `installer/app.py:230`. The refusal for `shellrc_path` is
correct (foreign file, the stub write would clobber the link's target); the one
for `myshellrc_path` is not. Net effect: any user whose `~/.myshellrc` is
symlinked into a dotfiles repo *and* who has a `~/.shellrc` gets a permanent
refusal, plus WR-04's permanent Doctor error, for a setup the rest of the
project supports.

**Fix.** Drop the `myshellrc_path.is_symlink()` arm; the `samefile` /
`realpath` checks at :723-742 already cover the only real hazard (the two paths
resolving to one file).

### WR-03: `. '$HOME/.myshellrc'` is classified `rewritable` although no shell expands it

**Severity:** MEDIUM (WARNING)
**File:** `installer/shellrc.py:375` (`_expanded_argument` strips quotes before expanding), pinned by `tests/test_shellrc.py:1520`

`_expanded_argument` deletes `'` and `"` *before* deciding whether `$HOME`
expands, so a single-quoted argument is treated as an expanded path. In a real
shell it is a literal relative path:

```
$ HOME=$D bash -c ". '\$HOME/.myshellrc'"
bash: $HOME/.myshellrc: No such file or directory
```

The consequence is a content change based on a false premise: `consolidated_body`
comments out a line that never sourced the target. The test at
`tests/test_shellrc.py:1520` asserts this wrong verdict as correct behaviour, so
the defect is pinned rather than caught.

**Fix.** In `_expanded_argument`, refuse (return `None`) when the raw argument is
single-quoted and contains `$` or `~`; only strip double quotes before
expansion.

### WR-04: a permanently un-consolidatable `~/.shellrc` makes Doctor's apply fail on every future run, with no opt-out

**Severity:** MEDIUM (WARNING)
**File:** `setup.py:1021-1029`, `installer/app.py:256-258`

The refusal reasons are, by design, mostly conditions the user is not going to
fix (a here-document, an `eval`, a `source "$ZDOTDIR/x"` — the architecture doc
itself calls these "ordinary rc content"). `_apply_fix` raises `ShellrcRefusal`
unconditionally whenever `configure_path` returns `refused`, and `run_live` maps
that to the screen's error state. So a user with an ordinary `~/.shellrc`
containing a single `eval "$(brew shellenv)"` sees the Doctor apply reported as
**failed, forever**, on every apply, even though PATH wiring succeeded every
time. There is no state, setting, or flag that lets them acknowledge it once.

**Fix.** Record the refusal (e.g. a settings key keyed on the refused file's
digest) and downgrade the second and later occurrences to an informational line,
or surface it as a distinct "wired, with a note" state rather than as the
apply's failure.

### WR-05: the backup is written with a single unchecked `os.write`

**Severity:** LOW (WARNING)
**File:** `installer/shellrc.py:921-927`

`os.write(fd, snapshot.data)` can return a short count (signal interruption, a
full filesystem). The return value is discarded, so a partially-written backup
is then `chmod`'d, marked `created_backup = True`, and the stub write at :944
proceeds — replacing `~/.shellrc` while the promised one-`mv` restore would
restore truncated content. Every other durability claim in this module is
carefully defended; this one is not.

**Fix.** Loop until the buffer is drained (`written = 0; while written < len(data): written += os.write(fd, data[written:])`), or use `os.fdopen(fd, "wb")` and `.write()`.

### WR-06: an `OSError` between the `~/.myshellrc` write and the backup escapes with the content duplicated

**Severity:** LOW (WARNING)
**File:** `installer/shellrc.py:916-927`

If `os.open(backup, O_CREAT|O_EXCL)` or `os.chmod` fails (read-only home, quota,
EPERM), the exception propagates out of `consolidate_shellrc` and
`configure_path` after `~/.myshellrc` has already received the consolidated
block but before `~/.shellrc` was replaced. Unlike the identity-revalidation
path at :929-942, this branch has no rollback, so the foreign content now exists
in both files and will execute twice once the rc files are wired. The docstring's
"every intermediate crash state has the content in at least two places" is true,
but this is a live process that knows what it wrote — the same argument the
:929 branch uses for rolling back.

**Fix.** Wrap the backup creation in `try/except OSError` and reuse the existing
rollback block (restore `pre_myshellrc_bytes` / unlink) before returning a typed
`refused` outcome.
