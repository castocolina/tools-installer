# 15.8-03 — D-02a deletion, the repo invariant, and atomic writes

## What shipped

**Task 1 — D-02a, DELETE branch taken.** `write_pnpm_home` and
`existing_managed_bin_dirs` are gone, along with the `_PNPM_BEGIN`/`_PNPM_END`
markers only they used. Both had zero callers since `installer/install_actions.py`
was deleted in `67d29c3`, no tests, and no vulture whitelist entry (they survived
`make validate` only because `[tool.vulture] min_confidence = 80` sits above the
confidence vulture assigns an unused function). Nothing user-visible is lost:
pnpm's bin dir stays managed through the ordinary `registry.toml` `bin_dir` →
`collect_bin_dirs` → `managed_block` path. The `PNPM_HOME` environment variable
those functions also exported was already written by no live code path — a
pre-existing gap this deletion surfaces rather than creates, with
`installer/ownership.py:446` reading it opportunistically.

**Task 2 — repo-level invariant.** An AST scan over `installer/**/*.py` and
`setup.py` that flags a PATH assignment whose value references `$PATH` (any
expansion spelling), exempting `path_export_guard` and `rcclean.py`'s
documentation. Seeded-violation tests prove it flags a bare prepend near an
unrelated guard opening, a shape assembled from split fragments, every PATH
expansion spelling, and a production expression inside a file named
`rcclean.py`, while `$PATHOLOGICAL` stays unflagged.

**Task 3 — atomic writes.** All four read-modify-write sites in
`installer/shellrc.py` (`remove_managed_block`, `write_myshellrc`,
`write_managed_path`, `ensure_source`) route through `atomic_write_text`, with
failure-injection tests asserting the original file is byte-identical after the
write raises. This closes the "two durability disciplines in one module" wart
honestly rather than documenting it.

**Two real defects found in Task 2's own committed test, fixed in Task 3.**
Neither was reported by either agent; both surfaced when `make validate` was run
against the finished tree.

1. *The liveness assertion was satisfiable by a comment.* It asserted
   `has_guarded_implementation or has_guarded_doc`, where the fallback was a
   substring check for `"case-guarded"` in `shellrc.py`. Investigation found the
   scan reports **zero** hits for `path_export_guard`, so the fallback was
   load-bearing: the half of the test meant to prevent vacuity was itself
   vacuous. The zero-hit result is not an emitter defect — `path_export_guard`
   assembles its assignment through an intermediate local
   (`value = f"{declared}${{PATH:+:$PATH}}"`, then `export PATH="{value}"`), so
   no single reconstructed expression carries both the assignment head and a
   `$PATH` reference. That is exactly the reconstruction limit accepted in this
   plan's Review Dispositions Ledger (cross-AI cycle-3 MEDIUM-03). The fallback
   was removed rather than weakened further. Liveness now rests on the
   seeded-violation tests, which fail if the needle is narrowed until it matches
   nothing, and the comment at the end of the invariant test states plainly why
   no hit is asserted inside the emitter.
2. *The parent map was closed over from inside the enclosing loop* (ruff `B023`),
   so the docstring classification could consult whichever per-file map the loop
   last left behind. It is now bound explicitly through the visitor's
   constructor.
