# Phase 15.8: Fix real (not just cosmetic) PATH duplication from managed-block sourcing — Verification Report

**Phase Goal:** Every PATH entry this installer writes into a shell rc file is self-deduping at runtime — a nested or child shell that re-sources the file N times ends up with exactly one copy of each managed directory, proven by running real shells rather than by asserting on the emitted string — existing installations migrate automatically the next time apply/fix runs through the block-replacement mechanism that already exists, no PATH-writing code in the repo emits a plain unconditional export any more, and a machine carrying a generic `~/.shellrc` ends up with one canonical file (`~/.myshellrc`) plus a marked stub, with the foreign content copied forward before anything is replaced.

**Verified:** 2026-09-23
**Status:** verified (3 gaps found, all repaired post-verification — see Gaps Summary)
**Re-verification:** No — initial verification (no prior `*-VERIFICATION.md` in the phase directory; the #3304 evidence gate is a no-op here).

## Summary judgement

The phase's *behavioural* goal is achieved, and I proved it myself rather than
reading it in a SUMMARY: I emitted real blocks from the shipped code, sourced
them in real bash, zsh and `/bin/sh`, exercised every documented refusal path

### Gaps Summary

Three failures, one root cause, entirely inside the phase's defence-in-depth
layer.

When plan 15.8-03 was executed, the AST invariant's emitter-side liveness
assertion was found to be satisfiable by a comment (it was
`has_guarded_implementation or has_guarded_doc`, the fallback being a substring
search for `"case-guarded"` in `shellrc.py`). Investigation showed the real
reason the fallback was load-bearing: the scan reports **zero** hits inside
`path_export_guard`, because the emitter assembles its assignment through an
intermediate local (`value = f"{declared}${{PATH:+:$PATH}}"`, then
`export PATH="{value}"`), so no single reconstructed expression carries both the
assignment head and a `$PATH` reference. The executor removed the assertion
rather than weakening it further and documented the removal in
15.8-03-SUMMARY.md and in the test's own closing comment. I re-derived that zero
independently.

That was a defensible engineering call — the substituted positive controls (four
seeded fixtures calling the same `_accumulating_hits`) are arguably a stronger
guard against a gutted needle than the removed assertion was, because they
cannot be neutralised by editing the emitter. But three artifacts still assert
the stronger property and now disagree with the tree: plan 15.8-03's
`must_haves` truths 6 and 10, threat `T-15.8-09e`'s "mitigate" disposition, and
`.claude/architecture.md`'s liveness clause — which is exactly the kind of
inherited-doctrine inaccuracy plan 15.8-06's own must-have was written to
prevent. A live residual remains too: the
`(installer/shellrc.py, path_export_guard, False)` exemption matches nothing,
so it is a permanent blanket allowance sitting in the table looking
load-bearing.

**Nothing about the shipped behaviour is in question.** The runtime guarantee —
the entire point of the phase — is independently proven, by me, in real bash,
zsh and `/bin/sh`: five sources, one copy; empty PATH with no empty component;
`set -u` safe; no cwd executable reachable; symlinked-home second spellings
matched; old blocks migrated in one write; `rcclean` unchanged and correct in
both directions; the dead code gone with nothing referencing it; and sixteen
`~/.shellrc` refusal shapes each a byte-exact no-op with a real-shell proof that
the consolidated stub terminates and yields one copy. `make validate` exits 0
and `make test` reports 3142 passed, 5 skipped, 96.09% coverage on the exact
tree verified.

## Resolution (post-verification repair)

All three gaps were repaired rather than overridden. The override block this
report originally proposed was **not** used: it would have written down that a
permanently-inert exemption is acceptable, and the cheaper fix turned out to be
deleting the thing the assertion was supposed to police.

**1 + 2 — the inert exemption is gone, and no exemption can be inert again.**
The `(installer/shellrc.py, path_export_guard, False)` entry was removed from
`exempted_triples`. It bought nothing: the scan produces zero hits for that
function, so the entry could only ever act as a blanket allowance over whatever
the emitter might later build. The emitter's runtime guarantee never depended on
it — that lives in the real-shell repeated-source tests, which observe actual
`$PATH` contents rather than source shape. With the entry gone, a refactor that
makes the emitter's shape reconstructible will fail this test, and re-adding an
exemption becomes a conscious decision with a live hit to point at, which is the
fail-closed direction.

In its place the test now asserts the general property the removed assertion was
reaching for, keyed on node KIND exactly as the must-have requires:

    matched_triples = {(h.file_path, h.enclosing_function, h.is_docstring) for h in hits}
    inert = exempted_triples - matched_triples
    assert not inert, ...

This is stronger than the original must-have. The original pinned two named
exemptions; this pins *every* exemption, including ones a future phase adds.
