<objective>
Teach the pnpm-globals snapshot/replay mechanism about install groups and build allowances,
so the Doctor's reinstall action cannot silently undo the `mmdc` + `puppeteer` co-install
that plan 05-03 ships.

Purpose: Phase 4 shipped `installer/pnpm_globals.py` to replay pnpm's live global set in one
invocation after a pnpm self-update loses it (plan 04-05). It builds
`[pnpm, "add", "-g", *packages]` — packages separated by SPACES. pnpm's own Global Packages
documentation states that space-separated packages in a single command each get their own
isolated `node_modules` tree and lockfile, and that only a comma-separated list bundles them
into one group that resolves peer dependencies against each other. Before this phase that
distinction was invisible, because the residual `kind="node"` set was `mmdc` alone. Plan
05-03 makes `mmdc` + `puppeteer` the first real install group in this catalog, and from that
moment the existing replay actively breaks it: `pnpm list -g --json` reports both packages,
the replay reinstalls them space-separated as two isolated groups, and `mmdc` stops being
able to load `puppeteer`. That is exactly the runtime failure 05-RESEARCH.md Pitfall 1
describes, reintroduced by a remediation action the user is invited to run.

This plan closes it rather than leaving it as a known-broken gap. It is additive: every
existing caller that passes no policy keeps today's exact argv.

Decisions implemented:
- D-01: `mmdc` stays on pnpm, so it remains a pnpm-managed global and stays inside this
  module's scope — the Volta redirect never covers it. That is the whole reason this
  interaction exists and has to be handled here.
- D-03: `puppeteer` is a real catalog entry with its own build allowance, so the replay must
  carry that allowance too or a replay onto a cold browser cache reproduces Pitfall 2.

Output: a registry-derived install policy, a group-aware and allowance-aware argv builder,
the two `setup.py` wiring lines that feed it, and a corrected module docstring.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| pnpm's live global set -> replay argv | Package names read from `pnpm list -g --json` become argv elements of a global install. |
| registry -> build allowances in a replay | Registry-declared names decide which postinstall scripts run unrestricted during a replay. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-14 | Elevation of Privilege | `--allow-build` flags added to the replay argv | high | mitigate | The flags come only from `node_install_policy`, which reads the registry's `allow_build` params — themselves already constrained at load time by plan 05-01's rule that an allowance may only name a package the same invocation installs. The replay additionally emits an allowance only for a package present in pnpm's live set, so it cannot un-gate a build for something it is not reinstalling. |
| T-05-15 | Tampering | the replay widening the installed set | high | mitigate | Task 1's group logic emits only group members that already appear in `packages`. A declared group whose other half pnpm does not manage replays only the half it does, so the remediation action can never install a tool the user never chose. Covered by an explicit acceptance criterion and a `<behavior>` case. |
| T-05-16 | Repudiation | preview diverging from effect | medium | mitigate | `reinstall_preview` and `reinstall_node_globals` both call the one `reinstall_argv`, and Task 2 passes the same policy object to both from a single construction site. An acceptance criterion asserts the preview string equals `shlex.join` of the argv for the same inputs. |
| T-05-17 | Denial of Service | a replay onto a cold `~/.cache/puppeteer` | medium | mitigate | The build allowance travels with the replay, so the browser download runs rather than being silently skipped — the same Pitfall 2 signal plan 05-01's tracer asserts against. |
| T-05-SC | Tampering | npm/pip/cargo installs | high | mitigate | This plan adds no dependency to the project and introduces no new package into the catalog. The npm packages it can replay were legitimacy-checked in plan 05-03 Task 1 before their registry entries landed. |
