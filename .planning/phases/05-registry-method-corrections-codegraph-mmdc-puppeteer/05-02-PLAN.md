<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Releases -> local filesystem | A remote tarball is downloaded, unpacked and symlinked into the user's `~/.local/bin`. |
| registry -> download executor | Registry-declared repo/asset/member strings determine what URL is fetched and what path is made executable. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-05 | Tampering | unverified binary download from GitHub Releases | high | mitigate | Both methods declare `checksum = "SHA256SUMS"`, routing the download through `installer/download.py::_install_verified` and `installer/checksums.py`. The file's `<hash>  <filename>` format was confirmed line-for-line against the existing parser, so the verification really engages rather than silently finding no entry. |
| T-05-06 | Tampering | a checksum mismatch degrading to another install channel | medium | mitigate | Deliberately no brew fallback exists, and `installer/engine.py`'s default `checksum_policy="fail"` halts the ladder on `ChecksumMismatch` rather than continuing. Recorded in the entry comment (Task 2) so the absence of a fallback reads as a decision, not an oversight. |
| T-05-07 | Spoofing | a look-alike repo or asset name | medium | mitigate | `repo` is pinned to `colbymchenry/codegraph` and was resolved live via the GitHub Releases API on 2026-09-05; the asset names come from that same API response, not from a search result or a blog post. Recorded with its re-verification date. |
| T-05-08 | Elevation of Privilege | the vendored `node` runtime inside the tarball | medium | accept | The tarball ships its own `node` binary, so installing codegraph installs a Node runtime the user did not separately choose. Accepted: it is upstream's published distribution shape, it is covered by the same sha256 verification as the rest of the archive, and it is confined to `~/.local/opt/codegraph/` rather than being placed on PATH — only `bin/codegraph` is symlinked. |
| T-05-SC | Tampering | npm/pip/cargo installs | high | mitigate | Not applicable to this plan: `codegraph` is not npm-distributed under `kind="github_release"`, so the npm package-legitimacy gate does not apply. 05-RESEARCH.md's Package Legitimacy Audit records this explicitly and substitutes direct GitHub Releases API verification. |
</threat_model>
