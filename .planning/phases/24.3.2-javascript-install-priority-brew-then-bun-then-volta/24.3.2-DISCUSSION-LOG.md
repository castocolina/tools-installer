## Live facts that changed the plan

- **`bun add -g` does not update.** With semver 7.5.0 installed, `bun add -g semver@^7` (and `--force`) kept 7.5.0. `bun update -g semver` moved it to 7.8.6 and rewrote the range to `^7.8.6`. So the analyzer's "re-run the install executor" update was replaced by `bun update -g` plus the smoke check (D-13).
- **Trust for globals.** A user list of `["esbuild"]` blocked puppeteer's postinstall ("Blocked 1 postinstall"). `bun pm -g trust` and `bun pm trust` in the global dir reported "0 scripts ran", and `bun pm untrusted` listed nothing. `bun add -g --trust puppeteer@^25` appended puppeteer to the user's list (D-21, SPEC PRIO-06 amended).
- **Relocation.** `BUN_INSTALL_BIN` and `BUN_INSTALL_GLOBAL_DIR` moved the bin links and the tree, and `bun pm bin -g` followed them (D-07). `bun pm bin -g` errors before the first global install.
- **Peers.** mmdc installed alone left puppeteer as an unlisted peer with no bin link. It stayed in the tree after mmdc was removed (D-19, D-14).
- **SPEC contradictions reported by the analyzer and amended:**
  - a known too-old node plans BLOCKED rather than failing in the executor (D-02);
  - the fallback cannot be shown in a catalog run (D-10);
  - `NPM_PACKAGE_RE` does not check `npm_pkg` today (D-05, edge row).
