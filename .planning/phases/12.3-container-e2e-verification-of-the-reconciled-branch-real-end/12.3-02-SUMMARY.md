# Phase 12.3 Plan 02: Full catalog clean install Summary

**The full ~90-tool `registry.toml` catalog installs cleanly inside a disposable Fedora 44 container through the real `uv run setup.py --all --yes` entrypoint; the puppeteer failure the first pass surfaced traced to a genuine cross-tool PATH-visibility bug (fixed), not a platform limitation**

## Accomplishments

- `scripts/container-e2e-verify.sh` created: `bootstrap`/`pass1`/`resync` subcommands driving a named, long-lived `tools-installer-e2e-12-3` container (reused by Plan 12.3-03).
- First full pass surfaced a real bug: `puppeteer` failed with a garbled, unhelpful message. Root-caused across three layers:
  1. `installer/render.py` never printed a FAILED outcome's actual exception (only `CHECKSUM_MISMATCH` did) — fixed with `render_failure_details`, which made the real error (`pnpm ... does not meet the required minimum 10.4.0`) visible at all.
  2. The real cause: `installer/engine.py` never made a freshly-installed tool's declared `bin_dir` visible on the *current process's* PATH, so `puppeteer`'s `_node()` step — needing `pnpm`, installed earlier in the *same* `--all` run — couldn't find it and fell through to Volta's unrelated placeholder shim. Fixed with `prepend_path()` after a successful install.
  3. `installer/registry.toml`'s pnpm `bin_dir` was stale (`~/.local/share/pnpm`, missing the `/bin` pnpm's current installer actually uses) — corrected.
- Separately, the harness itself had three bugs blocking accurate diagnosis: Rich's non-tty `Console` wraps `render_summary`'s one-line output at 80 cols, silently zeroing every parsed count; a `trap ... RETURN` referenced a `local` variable after bash had already popped it under `set -u` (`tmp: unbound variable`); `resync`'s `cp -r` couldn't overwrite read-only git objects. All three fixed.
- Fixed a fourth, unrelated but actively-destructive bug the same install run hit: `installer/rcclean.py`'s duplicate-PATH-line stripper flagged an *indented* line inside Fedora's default `.bashrc`'s `if ! [[ ... ]]; then PATH=...; fi` block and stripped it, leaving an empty `then`-clause — a bash syntax error that broke every later login shell in the container. Fixed: an indented line is never a strip candidate.
- Final pass: `PASS1_COUNTS installed=69 already=1 failed=0 dependency_failed=1 mismatched=0 no_method=0 manual_required=7`. The one `dependency_failed` (`superpowers`, blocked by `pi`) is machine-verified against the same run's `manual_required` list — `pi`'s own postinstall needs interactive auth and cannot run under `--yes`, a structural handoff present since the very first pass, unrelated to the puppeteer bug. `container-e2e-verify.sh` now recognizes this class of fully-explained dependency chain as `TRACER_CLEAN_INSTALL_OK` rather than requiring a literal zero.

## Cross-AI Execution (Rule 12)

Dispatched per `workflow.cross_ai_execution` to `opencode run --model router-env/my-coding --auto`. The agent ran ~1h37m, correctly diagnosed the puppeteer/pnpm/Volta interaction, and produced two correct fixes (kept: `engine.py` PATH-prepend, `registry.toml` bin_dir) and one incorrect, over-broad fix (reverted: a `guards.py` change that could never distinguish a broken unpinned Volta shim from a working pinned one, regressing `tests/test_executors.py` on any host where Volta's pnpm is legitimately pinned). It then exhausted its model-router quota mid-loop (stuck retrying a test command silently rewritten by the session's own RTK shell hook, a false "No tests collected" each time) and exited without committing. This is a demonstrated, recorded cross-AI failure for this plan; the orchestrator completed it directly per Rule 12's fallback, reconciling the agent's correct partial work rather than discarding it wholesale.
