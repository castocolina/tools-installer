# Phase 12.3 Plan 03: Rerun/uninstall/reinstall idempotency pass Summary

**A second full-catalog install over already-installed state, a full uninstall sweep, and a third reinstall all complete cleanly against the same disposable container Plan 12.3-02 left running — surfacing zero real idempotency or uninstall bugs, with the container torn down and the host proven untouched across the entire multi-pass run**

## Accomplishments

- Added a `pass2` subcommand to `scripts/container-e2e-verify.sh`: three sequential steps against the still-running `tools-installer-e2e-12-3` container — `--all --yes` (rerun), `--uninstall --yes`, `--all --yes` (reinstall) — each appending raw output to one `pass2-transcript.log`, reusing `pass1`'s `run_setup_as_tester`/`accumulate_summaries`/`dependency_failures_explained()` machinery for the rerun/reinstall gates and a plain exit-code check for uninstall (no `render_summary` line exists for `--uninstall`).
- First `pass2` run: rerun and uninstall both passed cleanly (`TRACER_RERUN_OK`, `TRACER_UNINSTALL_OK`), but the reinstall step hit `drawio-desktop`/`wezterm` FAILED with `HTTP Error 403: rate limit exceeded` while resolving GitHub release tags, with `drawio-cli`/`superpowers` dependency-failing as a result.
- Root-caused via `curl -s https://api.github.com/rate_limit`: the host's unauthenticated `api.github.com` core quota (60 req/hour/IP) was at 0/60, exhausted by this session's own back-to-back bootstrap/pass1/rerun/reinstall cycles sharing the container's egress IP. Confirmed `installer/versions.py`'s `resolve_github_tag()` is the sole call site (it hits `api.github.com/repos/{repo}/releases/latest` to find the latest tag before building the download URL) — the actual asset download (`github.com/.../releases/download/...`) is a separate, unthrottled path never affected. This is an external, time-bound platform condition, not an installer defect.
- Waited for the rate-limit window to reset (confirmed back to 60/60 via the same endpoint) and re-ran `pass2` from scratch with no code changes: all three steps passed cleanly (`TRACER_RERUN_OK installed=2 already=1 failed=0 dependency_failed=1(explained)`, `TRACER_UNINSTALL_OK`, `TRACER_REINSTALL_OK installed=15 already=1 failed=0 dependency_failed=1(explained)`), and the container was torn down (`TRACER_CONTAINER_TEARDOWN_OK`).
- Wrote the phase's final whole-run host-untouched attestation (`host-attestation.log`): re-captured `~/.myshellrc`, `~/.zshrc`, `~/.bashrc`, `~/.local/bin/wezterm` stat+sha256 and confirmed byte-identical to the pre-Plan-12.3-01 baseline (since Plan 12.3-02's fixes never touched host `$HOME`), plus `~/.local/bin`'s full listing and a `git status --short` check showing nothing beyond the pre-existing untouchable file and this plan's own script edit.

## Cross-AI Execution (Rule 12)

Dispatched per `workflow.cross_ai_execution` to `opencode run --model router-env/my-coding --auto`. Both attempts failed immediately with `Error: Service temporarily unavailable: all targets were skipped by pre-dispatch filters`. `podman logs omniroute` confirmed all 3 backend targets of the `my-coding` combo were unavailable: `grok-cli` quota-exhausted (carried over from Plan 12.3-02's cross-AI run) and `opencode-go/deepseek-v4-flash` reporting an expired connection credential — neither recoverable on a retry timescale. This is a demonstrated, recorded cross-AI infrastructure failure for this plan; the orchestrator executed Plan 03 directly per Rule 12's fallback.
