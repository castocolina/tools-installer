> Generated by gsd-ui-researcher in `--auto` mode (no user questions). To be verified by gsd-ui-checker.

This is a **Textual terminal UI** plus a headless Rich console, not a web frontend. Units are terminal **cells** and **rows**. The design system is the Phase 21 contract (`21-UI-SPEC.md`) as extended by Phase 22 (`22-UI-SPEC.md` with its two 2026-11-04 amendments). ## 1. Install review: run options (CONF-05 environment.d, CONF-08, CONF-09, CONF-12; D-09)

### Where and when

The run options are rows in the existing review list (`#plan-rows`), **under** the plan rows, so the plan stays the focal element. They appear only before the run starts.

| Option id | Shown when (computed from the settled plan) | Applies to |
|-----------|---------------------------------------------|------------|
| `auto-approve` | at least one of `claude`, `codex`, `opencode`, `cursor-agent` has a runnable row (INSTALL, REPAIR, REINSTALL, UPDATE, RECONFIGURE) | every such agent whose row ends `done` |
| `no-attribution` | `claude` or `cursor-agent` has a runnable row | those two, when their row ends `done` |
| `vscode-lean` | `vscode` has a runnable row | VS Code |
| `vscode-ai-off` | same as `vscode-lean` | VS Code |
| `vscode-ext-updates-off` | same as `vscode-lean` | VS Code |
| `desktop-shell` | Linux, and `zsh`, `kitty` or `wezterm` has a runnable row | the user's `environment.d` |

- An agent that is already current (SKIP) is **not** listed: Policies changes it (U1). A plan with none of the triggers shows no heading and no option row (the review reads exactly as in Phase 22).
- Every option starts **off** on every review, is never remembered between runs, and is never turned on by `--yes`, by `a`, or by any default (SPEC prohibition R4/R8/R9).

### Row text

Heading (a disabled option, `bold`): `run options — off unless you turn them on with space` (52 cells).

Each option row is `{cell} {label} — {effect}`; the cell is `[ ]` off or `[x]` on (`[x]` in `green`, the Phase 21 mark rule). Continuation notes are dim, indented 4 cells, and fold with the same hanging indent (`fold_reason`, column 4).

| Option | First line (template) | Continuation lines (dim; each only when it applies) |
|--------|-----------------------|-----------------------------------------------------|
| `auto-approve` | `[ ] auto-approve agents — {agents}: no permission prompts` | `pi: nothing written; its approvals come only from extensions` (pi has a row in the plan) |
| `no-attribution` | `[ ] attribution off — {agents}: no agent credit in commits/PRs` | `no documented key: {ids} (nothing written for them)` (any of codex, opencode, pi in the plan) · `cursor-agent: its CLI ignores the commit opt-out (as of 2026-10-04)` (cursor-agent listed) |
| `vscode-lean` | `[ ] VS Code lean mode — telemetry, experiments, minimap, auto-detect off` | `zsh terminal; update.mode not written on Linux (this installer updates it)` (Linux) · `zsh terminal; update.mode set to none` (macOS) |
| `vscode-ai-off` | `[ ] VS Code built-in AI off — chat.disableAIFeatures` | — |
| `vscode-ext-updates-off` | `[ ] VS Code extension auto-update off — security fixes only on demand` | — |
| `desktop-shell` | `[ ] SHELL=zsh for desktop apps — ~/.config/environment.d (log in again)` | — |

- `{agents}` are the listed catalog ids, comma-joined, in catalog order. Widest fixture (`claude, codex, opencode, cursor-agent`): 75 cells; longer lists fold at column 4.
- Order: the six options in the table order. The heading is never highlighted by the cursor (disabled option).

### Keys and states

| Key / event | Effect |
|-------------|--------|
| `space` on an option row (review idle) | toggles `[ ]` ↔ `[x]`; the status is cleared; nothing is written yet |
| `space` on a plan row or the heading | nothing changes; status `warn`: `space toggles run options only; plan rows change with r.` (56 cells) |
| `r` on an option row | nothing, no status (`_row_for` finds no tool) |
| `enter` | starts the run with the current answers (unchanged `action_start`); a replan after a publish keeps the answers of options that are still shown and drops the others |
| `space` while waiting for the state check, running, or finished | nothing changes; status `warn`: `A run option is set before start; it cannot change now.` (55 cells) |
| Unattended TUI (`--yes`) | the run starts at mount; every option is off; the option rows still render (all `[ ]`) so the log shows what was not asked |
| Finished | option rows stay, painted `dim`, with their final cell; the report (section 4) says what each one wrote |

Keys line while idle, when at least one option row exists: `enter start · space option · r reinstall · up/down move · esc cancel` (68 cells; `r reinstall` only when a row can reinstall, as today). Without option rows the keys line is unchanged.

Fit at 80×20: `#execute-head` (≤ 3 rows), `#plan-rows` (`1fr`, scrolls), status, keys. The option rows scroll with the plan; the heading and every option are reachable with `down`/`end`. Every rendered line is ≤ 78 cells; nothing truncates (rows fold).

## 2. Shell init at install: the keyed sensitive prompt (CONF-04, CONF-11; D-11, D-13)

Asked **during** the run, per tool, through `SensitiveActionScreen` when the `source_shell_init` action of starship, direnv, zoxide, fzf, fnm or volta runs after a successful install. Headless `--yes` passes `confirm=None`, so it is never asked and never turned on.

Prompt (Label, 70 text cells, wraps): `Turn on {tool} shell init? It adds one guarded block to ~/.myshellrc that {effect}. It stays off unless you choose yes; Policies can change it later.`

| Tool | `{effect}` |
|------|-----------|
| starship | `makes starship draw your prompt and sets ZSH_THEME="" so Oh-My-Zsh draws none` |
| direnv | `loads and unloads a directory's .envrc as you cd` |
| zoxide | `adds z, a cd that learns the directories you use` |
| fzf | `adds ctrl+r history search, ctrl+t file picker and alt+c` |
| fnm | `switches Node versions from .node-version or .nvmrc as you cd` |
| volta | `exports VOLTA_HOME and puts Volta's bin directory on PATH` |

Choices: `Yes, turn it on` (id `opt-yes`) / `No, leave it off` (id `opt-no`). `esc` = no and writes the existing log line `{tool}: sensitive-action prompt dismissed; the answer was therefore no.` The `set_login_shell` prompt and its choices keep today's text byte for byte. The headless interactive route asks the same prompt sentence through `prompter.confirm` (default no).

| Answer | Result |
|--------|--------|
| yes | bundle `{tool}` ON; post-install handoff (section 4) line `  Shell init on: open a new terminal to use it.`; starship also writes `ZSH_THEME=""` through `omz.set_theme` (no handoff line about OMZ when Oh-My-Zsh is absent) |
| no / esc | bundle OFF; no health state; no handoff line; the tool row ends `installed` and `✓` |

Prompt choice (CONF-11): the starship question **is** the prompt choice. "yes" → starship draws the prompt and `ZSH_THEME=""`. "no" → Oh-My-Zsh keeps its theme; when `~/.zshrc` had no `ZSH_THEME` line the OMZ writer adds `robbyrussell`. An existing theme is never touched.

### State cell for settings rows (agent, VS Code)

Shell-init and desktop `SHELL` rows use the existing three states unchanged. Settings rows read the config-write ledger plus the live file:

| State | Cell (9 cells max) | Style | When | `space` does |
|-------|--------------------|-------|------|--------------|
| ON | `● [on]` | green | at least one key this installer wrote (ledger) still holds its value | remove: reverts exactly those keys |
| YOURS (new, settings rows only) | `● [yours]` | green | every key of the setting already holds the wanted value and the ledger records none of them | nothing is written; status `warn`: `{label}: you set these keys yourself; edit {path} to change them.` |
| OFF | `○ [off]` | dim | neither of the above | apply: writes only absent keys |
| DRIFT | `! [drift]` | yellow | the ledger records keys but none holds its value now | apply: writes the keys that are absent again, forgets ledger entries whose value someone changed |
| unreadable | empty | — | the file does not parse, or the read failed | refused: existing `Could not read the policy state: {reason}.` (`error`) |

`{reason}` for an unparsable file: `{path} is not valid {JSON|JSONC|TOML} ({where}); nothing is written until it parses`, where `{where}` is `line {n}` (plus `, column {c}` when known).

### Alias migration notice (CONF-10; ledger Q9)

The migration runs once per launch (TUI and headless) before the first view renders, and at the start of an uninstall; it is idempotent (no legacy block → no action, no line). An alias block is stripped only after its keys were written, found already set, or found set by you; when the target file is unparsable the alias is **kept** and retried on the next launch (U9).

TUI: written during first entry to the first view's status (Phase 21 first-entry rule: it stays until the user leaves that view). At most three lines:

| Case | Line | Severity |
|------|------|----------|
| one or more aliases moved | `Moved {aliases} to agent settings; see Policies.` (77 cells for the three agent aliases; a longer list wraps) | ok |
| cursor-agent model wrapper removed | `cursor-agent-model alias removed: pick the model with /model in cursor-agent.` (77 cells) | warn |
| alias kept | `{alias} alias kept: {path} is not valid {format}; fix it and relaunch.` | warn |

Headless (`--all` / `--categories`, `--uninstall`): the same lines, printed first with `markup=False, soft_wrap=True`. In an uninstall the alias block is only stripped (no key is written) and the line reads `Removed the {aliases} alias block(s) from {rc}.` (U8).
