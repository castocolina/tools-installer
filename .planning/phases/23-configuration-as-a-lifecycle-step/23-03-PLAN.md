The both-roots-exist case stays a known limit (22 C-17).
- D-13 (locked) with an ownership record (Claude's discretion, needed so a later starship "yes" can replace the installer's own default without ever touching a user theme):
  - A theme line is a line matching `^\s*(export\s+|typeset\s+(-g\s+)?)?ZSH_THEME=` (review R1-17: `export ZSH_THEME="agnoster"`, `typeset ZSH_THEME=…` and an assignment indented inside an `if` all count; a line whose first non-blank character is `#` never does). `set_theme(content: str, name: str, *, replace: str | None = None) -> str` (pure): when a theme line exists, return the content unchanged unless `replace` is not None and the LAST such line's value equals `replace`, in which case only that line's value is rewritten to `"{name}"` (its indent and any `export`/`typeset` prefix are kept); when none exists, insert `ZSH_THEME="{name}"` as its own line right before the index `_sourced_oh_my_zsh` returns; no source line → unchanged. Keep CRLF lines CRLF (`_crlf_line`). The value of a line is the text after `ZSH_THEME=` with one pair of matching `"` or `'` quotes removed and a trailing `# comment` ignored.
  - The record (23-REUSE.md 03-1, Important): a closed comment-only block in `state_path` with markers `THEME_BEGIN = "# >>> tools-installer omz-theme >>>"` / `THEME_END = "# <<< tools-installer omz-theme <<<"` and one body line `# ZSH_THEME="{name}"`. Write NO second line-walking reader: give the existing `_record`, `_record_owned` and `_clear_owned` `begin`, `end` and body-prefix parameters; the plugin callers pass `_OWNED_BEGIN`/`_OWNED_END`/`_ADDED_PREFIX` unchanged (the existing omz tests stay green unchanged), and `owned_theme(state_path) -> str | None` is `_record(state_path, THEME_BEGIN, THEME_END, '# ZSH_THEME=')` reduced to its one value (the orphan-begin rule and last-closed-block-wins come along for free).
  - `@dataclass(frozen=True) class ThemeResult: outcome: Literal["added", "replaced", "yours", "no-source"]; theme: str | None` (the theme now in force, None for `no-source`).
  - `apply_theme(zshrc_path, state_path, name) -> ThemeResult`: missing zshrc or no source line → `no-source`, nothing written; computes `set_theme(content, name, replace=owned_theme(state_path))`; unchanged with an existing line → `yours` (theme = that line's value); changed → the `write_plugins` order (23-REUSE.md 03-2, Important; review R1-02): reserve the record first (`_record_owned` with the theme markers set to `name`), then the atomic write of the zshrc, and on `OSError` from that write restore the previous record (or clear it with `_clear_owned` when there was none) and re-raise → otherwise `added` or `replaced`. Recording after the edit would strand the claim: a failed record write would leave the installer's own `robbyrussell` reading `yours` forever, so starship could never replace it.
  - `default_theme(state_path) -> str`: `""` when `tweaks.bundle_marker_present("starship", state_path)` else `"robbyrussell"`.
  - `write_plugins` calls `apply_theme(zshrc_path, state_path, default_theme(state_path))` after its plugin edit committed; its return value (the added plugin names) is unchanged. `remove_plugins` never touches the theme line or its record.
- `tweaks.bundle_marker_present(bundle_id: str, rc_path: Path) -> bool`: the begin marker of `_markers(bundle_id)` is a line of `rc_path`; `tweak_present` delegates to it. (The starship bundle itself lands in 23-09.)
