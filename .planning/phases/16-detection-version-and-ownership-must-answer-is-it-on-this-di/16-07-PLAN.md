<objective>
Correct the skill-pack data detection is built on (D-09), and show install instructions only for
hosts this machine actually has (D-15).

Purpose: CONTEXT.md D-09. The registry's host lists are factually wrong for at least superpowers
(declared Pi-only; it supports ten hosts). D-09 says to re-audit every pack before trusting
detection. D-15 says to show instructions only for hosts present, with Cursor detected from disk.

Output:
- An audited registry with `# Verified` comments, `status_probes`, and `by_harness` install
  instructions where upstream documents per-host commands.
- `HARNESS_PRESENCE` and `present_harnesses`, plus host filtering in `perform_action`.
- `SKILL_HARNESS_LABELS`.

**Live verification is required in Task 1.** For each pack, the executor fetches the upstream README
(WebFetch on the `source` URL's README, or `gh api repos/<owner>/<repo>/readme`) and records what it
found. Where upstream lists a host this installer has no `SKILL_HARNESSES` id for, add the id to
`SKILL_HARNESSES` in model.py (Task 3 then gives it a `SKILL_HARNESS_LABELS` entry), never drop the host. Where
upstream is ambiguous, keep the narrower verified set and say so in the comment.

Follow `.claude/skills/tool-onboarding/SKILL.md` and `.claude/architecture.md`'s "Per-tool, per-OS
verification checklist" for the `# Verified` comment convention.

Output harness note: if `uv run pytest` prints a false "No tests collected", re-run via `.venv/bin/pytest`.
</objective>
