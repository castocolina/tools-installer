<objective>
Add the argv-conditional global-install redirect: `npm`/`pnpm` invocations carrying
`-g`/`--global` on an `install`/`add`/`i` subcommand exec into `volta install <pkg>`;
everything else keeps today's behaviour — the hard block for npm, a transparent
pass-through to the real binary for pnpm.

Purpose: D-06 and R-01. This is the phase's highest-risk mechanism, because `pnpm` is the
first tool this installer shims that must remain fully functional through its own shim
(04-RESEARCH Pattern 3 / Pitfall 3). It builds on the `REDIRECTED` mechanism plan 04-01
proved and on the `volta` catalog entry plan 04-02 added.

Correction carried in from cross-AI review cycle 1 (CRITICAL): 04-RESEARCH.md's Pitfall 4
and its "The internal executor call this redirect does NOT touch" example both assert that
`runner(["pnpm", "add", "-g", pkg])` is "never resolved through the shell/PATH-shim
layer". That is factually wrong. `installer/run.py::run_command` is
`subprocess.run(cmd, check=True)` with `argv[0] == "pnpm"`, and `subprocess.run` resolves a
bare program name through the live `PATH` exactly like a shell does. The moment this plan
writes `~/.local/bin/pnpm` — a directory the doctor insists is FIRST on PATH — the
installer's own `kind="node"` executor starts hitting its own wrapper and a catalog install
of `mmdc` silently becomes `volta install @mermaid-js/mermaid-cli`, dropping pnpm's gated
postinstall: the exact property plan 04-05 exists to preserve. Task 1 below closes this
before Task 3 ever writes the wrapper. Do not trust the research file's wording on this
point; trust `installer/run.py:19-26`.

Decisions implemented:
- D-05: non-global `npm` stays hard-blocked with today's message and exit code; its subcommand-allowlist question is untouched.
- D-06: a `-g`/`--global` flag on an `install`/`add` invocation of npm or pnpm is detected and routed to `volta install <pkg>`; every other shape keeps its existing behaviour.
- D-07: the redirect ships as the documented security-for-stability tradeoff the research established, never as an assumed-safe win.
- D-01: the conditional wrapper is a second, parallel structure — it does not widen `BANNED` and it does not widen the flat `REDIRECTED` dict either.
- R-01: `pnpm add -g` is literally intercepted, which requires a pass-through wrapper on a sanctioned binary and its own argv-parsing tests.
- R-02: the redirect is gated on volta resolving, and fails safe to the existing hard block when it does not.

Output: `real_pnpm`, `GlobalRedirect`, `GLOBAL_REDIRECTED`, `GLOBAL_SUBCOMMANDS`,
`global_redirect_shim_script`, `install_global_redirect_shims`; extended
`guarded_names`, `guard_label`, `ban_alias_block`, `guard_path_warning`,
`guard_redirect_warning`; a rewritten `BANNED["npm"]` hint; `installer/executors.py::_node`
invoking pnpm by absolute path; both apply call sites updated.

       ```
       #!/bin/sh
       {REDIRECT_SENTINEL}
       subcmd=''
       is_global=0
       for arg in "$@"; do
         case "$arg" in
           -g|--global) is_global=1 ;;
           -[!-]*) case "$arg" in *g*) is_global=1 ;; esac ;;
           -*) ;;
           *) if [ -z "$subcmd" ]; then subcmd="$arg"; fi ;;
         esac
       done
       if [ "$is_global" -eq 1 ]; then
         case "$subcmd" in
           install|add|i)
             argc=$#
             seen=0
             while [ "$argc" -gt 0 ]; do
               arg="$1"
               shift
               argc=$((argc - 1))
               case "$arg" in
                 -*) ;;
                 *) if [ "$seen" -eq 0 ]; then seen=1; else set -- "$@" "$arg"; fi ;;
               esac
             done
             if [ "$#" -gt 0 ]; then
               exec {volta} install "$@"
             fi
             echo "tools-installer: a global install needs a package name." >&2
             exit {EXIT_CODE}
             ;;
         esac
       fi
       {fallback}
       ```

       Three structural rules the body depends on and that a comment in the Python
       generator must state:
       - The first loop only READS `"$@"`; the second loop rewrites it with the standard
         POSIX rotate idiom (take `$1`, `shift`, append the keepers). Because the rotate
         loop mangles `"$@"`, the branch it lives in always ends in an `exec` or an
         `exit` — control never reaches the fallback with a rewritten argv.
       - The first non-flag token is the subcommand and is dropped; every later non-flag
         token is a package name and is kept. Every flag, `-g`/`--global` included, is
         dropped, because `volta install` takes bare package names.
       - The `-[!-]*` arm is the combined-short-flag rule (cross-AI review cycle 1,
         MEDIUM): a POSIX `case` pattern matches a WHOLE token, so `-g|--global` alone
         never fires for a packed cluster like `-gD`, and a global install would slip past
         the redirect. The arm matches a single-dash cluster and re-tests it for a `g`.
         Its scope is deliberately narrow — a token beginning with `--` never reaches it,
         so `--filter=-g` and any other long option carrying `-g` in its value cannot
         trigger it. The only single-dash flags npm and pnpm define for their install
         subcommands that carry a `g` are the global flag itself, so an over-trigger would
         take a deliberately unusual invocation; the `<behavior>` matrix pins both
         directions.

       stays one source of truth. Do not refactor `shim_script`; build the two lines
       independently and let the test in `<behavior>` prove they cannot drift.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user shell → npm/pnpm shim | Arbitrary user argv is inspected by a generated POSIX-sh script before being forwarded. |
| shim → volta | Package names extracted from user argv become `volta install` arguments. |
| shim → real pnpm | Full user argv is forwarded unmodified to a sanctioned binary. |
| installer process → pnpm | The installer's own `kind="node"` executor spawns pnpm through `subprocess.run`, which resolves a bare program name through the same PATH the shims occupy. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-09 | Denial of Service | pnpm wrapper self-recursion | high | mitigate | The pass-through branch execs a `real_binary`-resolved absolute path, looked up with `shim_dir` removed from PATH and refused if it carries either sentinel; `global_redirect_shim_script` raises `ValueError` rather than emit a pass-through wrapper with no resolved path. Proven by real-subprocess tests against a fake real pnpm, not by mocks. |
| T-04-10 | Tampering | argv filtering before `volta install` | medium | mitigate | Filtering happens entirely in POSIX-sh positional parameters; nothing is re-expanded through a second shell and no user token is interpolated into a command string. The rotate loop's branch always terminates in `exec` or `exit`, so a mangled argv can never reach the pass-through branch. |
| T-04-11 | Elevation of Privilege | npm postinstall scripts via `volta install` | high | accept | Accepted in D-06/D-08; recorded on the registry entry in plan 04-02 and surfaced in the doctor copy in plan 04-04. |
| T-04-12 | Spoofing | redirect to a volta that is not installed | high | mitigate | The writer gates on `real_binary(VOLTA, ...)`; with volta absent npm keeps its hard block and pnpm is not shimmed at all, and `guard_redirect_warning` reports the degradation. |
