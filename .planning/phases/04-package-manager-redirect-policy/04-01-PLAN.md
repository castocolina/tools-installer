<objective>
Add the `REDIRECTED` shim mechanism to `installer/guards.py`, parallel to the existing
`BANNED` hard-block dict, and use it to redirect `npx` into `pnpm dlx "$@"` end to end —
data structure, POSIX-sh exec-through body, idempotent writer, ownership/removal
lifecycle, and the two apply call sites that already exist.

Purpose: this is the phase's thin vertical slice. It proves the exec-through shim shape
(real exit code, real streams, no self-recursion, safe fallback when the target is
absent) on the one command that has no conditional branch, so plan 04-03 can add the
argv-conditional npm/pnpm cases on a mechanism that is already known to work.

Decisions implemented:
- D-01: the new `REDIRECTED` mechanism sits parallel to `BANNED`, never generalizes it; `shim_script`, `EXIT_CODE`, `SHIM_SENTINEL` stay untouched.
- D-02: `guard_status()` keeps its `{name: bool}` shape; the redirect/block distinction lives in label text (`guard_label`), consumed by the UI in plan 04-04.
- D-03: `npx` execs into `pnpm dlx "$@"` using the explicit two-token form, with no dependency on a second binary name.
- D-04: research found a real gap, so pip and pip3 stay hard-blocked and the gap is recorded in the module docstring rather than papered over.

Output: `REDIRECT_SENTINEL`, `Redirect`, `REDIRECTED`, `redirect_shim_script`,
`which_in_path`, `real_binary`, `install_redirect_shims`, `guarded_names`,
`guard_label`, `guard_redirect_warning`; extended `is_our_shim`, `remove_shims`,
`guard_status`, `guard_path_warning`, `ban_alias_block`; `BANNED` gains its `npx`
entry (REQ-npx-ban) as the fail-safe body.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user shell → managed shim dir | Arbitrary user argv crosses into a generated POSIX-sh script this installer writes. |
| shim → redirect target binary | The shim hands argv to a binary resolved from PATH at shim-write time. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01 | Tampering | `redirect_shim_script` argv handling | medium | mitigate | Argv reaches the target as `"$@"` — discrete POSIX-sh positional parameters, never re-expanded through a second shell and never string-interpolated by Python. Every path this installer bakes into a shim body is `shlex.quote`d. |
| T-04-02 | Denial of Service | `npx` shim self-recursion | medium | mitigate | `real_binary` removes `shim_dir` from the search PATH and refuses any result carrying `SHIM_SENTINEL`/`REDIRECT_SENTINEL`; the resolved absolute path is baked into the body, so the target is never re-resolved through PATH at exec time (04-RESEARCH Pitfall 3). |
