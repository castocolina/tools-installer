<objective>
Ship the snapshot-and-reinstall mitigation for the pnpm-managed global set that survives
the Volta split, as a manually-invokable Doctor remediation: a read-only audit that
reports when a `pnpm add -g`-installed command has gone missing, and an explicit action
that reinstalls the whole set in one `pnpm add -g` call.

Purpose: D-08 and R-03. The residual set is NOT empty — `mmdc` is the registry's only
`kind="node"` tool and moving it off pnpm is Phase 5's decision, not this phase's — so
the requirement cannot be closed by elimination. `installer/executors.py::_node` calls
`pnpm add -g` through the `Runner` seam, which is a shape the user-facing shell redirect
in plans 04-01/04-03 does not steer, so the pnpm-managed global set survives the volta
split and still needs the requirement's own mitigation.

Two corrections carried in from cross-AI review cycle 1, both CRITICAL, both verified
against the live source:

1. **The `Runner` seam is not PATH-immune.** 04-RESEARCH.md's Pitfall 4 and its "The
   internal executor call this redirect does NOT touch" example claim that
   `runner(["pnpm", "add", "-g", pkg])` is "never routed through the shim/PATH-interception
   layer". That is wrong: `installer/run.py:19-26`'s `run_command` is
   `subprocess.run(cmd, check=True)`, and `subprocess.run` resolves a bare program name
   through the live `PATH`. Plan 04-03 fixed `_node` by routing it through
   `installer/guards.py::real_pnpm`; this plan's reinstall must use the same resolver, or
   pressing the remediation key on a machine with the wrapper installed would run
   `volta install` and destroy the exact property the remediation exists to preserve.
2. **`CommandError` is not an `OSError`.** `installer/run.py:10` defines
   `class CommandError(RuntimeError)`, and `installer/ui_common.py:40-48`'s `run_live`
   catches `OSError` only. A failed reinstall would therefore crash `DoctorScreen` rather
   than degrade. `action_apply` gets away with it today only because the PATH fix's
   failures come from file IO. Task 3 widens `run_live`.

Decisions implemented:
- D-08: the residual `pnpm add -g` set is determined after the volta split rather than assumed empty, is found to contain `mmdc`, and the requirement's original snapshot-reinstall mechanism is implemented for it in this phase.
- D-06: the volta split removes user-typed global installs from pnpm, which is precisely why the remaining exposure is the internal `kind="node"` executor and not the shell layer.
- R-03: the mechanism ships as a manually-invokable Doctor remediation, audit-only until invoked, taking no dependency on Phase 12's not-yet-built update action. Because that narrows `REQ-pnpm-global-reinstall-mitigation`'s literal "after `pnpm` itself updates" trigger, Task 4 records the narrowing in REQUIREMENTS.md and ROADMAP.md instead of leaving the requirement reading as fully closed.

Output: `installer/pnpm_globals.py`, its guidance/render surface, a second explicit
action on the Doctor view wired through `VIEWS`, `run_live` and `setup.py`, a widened
`run_live`, and the REQUIREMENTS/ROADMAP status correction for R-03.
</objective>
