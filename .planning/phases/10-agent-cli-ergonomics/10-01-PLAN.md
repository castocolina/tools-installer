<design_decisions>
**One `TweakBundle` for both `cursor-agent` and `cursor`, id `cursor-agent-model` (distinct
from the catalog tool id `cursor-agent`).** Resolves 10-RESEARCH.md's Open Question 1: a
single bundle whose body defines both functions guarantees they are always co-installed —
independently toggleable halves (Assumption A3's failure mode) could let a user enable
`cursor-agent`'s injection while `cursor` stays on stock behavior, or vice versa, which
REQUIREMENTS.md treats as one requirement (REQ-cursor-agent-default-model-wrapper). `cursor()`
purely delegates to `cursor-agent "$@"` rather than re-implementing its own `"$@"` scan, per
10-RESEARCH.md's own recommendation.

**`opencode-auto`'s label is `"opencode auto-approve"`, never `"...skip-permissions"`.**
`claude-skip`/`codex-skip` both use "skip-permissions" because that is literally what they do;
reusing that wording for `opencode-auto` would misrepresent it as a full bypass before a user
even opens the detail panel, undermining REQ-opencode-auto-tweak's honesty requirement at the
label level, not only in the expanded copy.

**The 1M-context re-verification finding (CONTEXT D-01) is recorded as a Python-level dated
comment above `_CURSOR_DEFAULT_MODEL` in `installer/tweaks.py`, not inside the shell body
text.** A shell comment would be duplicated verbatim into every enabling user's own
`~/.myshellrc` for no functional benefit; a source comment is where a future maintainer
reading this bundle's definition will actually find it, mirroring how `installer/registry.toml`
records its own "Verified {date}: ..." findings next to the entry they justify.

**Bundle placement in the `BUNDLES` tuple:** `codex-skip` is inserted directly after
`claude-skip` (grouping the two full-bypass "-skip" tweaks together for a reader scanning the
file top-to-bottom); `opencode-auto` and `cursor-agent-model` are appended after the existing
final entry (`apt-upgrade`), since neither is a natural neighbor of the Linux-only
`apt-upgrade` bundle. This changes `BUNDLES`' declared order, so the existing order-sensitive
`test_four_bundles_with_stable_ids` is renamed ONCE, in Task 1, to the count-agnostic
`test_bundles_have_stable_ids_and_order` (corrected during cross-AI review cycle 1 — see the
numbered list below: the original draft of this decision deferred the rename AND the

gates on their own commits). Each task then updates only the list literal to its own running
total (5 in Task 1, 6 in Task 2, 7 in Task 3) in the same commit that appends its bundle.

3. **`cursor()`/`cursor-agent()` contradiction resolved: only `cursor-agent()`'s OWN calls to
   the real binary need `command`; `cursor()`'s one delegation to the `cursor-agent` FUNCTION
   must stay bare.** The prior action text required "both functions" to always call through
   `command`, then separately required `cursor()` to "simply delegate to `cursor-agent \"$@\"\"`
   — a bare call — which its own proposed regression test then rejected. The corrected
   invariant (verified against 10-RESEARCH.md Pattern 2 and Pitfall 3 directly): self-recursion
   can only happen when a function calls its OWN name bare, so `cursor-agent()`'s two internal
   calls to the vendor binary must use `command cursor-agent "$@"` (bypassing its own function
   definition), while `cursor()` calling bare `cursor-agent "$@"` reaches a DIFFERENT function
   name — not itself — which is exactly how `cursor` inherits `cursor-agent`'s argv-scan/
   injection logic. If `cursor()` used `command cursor-agent "$@"` instead, `command` forces
   PATH-only resolution, so it would call the real binary directly and SKIP the injection
   entirely — breaking the plan's own required behavior that bare `cursor chat hello` gets
   `--model gpt-5.6-sol-high` injected. Task 3's action and its structural regression test are
   rewritten to state and check this exact, corrected invariant.

   shims, and `hash -r` really does refresh bash's PATH lookup cache for those) and by

   second, tweak-specific constant used only by `tweak_policy`'s `_apply`/`_remove`, and updates

   fixes the hint for `docker`/`countdown`/`claude-skip`/`apt-upgrade` too, for free, since
   `tweak_policy` is one shared function — not a new-tweaks-only patch.

5. **Fresh-shell tests extended to cover a pre-existing conflicting alias and zsh execution

   semantics were wrong, discovered only by actually running real shell processes on this
