Decisions recorded for this plan (Claude's discretion):
- Propagation set (CR-04): `unsatisfied = {row.tool_id for row in rows if row.disposition is BLOCKED and not _settled(state_of(row.tool_id))}`; the loop over runnable rows uses it in place of today's every-BLOCKED set, and a row it turns into `blocked — needs X` joins the set only when that row's own state is not settled (an UPDATE or RECONFIGURE row that gets blocked stays present and still satisfies its own dependents). Rows come in deps-first order, so one pass suffices.
- Prune (WR-04): after propagation, walk the rows in reverse plan order (dependents before dependencies). A row is pruned when it is runnable (INSTALL, UPDATE, REPAIR, RECONFIGURE, REINSTALL), is not a direct selection, and every plan row whose tool lists it in `requires` is BLOCKED or already pruned. A pruned row keeps its tool id, `requested_by`, health and ownership and becomes `Disposition.SKIP` with the reason `not needed while {requested_by} is blocked`. A runnable dragged row with no requiring row in the plan is never pruned. The copy is new UI copy: it follows the Disposition-copy register (`skipped — {reason}`, dim) and is recorded for the UI-SPEC amendment in the SUMMARY.
- `_blocked_row` (P-02, IN-02): first, `state is None or state.health is Health.CHECKING` returns `PlanRow(blocked.tool_id, Disposition.WAIT, "", requested_by=requester)`; the UNAVAILABLE branch and the `needs` branch stay; the last fallback becomes the fixed text `not available on this platform`, so `_blocked_row` no longer reads the resolver's free-text field (that field and the warnings it feeds become dead and are deleted by plan 20-28). Dependents of a WAIT row may stay `blocked — needs X` until the replan; one WAIT row is enough to make Enter wait and rebuild (UI-SPEC Waiting).
- `deps.py` is not touched here (plan 20-28 owns its dead fields).
