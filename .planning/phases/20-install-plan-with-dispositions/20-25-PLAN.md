Decisions recorded for this plan (Claude's discretion):
- Placement: the extras are a report line, not row text. UI-SPEC Outcome copy says a `done` row is its done word alone, and the end-of-run reports run after the summary; so the row stays `✓ pnpm  updated` and the notes go in a report renderer, like the old screen's `_updated_line` (`updated {id} — replayed …`), reworded to lead with the id and the vocabulary's done word `WORDS[Disposition.UPDATE].done`.
- `render_update_notes(outcomes: Sequence[RowOutcome], console)`: for each outcome with `result == "done"` and `update is not None`, collect the notes in this order and skip empty ones; print nothing when there are none; each line goes through `sanitize_log_line` and is printed with `markup=False, highlight=False, soft_wrap=True`, because `detail` and the warnings can carry child-process output. A failed or blocked update prints nothing here (its row already shows the reason).
- `render_run_report(outcomes: Sequence[RowOutcome], console)`: `render_run_summary`, then over `[o.install for o in outcomes if o.install is not None]` the existing renderers in today's order (failure details, dependency-failed reasons, handoff, post-install handoff, postinstall warnings), then `render_update_notes(outcomes, …)`, then verification. `run_wizard`'s state-check-failure branch keeps its bare `render_run_summary` (nothing ran, no report). Do not name the moved renderers in comments in `app.py` or `execute_screen.py`.
- `outcome_detail_text`, failed branch: `errors[-1]`'s first line when there are errors (install first, then update, as today), else `outcome.detail`'s first line, else `no method succeeded`; always sanitized.
