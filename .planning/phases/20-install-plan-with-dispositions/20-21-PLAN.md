Decisions recorded for this plan (Claude's discretion):
- Counters: `accumulate_summaries` adds 1 to `ACC_RUNS` on every call (one call = one setup transcript) and 1 to `ACC_SUMMARIES` when the `Summary — ` line matched `SUMMARY_RE` and parsed; it also accumulates `ACC_NOT_ATTEMPTED` and `ACC_CRASHED` beside the existing eight. Every place that zeroes the existing counters (pass1, pass2 step 1, pass2 step 3) zeroes the four new ones too. Arithmetic is `x=$((x + 1))`, never `((x++))`, which returns 1 from 0 and kills the script under `set -e`.
- `install_step_ok <setup_exit>`: returns 0 iff `ACC_RUNS > 0`, `ACC_SUMMARIES == ACC_RUNS`, `ACC_FAILED`, `ACC_MISMATCHED`, `ACC_NOT_ATTEMPTED` and `ACC_CRASHED` are 0, `ACC_DEP_FAILED == 0 || dependency_failures_explained`, and (`setup_exit == 0` or (`setup_exit == 1` and `ACC_DEP_FAILED > 0`)). It prints nothing; callers keep printing their `TRACER_*_OK` / `TRACER_*_INCOMPLETE` lines, and every INCOMPLETE line (and `PASS1_COUNTS`) additionally prints `not_attempted=`, `crashed=`, `summaries=`/`runs=` and the setup exit. A setup exit outside {0, 1} in pass2 fails the step through the gate (the step-specific `die` may stay, but such an exit must never pass).
- The `TRACER_RERUN_OK`, `TRACER_REINSTALL_OK`, `TRACER_CLEAN_INSTALL_OK` lines and their order in `cmd_pass2` stay (pinned by `test_receipt_checks_are_wired_into_the_passes`).
- Parser: per category, a regex held in a local variable, `(— |, )([0-9]+) ${category}(,|$)` against the line; on a match `printf -v "PARSE_${name}" '%s' "${BASH_REMATCH[2]}"`, else 0. A count is always preceded by `— ` or `, ` in the head, so `installed` never matches inside `reinstalled` and `failed` never matches `dependency failed`. The regex sits in a variable because bash 3.2 treats a quoted right-hand side of `=~` literally.
- Folded rows: replace the dependency-failed `grep` in `accumulate_summaries` with a bash `while IFS= read -r line` loop: a line containing ` dependency failed — ` starts a row; following lines that begin with at least four spaces are appended to it with one space after trimming their leading blanks; any other line ends the row; every finished row is appended to `ACC_DEP_LINES_FILE`. Outcome-row continuations start at the word column (at least six cells), while the report blocks indent two spaces, so the four-space rule separates them. The manual-names `sed -nE` capture stays (POSIX ERE, portable; its row never folds).
- Tests live in `tests/test_container_e2e_receipts.py`, which already extracts functions with `_function` and runs them through `_bash`/`_run`; broaden its module docstring to "the container e2e's host-side checks". A new local helper assembles `SUMMARY_RE` (extract its one line with a regex: it contains spaces, so `_constant` cannot read it), `parse_summary_line`, `accumulate_summaries`, `dependency_failures_explained` and `install_step_ok`, initialises every `ACC_*` counter to 0 and the two accumulator files with `mktemp`, then feeds a fixture transcript file.
