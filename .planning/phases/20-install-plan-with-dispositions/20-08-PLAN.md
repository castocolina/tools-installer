Decisions recorded for this plan (Claude's discretion):
- `in_directory(cwd: Path, argv: Sequence[str]) -> list[str]` returns `["sh", "-c", 'cd -- "$1" && shift && exec "$@"', "sh", str(cwd), *argv]`: argv stays separate arguments, nothing is shell-interpreted; portable (no `env -C` on macOS, no process-global `chdir`). A `shortcut:` comment is not needed; this is the chosen design.
- cwd validation `_valid_cwd(path) -> str | None` (None = valid, else the refusal text): `path.is_absolute()`, `path.lstat()` is a directory (`stat.S_ISDIR`), not a symlink (`S_ISLNK` false). Failure detail: `{step.text}: {refusal}`.
- Handoff lines: `perform_action` returns a `LifecycleOutcome` with `mode == "manual-required"` and `instructions`; the row's `RowOutcome.install = InstallOutcome(tool.id, InstallStatus.MANUAL_REQUIRED, handoff=instructions)` so the existing `render_handoff` prints them unchanged and the screen's log shows "see the setup steps in the log" (UI-SPEC Outcome copy).
- `terminal_sync` step with `ctx.terminal_sync is None` fails with detail `no terminal synchronizer bound`; a returned warning string becomes the row detail but the step counts as run.
- `pnpm_group_install` with no node method on the tool fails with detail `no node method declares the group`.
- A step kind with an empty argv that is not one of the three special kinds fails with detail `step has no command`.
- Step failure detail: `{step.text}: {exception first line}`; `CommandError` and `OSError` from the runner are caught per step (not the per-row `crashed` path, which stays for unexpected exceptions).
</context>
