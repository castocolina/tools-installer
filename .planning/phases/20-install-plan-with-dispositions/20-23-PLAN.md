Decision being implemented (RUN-LEDGER, L-20-10, TypeSafe defer_writes p=0.97): the pre-confirmation refresh writes nothing; receipt adoption/retirement and the version-cache save commit only after the user consents.

Scope, stated honestly:
- Headless (`--all`, `--categories`): fully held, as in the truths.
- TUI: not held. Holding the shared service while a review is open would also hold the catalog's own pass (one single flight), and a declined review would leave the catalog and the Uninstall screen showing in-memory receipts that are not on disk, so `remove_proven` (which reads receipts from disk) would disagree with the screen. The TUI keeps Phase 19's write-at-refresh contract and its boundary is documented; no TUI copy claims nothing was written (`grep -cF "nothing was changed" installer/execute_screen.py` is 0 today and stays 0).
- Out of this decision: the probes the pass runs (`--version`, native queries, harness CLIs) are reads; whatever those third-party tools cache themselves is not the installer's write.

Decisions recorded for this plan (Claude's discretion):
- Seam: `VersionRefreshService.hold_writes()` starts queueing (idempotent); `commit_writes()` takes the queue under `_lock`, sets it back to None (writes go direct from then on, e.g. `UpdateService`'s `invalidate` after an update), and runs each queued write outside `_lock` (the cache-save writes take `_lock` themselves; `_lock` is not reentrant). Queue type: a list of zero-argument callables, `None` when not holding. Appending happens under `_lock`. The seam is for one thread (the headless route); the docstrings say so.
- Adoption: `receipts.adopt` gains keyword `write: bool = True`; with `write=False` it runs the same `receipt_exists` check and fresh fingerprint under `_WRITE_LOCK` and returns the receipt it would write, without writing. While held, `_adopt` calls it with `write=False`, queues the ordinary `receipts.adopt(...)`, and the state carries the in-memory receipt and `ADOPTED_NOTE`.
- Retirement: while held, `_receipt_evidence` queues `receipts.retire(tool.id, receipt)` when `receipts.all_gone(receipt)` and returns the retired result `(None, (), ())` at once.
- Cache saves: the pass's merge-and-save block, the `refresh_skills` save and `invalidate`'s save each become a queued write while held, with today's error handling kept inside the queued write (`warning`, `_skills_unsaved`); `invalidate`'s in-memory effects (epoch bump, `_skills_probed`, stale skill answers) still happen at once. A queued `invalidate` save that raises OSError at commit sets `warning` instead of propagating (consent is given; the run proceeds).
- Headless consent: in `run_wizard`, `hold_writes()` is the first call on the service, before `refresh`/`refresh_skills`; `commit_writes()` runs after the decline check when `options.yes` is set or the plan has a runnable row (which, without `--yes`, means the user just answered yes), and before `execute_plan`. The decline copy `Cancelled; nothing was changed.` stays as it is (now true).
- IN-08 drift note: in `_pass`, drop the broken arm of the note condition so the note needs `receipt is None`; with no receipt the receipt-derived broken facts are always empty, and the drifted-directory note from `_receipt_evidence` (receipt present, not broken, `r` eligible) is unchanged.
