Decisions recorded for this plan (Claude's discretion, best over easiest):
- WR-08 offers a new done glyph or a dim skipped mark. A new done glyph (U+2714) still leaves two green checks side by side, differing only in stroke weight; dimming the rows that changed nothing makes the changed rows stand out in color and the word on the same line still carries the meaning without color (UI-SPEC Accessibility, "Glyph and word first"). The rule covers every finished result except `done` and the three failure results, not only `skipped`, because a reinstall of an OK tool that ends `dependency_failed` or `not_attempted`, or an OK row that ends `blocked`, would otherwise show the same green check. `outcome_mark` keeps the glyph and returns style `dim` for those results; the comment above `_DONE_MARK` is updated to say so. The UI-SPEC Marks table row for those results changes from "unchanged / unchanged" to "health glyph from plan time / dim", and its "all eight marks are distinct glyphs" bullet must say the OK health glyph and the done mark share `✓` by design (both say the tool is now fine); the orchestrator records both amendments (executors do not edit `.planning/`).
- IN-02 suggests rewording the dependency-failure note. Rewording it would still print the fact twice: `render_run_summary` already prints the row `dependency failed — {ids}` (or `— an earlier failure`) for every such outcome in the same report. The renderer is therefore deleted, with its call in `render_run_report` and the two docstrings that compare themselves to it. The four tests that exercised it are deleted; their behaviour stays covered by `tests/test_render.py::test_outcome_row_text_per_result` (the `dependency_failed` cases with blockers `node, java` and with none) plus the new report test below. Two tests assert the old note line and are changed, not deleted: `tests/test_execute_screen.py::test_post_run_log_carries_every_renderer_in_wizard_order` and `tests/test_app.py::test_run_wizard_reports_a_skipped_dependent_with_its_reason`: each now asserts the row text `dependency failed — {blocker}` is present and that no line contains `skipped — dependency failed`.
- The TUI's separate not-attempted log line is deleted: the summary rows in the same log already print `{id}  not attempted`. `test_cancel_mid_run_lets_the_in_flight_tool_finish` stays unchanged and green (its `bat` and `not attempted` assertions are satisfied by the summary row).
- Cursor: `_paint_review` reads the highlighted option id before it clears the list and, after adding the rows, highlights that id when it is still a planned row, else index 0. The restore code in `on_resize` and in `action_toggle_reinstall` then goes (it is now redundant). The in-flight cursor in `on_row_started` is untouched.
