Decisions recorded for this plan (Claude's discretion):
- Order inside both waits: `refresh(tools)` first, then `refresh_skills(tools)`. `refresh_skills` rebuilds the pack states the pass just published from that pass's scan; it is single-flight (`_skills_pass_lock`) and returns at once when the packs were already probed this epoch, so joining it costs nothing when the catalog's skill worker already answered.
- Headless: both calls stay inside the existing `try` whose `except (OSError, CommandError, ValueError)` builds the `State check failed:` detail; no new except clause.
- TUI `_wait_worker`: initialise the error to the fixed text `state check did not complete`, run `run_live(lambda: (refresh(catalog), refresh_skills(catalog)))` in a `try`, turn any other `Exception` into its first line (type name when empty) in an `except Exception` clause, and post `StateSettled(token, error)` from `finally`. Ruff selects `E, F, I, B, UP, SIM` (pyproject `[tool.ruff.lint]`), so `except Exception` is lint-clean and needs no `# noqa`; do not add one. Never `return` inside the `finally` (ruff B012).
- `on_state_settled`: after the token check, set `_waiting = False`; then, when `self.started or self.finished`, return without repainting (the start request is already consumed or irrelevant). Only after that guard does the existing error/replan logic run. The error text is cut to its first line before `Text.truncate`.
- `tests/state_doubles.py::skill_pack_tool(tool_id)` returns a `Tool` with one `skill_pack` method, tier `ai`, and a `SkillLifecycle` with manual-required operations and one `SkillStatusProbe("claude", "plugin-cli", tool_id)`, the same shape as `tests/test_version_status.py::_skill_pack` (that helper is module-private; importing it would need a `reportPrivateUsage` suppression, so the double is public in `state_doubles`).
