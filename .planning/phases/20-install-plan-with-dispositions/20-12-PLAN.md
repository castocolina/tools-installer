Decisions recorded for this plan (Claude's discretion):
- `StateSettled(token: int, error: str | None)` message posted from the worker.
- `_await_state()`: `token = self._wait_token`; `self._wait_worker(token)` where `_wait_worker` is `@work(thread=True, exclusive=True, group="execute-wait", exit_on_error=False)` and does `_result, error = run_live(lambda: refresh.refresh(self._inputs.catalog))` then `self.post_message(StateSettled(token, error))`. `exclusive=True` is for Textual's bookkeeping; the token is the correctness guard (a thread worker cannot be interrupted).
- `on_state_settled`: `if message.token != self._wait_token: return`; error -> status `error` `State check failed: {truncated error}. enter retries · esc closes.`, `_start_requested = False`, return; else `_replan()`, repaint; if `_start_requested` and no WAIT row: `_start_requested = False`, `_begin_run()`; if a WAIT row survives: status `error` `State check failed: no state for {ids}. enter retries · esc closes.`, `_start_requested = False`.
- `action_start` (from 20-10) with a WAIT row: set `_start_requested = True`, set the Waiting status/keys, and call `_await_state()` once per request (a second Enter while waiting is a no-op: guard on `_start_requested`).
- `action_close` while `_start_requested`: `_wait_token += 1`, `_start_requested = False`, status `warn` `Wait cancelled; nothing started. enter waits again · esc closes.`, keys back to the idle line, return without dismissing.
- `on_mount`: after `_replan()`, if any WAIT row, `_await_state()` (no start request) so `checking…` rows repaint by themselves; the unattended auto-start then calls `action_start`, which registers the request on the same token.
- Truncation: `_fit(text, 78)` helper: cut and append `…` when `cell_len` exceeds 78.
- `HeldRefreshService(FrozenStateService)`: `__init__(..., pending: Iterable[ToolState])`, `release = threading.Event()`, `calls: list[frozenset[str]]`; `refresh(tools)`: append the id set, wait on `release`, then `publish(pending)`. `refresh_skills` as the parent. A `raising=OSError("probe failed")` option makes `refresh` raise after release instead of publishing.
