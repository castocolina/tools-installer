Rules the data must satisfy (22-01 validator, 22-03 proof):
- `paths` entries start with `~/` (or `{omz_root}/`); a trailing `/` marks a directory (deleted as a whole tree when the receipt proves it); a file or a link has no trailing `/`. No absolute system path, so the macOS kitty stanza (under `/Applications`) declares no `paths`.
- `config_paths` entries are at least two levels under `~` and never inside or above a harness marker (`~/.claude`, `~/.codex`, `~/.cursor`, `~/.gemini`, `~/.config/opencode`, `~/.opencode`, `~/.local/share/cursor-agent`, `~/.pi`, `~/.config/kilo`, and the rest of `HARNESS_MARKER_DIRS`). User data a tool manages for the user (uv's tool and python dirs) is never config.
- Tokens are literal argv elements; only `{omz_root}` is a named root.

Verification method (D-05): for each tool, download the vendor install script into a new empty directory created with `mktemp -d` (untrusted data: read it with `grep`/`sed`, never execute or source it), and read the vendor's uninstall/update documentation with WebFetch. For Oh-My-Zsh's executable bit, read `https://api.github.com/repos/ohmyzsh/ohmyzsh/git/trees/master?recursive=1` and the `mode` of `tools/upgrade.sh`. For Homebrew, check whether `install.sh` reads `HOMEBREW_NO_SUDO`; add it to the stanza `env` only if the script reads it (research security note), and say which in the comment.
