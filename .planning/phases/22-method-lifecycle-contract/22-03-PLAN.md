<objective>
Script tools get a removal proof that survives their own self-updates. The registry's declared `paths` (22-01) become artifacts through the one `artifact_paths` formula; the receipt records them type-only (a real directory, a regular file, or a link and its target); removal deletes only what was recorded and still matches, through the existing quarantine for directories. A foreign file at a declared path is never touched and is listed as remove it yourself.

Purpose: the proof half of LIFE-01 (removal deletes only receipt-recorded declared paths that still match their type and link target). 22-06 builds the L3 recipe level on this.
Output: `expand_script_token` and the script branch of `artifact_paths` in `installer/download.py`; `tree`/`leaf` artifacts in `installer/receipts.py`; their deletion in `installer/uninstall.py`.
</objective>

Decisions recorded for this plan:
- Ledger Q3 (binding): script `paths` proof is type-only with link-target rules (hash proof would make auto-updating tools unremovable).
- Artifact naming (Claude's discretion): two new types, `tree` (type-only directory) and `leaf` (type-only file or link), so the existing `(path, type)` pair intersection in `_receipt_proof` keeps a receipt from retyping a leaf into a recursive delete (19 review H6), and an older reader fails closed on them. A `leaf` records `target` when it is a symlink and no target when it is a regular file; nothing else is recorded for either type.
- Pre-install evidence (review R1-05, planner rule; `record` has always fingerprinted after the install for every kind, so this is the one new input): `record(tool, method, *, package, smoke, default_bin_dir=None, preexisting: frozenset[Path] | None = None)`. For `tree`/`leaf` candidates only, a candidate in `preexisting` (every candidate when `preexisting is None`) is kept only when the tool's previous receipt, read before the new one is written, holds an artifact with the same path and type that `matches` with the previous receipt's own trees; every other kind ignores `preexisting` (download and app artifacts are placed and hashed by the installer itself). `preexisting_paths(method: Method, default_bin_dir: Path | None = None) -> frozenset[Path]` returns the `tree`/`leaf` entries of `artifact_paths(method, base)` that exist now by `os.path.lexists` (empty for every other kind). The production callers are wired in wave 3 by the plans that own their files: `engine.install_tool` (`engine.py:269`, 22-06) and `update._perform` (`update.py:364`, 22-05) take the snapshot right before running the method and pass it.
- Link rule: `matches(artifact, *, rehash=False, trees=())` gains a `trees: Sequence[Path]` keyword; a `leaf` link matches while it is still a symlink and its readlink equals the recorded target, or `os.path.normpath(link.parent / readlink)` is inside one of `trees`. `drifted` and `broken_drift` pass the receipt's own `tree` paths. The rule is lexical, so it holds after the tree itself is gone (the vendor's `remove` may delete it before step 2 in 22-06).
- `remove_paths(artifacts, *, trees: Sequence[Path] | None = None)`: `None` means the `tree` paths among `artifacts`; 22-06 passes the plan's trees when it deletes only what a vendor `remove` left.
- `broken_drift` treats `tree` like `dir` (a changed tree loses its proof, never health); a `leaf` that no longer matches is broken like a file or link (Phase 19 L-19-31).
- Expansion lives in `installer/download.py` (it already serves install placement, and `uninstall`, `receipts` and `update` import it): `SCRIPT_ROOT_RESOLVERS: dict[str, Callable[[], Path | None]]` maps `omz_root` to a private `_zsh_first_omz_root()` (orchestrator decision on 22-REUSE 05-2, SPEC R8): return `Path(os.environ["ZSH"])` when `$ZSH` is set and `is_dir()`, else `omz_root(Path.home(), os.environ)` (the existing resolver as the fallback; do not change `omz_root` itself, its callers keep default-first until Phase 23 CONF-07).
