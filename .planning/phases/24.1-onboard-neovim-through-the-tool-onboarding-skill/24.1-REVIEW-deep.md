# Phase 24.1: Deep Code Review

**Reviewed:** 2026-11-13
**Depth:** deep (cross-module: shellrc, tweaks, post_install, version_status, engine, app removal, setup wiring, e2e harness)
**Range:** `git diff fda6f2f..004a4a2`, `.planning/` used only as context
**Status:** issues_found

## Summary

The clone path in `_clone_nvim_starter` is careful. It works in a mkdtemp sibling, re-checks absent-or-empty before the move, renames so that a non-empty dir, file or symlink at the target refuses the move, cleans up in `finally`, passes only constant argv and sanitizes the error text. I found no data-loss, injection or sudo path in it. Removal symmetry for the editor bundle holds: `app._after_removal` strips the block and forgets the record, and `removal_change_lines` previews it. The phase tests pass locally (`tests/test_neovim.py`, `test_post_install.py`, `test_shellrc.py`, `test_tweaks.py`, `test_version_status.py`, `test_container_e2e_receipts.py`, `test_setup.py`).

The weak part is the `EDITOR`/`VISUAL` yield gate. `find_export` misses realistic user forms, and the gate never removes a block an earlier run wrote. Either way the installer's `export EDITOR=nvim VISUAL=nvim` takes effect over the user's own choice, which the SPEC prohibition forbids. There is also one macOS-only defect: the starter runs `/usr/bin/git` without the stub check the codebase already has.

The decisions D-03 (refined), D-14, D-15 and D-17 are taken as given. The findings below concern only how they were implemented.

Necessity rubric (`.claude/gsd-core/references/necessity-review.md`) read; one necessity item (LR-08).

## High

### HR-01: The yield gate misses `case`-arm exports, so the bundle overrides the user's editor

**File:** `installer/shellrc.py:1236-1255` (`_LEADING_RESERVED`, `_statement_assignments`). Consumed by `installer/tweaks.py:461-492` (`user_export`) and `installer/post_install.py:279-286`.

**Issue:** `_statement_assignments` counts an export only when `export`/`typeset -x`/`declare -x` is the first word, after stripping just `then else do { ( !`. A `case` arm puts its pattern word first, so the export is never seen. I verified this with `find_export` directly:

```
case "$(uname)" in
  Darwin) export EDITOR="code -w" ;;
  *) export EDITOR=vim ;;
esac                                  -> None
case $X in a) export EDITOR=vim ;; esac   -> None
time export EDITOR=vim                    -> None
```

**Failure scenario:** A user's `~/.zshrc` picks the editor per OS or per SSH session in a `case` block (a common dotfiles idiom). `user_export` returns None, so `_tune_shell_init` writes `tweak:neovim` into `~/.myshellrc` and records it. `ensure_source`/`apply_block` (`installer/shellrc.py:155-172`, `:293-303`) appended the `~/.myshellrc` source block to the end of the rc, so the bundle runs after the user's `case` block. A new shell then has `EDITOR=nvim`, and git, crontab and sudoedit open nvim. This breaks the SPEC prohibition "MUST NOT write `EDITOR`/`VISUAL` when the user's own shell files already export either". `version_status` uses the same gate, so the `≈` pending step offers the same override again after a removal.

The documented shortcut (sourced files are not followed, `shellrc.py:1283`) fails the same way for the very common `source ~/.config/shell/exports.sh` layout. It is accepted in the docstring, but the effect is the same prohibition breach. It is worth naming in the SPEC edge table as a known gap rather than leaving it only in a code comment.

**Fix:** The gate fails closed, so a false positive (yield) is the cheap error. Recognise the export command anywhere in a statement, not only at its head. Skip leading words until the first `export`/`typeset`/`declare`/`NAME=` word, which covers `pat)`, `time`, `case … in pat)` and `if`:

```python
_EXPORTERS = frozenset({"export", "typeset", "declare"})

def _statement_assignments(words: list[str]) -> list[str]:
    start = next((i for i, w in enumerate(words) if w in _EXPORTERS), None)
    if start is not None:
        words = words[start:]
        head = words[0]
        if head == "export" or (len(words) > 1 and re.fullmatch(r"-\w*x\w*", words[1])):
            return [w for w in words[1:] if _ASSIGNMENT.match(w)]
        return []
    while words and (words[0] in _LEADING_RESERVED or words[0].endswith(")")):
        words = words[1:]
    return words if words and all(_ASSIGNMENT.match(w) for w in words) else []
```

Add `find_export` cases for a multi-line `case`, a one-line `case`, and `time export`.

## Medium

### MR-01: A block written earlier survives the yield, and the summary says it was not written

**File:** `installer/post_install.py:270-290` (`_tune_shell_init`). Same gate in `installer/version_status.py:672-673`.

**Issue:** The yield returns before `tweak_policy(...).apply()`, but it never strips a `tweak:neovim` block that an earlier run wrote and recorded. I reproduced it in a scratch HOME: a first install writes the block and records `neovim`; the user then adds `export EDITOR=hx` to `~/.zshenv`; a reinstall returns `Kept your EDITOR=hx (the neovim shell init was not written).` The block `export EDITOR=nvim VISUAL=nvim` is still in `~/.myshellrc`.

**Failure scenario:** zsh reads `~/.zshenv` (and bash reads `~/.bash_profile`/`~/.profile`) before `.zshrc`/`.bashrc` sources `~/.myshellrc`. The old block therefore overrides the user's later export. The reinstall summary says the opposite, and `version_status` hides it because the gate returns `_NO_FACTS`. VISUAL also stays `nvim` even when the user's `.zshrc` export runs last. The written-once record still lists `neovim`, so nothing ever brings this back to the user's attention. No test covers "block present + user export" (`test_neovim_reinstall_rewrites_the_block_in_place` has no user export).

**Fix:** When `user_export` yields and the bundle's marker is present, remove the block through the same policy (`tweak_policy(bundle, rc_path=rc_path).remove()` or `sweep_policies(active_policies((bundle,), ...))` as `_after_removal` does). Then call `forget_shell_init(rc_path, tool.id)` and return e.g. `Kept your EDITOR=hx; removed the earlier neovim shell init.` Add a test with both the block and a `~/.zshenv` export.

### MR-02: On macOS the starter runs the `/usr/bin/git` stub, which pops the CLT installer dialog

**File:** `installer/post_install.py:218` (`shutil.which("git") is None`).

**Issue:** On a Mac without the Command Line Tools, `/usr/bin/git` is the xcrun shim. Running it opens the system dialog "The git command requires the command line developer tools…" and exits non-zero. The codebase already knows this: `installer/status.py:18-21` maps `/usr/bin/git` to `xcode-select -p` in `MACOS_STUBS`, and `macos_stub_reason` exists for exactly this case. The new action uses a bare `which`.

**Failure scenario:** On macOS without Homebrew or CLT, the resolver picks the `github_release` tarball first (`registry.toml` neovim, `os = ["macos"]`), which needs no CLT, so the install succeeds. Then `clone_nvim_starter` runs `git clone` from a background worker while Textual owns the terminal, or headless. A GUI install prompt for system developer tools appears from a "non-interactive" action, and the summary prints `Starter not added: xcode-select: note: No developer tools were found…`. This bypasses the host-safety doctrine in the module docstring ("never spawns an interactive child"). Linux is unaffected, and CI cannot see it because the tests fake `which`.

**Fix:** Reuse the existing probe before the first `_git` call:

```python
git = shutil.which("git")
if git is None or (sys.platform == "darwin" and git in MACOS_STUBS
                   and not _default_stub_probe(MACOS_STUBS[git])):
    return ("Starter not added: git is not installed.", *_by_hand())
```

Or factor the check into a helper `status.real_command("git")` that `macos_stub_reason` also uses. Add a test with `darwin=True` and a failing stub probe.

## Low

### LR-01: The "Kept your NAME=value" text is neither verbatim nor the effective value

**File:** `installer/tweaks.py:470-492`, `installer/shellrc.py:1229` (`_SHELL_WORD`).

**Issue:** The tokenizer splits inside `$(…)` and `${…}` at spaces and at `||`. So `export EDITOR=$(command -v nvim || echo vi)` is reported as `Kept your EDITOR=$(command`, and `${EDITOR:-code --wait}` as `${EDITOR:-code`. The SPEC encoding edge asks for the value "verbatim". Also, `user_export` returns the first file in scan order with any export (`~/.myshellrc` before `.zshrc`), not the one that runs last, so the reported value can be one the shell overrides.

**Fix:** Treat `$(` … `)` and `${` … `}` as balanced spans in `_SHELL_WORD`, or report the raw line text up to the comment. Collect hits from all files and report the last in source order.

### LR-02: The child git inherits user git config and environment that can redirect or break it

**File:** `setup.py:771-773` (`_run_git`), `installer/post_install.py:226-233`.

**Issue:** The child gets `{**os.environ, "GIT_TERMINAL_PROMPT": "0"}`, so several inputs still reach it:
- **`GIT_DIR`/`GIT_WORK_TREE`/`GIT_INDEX_FILE`** (set by `yadm enter`, `vcsh enter`, or inside a git hook). I probed this with scratch repos: the clone or checkout fails and the dotfiles repo is not modified, so the outcome is a failure, not data loss. An inherited `GIT_INDEX_FILE` would make the checkout write a foreign index.
- **`url.<base>.insteadOf`** rewriting github https to ssh. With `SSH_ASKPASS` set (KDE/Bazzite sets ksshaskpass) and no tty from `start_new_session`, ssh shows a GUI passphrase or host-key prompt.
- **A global `core.hooksPath`/`init.templateDir` post-checkout hook** (for example git-lfs's, when lfs is missing). It makes the checkout exit non-zero.
- **`core.autocrlf=true`.** It can make `git apply` fail.

**Fix:** Build the child env without these variables and harden the commands:
- drop `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, `GIT_OBJECT_DIRECTORY`, `GIT_ALTERNATE_OBJECT_DIRECTORIES` and `GIT_CONFIG_PARAMETERS`;
- add `GIT_SSH_COMMAND="ssh -oBatchMode=yes"` and `SSH_ASKPASS_REQUIRE=never`;
- pass `-c core.hooksPath=/dev/null -c core.autocrlf=false` to the clone and the checkout.

### LR-03: The by-hand patch command is unquoted and points into the installer's own tree

**File:** `installer/post_install.py:186-192`.

**Issue:** `git -C ~/.config/nvim apply {_KICKSTART_PATCH}` interpolates an absolute path without quoting. A checkout under `~/My Projects/` gives a command that fails when pasted. When the installer runs from a uv cache or an ephemeral environment, the path may no longer exist after the run.

**Fix:** Use `shlex.quote(str(_KICKSTART_PATCH))`. Optionally add a line saying the patch replaces the `servers` table with `{}` at the end of its block, so the user can still do it by hand when the file is gone.

### LR-04: The XDG comparison is lexical, and NVIM_APPNAME is ignored

**File:** `installer/post_install.py:214`.

**Issue:** `xdg_config_base(home, os.environ) != config_dir` compares paths as strings. On Fedora Atomic/Bazzite `/home` is a symlink to `/var/home`. If `XDG_CONFIG_HOME=/home/u/.config` while `HOME=/var/home/u`, the starter refuses with "points elsewhere", although both name the same directory. Separately, with `NVIM_APPNAME` set, nvim reads `~/.config/$NVIM_APPNAME`, and the placed starter is dead weight.

**Fix:** Compare with `os.path.samefile` when both exist, falling back to the resolved path. Skip, with a reason, when `NVIM_APPNAME` is set and is not `nvim`.

### LR-05: A crashed or killed run leaves `~/.config/.nvim-starter.*` forever

**File:** `installer/post_install.py:223`, `:249-251`.

**Issue:** `finally` covers exceptions only. A SIGKILL, a power loss, or the app exiting while the worker thread is inside `_git` leaves the mkdtemp dir. `start_new_session=True` means the git child even keeps cloning into it after the installer is gone. Nothing sweeps the prefix later, and the removal plan does not know it.

**Fix:** At the start of `_clone_nvim_starter`, remove stale `config_dir.glob(".nvim-starter.*")` dirs older than the git timeout (600 s), or document the leftover in the hint.

### LR-06: The hints and the "is yours" message overstate the situation

**File:** `installer/post_install.py:180-183`, `:217`.

**Issue:** `_NVIM_HINTS` always says "Neovim runs no language server". `test_neovim_hints_print_with_your_own_config` pins that it prints even when `~/.config/nvim` is the user's own config, which may well run servers. On a reinstall over the installer's own starter, the line `~/.config/nvim is yours` is also inaccurate.

**Fix:** Print the no-LSP line only when this run placed the starter. Word the skip as `~/.config/nvim already exists (left as is).`

### LR-07: The installer's own nvim probes leave `~/.local/state/nvim`, and the e2e allowlist hides it

**File:** `scripts/e2e-residue-allowlist.txt:27`.

**Issue:** The allowlist entry says the dir is written by the installer's own `nvim --version` smoke run and status probe. After a full uninstall the user's HOME still holds a dir the installer caused. Allowlisting accepts the residue instead of preventing it. The e2e probes themselves avoid it by pointing the XDG dirs at a mktemp dir (`container-e2e-verify.sh`, `nvim_probe_installed`).

**Fix:** Run nvim version probes with `XDG_STATE_HOME` (and `XDG_DATA_HOME`/`XDG_CACHE_HOME`) set to a temp dir, as the e2e gather does, or with `--clean`. Then drop the allowlist line.

### LR-08: Already-defended-elsewhere: `git apply --check` before `git apply`

**File:** `installer/post_install.py:232-233`.
**Category:** necessity

**Issue:** By default, `git apply` refuses the whole patch and leaves the working tree untouched when any hunk fails (all-or-nothing, git-apply(1), `--reject` description). The separate `--check` run guards against a partial apply that cannot happen, and it costs one more child process and one more fake-runner step in every test.

**Fix:** Drop the `--check` call and keep the single `git apply`. Its failure already lands in the same `CommandError` branch, and `tmp` is removed.

## Checked and found sound

- **Clone safety:**
  - Symlinked, file, dotfile-only, non-UTF-8-named and unreadable targets count as the user's.
  - A rename onto a non-empty dir, a file or a symlink fails (ENOTEMPTY/ENOTDIR), so content created during the clone is never replaced.
  - An empty target dir is replaced atomically.
  - The patch path is package data: hatch's wheel target includes the whole `installer` package.
- **Injection:** the URL, pin and patch path are constants, `--` precedes the URL, and the work dir is an absolute mkdtemp path. Error text goes through `sanitize_log_line` (the head-mismatch text is git hex output).
- **Host safety:** no sudo, pkexec or doas. Git runs with DEVNULL stdin and a timeout. RECONFIGURE (`apply_install_tuning`) never runs the starter, and shell-init bundles are filtered out of the Policies view (`setup.py:990`), so the yield gate cannot be bypassed there.
- **`user_export` fail-closed handling:** an oversized file is refused, an unreadable one is refused with a sanitized message, missing and non-regular files are skipped, and the `~/.zshenv`/ZDOTDIR cases are covered.
- **`find_export` parsing:**
  - CRLF, tab and `#` comments, `#` inside values, quoted spans and stray quotes are handled.
  - Nested and unterminated installer blocks are handled, and the consolidated shellrc block is read as user content.
  - The regex has no catastrophic backtracking.
- **E2E harness:** `pipefail` is set, the verdicts fail closed on a missing `D`/`NVIM_LSP_DONE`, and the zero-LSP probe also asserts the lspconfig and mason plugin dirs, so a no-plugin run cannot pass. The Fedora log in the session scratch shows `TRACER_NVIM_INSTALLED_OK`, `TRACER_NVIM_LSP_OK clients=0 mason_entries=0` and `TRACER_NVIM_REMOVED_OK`.
