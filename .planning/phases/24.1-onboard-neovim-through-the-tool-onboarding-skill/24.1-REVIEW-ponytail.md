**What this change does:** It adds Neovim to the catalog (GitHub release tarball into
`~/.local/opt/nvim`, with brew and native handoffs), an `EDITOR`/`VISUAL` shell-init block that is
skipped when the user's own shell files already set one of them, and a pinned kickstart.nvim
starter. The starter is cloned through an injected non-interactive git runner, gets a one-line
no-LSP patch, and is moved into an absent or empty `~/.config/nvim`. The container harness gains
probes for the install, the uninstall and a zero-language-server check.

## MEDIUM

### 1. A stale installer EDITOR block survives the yield, and the message says the opposite
(`installer/post_install.py:279-282`, `installer/version_status.py:672-673`)

- **What this is:** On install, `_tune_shell_init` asks `user_export` whether the user already
  exports `EDITOR` or `VISUAL`. If so it returns "Kept your EDITOR=..." and writes nothing.
- **Problem:** The yield only skips the write. It never removes a `tweak:neovim` block the
  installer wrote earlier. Concrete case: install neovim with no EDITOR set (block written to
  `~/.myshellrc`), then the user adds `export EDITOR=vim` to `~/.profile` or `~/.zshenv`, then
  reinstalls or repairs neovim. The summary says "Kept your EDITOR=vim (the neovim shell init was
  not written)", but the old block still sits in `~/.myshellrc`. That file is sourced after
  `.profile`/`.zshenv`, so new shells still get `EDITOR=nvim`. The status view also shows nothing
  pending, because `_shell_init_tuning_fact` returns `_NO_FACTS` as soon as `user_export` yields.
  The record stays too. No test covers "block present, then the user exports" (the tests cover a
  fresh yield and a plain reinstall only).
- **Fix:** In the yield branch, when `bundle_marker_present(tool.id, rc_path)` is true, remove the
  block the same way uninstall does (the bundle's `tweak_policy(...)` removal / `strip_block`) and
  call `forget_shell_init(rc_path, tool.id)`, then return the "Kept your ..." line. Add one test:
  write the block, add `export EDITOR=vim` to `~/.zshrc`, rerun, and assert the block and the
  record are gone.
- **If we skip it:** The installer tells the user their editor won, while its own line keeps
  overriding it, and nothing in the UI shows how to get rid of it short of uninstalling neovim.

## LOW

### 2. The hint "Neovim runs no language server" is printed over the user's own config
(`installer/post_install.py:180-183`, `414-420`)

- **What this is:** `show_nvim_hints` always prints two lines after the starter step.
- **Problem:** When `~/.config/nvim` is the user's own config (starter skipped as "yours"), that
  config may well run language servers. The first line then states something false.
  `test_neovim_hints_print_with_your_own_config` pins this wording.
- **Fix:** Reword it to "The starter runs no language server: ..." (one string, no new logic).
- **If we skip it:** A user with an LSP setup reads a wrong claim about their own editor.

### 3. The by-hand patch command breaks when the repo path has a space
(`installer/post_install.py:191`)

- **What this is:** On failure the starter prints three commands for the user to paste.
- **Problem:** `git -C ~/.config/nvim apply {_KICKSTART_PATCH}` interpolates an absolute path
  inside the installer checkout unquoted. A checkout under `~/My Projects/` gives a command that
  fails with "can't open patch".
- **Fix:** `shlex.quote(str(_KICKSTART_PATCH))` in that one f-string.
- **If we skip it:** The recovery instructions fail for that user.

### 4. A killed install leaves a hidden starter clone in `~/.config` forever
(`installer/post_install.py:223`, `249-251`)

- **What this is:** The clone goes into `~/.config/.nvim-starter.XXXX` and `finally` removes it.
- **Problem:** `finally` does not run on SIGKILL, a power loss or a terminal close that kills the
  worker. The next run makes a new temp dir and never looks at the old one, so each such crash
  leaves a full kickstart clone behind.
- **Fix:** Before `mkdtemp`, sweep old ones:
  `for old in config_dir.glob(".nvim-starter.*"): shutil.rmtree(old, ignore_errors=True)`.
- **If we skip it:** A few MB of hidden clutter per crashed run. No data loss.

### 5. An `XDG_CONFIG_HOME` that names `~/.config` through a symlinked home skips the starter
(`installer/post_install.py:214`)

- **What this is:** The starter refuses when `XDG_CONFIG_HOME` points anywhere but `~/.config`.
- **Problem:** The check compares path spellings. On Fedora Atomic (the project's own host
  family), `/home` is a symlink to `/var/home`. With `HOME=/var/home/u` and
  `XDG_CONFIG_HOME=/home/u/.config`, both name the same directory, but the starter says
  "XDG_CONFIG_HOME points elsewhere" and is skipped.
- **Fix:** Compare resolved paths:
  `xdg_config_base(home, os.environ).resolve() != config_dir.resolve()`.
- **If we skip it:** Those users get no starter and a misleading reason.

### 6. A user's SSH `insteadOf` rewrite can pop a GUI passphrase dialog during install
(`setup.py:771-773`)

- **What this is:** `_run_git` sets `GIT_TERMINAL_PROMPT=0`, a 600 s timeout, no stdin and a new
  session.
- **Problem:** `GIT_TERMINAL_PROMPT=0` only stops git's own HTTPS credential prompt. A common
  dotfile rule, `url."git@github.com:".insteadOf = https://github.com/`, turns the clone into SSH.
  With a passphrase key not in the agent and `SSH_ASKPASS` set (KDE sets it to `ksshaskpass`),
  ssh opens a GUI dialog in the middle of the install, and the worker waits up to 10 minutes.
- **Fix:** Add `"SSH_ASKPASS_REQUIRE": "never"` to the same env dict. ssh then fails at once
  without a terminal and the user gets the by-hand lines.
- **If we skip it:** A surprise dialog, or a long silent wait, for that set of users.

### 7. A command-substitution EDITOR is shown cut in half
(`installer/shellrc.py:1234`)

- **What this is:** `_SHELL_WORD` splits a line into shell words for `find_export`.
- **Problem:** Only quotes group spaces, so `export EDITOR=$(command -v vim)` yields the word
  `EDITOR=$(command`. The yield is still right, but the summary says
  "Kept your EDITOR=$(command (the neovim shell init was not written)."
- **Fix:** Add `\$\([^)]*\)` and `` `[^`]*` `` as grouped alternatives in `_SHELL_WORD`, plus one
  parametrized case in `test_find_export_statement_forms`.
- **If we skip it:** A garbled but harmless message.
