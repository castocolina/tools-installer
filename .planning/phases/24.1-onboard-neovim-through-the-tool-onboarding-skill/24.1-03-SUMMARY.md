# Phase 24.1 Plan 03: pinned no-LSP kickstart starter for neovim

A neovim install now places the pinned kickstart.nvim starter, patched so it carries no language server, into an absent or empty `~/.config/nvim` through a git runner the composition root injects. It touches nothing else, and prints the two hints on every install.

## What was built

- `clone_nvim_starter` (post_install.py): XDG check, absent-or-empty check (symlink, file, dotfile, non-UTF-8 name all count as "yours"), `git` presence check, then clone, checkout of the full SHA, `rev-parse` against the pin, `apply --check`, `apply` inside a `mkdtemp` dir under `~/.config`, a re-check, and `os.rename` onto the target. Every failure returns `Starter not added: <reason>.` plus the by-hand commands; a `finally` removes the temp dir (also on `KeyboardInterrupt`).
- `show_nvim_hints`: its own action, so the hints survive a skipped or crashed starter.
- `use_git_runner` / `_no_git` / `_git`: refusing default (`CommandError` 127). `setup.py` `_run_git` wires `run_output(argv, timeout=600, env={..., "GIT_TERMINAL_PROMPT": "0"})` on the app route and the headless route.
- `installer/patches/kickstart-no-lsp.patch`: one hunk, one added line. Shipped in the wheel (listing below).
- Registry/model: neovim's `post_install` is `source_shell_init, clone_nvim_starter, show_nvim_hints`; both names are in `POST_INSTALL_ACTIONS`.
- `apply_install_tuning` is untouched, so RECONFIGURE never runs the starter. No receipt record, no `≈` step.
- D-21 comments in post_install.py, model.py, engine.py and tests/test_execute_screen.py now say the sensitive machinery has no user and Phase 25 sweeps it (24.1 D-21). `.claude/architecture.md` has the paragraph on the one child-spawning action.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] The patch's one-space context line was written as an empty line**
- **Found during:** Task 2 (`test_kickstart_patch_is_one_reviewed_hunk`)
- **Issue:** The Write tool stripped the trailing space, so the line between the added line and `  vim.pack.add {` was empty, not one space. `git apply` tolerates it, but the plan requires the exact bytes.
- **Fix:** Rewrote that one byte with a script. The hunk then passes `git apply --check` and `git apply` against a synthetic `init.lua` with the six old-side lines at 778 (format check only; the real check at the pin is the container's).
- **Files modified:** installer/patches/kickstart-no-lsp.patch
- **Commit:** 4f38cf2 (the Task 1 commit 440388c carried the empty line; the tree is correct from 4f38cf2 on)

**2. [Rule 3 - Blocking] The test helper is public**
- The plan names `FakeGit` in tests/test_post_install.py and imports it into tests/test_neovim.py. The helper that installs the fake runner is `use_fake_git`, with no underscore, because strict Pyright reports `reportPrivateUsage` on a cross-module import of an underscore name.

## Known limits (not defects)

- `os.rename` moves the `mkdtemp` directory, which is mode 0700, so a fresh `~/.config/nvim` is 0700 rather than umask-default. Left as is; harmless for a user config dir.
- The real clone, the real `git apply --check` at the pin and the move run only in the container (24.1-05).
- D-15 and D-17 (amended) remain "needs confirmation".
