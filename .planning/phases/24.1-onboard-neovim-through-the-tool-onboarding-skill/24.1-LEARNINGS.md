# Phase 24.1 Learnings: Onboard Neovim through the tool-onboarding skill

## Decisions

### Neovim ships as a registry-only row on the existing release, receipt and removal paths
The `neovim` row (cmd `nvim`, category editor, tier user) carries a `github_release` tarball per Linux and macOS arch, then brew, then dnf/apt/pacman as MANUAL handoffs. No neovim-specific install or removal code was added.

**Rationale:** the generic engine already installs, receipts and removes archive tools; the tests pin that engine on the shipped entry instead of adding code (CONTEXT D-01..D-03).
**Source:** 24.1-01-SUMMARY.md, 24.1-CONTEXT.md

---

### Verify the tarball by the GitHub API digest only
The entry sets no `checksum` template because upstream ships no checksum file; `download.py` falls back to `release.digests[asset]` and raises `ChecksumMismatch` before extraction.

**Rationale:** the digest comes from the same API snapshot as the tag, so it is the only available integrity check. Residual risk: if the API returns no digest the tarball installs as `unverified` (shown, not silent).
**Source:** 24.1-01-SUMMARY.md, 24.1-SECURITY.md (T-24.1-01, R3)

---

### The opt tree is removed whole, including a file the user dropped in it (D-03 refined)
Removal takes `~/.local/opt/nvim` as one `dir` artifact proven by one key-file fingerprint. The SPEC R3 clause "a dropped file is listed, not deleted" was amended away.

**Rationale:** 22 D-07 lists foreign files only at declared paths; `update_download` already replaces the same tree whole; a per-member manifest of a 40 MB tree would not fit the receipt's 64 KiB read cap. Reversal would be a generic manifest plan across `receipts.py`, `uninstall.py` and `download.py`. Owner kept it (UAT test 3).
**Source:** 24.1-CONTEXT.md, 24.1-01-SUMMARY.md, 24.1-SECURITY.md (T-24.1-04), 24.1-UAT.md

---

### EDITOR/VISUAL is install tuning with no question, and it yields to the user (D-14)
Install writes `export EDITOR=nvim VISUAL=nvim` into `~/.myshellrc` only when none of the user's own startup files assigns either. ONB-09 had been locked as "asks whether"; the install-tuning rule replaced the question.

**Rationale:** the user's 2026-11-07 install-tuning rule; the block body uses the `if` form so a missing `nvim` never leaves a non-zero status as the sourced block's last command. Reversal: an asked item under a new sensitive action name (D-21). Owner kept it (UAT test 1).
**Source:** 24.1-02-SUMMARY.md, 24.1-CONTEXT.md, 24.1-UAT.md

---

### A pinned, patched kickstart.nvim starter is cloned with no question, only into an absent or empty `~/.config/nvim` (D-15)
The starter is pinned to commit `8e35dbe…`, patched with a one-hunk `servers = {}` line so it carries no language server, and moved into place with `os.rename`. Owner kept it (UAT test 2).

**Rationale:** the same install-tuning rule as D-14. `os.rename` onto a non-empty target fails, so it is the last time-of-check guard. The checkout uses `-B master` so the user's later `git pull` works, and the patch stays an uncommitted working-tree change so no git identity is needed.
**Source:** 24.1-03-SUMMARY.md, 24.1-CONTEXT.md (D-08 refined), 24.1-UAT.md

---

### neovim declares no `requires = ["git"]`; the starter action checks for git itself (D-17 amended)
When git is missing the action returns a skip reason plus by-hand commands and the `neovim` row stays OK.

**Rationale:** `resolve_dependencies` blocks a dependent when its required tool is unavailable, and git is a native handoff on mutable Linux; a host without git would hold back the nvim binary though only the optional starter needs git. Reversal: add `requires = ["git"]` back. Owner kept it (UAT test 2).
**Source:** 24.1-CONTEXT.md, 24.1-03-SUMMARY.md, 24.1-UAT.md

---

### Any assignment of EDITOR or VISUAL in a user shell file counts as the user's, and a false yield is the cheap error (review F1/F10)
`find_export` yields on any assignment (inside a `case` arm, after `time`, in a `&&` chain, as a command prefix, or empty). The summary names the file and line instead of re-parsing the value.

**Rationale:** the SPEC says never override a user's own editor; writing over it is the costly error, and re-parsing `$(...)` values truncated them. Owner kept it (UAT test 4).
**Source:** 24.1-REVIEW.md (F1, F10), 24.1-UAT.md

---

### The starter's files get no receipt record, and no pending step
A deleted starter is placed again only by an explicit reinstall; RECONFIGURE never runs it.

**Rationale:** receipt paths are deleted on a default removal while config goes only through the per-row toggle, so a receipt record would delete the user's config. No pending `≈` step keeps 24 D-25's rerun pass free of a pending clone.
**Source:** 24.1-CONTEXT.md (D-16, D-18), 24.1-03-SUMMARY.md, 24.1-SECURITY.md (T-24.1-19)

## Lessons

### The new row broke three pinned registry tests the plan did not list
Adding a `human`/`user` row broke the exact human set, the audience distribution (human 27 to 28) and the tier distribution (user 48 to 49) tests. Plan review caught it before execution.

**Context:** pinned counts must move in the same commit as the row; the plan's "pinned tests this task breaks" list must be the complete set.
**Source:** 24.1-REVIEWS.md (R1-01), 24.1-01-SUMMARY.md

---

### A global injected runner needs a per-test reset
Wiring `use_git_runner(_run_git)` in `setup.py` leaks into later tests unless an autouse fixture resets `post_install._git` to the refusing default, as `no_shell_init_sourcing` does.

**Context:** plan 24.1-03 first omitted `tests/conftest.py`; cycle-1 review made it a HIGH. A second HIGH followed: tests must not name private module members (strict Pyright `reportPrivateUsage`), so they use `vars(module)["_name"]`, or the helper is public (`use_fake_git`).
**Source:** 24.1-REVIEWS.md (R1-04, R2-01), 24.1-03-SUMMARY.md

---

### Shell-level tests must avoid the sandbox's `-c` string and a fixed child PATH
`. "$HOME/.myshellrc"` inside `bash -c` cannot resolve under the 23.1 sandbox, and a child `PATH` of `/usr/bin:/bin` drops a host-only zsh. Probes are written to a file under `tmp_path` with absolute paths expanded by Python, and run via `shutil.which`-resolved interpreters.

**Context:** found in plan review for 24.1-02; the `tests/test_shellrc.py` precedent already did this.
**Source:** 24.1-REVIEWS.md (R1-02, R1-03), 24.1-02-SUMMARY.md

---

### Harness code must not depend on tools macOS CI lacks
The `nvim-lsp` gather called bare `timeout`, absent from macOS CI's `/usr/bin:/bin`. The real-run test plants a `timeout` stub beside the fake `nvim`.

**Context:** review HIGH on plan 24.1-04.
**Source:** 24.1-REVIEWS.md (R1-05), 24.1-04-SUMMARY.md

---

### A probe that discards stderr can print OK over a broken config
The zero-LSP probe ignored nvim's stderr, so a Lua error in `init.lua` with exit 0 still printed `TRACER_NVIM_LSP_OK`. Each launch now records exit status and stderr; an error line fails the verdict, and network failures are classified only by positive stderr evidence (a download, DNS or rate-limit message), never by exit status alone.

**Context:** plan reviews R1-08, R2-02, R2-03, R3-01, then code-review fix F4.
**Source:** 24.1-REVIEWS.md, 24.1-REVIEW.md (F4)

---

### The first draft of EDITOR detection missed real statement forms
`export` was seen only as the first word of a statement, so `case` arms, `time`, `&&` chains and a later empty `export EDITOR=` slipped past and the installer overrode the user's editor. Also: on a yield with the installer's block already present, the block must be stripped (a reinstall had said "Kept your EDITOR" while the block still overrode `~/.zshenv`).

**Context:** deep review HR-01 and MR-01 (the phase's only HIGH), fixed as F1 and F2.
**Source:** 24.1-REVIEW.md (F1, F2)

---

### git run from an installer inherits the user's git environment
The starter's git child inherited `GIT_DIR`/`GIT_WORK_TREE`/`GIT_INDEX_FILE`, `insteadOf` rewrites to SSH (askpass GUI, 600 s wait), global hooks and `core.autocrlf`. `run_git_isolated` scrubs these and sets `GIT_TERMINAL_PROMPT=0`, `SSH_ASKPASS_REQUIRE=never`, no hooks and `autocrlf=false`.

**Context:** code review F7; also the XDG path comparison must resolve paths, so Bazzite's `/var/home` vs `/home` is not read as "points elsewhere" (F8).
**Source:** 24.1-REVIEW.md (F7, F8), 24.1-SECURITY.md (T-24.1-16)

---

### macOS without Command Line Tools runs the `/usr/bin/git` stub, which opens a system install dialog
The starter must refuse the stub through the shared stub check (`status.command_stub_reason`) with the existing how-to line.

**Context:** code review F3. Not exercised on a Mac: UAT test 8 stayed deferred.
**Source:** 24.1-REVIEW.md (F3), 24.1-UAT.md

## Patterns

### One gate helper consulted by both the writer and the pending-fact reader
`user_export` is called by `_tune_shell_init` (the writer) and `_shell_init_tuning_fact` (the status reader), so install and status can never disagree on whether the user manages EDITOR.

**When to use:** any tuning that is conditionally applied and also reported as pending.
**Source:** 24.1-02-SUMMARY.md, 24.1-VERIFICATION.md

---

### Injected runner with a refusing default and an autouse reset
`post_install` holds a `_git` that raises `CommandError` 127 until the composition root wires the real runner; unit tests fake it and never launch git.

**When to use:** any post-install action that spawns a child process; keeps the real spawn out of unit tests and makes an unwired route fail loudly.
**Source:** 24.1-03-SUMMARY.md, 24.1-SECURITY.md (T-24.1-16)

---

### Check, work in a sibling temp dir, re-check, then `os.rename`
Absent-or-empty is checked before the work and again just before the move; the temp dir is a `mkdtemp` sibling under `~/.config` (same filesystem), removed in `finally`, with stale installer-named dirs swept first (F9).

**When to use:** placing a directory the user may own, where a time-of-check race must not overwrite their data.
**Source:** 24.1-03-SUMMARY.md, 24.1-SECURITY.md (T-24.1-17), 24.1-REVIEW.md (F9)

---

### Container probe = gather script plus pure verdict function
A gather is one `exec_tester` script (single-quoted heredoc body, values passed as a `printf %q` preamble) printing fact lines; the verdict is pure bash over facts on stdin, each miss with its own `TRACER_NVIM_*` line. Each gather is also run for real over a scratch HOME with stub programs.

**When to use:** adding a container-e2e check that must be unit-testable without a container.
**Source:** 24.1-04-SUMMARY.md, 24.1-SECURITY.md (T-24.1-07)

---

### Count clients inside the running tool, not after it exits
The zero-LSP check opens five files after `VimEnter`, polls `vim.lsp.get_clients()` for 8 s, scans `/proc`, and requires `nvim-lspconfig` and `mason.nvim` to be present so a zero count is meaningful; XDG dirs point at a temp dir outside HOME.

**When to use:** proving a negative about child processes a tool starts, since servers die with the tool.
**Source:** 24.1-CONTEXT.md (D-12/D-13 refined), 24.1-04-SUMMARY.md, 24.1-UAT.md (test 7)

---

### Agent-run UAT in a disposable container through the real TUI, owner decisions recorded as "kept"
Tests 5-7 ran in a disposable fedora:44 container driven through the real TUI with numbered captures; tests 1-4 (owner decisions) were delegated and recorded as kept; macOS stayed explicitly deferred rather than flipped.
**When to use:** closing human-verification items without touching the real host.
**Source:** 24.1-UAT.md, 24.1-VERIFICATION.md

## Surprises

### The resolver does not keep the declared method order
The resolved order sorts by `_RANK` (release 20, native 30, brew 40), so tests pin the resolved order per platform: mutable Fedora/Debian/Arch `[github_release, native, brew]`, Bazzite and macOS `[github_release, brew]`.

**Impact:** tests asserting the declared order would have been wrong; plan 24.1-01 pinned the resolved order instead.
**Source:** 24.1-CONTEXT.md (D-02 refined), 24.1-01-SUMMARY.md

---

### SPEC R3's "dropped file is listed, not deleted" rested on a misreading of 22 D-07
Found by the planner in code: foreign files are listed only at a declared path, and an archive tool's opt dir is one receipt artifact.

**Impact:** a SPEC clause and part of AC 4 were amended on 2026-11-13 and needed owner confirmation (kept in UAT test 3).
**Source:** 24.1-CONTEXT.md (D-03 refined), 24.1-UAT.md

---

### `make verify-registry` hung twice during execution and wrote state to the real HOME
Both runs printed nothing for about five minutes and were stopped (`Error 143`). The first persisted partial state to `~/.local/state/tools-installer/verify-registry.json` before it was stopped, and its earlier contents could not be restored.

**Impact:** the check was open until the orchestrator re-ran it with `--state` redirected into the scratchpad; neovim then passed on all four OS/arch pairs. Drift on other entries (drawio-desktop 32.6.1 vs 32.6.10) was logged as a follow-up, not a 24.1 failure.
**Source:** 24.1-01-SUMMARY.md, 24.1-05-SUMMARY.md

---

### The Write tool stripped the patch's one-space context line
The kickstart patch's context line was written as an empty line; `git apply` tolerates it but the plan required the exact bytes. A byte-count test (`test_kickstart_patch_is_one_reviewed_hunk`) caught it and a script rewrote the byte.

**Impact:** the Task 1 commit carried the wrong byte; the tree was correct from the Task 2 fix commit on.
**Source:** 24.1-03-SUMMARY.md

---

### A first interactive nvim run in the container failed on a missing `tree-sitter` CLI, not a language server
nvim-treesitter's parser builds failed with `ENOENT: 'tree-sitter'`; the zero-LSP result was unaffected (0 clients, no server process, Mason empty). Also, `~/.local/state/nvim/nvim.log` survives removal because the installer's own `nvim --version` probes run in two generic paths with no per-tool environment (review F11, allowlist line kept).

**Impact:** a container gap and a small accepted residue, neither a product defect; both are listed as residuals.
**Source:** 24.1-UAT.md (test 7), 24.1-REVIEW.md (F11), 24.1-VERIFICATION.md
