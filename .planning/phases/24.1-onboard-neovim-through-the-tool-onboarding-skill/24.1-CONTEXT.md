## Implementation Decisions

**Decision rule:** best over easy, with the jev ladder.

### Registry, install and removal (R1–R3)
- **D-01:** `neovim` (cmd `nvim`, category editor, tier user) uses the proven archive shape (codegraph `registry.toml:1552-1567`, gh `:424-434`):
  - `github_release` with `asset = "nvim-{linux|macos}-{arch.suffix}.tar.gz"` (`assets.py:8-27`), `strip = 1`, `member = "bin/nvim"`.
  - **No `checksum` key.** Verification uses the 18 D-05 `Release.digests` from the API. The researcher confirms that no checksum file is published.
  - `github_release` floats with the latest release (18 D-03 pins only app/tarball).
- **D-02:** Methods in order: `github_release` (linux and macOS × x86_64/arm64), then `brew` (`formula = "neovim"`), then dnf/apt/pacman, which are only 22 D-12 MANUAL handoffs and are never executed.
  - The entry carries `verified = 2026-10-13` and the tool-level `config_paths = ["~/.config/nvim"]`.
  - `make verify-registry` (18 D-07) passes on all four OS/arch pairs.
- **D-03:** **No neovim-specific install or removal code.**
  - The opt tree and link come from the generic `artifact_paths` and receipt (19 D-07/D-08).
  - Removal follows 22 D-07: a foreign file in `~/.local/opt/nvim` is listed, not deleted, and `~/.config/nvim` is kept unless the 22 D-11 toggle is on.
  - Only regression tests are added for this tool.

### `EDITOR`/`VISUAL` (R4)
- **D-04:** A `TweakBundle` with `id="neovim"` (23 D-11: bundle id = tool id) and `requires=("nvim",)`.
  - Its body is `command -v nvim >/dev/null && export EDITOR=nvim VISUAL=nvim`.
  - It is asked through `source_shell_init`'s per-tool sensitive confirm, default no. Headless never opts in (`post_install.py:62`).
  - Removing the tool disables only this bundle (23 D-11's scoped sweep), so the earlier value applies again.
- **D-05:** The managed block is appended at the end of the rc through `apply_block` (`shellrc.py:147-164`), so it overrides earlier user exports with no position logic.
  - A test pins this ordering assumption.
- **D-06 (dependency on 23):** `SensitiveActionScreen`'s text is hardcoded to the login-shell question (`execute_screen.py:161-165`).
  - Phase 23 must make the prompt text depend on the action name before a second sensitive action can ask sensibly. 23 D-11 is amended to say so.
- **D-07 (best, not easy):** "Overrides EDITOR=…" comes from **scanning the target rc text**.
  - A new pure `shellrc.find_export(content, "EDITOR")` takes the last assignment before the managed block and reports its right-hand side verbatim, never re-quoted.
  - The same function feeds the removal message.
  - Never `os.environ`.
  - jev: Laya 0.52 (needs fallback); TypeSafe scan_rc_text 1.00.

### kickstart starter (R5)
- **D-08 (best, not easy):** **Pinned `git` checkout.**
  - `git clone --no-checkout` into a temp dir, `git checkout 8e35dbedb7966e3a95e1f26f9fc1179ab6c68db4`, then assert `rev-parse HEAD == pin`.
  - Run `git apply --check` and then `git apply` with the checked-in `installer/patches/kickstart-no-lsp.patch`, which empties `servers` and Mason's `ensure_installed`.
  - Only then move the tree into `~/.config/nvim`.
  - `git` is declared in `requires`.
  - Tests use a local `git bundle` fixture, with no network.
  - The user keeps real history for their own `git pull`.
  - jev: Laya codeload_tarball 0.59 (needs fallback); TypeSafe git_clone_pinned 0.97.
- **D-09:** "Absent or empty" is `not p.exists() or (p.is_dir() and not any(p.iterdir()))`, so a dir holding only a dotfile is non-empty.
  - A non-empty dir is never touched, and the summary says why.
  - The check runs again just before the move, to close the time-of-check gap.
- **D-10:** No ledger entry. `~/.config/nvim` is covered by `config_paths` and the delete-config toggle.
  - 23 D-08's ledger is for settings keys, not cloned trees, so a second record would be a second source of truth.
- **D-11:** It is offered through the same per-tool sensitive confirm, default no. Headless never opts in.
  - The summary names `:!pre-commit run --files %` and `:lsp enable <name>`.

### Zero-LSP verification (R6)
- **D-12 (best, not easy):** A new `cmd_verify_nvim_lsp` subcommand in `scripts/container-e2e-verify.sh`, reusing its container helpers (`:63-77, 89-134`).
  - It runs on one distro, outside the `--distro` matrix, and the container is removed in the same run.
  - jev: Laya 0.73 with own confidence 0.15, so I pivoted; TypeSafe 1.00.
- **D-13:** Headless nvim opens one file each of Python, Lua, TypeScript, Go and Java.
  - It waits for `VimEnter` and the lazy-load autocmds that kickstart registers at the pin, which the researcher reads from the pinned `init.lua`.
  - It **polls** `#vim.lsp.get_clients()` with a bounded timeout, not a fixed sleep.
  - It asserts that no server process exists and that the Mason packages dir (`stdpath("data")/mason/packages`, confirmed live in the container) is empty.
