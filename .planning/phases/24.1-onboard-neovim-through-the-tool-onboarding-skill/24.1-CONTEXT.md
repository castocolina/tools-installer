#### `EDITOR`/`VISUAL` (SPEC R4 amended, ONB-09)
- **D-14: The neovim `EDITOR`/`VISUAL` bundle is install tuning with no question, and it yields to the user (needs confirmation).**
  - `neovim` joins `SHELL_INIT_TOOLS` (`tweaks.py:87`) and declares `post_install = ["source_shell_init"]`. Every path keyed on that tuple then carries it with no new code: apply (`post_install.py:145`), removal preview (`app.py:677`), per-tool removal (`app.py:727`), full sweep (`uninstall.py:620-628`), and 23.2's Policies filter (D-09), written-once record (D-08), pending fact (D-04) and RECONFIGURE step (D-03).
  - The bundle is written only when the user's own shell files, outside managed blocks, export neither `EDITOR` nor `VISUAL`. OS defaults do not count (live: on this host `EDITOR` comes only from `/etc/profile.d/ms-edit-default-editor.sh` and `nano-default-editor.sh`, both `-z`-guarded; `VISUAL` is set nowhere). When the user set one, nothing is written, the summary says "kept your EDITOR=…" (verbatim, D-07), and no `≈` is raised for it.
  - Why yield and not override: with no question there is no "yes" to justify replacing a user value (the SPEC's original override rested on that "yes", `24.1-SPEC.md` interview log); every other unasked write sets only absent values (TUNE-01, CONF-11); and the bundle sits in `~/.myshellrc`, mid-rc, so a later user export would win anyway while the summary claimed `nvim`.
  - Supersedes D-04's "asked … default no, headless never opts in".
  - **Needs confirmation:** ONB-09 was user-locked on 2026-10-13 as "asks whether"; the user's 2026-11-07 rule is "always, no question". Alternatives were: always override and name the value, keep asked, or a summary hint only.
  - **Own reasoning** (jev low 0.69, tuning_override; Laya low 0.28, tuning_override): overriding contradicts the absent-only rule of every other unasked write, and the source-block position (D-05 refinement) means an override cannot be guaranteed anyway. Ledger.
