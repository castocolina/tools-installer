<objective>
Add `cursor-agent` and `antigravity` as verified `tier="ai"` catalog entries — the
agent-host half of ROADMAP Phase 8 SC#2 — using each vendor's own official install
script, live-fetched and read verbatim by 08-RESEARCH.md this same research cycle
(2026-09-06), per CONTEXT.md D-02: "If research finds the only official install method
... is a vendor-provided curl|bash-style script ... that is acceptable and should be
used — do not hold out for a stronger alternative." Both tools have exactly this shape:
neither vendor publishes a Homebrew formula or a cask that installs the CLI itself (the
one cask each vendor DOES publish — `cursor`, `antigravity` — installs the GUI IDE
app, a different product, confirmed live via `formulae.brew.sh`'s cask API this
research session).

`cursor-agent`'s own install script (fetched live from `https://cursor.com/install`
this session) creates TWO symlinks to the same downloaded binary: `~/.local/bin/agent`
(the newer, primary name, shown in the script's own "next steps" messaging) and
`~/.local/bin/cursor-agent` (the script's own comment labels this "legacy"). This
plan's entry deliberately uses `cmd = "cursor-agent"` — the older but still-real,
vendor-created, collision-safe name — because a bare `"agent"` risks colliding with an
unrelated `agent` binary from a different installed CLI on a machine that has more than
one agent tool, a real, documented risk 08-RESEARCH.md's Pitfall 3 surfaced. This
matches every other reference to this tool already in this project (CONTEXT.md,
ROADMAP Phase 8/10, REQUIREMENTS.md all consistently say `cursor-agent`), so this is
not a new naming decision, only its first registry instantiation.

`antigravity`'s own install script (fetched live from
`https://antigravity.google/cli/install.sh` this session) installs a single binary
named `agy` into `~/.local/bin` and additionally performs its own SHA-512 verification
of the download against a signed manifest before installing — a stronger self-check
than most `kind="script"` entries already in this registry carry, worth recording as a
finding rather than treating as equivalent to a bare unsigned script.

Purpose: REQ-agent-host-entries — ROADMAP Phase 8 SC#2.

Decisions implemented:
- CONTEXT.md D-02: both tools' only official install method is a vendor curl|bash
  script; this is accepted, not held out for a stronger alternative that does not
  exist.

  the vendor's GUI-IDE cask — that would technically satisfy "a verified official
  install method exists" while installing the wrong product for an agent-facing
  terminal-tool catalog.
- 08-RESEARCH.md Pitfall 3: `cmd = "cursor-agent"`, not `cmd = "agent"`.

Scope boundary: this plan adds registry data and tests only — no executor, model, or
resolver code changes (the `script` kind, `_script` executor, and `is_installed`'s
`shutil.which` check all already exist and are already generically tested; this plan
exercises them with real data). It does not wire `recommends` onto either entry (Plan
08-04's concern, sequenced after `rtk` exists) and does not touch `codegraph` (already
shipped in Phase 5, unmodified here).
