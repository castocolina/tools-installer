<objective>
Add `rtk` as a verified `tier="ai"` catalog entry — ROADMAP Phase 8 SC#3 — via a
checksum-verified `kind="github_release"` ladder from `rtk-ai/rtk`, the last of the
four new tools this phase's ROADMAP section names. `rtk` ("Rust Token Killer") is a CLI
proxy that reduces LLM-visible token consumption on common dev commands (git, docker,
pytest, etc.) — this project's own global `CLAUDE.md`/`RTK.md` already documents living
daily use of it, so its own catalog entry closes a real gap between "this project's
developer already relies on this tool" and "this project's catalog can install it for
someone else."

08-RESEARCH.md's live GitHub Releases API check (tag `v0.48.0` at research time) found
`rtk`'s Linux release assets are asymmetric in a way a naive single-template method
would miss entirely: `rtk-x86_64-unknown-linux-musl.tar.gz` for amd64 (a static musl
build) but `rtk-aarch64-unknown-linux-gnu.tar.gz` for arm64 (a dynamically-linked gnu
build) — confirmed directly from the release's own `checksums.txt` listing, not
inferred. This entry declares two separate arch-gated Linux `github_release` methods,
mirroring this registry's own existing precedent for exactly this shape (`puppeteer`'s
Linux-arm64 gate, `gnu-bash`'s two arch-split brew methods), so `resolve_methods`
selects the correct asset per architecture with zero new resolver code — the arch gate
already exists and is already generically tested; this plan only supplies the data.

08-RESEARCH.md also found a genuine Homebrew formula `rtk` (bare name, homebrew-core)
that is the SAME upstream project — confirmed via `formulae.brew.sh/api/formula/
rtk.json` matching homepage, description, and exact version `0.48.0`, not a
name-collision namesake. This entry adds it as an explicit fallback method AFTER the
three `github_release` methods, per this registry's dominant convention (most
`github_release` entries pair with a `brew` fallback) and the Phase 6 brew-preference
guideline — this does not weaken REQ-rtk-github-release, which mandates that a
checksum-verified `github_release` method EXISTS, not that it be the tool's only
method.
