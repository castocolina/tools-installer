<objective>
REG-03 (D-07, Ledger L-18-04), check core: there is no way to learn that an upstream asset was renamed, a member moved or a checksum changed until a user's install fails. This plan builds `installer/verify_registry.py`: a read-only check over every downloadable method and declared platform that reuses the real install resolver and verifies digests and members only when an asset changed since the last verified run.

Purpose: drift is caught by a check before a user hits it.
Output: the module (`Probe`, `Finding`, `Report`, `check_registry`, `format_report`, `main`) and offline tests. Plan 18-17 adds newer-stable detection for pins, the not-checkable listing, the run verdict that a single failing host cannot flip, the `Unverified at install` section and the gh-login token fallback. The registry writer (`--write`, `--candidate`) is plan 18-13. The GitHub issue upsert (`--issue`), the Makefile target and the weekly workflow are plan 18-14.

Scope split (checker scope_sanity, 2026-10-15): the original plan was estimated at 130k tokens with three tasks, and the revision added three findings to the same module. Its third task moved to plan 18-17 together with them.

Decisions recorded (RESEARCH Open Question 3, Ledger L-18-04): state is a JSON map `{url: fingerprint}` in `~/.local/state/tools-installer/verify-registry.json` by default (`--state PATH` overrides; the weekly job restores/saves it with `actions/cache`, never commits it); fingerprint = `sha256:<hex>` when a digest/pinned/checksum hash is known, else the HEAD validators.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| upstream release hosts and the GitHub API -> verify_registry | untrusted archives and metadata are read by the check |
| verify_registry -> state file | a local file decides whether an asset is re-downloaded |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-18-28 | Tampering | path traversal from a malicious archive during the member check | medium | mitigate | members are listed (`getnames`/`namelist`), never extracted; temp dir per download |
| T-18-30 | Tampering | a stale or forged state file hides a changed asset | low | mitigate | the fingerprint is the expected sha256 (or HEAD validators); any upstream change alters it and triggers a download; a cache miss downloads everything once |
| T-18-31 | Information Disclosure | the GitHub token sent to download hosts | low | mitigate | HEAD/download send no token; only `urlopen_fetch` adds it, for api.github.com |
| T-18-SC | Tampering | npm/pip/cargo installs | high | accept | No package installs; `pyproject.toml` and `uv.lock` unchanged |
</threat_model>
