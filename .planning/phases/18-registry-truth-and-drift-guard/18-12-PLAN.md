<objective>
REG-03 (D-07, Ledger L-18-04), check half: there is no way to learn that an upstream asset was renamed, a member moved, a checksum changed, or a pinned version fell behind until a user's install fails. This plan builds `installer/verify_registry.py`: a read-only check over every downloadable method and declared platform that reuses the real install resolver, verifies digests and members only when an asset changed since the last verified run, separates "not checkable" kinds, and turns network trouble into "inconclusive" instead of a false result.

Purpose: drift is caught by a check before a user hits it.
Output: the module (`Probe`, `Finding`, `Report`, `check_registry`, `format_report`, `main`) and offline tests. The registry writer (`--write`, `--candidate`) is plan 18-13; the GitHub issue upsert (`--issue`), the Makefile target and the weekly workflow are plan 18-14.

Decisions recorded (RESEARCH Open Questions 3 and 4, Ledger L-18-04): state is a JSON map `{url: fingerprint}` in `~/.local/state/tools-installer/verify-registry.json` by default (`--state PATH` overrides; the weekly job restores/saves it with `actions/cache`, never commits it); fingerprint = `sha256:<hex>` when a digest/pinned/checksum hash is known, else the HEAD validators; exit codes 0 ok, 1 drift, 2 inconclusive. Pinned urls not hosted on github.com (Sublime) have no release source to compare: the report notes "newer stable: no release source"; plan 18-13's `--candidate` handles their bump.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| upstream release hosts and the GitHub API -> verify_registry | untrusted archives and metadata are read by the check |
| verify_registry -> state file | a local file decides whether an asset is re-downloaded |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-18-28 | Tampering | path traversal from a malicious archive during the member check | medium | mitigate | members are listed (`getnames`/`namelist`), never extracted; temp dir per download |
| T-18-29 | Repudiation | a rate limit or outage read as "no drift" | medium | mitigate | 403/429/5xx/network errors are inconclusive and force exit 2 (Task 3 tests) |
| T-18-30 | Tampering | a stale or forged state file hides a changed asset | low | mitigate | the fingerprint is the expected sha256 (or HEAD validators); any upstream change alters it and triggers a download; a cache miss downloads everything once |
| T-18-31 | Information Disclosure | the GitHub token sent to download hosts | low | mitigate | HEAD/download send no token; only `urlopen_fetch` adds it, for api.github.com |
| T-18-SC | Tampering | npm/pip/cargo installs | high | accept | No package installs; `pyproject.toml` and `uv.lock` unchanged |
