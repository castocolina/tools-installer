<objective>
REG-05 (D-06): nothing runs a freshly installed binary, so a glibc-floor or wrong-architecture binary links "successfully" and fails at first use (audit D C6). Per D-06 one shared `smoke_binary` built on `run_output`/`CommandError` runs the binary once; download kinds smoke the staged binary before the atomic swap so a broken binary is never linked and an existing good install is untouched; any failure falls through to the next method. A method may declare its own `smoke_argv` (a new key, distinct from node's closed-dispatch `smoke` name).

Purpose: a binary that cannot run on this host never becomes "installed".
Output: `run_output(env=...)`, `smoke_binary`, `method_smoke_argv`, the install path on the staged swap (`_replace_archive`/`_replace_raw` with a smoke hook), the `smoke_argv` loader key, its authoring docs, and the registry comments that still name deleted download functions.

The install path moves from in-place extraction to the update path's staged swap here (RESEARCH Pattern 3): extracting in place would overwrite an existing good tree before the smoke run, which contradicts D-06 ("an existing good link is untouched").
