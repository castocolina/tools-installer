<objective>
Close REVIEW WR-03 (smoke failures lose their reason), the opencode MEDIUM "non-UTF-8 smoke output aborts the install ladder", ponytail #17 (unreachable fallback in `smoke_binary`) and IN-01's `smoke_binary` docstring.

Purpose: when a fresh binary fails its smoke run, the user sees why. This is the one line the 18-18 container diagnosis had to dig out by hand: FUSE, X server, GLIBC, wrong architecture. A garbled byte in a child's output must not turn a method failure into a crash.
Output: about four small edits in run.py, executors.py and render.py, each with a test that was RED before the fix.

Planner verification (2026-10-15, HEAD 6794a65):
- `run.run_output_with_stderr` (run.py:70-102) raises `CommandError(cmd, 127)` with no detail on `OSError`.
- It decodes with `text=True` and strict errors. An invalid byte raises `UnicodeDecodeError` from `subprocess.run` before the exit status is mapped.
- `executors.smoke_binary` (79-109) puts the whole `str(CommandError)` in its message. The fallback `raise` after its line loop is unreachable, because no `_LOADER_ERROR` alternative spans a newline (ponytail #17 confirmed).
- `render.render_failure_details` (90-102) prints only `errors[-1]`.
- Partly refuted: the review says the `_LOADER_ERROR` alternatives `Exec format error` / `cannot execute binary file` "can never match". After this plan the OSError text carries `Exec format error`, and bash prints `cannot execute binary file` when a shell launcher execs a wrong-arch ELF (VS Code's `bin/code` is such a launcher). So both alternatives stay.
</objective>
