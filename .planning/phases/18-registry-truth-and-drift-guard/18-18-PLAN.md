This plan runs them on a real (disposable) Fedora system over the final registry, and records ROADMAP SC4's container evidence: ruff's resolved owner under the launch form, from a venv synced with the dev group the way `make install` syncs it.

Purpose: prove the install-time checks and the dev-venv fix on real installs, never on the host.
Output: run evidence in the SUMMARY (pass verdicts, ruff probes and rows, GUI smoke results). Harness or registry changes are made only when the run proves a container-only gap.

Decisions recorded: a missing FUSE device in the container is a container gap, not a registry fact. The harness lets AppImages extract-and-run there, while a real host that cannot mount an AppImage still fails its smoke (the honest D-06 outcome). The ruff probe needs a control (plain `uv run`) that resolves the dev ruff in `.venv`; otherwise the launch-form probe could not fail (checker finding 2026-10-15). Plan 18-05 keeps the harness's `uv sync` with the dev group for this reason.
</objective>
