## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| installing environment -> unit / plist text | Only the closed `PASSTHROUGH_KEYS` reach a unit; the token variables are not among them. Proxy values the user configured are carried like for every row, in private 0600 units | environment |
| runner parent env -> runner child -> log | Closed `_PASSED_ENV` list; the log holds fixed result lines | environment, text |
| check text -> notify-send / osascript argv | Registry ids and counts only | argv |
| GitHub / npm responses -> version cache | Tags and digests stored in `versions.json` | text |
| `update-check.json`, `versions.json` -> the check | User-state files that can be corrupt, oversized, links, directories or FIFOs | bytes |
| checkout and git config -> git | The user's own repository and configuration are partly in effect | git queries |
| git diagnostics -> result line | Git prints remote URLs, which can carry a credential, into a shared log | text |
| stale or failed evidence -> notified set | A failed lookup must not add or remove an id | ids |
| `uv run` -> the checkout | Frozen lockfile, no bytecode | writes |
| container harness -> host | The harness is orchestrator-run only | process |

## Notes (informational, non-blocking, not counted)

- **Schedules container check: recorded, PASS.** Run by the orchestrator on 2026-11-22 (`scripts/container-e2e-verify.sh schedules`, exit 0, no leftover container, no prune or reset), recorded in 34-07-SUMMARY.md as `schedules-container-check-updates: PASS`: row ON by default (`next=2026-11-22T09:00`), `result=ok`, result line `ok: 0 updates available; installer check skipped: not a git checkout`, cell, `TRACER_SCHEDULE_CHECKOUT_UNCHANGED`, OFF and teardown observed. The `--direct` route was not run. This audit did not re-run it.
- **Remaining owner UAT (not proven by any test or the container):** real Bazzite desktop delivery of the notification; the session bus variable reaching `notify-send` from a systemd user unit (the container has no desktop session and sent no notification); macOS `osascript` delivery and its Script Editor notification permission; the argv-only `osascript` behavior with no `--` (decision 4). Not security gaps, but delivery and the bus path are unproved on a real host.
- **Result-line reasons that are not git.** The refresh failure sink passes `str(exc)` of a lookup failure (e.g. `failed to resolve tag for <repo>: <urllib error>`) and a total refresh failure passes `command_error_line` (first stderr line of a manager query, else the command text) to `reason_line` (control characters stripped, 300 characters) and into the one result line. These are not git diagnostics and carry no notification body or token (the runner child has none, installer/versions.py:361-370 reads a token only if present). A manager that echoes a credential-bearing proxy URL in its first stderr line would put it in the shared log; the same exposure exists for every other schedule row's failure line. Not registered as a threat by the plans; below the block threshold.
- **Temp file mode window.** `atomic_replace_entry` writes the sibling temp and then `chmod`s it (installer/atomic.py:67-69), so the temp exists briefly under the process umask before the final 0600 entry replaces the target. The content is a sorted id list. Negligible.
- **Bus variable scope.** `DBUS_SESSION_BUS_ADDRESS` is passed to every runner child (tmp cleanup, manager prunes, update children), not the check child alone; see AR-34-02.
- **Nothing runs on the host from tests.** The default `RunDeps.notify` is `no_notifier` (installer/schedule_run.py:34), the real notifier is wired only in setup.py's `_schedule_run_deps` (setup.py:546-548); the hermetic job test uses a fake `notify-send` and a fake `uv`; the lifecycle and engine tests use scratch HOME with stubbed `systemctl`, and tests/conftest.py's child and socket guards stay in force. The default-on reconcile includes the new row (`turned_on` ends with `check-updates`, tests/test_schedules_lifecycle.py:108) through the existing stubbed path.
