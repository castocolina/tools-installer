# Phase 19 — UI Design Contract

> Visual and interaction contract for the catalog health marks, legend and focused-row detail.
> Generated by gsd-ui-researcher in pipeline/auto mode (no user questions). Verified by gsd-ui-checker.

This is a **Textual terminal UI**, not a web frontend. Units are terminal **cells** (columns) and **rows**, not px. The "design system" is the existing house chrome (`installer/ui_common.py`), the `ToolBrowser` widget (`installer/tool_browser.py`) and the catalog adapter (`installer/catalog_tui.py`). Line references are from `main` at `424b301`.

**Sources:** `19-SPEC.md` R1–R10 (locked), `19-CONTEXT.md` D-01..D-21 (locked), ROADMAP Phase 19 success criterion 2, `.planning/research/2026-10-13-target-architecture.md` §1 (glyph and color per Health) and §7 ("Marks"), and the measurements below. ## Layout contract

### Vertical row budget (minimum terminal 80×20)

| Row(s) | Widget | Rows |
|--------|--------|------|
| 0 | WayfindingHeader | 1 |
| 1 | Rule (margin 0) | 1 |
| 2 | ModeBadge | 1 |
| 3–4 | Tabs (grouping views) | 2 |
| 5–10 | DataTable (header row + data rows + horizontal scrollbar) | **≥ 6** (`1fr`) |
| 11–13 | `#browser-legend` | **exactly 3** |
| 14–16 | `#browser-detail` | **exactly 3** (fixed; it does not resize as the cursor moves) |
| 17 | recommends line (`StatusLine`) | 1 |
| 18 | status line (`StatusLine`) | 1 |
| 19 | FooterBar | 1 |

- The legend and the detail bar must **stack, not overlap**. Stacking costs 2 rows, so the Rule margin fix must give those 2 rows back.
- **Recommended mechanism:**
  1. Drop `dock: bottom` from `#browser-legend` and `#browser-detail`. They already compose after the DataTable (`tool_browser.py:138-141`), and the DataTable is `1fr`, so vertical layout puts them below it in that order.
  2. Change the selector at `ui_common.py:326` to `AppScreen > Rule.-horizontal { margin: 0; color: $accent; }`.
  3. Set `#browser-detail { height: 3; }`.
- **Fallback** if the Rule change breaks another screen's pinned layout: give `recommends_line` `display: none` while its text is empty. That frees 1 row. Detail then stays 3 rows and the table is ≥ 5 rows; the planner must re-pin the table-height test to ≥ 5 and record why.
- At 120×30 the same rule gives a 16-row table.

## Health marks (the one `health_cell`)

One `health_cell(state: ToolState | None) -> Text` serves the system, user and ai tiers (D-15). It is the **only** writer of the Health column. Delete `_BROKEN_MARK`, `_inst_cell`, the skill `?` glyph and the skill `✓ ~` / `○ ~` variants (`catalog_tui.py:227, 494-517`).

| Health (`version_status.Health`) | Glyph | Style | Monochrome / `NO_COLOR` reading | Row treatment |
|-----|-----|-----|-----|-----|
| — (`state_of(id) is None`) = CHECKING | `…` | `dim` | glyph alone; dim intensity survives Monochrome | normal row, selectable |
| BROKEN | `!` | `red` | glyph alone | normal row |
| MISCONFIGURED | `≈` | `yellow` | glyph alone | normal row |
| OUTDATED | `↑` | `yellow` | glyph alone | normal row |
| OK | `✓` | `green` | glyph alone | normal row |
| MISSING | `○` | default foreground (no color) | glyph alone | normal row |
| UNAVAILABLE | `–` (U+2013) | `dim` | glyph + whole row dim | **every** cell dim, Sel blank, not selectable (existing `_row_cells` dim branch, `:619-634`) |

Rules:

- **Every state has its own glyph**, so meaning never depends on color. `↑` and `≈` share yellow and are told apart by glyph. Textual turns `NO_COLOR` into a `Monochrome` filter (`textual/app.py:614-616`); the contract holds there unchanged.
- **Never `✓` while pending** (SPEC prohibition): when `state_of(id)` is `None`, the cell is `…`, whatever the presence predicate or the cache says.
- **Before the first pass completes, every row's Health cell is `…`** (SPEC AC2). That includes rows the launch-time resolver marks unavailable. Those rows still render dim and stay non-selectable from the launch-time `unavailable` map; they switch to `–` once their state lands.
- **One swap means one repaint.** When a pass publishes, every row's mark changes in the same rebuild. There is never a partly updated catalog.
- **A navigation refresh does not flicker.** `enter_view` starts a pass but does not invalidate the current map, so the marks stay put until the new map swaps in. Rows go back to `…` only when a mutation bumps the epoch (install close, `u`), which is the O9 decision ("CHECKING: it is honest").
- **Live availability (R8):** when a pass reports a tool as no longer UNAVAILABLE (brew appeared mid-session), its row un-dims, gets a Sel cell and becomes selectable in the same repaint, with no restart. Selectability reads the state, not the launch-time map, once a state exists.
- Skill-pack rows use the same marks: a partial pack is `≈`, and duplicates or disabled copies are reasons (D-17, D-18).

### Ver cell (version facts only)

| Situation | Cell |
|-----------|------|
| CHECKING, MISSING or UNAVAILABLE | empty |
| Present, version unreadable | empty (the reason "version unreadable" is in the detail bar) |
| Present, no latest to compare (native package, unreadable inventory) | `1.2.3` |
| Present, current | `1.2.3` |
| Present, outdated | `1.2.3 -> 1.3.0` |
| Any of the two above with a stale cached latest | the text plus ` ~` in `dim` |

- Ver text uses the **default foreground**: the Health mark is the row's only color carrier. A BROKEN row that is also outdated shows a red `!` and a neutral `1.2.3 -> 1.3.0`, never a red/yellow mix.
- Delete `_VER_CHECKING`, `_VER_NO_VERSION`, `_VER_SOURCE_UNKNOWN` and `_VER_NO_COMPARISON` as cell text (`catalog_tui.py:215-225`). Their facts become `reasons` (D-15).

### Owner cell

- Same labels as today (`owner_label`, `_skill_owner_cell`), now read from `state.ownership` and `state.skill_hosts`.
- **Empty while CHECKING.** The Health `…` already says "checking", so the `checking…` text in Owner goes away (`:606`).
- Keep the ` ≠ policy` dim suffix (`:610-611`); the legend now decodes it.

## Legend (one string, three lines, ≤ 78 cells each)

The legend **replaces** `_LEGEND` (`catalog_tui.py:277-286`) and is identical on all three tiers (existing test `test_legend_is_identical_across_all_three_tier_views`). It is exactly 3 explicit `\n`-separated lines, each ≤ 78 cells measured with `rich.cells.cell_len` on the markup-stripped text (80-column minimum minus `padding: 0 1`).

```
[green]✓ ok[/] · [yellow]↑ update[/] · [yellow]≈ config[/] · [red]! broken[/] · ○ missing · [dim]… checking[/] · [dim]– unavailable[/]
[bold red]P0[/] essential · [bold yellow]P1[/] recommended · [blue]P2[/] nice-to-have · [dim]P3[/] niche · [bold cyan]AI[/] / [magenta]human[/] / both
Ver a -> b: newer release · [dim]~[/] cached latest · [dim]≠ policy[/]: other manager owns it
```

Measured plain widths: **78, 78, 77**.

- Line 1 is the health key. It contains the SPEC- and ROADMAP-locked substring `✓ ok · ↑ update · ≈ config · ! broken · ○ missing` verbatim, then `… checking` and `– unavailable`.
- Line 1 sits at the top of the legend, closest to the table.
- Each legend entry carries the same style as the cell it decodes: `○ missing` is unstyled because the cell is unstyled, and `…` and `–` are dim.
- Lines 1 and 2 have zero slack. Any future entry must replace an existing one, not append; the budget test fails loudly if it grows.
- All three lines must be **visible on the compositor** at 80×20 and at 120×30, not only present in `render_line`. Test: for each legend row `y`, `screen.get_widget_at(2, y)` is `#browser-legend`.

## Focused-row detail (`#browser-detail`, 3 rows)

When a tool row is highlighted:

| Row | Content | Overflow |
|-----|---------|----------|
| 1 | **Identity** (existing copy, `catalog_tui.py:656-676`): `[bold]{id}[/] — {desc}  \|  {Pn} {label}  \|  for {audience}` + `  \|  requires …` + `  \|  pairs well with …` when declared | single line, no wrap, ends in `…` when cut |
| 2–3 | **Health block**: `{glyph} {health detail label}` + ` — {reason 1} · {reason 2} · …` + ` — to configure: {step 1}; {step 2}` when `unconfigured` is non-empty | wraps onto row 3; ends in `…` when cut |

- Recommended mechanism: render a `rich.console.Group` of the identity `Text` (`no_wrap=True, overflow="ellipsis"`) and the health `Text` (`overflow="ellipsis"`) into the one `Static`. The `detail_text` test seam keeps the plain joined text, so existing assertions on `detail_text` keep working.
- The glyph in the health block uses the same style as the Health cell.
- **Reasons** come from `state.reasons` in tuple order. `tool_health` emits the reason for the winning Health first, then the other states' facts in precedence order, then the notes: shadowed, off-policy, unknown owner, version unreadable, stale cache, default shell, proof and adoption.
- **Configuration steps** come from `state.unconfigured` (`ConfigStep.text`, D-20) in tuple order.
- Every path or tool-supplied string in a reason is passed through `rich.markup.escape` (existing practice, `:741-753`).
- The default-shell note (`:677-682`) and the `UnavailableReason.detail` (`:672-676`) move from the identity line into the health block as reasons.
- A section row keeps today's behavior: the group's detail line in bold (`tool_browser.py:340-342`).
- At 80 columns the health block holds 156 cells and at 120 columns 236. Text beyond that is cut with `…`; it is never wrapped into a 4th row.

## Typography

Terminal cells have one size. "Size" is the 1-row cell; weight is the SGR attribute.

| Role | Size | Weight | Line height |
|------|------|--------|-------------|
| Body (cells, reasons, legend words) | 1 cell | regular | 1 row |
| Label (tool id cell, `{id}` in the detail) | 1 cell | bold | 1 row |
| Heading (section rows `── title (n)`, priority codes P0/P1) | 1 cell | bold | 1 row |
| Secondary (desc column, checking, unavailable, stale `~`, `≠ policy`) | 1 cell | regular + `dim` intensity | 1 row |

Two weights only: regular and bold. `dim` is an intensity attribute, not a third weight.

## Keyboard and accessibility

- **No binding changes.** Every key works as today: `←`/`→` (views), `space`, `a`, `i`, `enter`, `u`, the hidden `r`/`d` recommends prompt, `1-6`, `^p`, `esc`, `q` (`tool_browser.py:113-120`, `catalog_tui.py:317-321`, `ui_common.py:207`). The footer text is unchanged.
- **The detail bar follows the cursor.** Moving the row cursor (`↑`/`↓`, PgUp/PgDn) updates the 3-row detail. A rebuild keeps the cursor on the same row key, so a published pass does not move the user.
- **Glyph-first encoding.** The six visible states each have their own glyph, and checking and unavailable are also dim. Color is redundant, so the contract survives `NO_COLOR` (Monochrome filter) and color-blind readers. This matches the ModeBadge's redundant-encoding rule (`ui_common.py:297-300`).
- **No motion.** `…` is a static glyph, not a spinner (no animation, no timer repaint).
- **Width.** Every mark is one cell by `rich.cells.cell_len`. `↑ ≈ ○ … –` are East-Asian *ambiguous* width and may render two cells wide in a CJK-locale terminal. This is accepted and already true of `✓`/`○` today; it is listed as a backstop row below.
- **Escaping.** Reasons carry paths and tool output and are always escaped before markup, so a `[` in a path cannot restyle or hide the detail.
