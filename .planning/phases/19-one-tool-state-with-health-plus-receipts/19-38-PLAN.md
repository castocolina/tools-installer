<objective>
Gap closure round 3, data safety first: a dir receipt artifact is proven only by a key file that resolves inside that directory. Today `_safe_key` checks the key's text and `_file_fingerprint` checks the final component, but an intermediate symlink (`Demo.app/Contents -> /elsewhere/Demo.backup.app/Contents`) makes the backup's `Info.plist` authorize recursive deletion of a replacement `Demo.app` holding unrelated data, in the ordinary check and in the quarantine re-check (RR3-01, IN3-01).

Purpose: L-19-31 accepts a byte-identical key file as the same software; it never accepted a key file that lives in a different directory. The deleted tree must be the tree the key file is in.
Output: `_key_file` containment in receipts.py, three receipts regressions, the end-to-end replacement-tree regression in test_uninstall.py, and the architecture record.
</objective>
