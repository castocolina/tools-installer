## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| cached release digest -> adoption | a digest from the version cache turns a file into removable, installer-owned evidence |
| refresh worker vs install worker | both may write the same tool's receipt |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-19-41 | Spoofing | a foreign file adopted as installer-owned | high | mitigate | adoption needs an exact sha256 match with the cached digest of the asset the install renderer names, raw github_release only, no receipt present (Task 2) |
| T-19-42 | Tampering | adoption overwriting a concurrent install's receipt with an old hash | medium | mitigate | `adopt` re-checks inside the receipts lock: no receipt and unchanged fingerprint (Task 2) |
| T-19-43 | Tampering | the version cache file edited to plant a digest | low | accept | the cache is user-owned like the files it describes; adoption only enables removal of a file the user could delete themselves, and removal still intersects `artifact_paths` |
| T-19-44 | Denial of Service | hashing large AppImages on every pass | low | mitigate | non-match memo per (path, size, mtime_ns); matches skip hashing via the stat fingerprint (Task 2) |
| T-19-SC | Tampering | npm/pip/cargo installs | high | accept | No package installs; `pyproject.toml` and `uv.lock` unchanged |
</threat_model>
