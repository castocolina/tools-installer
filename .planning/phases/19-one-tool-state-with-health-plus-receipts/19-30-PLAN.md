<objective>
Gap closure for the Status view race: one health read per tool while grouping, and one state snapshot per rebuild shared by the grouping and the row cells (G7).

Purpose: `group_tools`' status branch calls `health_of` once per Health bucket per tool, and `CatalogScreen._health_of` reads live state; a publication between two buckets can place one tool in two groups and the table raises DuplicateKey. Even with one read, `_row_cells` reads live state again, so a row can show a mark that disagrees with its section.
Output: the two fixes in installer/catalog_tui.py with a pure test and a pilot test.
</objective>
