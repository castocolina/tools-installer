describes a catalog from two sessions ago.

`ast-grep` sits at `category = "search"`, `tier = "user"` — directly beside `rg` and `fd`, same

and CONTEXT.md D-07/D-08 locked the corrections.

The same discussion closed the "borderline" review the roadmap left open: `mmdc`, `gitleaks`, `vale`
and `drawio-cli` were checked against the same criterion and confirmed correct as `user` (D-09).
Nothing about them changes here — but the decision stops being invisible, because a test now pins it.

Two registry tests are deliberate tripwires that will go red on the tier edits, by design: one encodes
the wrong tier in its own NAME, and one pins the exact per-tier `Counter` with a comment saying any
phase that changes the catalog must update it in the same commit. Updating them is the job, not a
workaround.

Finally, D-10: the AI tab's own comment in `installer/ui_common.py` still names `claude` and `codex`
as examples of what lives in that tab. Both moved to `tier = "user"` in an earlier session; neither
is displayed there at all. The `palette` line directly below that comment (line 135) makes the same
promise in the copy the ctrl+p navigation shows the user, so the fix covers both: a corrected comment
above a stale header would leave the only user-visible half of D-10 untouched.

Purpose: each of the three catalog tabs lists what its own definition says it lists, and both the
comment explaining the AI tab and the description the user reads above it are true.
Output: two one-word registry edits with their reasons recorded, updated and extended tier tests, and
a rewritten AI-tab comment plus palette line that a test keeps honest.

## Design decisions this plan implements

- **D-07 — `ast-grep` becomes `tier = "ai"`.** Same `category = "search"` as `rg`/`fd`, which are
  already `ai`. Only the `tier` field changes; `category`, `audience`, `priority`, `cmd` and every
  method stay exactly as they are.
- **D-08 — `puppeteer` becomes `tier = "ai"`.** A runtime library dependency of `mmdc`, never launched
  by the human as their own interface. Its `requires = ["pnpm"]` and both `node` methods are untouched.
- **D-09 — `mmdc`, `gitleaks`, `vale`, `drawio-cli` stay `tier = "user"`, and this plan pins that.**
  Each is run by the human against the human's own artifact — a diagram, a repo scan, prose, an
  export. CONTEXT.md is explicit that this closes the borderline review rather than deferring it, so
  the outcome belongs in the suite, where the next person to re-open the question finds the answer.
- **The tripwires get updated, never worked around.** `test_registry_tier_distribution_is_pinned`'s
  own comment states the contract: a phase that changes the catalog updates the counts in the same
  commit. `test_puppeteer_is_a_user_tier_node_tool_requiring_pnpm` encodes the old tier in its
  function name, so renaming it is part of correcting it — a test whose name lies is worse than one
  that fails.
- **D-10 — the AI-tab comment cites only tools that are `ai` today, and a test re-derives that.**
  Which specific tools to cite is Claude's discretion; that the comment must not name a tool the tab
  does not contain is not. The test scans the comment for catalog ids and checks each one's live tier,
  so the comment cannot drift out of sync with the registry again without the suite saying so.
- **D-10 covers the palette string too, because it is the same claim in the place users read it.**
  CONTEXT.md names the comment (`~line 130`) as the artifact, and its stated intent is that the AI tab
  stops being described as the place you find agent CLIs you drive yourself. The `palette` field two
  lines below makes exactly that claim, in the ctrl+p description the user sees, so fixing only the
  comment would leave the user-facing half of the same untruth in place. This is copy inside the one
  view row, not a new fact and not a structural change: every other field on the row is untouched, and
  no test pins this row's palette (only `doctor`'s is pinned verbatim, at `tests/test_ui_common.py:171`).
- **Tier is not an ordering mechanism.** `.claude/architecture.md` is explicit: `Tool.requires`
  resolved by `installer/deps.py::resolve_dependencies` is the sole install-order mechanism and has no
  tier-aware branching. Moving two rows between tabs cannot change an install order, and no dependency
  edge is edited here to compensate for one.
