## Unregistered flags and informational observations

None of these blocks the ship. No SUMMARY has a `## Threat Flags` section, so no flag arrived from the executors.

1. **`--plan` as root is not refused** (`setup.py` `_plan_schedule`, `schedule_run.py:460-491`). Root refusal lives in `run_schedule`, which the preview never reaches. The preview mutates nothing (writes held, no lock, no executor), but it does run the read-only manager queries as root. Severity low. Suggested: add the same `deps.euid() == 0` check to `plan_update_all` if "no code path as root" is meant to cover reads.
2. **Unbounded in-memory capture of command output** (`schedule_run.py:126-149`, `communicate`). A vendor command can emit a large volume within its 1200 s bound. Severity low, a DoS on the same user's own session.
3. **Failure detail is not credential-scrubbed.** `update-all.log` (mode 0600) and the shared schedule log carry a command's first stderr line, control-stripped and capped at 300 characters (`schedule_run.py:205-206`, `schedules.py:507-527`). A vendor error that echoes a proxy URL with credentials would be logged. The same behaviour already exists in the per-tool rows. The notification and the summary carry only counts and ids, so they are not affected. Severity low.
4. **Full environment to vendor commands.** `update_all_runner` copies `os.environ` (`schedule_run.py:122`). On the timer route this is the stdlib runner's closed set (`_PASSED_ENV`) plus the bus address. On a manual run it is the caller's own environment. No secret is added by this phase, and the unit environment's proxy values are pre-existing and accepted (24.2 F8).
5. **A command that exits normally but leaves an in-group helper** is not swept. The group is ended only on a timeout or an interruption (`schedule_run.py:148-160`). `communicate` waits for the pipes, so a helper holding them is caught by the timeout. A helper that detached its descriptors and stayed in the group outlives the run. This is narrower than T-35-21 (timed-out commands) and falls under the T-35-18 residual.
6. **Check-then-open race in `held_by`** (`runlock.py:105-109`): `holder()` rejects a FIFO, but a same-user swap between that check and the `O_RDONLY` open could block. It needs the same user acting inside a microsecond window, so it is inside the accepted same-user residual.
7. **Container evidence binding to a revision is procedural, not coded.** The `35-10-SUMMARY.md` asks the orchestrator to record `git rev-parse HEAD` and a porcelain digest next to the transcript. The driver itself does not record them. This matters only for how AUTOUPD-08 is later certified.
