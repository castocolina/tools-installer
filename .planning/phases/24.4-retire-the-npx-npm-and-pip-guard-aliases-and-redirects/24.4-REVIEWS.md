## 24.4-01

**Summary:** Adds the launch-time remover, replaces the two rewrite repairs, and moves cleanup ahead of TUI state reads.

**Strengths**

- The plan distinguishes installer-owned shim files from symlinks and unmarked files, uses bounded reads, and tests scratch-HOME behavior (`.planning/phases/24.4-retire-the-npx-npm-and-pip-guard-aliases-and-redirects/24.4-01-PLAN.md:188-204`).
- It preserves bytes outside removed blocks and asks for per-path notices and idempotency tests (`.planning/phases/24.4-retire-the-npx-npm-and-pip-guard-aliases-and-redirects/24.4-01-PLAN.md:25-34`).

**Concerns**

- **HIGH — Concurrent rc edits can be lost.** The plan reads an rc file and later writes the stripped result without checking that the file or symlink target is unchanged (`.planning/phases/24.4-retire-the-npx-npm-and-pip-guard-aliases-and-redirects/24.4-01-PLAN.md:148`). `atomic_write_text` resolves a symlink at write time and replaces its target (`installer/atomic.py:36-52,76-78`). A user edit, another launch, or a swapped symlink between read and write can therefore be overwritten. Atomic replacement prevents a partial write; it does not preserve intervening changes.
- **HIGH — The planned block removal leaves valid guard blocks active.** The plan explicitly pins whole-file CRLF blocks and a valid block followed by an orphan begin marker as unchanged (`.planning/phases/24.4-retire-the-npx-npm-and-pip-guard-aliases-and-redirects/24.4-01-PLAN.md:190-191`). That follows from `strip_block` comparing LF-split lines exactly and selecting only the last begin marker (`installer/shellrc.py:175-188`), but conflicts with the amended requirement to remove every well-formed block (`.planning/phases/24.4-retire-the-npx-npm-and-pip-guard-aliases-and-redirects/24.4-SPEC.md:55-59`).
- **HIGH — The shim identity check does not guarantee the stated swap protection.** A replacement after `snapshot_matches` but before `os.unlink` can still be deleted; the plan itself acknowledges that window (`.planning/phases/24.4-retire-the-npx-npm-and-pip-guard-aliases-and-redirects/24.4-01-PLAN.md:149`). That does not satisfy the unqualified promise that a file swapped between read and delete is never deleted (`.planning/REQUIREMENTS.md:150`).
- **HIGH — Intermediate `--guard` coverage stubs out the behavior that recreates the guard.** The plan says each existing guard route leaves the files gone (`.planning/phases/24.4-retire-the-npx-npm-and-pip-guard-aliases-and-redirects/24.4-01-PLAN.md:135-137`), but `_headless_route_stubs` replaces `run_guard` (`tests/test_setup.py:4570-4594`). The actual `--guard` branch still calls it (`setup.py:1448-1470`). The test cannot establish the claimed intermediate behavior.
- **MEDIUM — Uninstall CLI reads state before cleanup.** The plan leaves CLI ordering unchanged on the premise that cleanup already runs first (`.planning/phases/24.4-retire-the-npx-npm-and-pip-guard-aliases-and-redirects/24.4-01-PLAN.md:239`), but `_teardown_cli` computes `installed` and its schedule context before `_launch_repairs` (`setup.py:1313-1320`).
- **MEDIUM — Read failures are silent despite the warning requirement.** The proposed remover silently skips `OSError` from both rc reads and shim reads (`.planning/phases/24.4-retire-the-npx-npm-and-pip-guard-aliases-and-redirects/24.4-01-PLAN.md:148-149`), while GUARD-02 says a failure is a warning naming the path (`.planning/REQUIREMENTS.md:149`). An unreadable leftover can remain active without an explanation.

**Suggestions**

- Resolve the safety contract for concurrent replacement before implementation; test edits and symlink swaps at the write boundary as well as shim swaps at deletion.
- Use block matching that handles CRLF markers and independently identifiable earlier blocks while preserving orphan markers and all outside bytes.
- Move teardown cleanup ahead of state reads, warn for actionable read errors, and test the real intermediate guard route or remove that route in the same change.

**Risk Assessment: HIGH.** The proposed cleanup can overwrite user content and deliberately leaves some eligible guard blocks behind.
