# Phase 24.4: Retire the npx, npm and pip guard aliases and redirects - Context

**Gathered:** 2026-11-14 (assumptions mode, after 24.4-SPEC.md)
**Status:** Ready for planning

<domain>
## Phase Boundary

The installer stops writing its package-manager guard: the npm, npx, pnpm, pip and pip3 PATH shims and the `tools-installer ban` alias block. Every launch removes the guard files and blocks an earlier version wrote, and the user's own lines and files stay. The Policies row, the make targets, the CLI flags, the Doctor section and the uninstall ban row go with it. Install-method priority is Phase 24.5.
</domain>

## Implementation Decisions

### Module shape
- **D-01: Only leftover recognition, the lookups and the new remover survive; the rest of `guards.py` is deleted.**
  - Survives: the two sentinels, `BAN_BEGIN`/`BAN_END`, one tuple of the five names (`npm`, `npx`, `pnpm`, `pip`, `pip3`), `_SHIM_MAX_BYTES` (8192), `is_our_shim`, `which_in_path`, `PathLookup`, `real_binary`, `look_through_shim`, `real_pnpm`.
  - Deleted: `BANNED`, `REDIRECTED`, `GLOBAL_REDIRECTED`, `GLOBAL_SUBCOMMANDS`, `BOOLEAN_*`, `VOLTA`, `EXIT_CODE`, `ban_body`, `shim_script`, `_NPX_*`, `redirect_shim_script`, `global_redirect_shim_script`, `install_shims`, `install_redirect_shims`, `install_global_redirect_shims`, `guarded_names`, `remove_shims`, `guard_status`, `guard_label`, `ban_alias_block`, `write_ban_aliases`, `remove_ban_aliases`, both `rewrite_outdated_*`, `guard_path_warning`, `exec_targets`, `_stale_target_message`, `guard_redirect_warning`, `shell_path`.
  - `status._is_installer_shim` checks the five-name tuple instead of `guarded_names()`. Without the tuple a leftover `pnpm` would read present, which breaks GUARD-05 (`installer/status.py:86-88,169`).
  - The callers of `real_binary`/`real_pnpm`/`look_through_shim` stay as they are, with only their imports and docstrings changed: `executors`, `update`, `manager_versions`, `pnpm_globals`, `version_status`, `session`, `app.py:899` and `status`.
  - Analyzer, Confident.
- **D-02: The survivors move to a new module, `installer/legacy_guard.py`, and `installer/guards.py` is deleted.**
  - After this phase the code guards nothing. It recognises and removes leftovers. The codebase names retired artifacts "legacy" (`tweaks.LEGACY_ALIAS_BUNDLES`, `strip_legacy_aliases`).
  - The rename touches the eight `installer/` import sites, about eight test files that import the sentinels, and the schedule runner's source comment (D-14).
  - **Own reasoning** (jev rename_module low 0.66; Laya none_of_these low 0.44): best design over smallest diff; a stale module name misleads the next reader into looking for guard behaviour. Ledger.
- **D-03: `executors.shell_path` and its `_path_prefix` export are deleted, so vendor shells inherit the process PATH unchanged (GUARD-05, SPEC S6).**
  - Accepted edge: if the launch cannot delete a leftover `npm` shim (a read-only `~/.local/bin`) and a real `npm` sits later on PATH, a vendor script's own `npm` hits the leftover. The launch warning names the file. Demotion never covered the "no real pnpm" case either (`executors.py:40-47,457,579`).
  - The installer's own pnpm calls still go through `real_pnpm` and skip the leftover (`executors.py:286,488`).
  - Analyzer, Likely; SPEC-locked (TypeSafe normal_order choice 1.00 at spec time).

### Launch removal
- **D-04: The remover returns `(text, severity)` lines and replaces the two rewrites in the second element of `setup._launch_repairs()`.**
  - The return type stays `tuple[LegacyStrip, tuple[tuple[str, str], ...]]`. Each removed file gives one `"ok"` line naming the path, for example "Removed the retired pip/npm guard shim ~/.local/bin/npx." or "Removed the retired guard alias block from ~/.myshellrc." Each failure gives one `"warn"` line naming the path and the fix. Final wording is Claude's discretion.
  - The rc set is `all_ban_rc_paths()`. The bin dir is `_DEFAULT_BIN_DIR`. Paths are shown through `sanitize_log_line(display_path(...))`, and errors use the `strerror` first line, as `guards.py:699-718,750-763` already do.
  - It never raises. `_print_repairs` and the TUI startup lines print it unchanged (`setup.py:681-704,900-902`).
  - Analyzer, Confident.
- **D-05: The rc removal reads bytes, decodes them as strict UTF-8, runs `strip_block` and writes atomically only when the text changed. It never reuses `remove_ban_aliases`.**
  - `read_capped(path, 1 MiB, follow_symlinks=True)`. A missing, oversize, unreadable or non-UTF-8 file is skipped silently, as the current rewrite does (SPEC R2 encoding edge). A write failure becomes a warn line.
  - Live check (analyzer, scratch dir): `remove_ban_aliases` reads with `Path.read_text()`, which uses universal newlines. On a CRLF file it dropped every `\r`, and it lets `UnicodeDecodeError`/`OSError` escape. That breaks GUARD-03. `strip_block` on text decoded from the raw bytes kept every `\r\n`. This is the C-11 approach already used in `guards.py:700-705`.
  - Analyzer, Confident.
- **D-06: The blank separator line that `apply_block` put above the block stays.** On the owner's `~/.myshellrc` this leaves two blank lines in a row. GUARD-03 locks every byte outside the block, and no remover in the codebase eats separators (`strip_block`, `remove_managed_block`, `strip_tweak_block`). Analyzer, Confident.
- **D-07: Every well-formed ban block in a file is removed in one launch.** `strip_block` repeats until the text stops changing, and the file gets one notice. An orphan begin marker with no end marker after it ends the loop and stays (SPEC R2 amended).
  - **Own reasoning** (jev last_only low 0.76; Laya all_copies low 0.37): the installer only ever wrote one copy, but a hand-duplicated copy would make the second launch change bytes, which GUARD-02 forbids. The loop is safe with an orphan marker. Ledger.
- **D-08: A shim is deleted only after this sequence; otherwise it is left alone.**
  1. `os.lstat` shows a regular file (`S_ISREG`). A missing file returns silently.
  2. `read_snapshot` succeeds (`O_NOFOLLOW|O_NONBLOCK`; it already refuses FIFOs).
  3. The file is at most 8192 bytes.
  4. It decodes as strict UTF-8.
  5. Either sentinel is present.
  6. `snapshot_matches` still holds.
  7. `os.unlink`.
  - `FileNotFoundError` at the unlink (a concurrent launch got there first) is silent. Any other `OSError` becomes one warn line.
  - It never uses `is_our_shim`, which follows symlinks: a volta `npx` symlink to a marked file would be deleted, which GUARD-03 forbids (`guards.py:732-749`, `installer/atomic.py:94-127`).
  - Analyzer, Confident.
- **D-09: `setup._warnings_only` is deleted, and `_teardown_cli` prints every repair line.** Its two reasons are gone: no "Rewrote …" notices remain, and no later step removes the same files (D-11). The launch's "Removed …" lines are now the teardown's only record of the guard removal. choice 0.94 (print_them).
- **D-10: `_launch_repairs()` moves to the first statement of `setup._build_app`,** ahead of the `installed`, `doctor_data` and service reads (today `setup.py:900`, after the reads at `:781-789,814`). This makes the TUI routes match the CLI routes (`:1235,1274,1320,1497`) and SPEC R1's ordering edge. choice 0.99 (run_first).
- **D-11: The guard calls in the teardown and in `perform_uninstall` are deleted.** That covers `app.py:1174-1177`, the `decision.remove_ban` branch (`:1379-1383`) and `UninstallDecision.remove_ban` (`:1209`). Every route that reaches them runs the launch removal first (`setup.py:900,1320`). Keeping them would bring back the CR-dropping `remove_ban_aliases`, and its unguarded raise would abort a teardown. Analyzer, Confident.
