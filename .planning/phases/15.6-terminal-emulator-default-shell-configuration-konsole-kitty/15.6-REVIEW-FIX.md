### CR-01: `ensure_zshrc_template` hardcoded `$HOME/.oh-my-zsh`, contradicting `omz_present`'s own `$ZSH`-aware check

**Files modified:** `installer/omz.py`, `installer/terminal_shell.py`, `tests/test_omz.py`,
`tests/test_terminal_shell.py`
**Commit:** `eb954e9`
**Applied fix:** new `omz_root()` resolves the real install directory (mirroring `omz_present`'s
own logic; `omz_present` is now defined directly in terms of it). `ensure_zshrc_template` takes an
optional `root` param; `terminal_shell.py`'s synchronizer resolves and passes the real root. The
conventional default is still emitted as the portable, symbolic `$HOME/.oh-my-zsh` string (not a
resolved absolute path) for callers that keep the `None` fallback (`write_plugins`, which has no
`environ` to resolve a root from), preserving existing test expectations exactly.
**Verified:** unit tests (`test_omz_root_agrees_with_omz_present_on_every_case`,
`test_ensure_zshrc_template_writes_the_real_root_when_one_is_supplied`,

**live reproduction**: ran `sync_terminal_shells` against a sandboxed home with `$ZSH` pointed at a
relocated install; `.zshrc` now emits `export ZSH=/tmp/.../custom-omz` instead of the wrong
`$HOME/.oh-my-zsh`.

### WR-01: Konsole's `Command=` was shell-escaped but never KConfig-escaped — the shipped test pinned the bug

**Files modified:** `installer/terminal_shell.py`, `tests/test_terminal_shell.py`
**Commit:** `b878367` (same commit as CR-05 — both are in the Konsole profile body)
**Applied fix:** new `_kconfig_value()` applies KConfig's own escaping (`\`, `\n`, `\t`, `\r`) after
`shlex.join`'s shell-argv quoting. The test that previously asserted the raw, un-escaped bytes as
correct is replaced with one that decodes the written value through KConfig's own escaping rules
and confirms round-trip equality to the intended argv, for a path containing a space, a double
quote, and a backslash — plus a dedicated `\t`-focused regression test matching the review's own
corruption example.
**Verified:** unit tests + manual mutation (reverted, both new tests failed, restored, green) +
**live reproduction against real KDE tooling on this host**: used the actually-installed
`kwriteconfig5`/`kreadconfig5` to confirm (a) the OLD unescaped output (`Command=/opt/a\test/zsh -l`)
is read back by real KConfig tooling as `/opt/a<TAB>est/zsh -l` — a literal tab, reproducing the
exact corruption the review describes — and (b) the FIXED output
(`Command='/opt/a\\test/zsh' -l`) round-trips correctly through `kreadconfig5` to
`'/opt/a\test/zsh' -l`, the intended value.

### CR-06: Konsole's own "reversible" selection was not actually reversible

**Files modified:** `installer/terminal_shell.py`, `tests/test_terminal_shell.py`
**Commit:** `b878367` (same commit as CR-05/WR-01 — all three are `_sync_konsole`/`_revert_konsole`)
**Applied fix:** `_revert_konsole` no longer infers `konsolerc` ownership from marker comments
alone. The state file at `terminal-shell-konsole-default` — previously write-only — is now
load-bearing: `_revert_konsole` reads the recorded `prior` default from it and rewrites the
`DefaultProfile` key directly (via new `_set_desktop_default()`) whenever the current value still
equals our profile, independent of whether the marker comments survived a Konsole rewrite.
**Verified:** unit test `test_revert_restores_the_prior_konsole_default_after_a_real_konsole_rewrite`
(strips the marker lines from `konsolerc` the way a real Konsole rewrite would, before reverting) +
manual mutation (reverted, test failed, restored, green) + **live reproduction**: confirmed this
host's real `~/.config/konsolerc` has zero `#` lines across 11 entries (`grep -c "^#"` = 0),
directly confirming the review's premise that KConfig does not preserve comments on this host,
which is exactly why the state-file-based (not comment-based) restore this fix adds is necessary.

### WR-06: the guarded-source idiom (`[ -f ... ] && source ...`) was not recognized as "already sourced"

**Files modified:** `installer/omz.py`, `tests/test_omz.py`
**Commit:** `941b453` (same commit as WR-05 — both are in `omz.py`'s source-detection/repair path)
**Applied fix:** `_OH_MY_ZSH_SOURCE` widened to recognize `source`/`.` preceded by the string's own
start, a shell operator (`;`, `&&`/`&`, `||`/`|`), or plain whitespace — any position a real shell
would actually execute a command from — while `[^#\n]*` (not `.*`) keeps "a comment never counts":
it cannot cross a `#`, so nothing after one is reachable.
**Verified:** unit tests for the idempotent (plugins already before a guarded source, left
unchanged), the needs-repair (plugins after a guarded/`;`-separated source, correctly relocated
rather than duplicated), and the still-refuses-a-comment cases + manual mutation (reverted, all
failed, restored, green) + **live reproduction**: reproduced the review's own example verbatim
(`export ZSH=...` + guarded source + `plugins=(git)` after it) against the real `ensure_zshrc_template`
and confirmed it now correctly relocates `plugins=(git)` before the guarded source (2 occurrences
of `oh-my-zsh.sh`, not 3 — no duplicate export/source pair appended), then syntax-checked the
result with real `zsh -n` (exit 0).

**Applied fix:** `on_install_run_finished` now sets a new `_install_state_changed` flag whenever a
run's `Summary.installed` bucket is non-empty (a real mutation; `already`/`failed`/`no_method`/etc.
are no-ops or failures). `_install_closed` consumes and resets the flag to gate the synchronizer

**Verified:** unit test

which is why they never previously exercised this gate; updated to `installed=False` so the
injected install callable actually runs.
