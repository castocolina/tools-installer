## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Catalog or Policies event → config synchronization | A successful UI mutation triggers a follow-up file operation in the user's home directory. |
| Synchronization failure → user-visible TUI state | A completed primary mutation and a failed follow-up must be distinguished accurately. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-15.6-06 | Tampering | policy and post-run callbacks | high | mitigate | Reuse the phase-02 ownership-aware writer; keep UI wiring free of raw file writes and run all sync work through the established `run_live` boundary. |
| T-15.6-07 | Repudiation | TUI status reporting | medium | mitigate | Aggregate and render sync failures after the primary mutation so the user can distinguish a completed install or policy change from incomplete terminal configuration. |
| T-15.6-08 | Denial of service | repeated lifecycle callbacks | medium | mitigate | Make synchronization idempotent and no-op when bytes already match; avoid launching subprocesses other than the bounded executable-discovery seam. |
| T-15.6-09 | Elevation | lifecycle follow-up | high | mitigate | Keep the callback confined to user configuration and prohibit system-login-shell commands and privileged writes. |
</threat_model>
