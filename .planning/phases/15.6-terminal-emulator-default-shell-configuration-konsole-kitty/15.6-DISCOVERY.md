# Phase 15.6 Discovery: Linux terminal shell configuration

## Scope and evidence

This phase changes only per-user Linux terminal-emulator configuration. It never
invokes `chsh`, changes `/etc/passwd`, writes a system path, or adds a dependency.

- kitty documents `~/.config/kitty/kitty.conf` as its normal configuration location;
  its `shell` option controls the process launched for a new terminal.
- WezTerm documents `config.default_prog` as the argument array for the default
  program, and its lookup order as `$XDG_CONFIG_HOME/wezterm/wezterm.lua`, then
  `~/.config/wezterm/wezterm.lua`, then `~/.wezterm.lua`. A normal Lua configuration
  builds a `config` value and ends with `return config`.
- Konsole profile files are user KConfig-style `*.profile` files under
  `~/.local/share/konsole`; their `General/Command` entry supplies the command.
  `~/.config/konsolerc` records the selected `Desktop Entry/DefaultProfile`.
- `installer/atomic.py::atomic_write_text` is the repository's established
  symlink-preserving, sibling-temp-plus-replace write primitive; `installer/omz.py`
  proves the intended safety pattern for user-owned shell configuration.
- `UnifiedApp._install_closed` is already the unconditional post-run resynchronization
  point. `omz_plugins_policy` owns the successful Policies activation path.

## Plan constraints

1. Sync must use the actual discovered zsh executable, not a hard-coded assumed path.
2. Sync operates only when `Platform.os == "linux"`; a macOS run must not create or
   alter any kitty, WezTerm, or Konsole file.
3. The installer owns only marker-delimited content it creates. Re-sync updates that
   content idempotently; removal restores the previous user configuration and never
   deletes an unmanaged profile or config line.
4. A pre-existing WezTerm config is changed only at a recognised `return config`
   boundary. An unsupported Lua shape is reported as a per-emulator failure rather
   than risk a syntactically invalid configuration file.
5. Konsole is configured only when `konsole` is present. An installer-owned profile
   is selected through the user configuration so that it provides an actual default
   terminal shell; its prior default is recorded/restored only while the installer
   still owns the selected value.
