**Two gaps nonetheless block completion — both missed by three planning-time cross-AI review cycles and the 14-finding post-execution review.**

**G-01 — the `.zshrc` repair is not `$ZDOTDIR`-aware.** `sync_terminal_shells` hardcodes `home / ".zshrc"` instead of calling `installer.locations.zshrc_path(home, environ)` — the resolver this codebase built for exactly this purpose, whose docstring names this failure mode verbatim: *"a ZDOTDIR setup where the detection predicate reads the environment but the write target does not is one that enables the Oh-My-Zsh policy and then edits a file zsh never sources."* `environ` is already a parameter and is already used two lines above for `omz_root(home, environ)`. This is the same bug class as CR-01 — which the review rated Critical and fixed for `$ZSH` while leaving `$ZDOTDIR` open — and the phase is internally inconsistent about it: the Policies OMZ route reaches the same file correctly through `setup.py::_ZSHRC`. Reproduced deterministically: on a ZDOTDIR host the synchronizer *created a `$HOME/.zshrc` the user never had*, containing `plugins=(git)`, while leaving the real `$ZDOTDIR/.zshrc` unrepaired. That is both a silent no-op of the D-04 deliverable and a spurious-file harm of the same class as CR-03. It does not affect this particular host (`ZDOTDIR` is unset here), which is why the green suite and the live session both missed it — but the ZDOTDIR host class is one the codebase explicitly supports. The fix is one line plus one regression test.

**G-02 — Phase 15.6's roadmap contract was written onto the wrong phases, twice.** Commit `4e39a94` ("docs(15.6): create terminal shell configuration plans") wrote 15.6's goal and `Requirements: D-01..D-04 (15.6-CONTEXT.md)` into the **Phase 15.8** entry; commit `08899c6` ("docs(15.6): revise terminal configuration plans") wrote the revised version into the **Phase 15.7** entry. Phase 15.6's own entry still reads `Goal: [Urgent work - to be planned]` / `Requirements: TBD`, and 15.7 even inherited `**Plans:** 6 plans` — 15.6's plan count. Both attributions come from `git log -L`, not inference. The impact is live, not cosmetic: Phase 15.8 is the currently checked-out branch, and anyone running `/gsd-plan-phase 15.7` or `15.8` would plan against Phase 15.6's terminal-shell goal instead of the tmp-prune and PATH-dedup goals in those phases' own heading text. It is also the direct reason this verification had no Success Criteria to check against and had to fall back entirely to PLAN frontmatter.

Neither gap requires rework of the shipped mechanism. G-01 is a one-line resolver swap plus a ZDOTDIR regression test; G-02 is a roadmap-entry correction plus a look at the write path that misfired identically twice.
