## Design decisions this plan implements

- **DD-2 — `link_mode` only.** The envelope carries a `"version": 1` field (mirroring
  `version_cache.py`) precisely so a later default-shell or headless-flag preference is an additive
  key rather than a migration. Those keys are NOT added now: CONTEXT.md raises neither as a bug in
  this phase.
- **DD-3 — flag overrides for one run, never overwrites.** Expressed as two pure functions,
  `resolve_link_mode(flag=..., stored=...)` and `link_mode_needs_choice(flag=..., stored=...)`, so
  the precedence rule is a tested property of `installer/` rather than an if-chain inside
  `setup.py`. Persisting is a separate, explicit `SettingsStore.set_link_mode` call that only the
  in-TUI picker makes.

WHOLE module is unused by production until plan 13-06 in Wave 4. The full reasoning is written once,
in `13-02-PLAN.md`'s `## Wave-1 dead-code standing` section; read it there. The short form, and the
two things this plan must do:

**The vulture gate does not fire, and this plan proves it rather than assuming it.**
`[tool.vulture]` is `paths = ["installer"]`, `min_confidence = 80`. Vulture scores an unused class,
function, method, attribute or module-level constant at 60% and an unused import at 90%, so at a
floor of 80 a wholly-uncalled `installer/settings.py` is below threshold — measured on this exact
tree with a throwaway probe module, `uv run vulture` exited 0 while the same probe at

`uv run vulture` exits 0 on this plan's own tree with `pyproject.toml` unmodified. Adding a
`[tool.vulture]` ignore entry or lowering `min_confidence` is forbidden — `CLAUDE.md`'s
"Never bypass a quality gate" — and if a symbol here ever is flagged, the only permitted fixes are
deleting it or moving it into plan 13-06, never widening an ignore list.

**The real constraint is `.claude/architecture.md` rule 5, and it is enforced, not waived.** Rule 5
forbids a helper with zero production callers kept "for later"; every symbol this module defines is
named against the plan and task that adopts it (13-06 Task 1 for `default_settings_path`,

supporting types). Because a named intention is not a proof, plan 13-07 Task 2 now carries a
phase-close rule-5 adoption gate asserting every one of them has a real production caller outside

landing `settings.py` inside 13-06 Task 1 — was rejected: 13-06 Task 1 is already the phase's
densest task (it deletes `_resolve_link_mode`, rewires five link-mode consumers to live reads, and

contradicts itself and that an executor can satisfy while never implementing the null case at all.
