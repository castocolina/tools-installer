## Design decisions this plan implements

- **DD-1 — continue with a running per-tool status list, plus a weak cancel.** A failed tool never
  aborts the batch. The screen shows a live list of every tool in the resolved order with its
  state: not-yet-reached, running, done, or not-attempted. Cancel stops new tools being queued and
  lets the in-flight one finish; it never kills a child process, because a half-written install is
  worse than a slow one.
- **D-05.3 — a dismissed prompt is never a silent no-op.** The mismatch prompt's `escape` path
  writes an explicit log line naming the tool, the fact the prompt was dismissed, and the resulting
  outcome, and sets a status line. `installer/session.py`'s `MismatchChoice` is a closed
  `Literal["retry", "skip", "fallback"]` with no cancelled member, so a dismissal must resolve to
  one of the three: it resolves to `skip`, the conservative choice for a download whose checksum
  did not match, and says so.
- **Mechanism** — `ask_from_worker` implements exactly the mechanism recorded under
  `## Worker-to-modal mechanism` in `13-VALIDATION.md` by plan 13-01. Do not re-derive it, and do
  not ship both. Exactly one of these two is true when this plan lands, and the recorded section
  says which:
  - **If mechanism A** (`call_from_thread` + `push_screen_wait`): `ask_from_worker` becomes this
    project's FIRST production use of `push_screen_wait`, which `.claude/architecture.md` rule 2
    ("Modals return results only via `push_screen(modal, callback)`", lines 16-17) does not
    describe. 13-01 Task 3 has already ruled it a documented exception; this plan's job is to make
    `ask_from_worker`'s docstring say so in one sentence and point at that section, so plan 13-07
    Task 1 can lift it into `.claude/architecture.md`. An undocumented first use of a primitive the
    architecture standard appears to forbid is how a correct seam gets ripped out later by someone
    enforcing the rule in good faith.
  - **If mechanism B** (`push_screen(screen, callback)` + `threading.Event`): that IS the rule-2
    shape, no exception is needed, and no `push_screen_wait` branch may remain anywhere in
    `installer/execute_screen.py` — a dead A-branch kept "in case" would reintroduce exactly the
    ambiguity plan 13-01 spent a wave removing.

## Trust Boundaries

| Boundary | Description |
