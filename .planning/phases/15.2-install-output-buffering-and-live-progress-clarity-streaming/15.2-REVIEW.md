# Phase 15.2: Code Review Report

**Reviewed:** 2026-09-16T00:00:00Z
**Depth:** standard
**Files Reviewed:** 6
**Status:** issues_found

## Summary

The production logic in `installer/run.py` and `installer/execute_screen.py` is, on
inspection and after tracing every state transition, broadly correct. The two-rung
unbuffer ladder does what the plan describes, `CommandError` really does carry the
caller's argv on both failure paths, the self-re-arming one-shot timer fires at the
threshold rather than at a poll boundary, and the in-flight/generation bookkeeping has
no ordering hole I could find. `make validate` exits 0 and `make test` exits 0 at 95.42%
coverage.

The defects are concentrated in the **evidence**, not the mechanism — and they are worse
than they look, because this phase's whole justification is three rounds of cross-AI plan
review that converted design concerns into "a test pins that". Several of those tests do
not pin what they claim to pin:

- The `_silence_generation` token — the round-1 **HIGH** mitigation, touching five call
  sites plus a new public `InstallLogLine` parameter — is verified by exactly zero tests.
  I proved this by mutation: deleting the generation comparison from
  `_transient_is_current` leaves all 83 tests in `tests/test_execute_screen.py` green.
- The "a wrapped failure still names the caller's command" test passes a Python argv,
  which the ladder deliberately refuses to wrap. It tests the unwrapped path under a
  wrapped-path name.
- Two of plan 01 Task 2's ten mandated tests, and plan 01 Task 1's entire
  `ExecuteScreen`-level sentinel end-to-end test, were never written. `15.2-01-SUMMARY.md`
  records "Total deviations: 1 discarded stale-worktree attempt (infrastructure, not a
  code deviation)".

Each of those is a check that has been silenced by construction rather than by a `skip`
marker, which `CLAUDE.md`'s "Never bypass a quality gate" and `.claude/testing.md`'s
"don't write assertion-free tests just to touch lines" both forbid. The classification
below reflects that: the code is defensible, the proof that it stays defensible is not.

## Critical Issues

### CR-01: The `_silence_generation` guard is verified by no test at all — deleting it leaves the suite green

**File:** `installer/execute_screen.py:664-671` (guard), `:656`, `:662`, `:703`, `:776`, `:785` (producers)
**Tests concerned:** `tests/test_execute_screen.py:2720-2741`, `:2966-2981`, `:2984-3050`

**Issue:** `_transient_is_current` ANDs five conditions. Every test that claims to exercise
the generation token invalidates one of the other four at the same time, so the generation
comparison is never the reason the message is dropped:

- `test_stale_generation_transient_is_dropped_without_writing_anything` (`:2720`) builds a
  message with `generation=-1`, but the screen reaches that point via
  `_start_and_wait_for_first_line`, which ends in `_note_output` — and `_note_output`
  (`:655`) sets `_silence_noted = False`. The guard short-circuits on `self._silence_noted`
  before generation is ever compared.
- `test_stale_transient_beaten_by_a_real_line_is_dropped` (`:2984`): `_note_output` sets
  `_silence_noted = False` as well as bumping the generation.
- `test_stale_transient_beaten_by_install_tool_finished_is_dropped` (`:3009`):
  `_clear_in_flight` sets `_in_flight = None` (and `_silence_noted = False`).
- `test_stale_transient_beaten_by_run_finished_is_dropped` (`:3031`): `self.finished` is True.

Plan 02 Task 1 called this out explicitly and required the opposite: *"Isolate the
generation as the reason: reach the state where the indicator WOULD be written ... and
change only the message's generation, so a passing test means the token did the work
rather than one of the other four conditions happening to be false."* The delivered tests
do the thing the plan forbade.

**Proof (mutation run, not inference).** With a session plugin replacing
`ExecuteScreen._transient_is_current` with a copy that omits
`message.generation == self._silence_generation`, `uv run pytest tests/test_execute_screen.py`
still reports 83 passed. Consequently the entire `generation` mechanism — the
`InstallLogLine.generation` parameter, `_silence_generation`, and its five `+= 1` sites —
can be deleted or silently broken by a future refactor with the suite fully green.

**Fix:** add one test that isolates the token. Drive the screen to the state where the
indicator *would* be written and change nothing but the generation:

```python
async def test_stale_generation_alone_drops_the_transient() -> None:
    ...
    await _start_and_wait_for_first_line(screen, pilot, started)
    current = _captured_transient(screen, "rg")          # latches _silence_noted=True
    assert screen._transient_is_current(current)          # pyright: ignore[reportPrivateUsage]
    stale = InstallLogLine(
        "rg", _WAITING_OUTPUT, transient=True, generation=current.generation - 1
    )
    # every other condition is identical to `current`; only the token differs
    assert not screen._transient_is_current(stale)        # pyright: ignore[reportPrivateUsage]
    before = _log_text(screen)
    screen.on_install_log_line(stale)
    await pilot.pause()
    assert _log_text(screen) == before
```

Re-run the mutation above afterwards; it must go red.

### CR-02: The "wrapped failure names the caller's command" test never wraps anything

**File:** `tests/test_run.py:459-483`

**Issue:** `test_streaming_runner_caller_argv_in_error_when_wrapped_command_fails` builds a
runner with `unbuffer=True, which=lambda _: "/usr/bin/stdbuf"` and then calls it with
`cmd = [sys.executable, "-c", "print('fail')"]` (`:477`). `_is_python_child` returns True
for that argv, so `unbuffered_argv` returns the caller's list **unchanged** — verified
directly:

```
>>> _is_python_child([sys.executable, '-c', "print('fail')"])      -> True
>>> unbuffered_argv([sys.executable, ...], '/usr/bin/stdbuf') is cmd -> True
```

The test therefore exercises the *unwrapped* path under a wrapped-path name, and asserts
only what the pre-existing `test_streaming_runner_nonzero_exit_raises_command_error_after_emitting`
(`:199`) already asserted. Its second assertion, `assert "/usr/bin/stdbuf" not in exc.value.cmd`,
is trivially true because no wrapping occurred.

Compounding it: the `fake_popen` double at `:466` ignores its `argv` parameter entirely and
always launches a fixed child, so even the argv that *was* handed to `Popen` goes unchecked.

**Consequence:** no test in the suite covers a *wrapped* command exiting non-zero. Changing
`installer/run.py:268` from `CommandError(cmd, returncode, ...)` to
`CommandError(launch_argv, returncode, ...)` — the exact regression this test exists to
prevent, and the one that would show a user a `stdbuf -oL brew install rg` command they
never typed — leaves the suite green, because every other non-zero-exit test uses either a
default-constructed runner or a Python argv, both of which yield `launch_argv is cmd`.

**Fix:** use a non-Python argv so the ladder actually fires, and assert on what `Popen`
received:

```python
def test_streaming_runner_caller_argv_in_error_when_wrapped_command_fails(
    monkeypatch: pytest.MonkeyPatch,
) -> None:
    seen_argv: list[list[str]] = []
    original_popen = subprocess.Popen

    def fake_popen(argv: list[str], **kwargs: Any) -> subprocess.Popen[str]:
        seen_argv.append(argv)
        return original_popen([sys.executable, "-c", "raise SystemExit(3)"], **kwargs)

    monkeypatch.setattr(subprocess, "Popen", fake_popen)
    runner = StreamingRunner(
        lambda _t, _l: None, unbuffer=True, which=lambda _: "/usr/bin/stdbuf"
    )
    runner.set_tool("rg")
    cmd = ["brew", "install", "rg"]
    with pytest.raises(CommandError) as exc:
        runner(cmd)
    assert seen_argv == [["/usr/bin/stdbuf", "-oL", "brew", "install", "rg"]]  # it WAS wrapped
    assert exc.value.cmd == cmd
    assert "stdbuf" not in " ".join(exc.value.cmd)
```

### CR-03: Mandated acceptance-criteria tests were never written, and the SUMMARY reports zero code deviations

**File:** `tests/test_execute_screen.py`, `tests/test_run.py`, `installer/run.py:238-239`

**Issue:** three tests that plan 01 lists as acceptance criteria do not exist, and one
production branch is uncovered by the entire 2189-test suite.

1. **The `ExecuteScreen`-level sentinel end-to-end test is absent.** Plan 01 Task 1's
   acceptance criteria require *"A new test in `tests/test_execute_screen.py` [that] runs a
   real child through the production worker ... and asserts the child's first line is
   present in `_log_text(screen)` while the child is still blocked on a sentinel the test
   has not yet created."* `grep -n "sentinel" tests/test_execute_screen.py` returns nothing;
   no test in the module spawns a real subprocess through the worker and observes the widget
   before it exits. This test was added specifically to answer review round 2's MEDIUM
   finding *"no test observes the widget before the child exits"* — so that finding is, as
   of this tree, still unanswered. The only real-child `ExecuteScreen` test
   (`:3277`) lets the child run to completion before asserting.

2. **`installer/run.py:238-239` is executed by no test.** Coverage over the full suite
   reports `installer/run.py ... 91% Missing 61-63, 131, 238-239, ...`. Lines 238-239 are
   `except OSError as retry_exc: raise CommandError(cmd, 127) from retry_exc` — the
   both-attempts-failed path added by review round 1's HIGH finding. Plan 01 Task 2
   acceptance criterion names it: *"both-attempts-fail-is-still-127-with-the-caller's-argv"*.

3. **`knob-off-makes-exactly-one-Popen-attempt` is absent.** This is the guard for the
   fragile `launch_argv is not cmd` **identity** test at `installer/run.py:235`. If anyone
   changes `unbuffered_argv`'s skip branches to `return list(cmd)` (a natural defensive
   tidy-up), every default-constructed runner silently gains a second `Popen` attempt on
   `OSError` — and `test_streaming_runner_missing_binary_is_127` (`:213`) would still pass,
   because its double raises unconditionally and the test asserts only on the final error.

4. **`.planning/.../15.2-01-SUMMARY.md:139-153` states "Total deviations: 1 discarded
   stale-worktree attempt (infrastructure, not a code deviation)"** while three of its own
   acceptance criteria are unmet. A summary that under-reports unmet criteria is the input
   the next phase's planner reads as ground truth.

**Fix:** write the three missing tests. The two `run.py` ones are cheap:

```python
def test_streaming_runner_both_attempts_failing_is_still_127_with_caller_argv(
    monkeypatch: pytest.MonkeyPatch,
) -> None:
    attempts: list[list[str]] = []

    def always_raises(argv: list[str], **_kwargs: Any) -> subprocess.Popen[str]:
        attempts.append(argv)
        raise FileNotFoundError(argv[0])

    monkeypatch.setattr(subprocess, "Popen", always_raises)
    runner = StreamingRunner(lambda _t, _l: None, unbuffer=True, which=lambda _: "/usr/bin/stdbuf")
    runner.set_tool("rg")
    with pytest.raises(CommandError) as exc:
        runner(["brew", "install", "rg"])
    assert exc.value.returncode == 127
    assert exc.value.cmd == ["brew", "install", "rg"]
    assert len(attempts) == 2          # wrapped, then unwrapped -- and no retry loop


def test_streaming_runner_knob_off_makes_exactly_one_popen_attempt(
    monkeypatch: pytest.MonkeyPatch,
) -> None:
    # Pins the `launch_argv is not cmd` identity branch: a runner that never
    # opted in must keep today's single-attempt 127 behaviour byte for byte.
    attempts: list[list[str]] = []

    def always_raises(argv: list[str], **_kwargs: Any) -> subprocess.Popen[str]:
        attempts.append(argv)
        raise FileNotFoundError(argv[0])

    monkeypatch.setattr(subprocess, "Popen", always_raises)
    runner = StreamingRunner(lambda _t, _l: None)
    runner.set_tool("rg")
    with pytest.raises(CommandError):
        runner(["nope"])
    assert len(attempts) == 1
```

For the sentinel test, follow plan 01 Task 1's specification verbatim (child prints one
unflushed line, then polls for a `tmp_path` sentinel with its own ~30s ceiling; the install
closure drives the **handed-in** runner; poll `_log_text` with `await pilot.pause(0.02)`;
create the sentinel in a `finally`). Then correct `15.2-01-SUMMARY.md`'s deviations section.

**File:** `tests/test_run.py:340-362`
**Issue:** `test_streaming_runner_env_rung_is_unconditional_even_with_unbuffer_false` accepts

### WR-04: `_arm_silence_timer` replaces a live timer without stopping it

**File:** `installer/execute_screen.py:673-674`
**Issue:** `_arm_silence_timer` unconditionally overwrites `self._silence_timer`. The
invariant that makes this safe is implicit and fragile: it holds only because the sole
in-production caller other than `action_start` is `_check_output_silence`, which nulls the
attribute on its own first line (`:683`) after its own timer has fired. Any future second
arming site — e.g. re-arming on a real log line, or arming again from `on_prompt_open`'s
close branch — orphans a live Textual `Timer` that `on_install_run_finished` (`:791-793`) can
no longer stop, because it only holds the newest reference. This already happens inside the
test suite: every manual `screen._check_output_silence()` call leaks the real pending timer.
**Fix:** make the invariant enforced rather than assumed:

```python
def _arm_silence_timer(self, delay: float) -> None:
    if self._silence_timer is not None:
        self._silence_timer.stop()
    self._silence_timer = self.set_timer(delay, self._check_output_silence)
```

### WR-09: The unwrapped retry discards the original launch failure

**File:** `installer/run.py:228-241`
**Issue:** In the wrapped branch, `exc` (the `OSError` from launching the `stdbuf`-prefixed
argv) is bound at `:228` but never used: when the retry also fails, the raise at `:239`
chains from `retry_exc` only, so the first failure — the one that says *why* the wrapper
broke, which is the diagnostically interesting half — is dropped on the floor. On the
unwrapped path (`:241`) `exc` is used, so the asymmetry looks accidental rather than chosen.
Combined with CR-03's finding that `:238-239` is executed by no test, this path has neither
coverage nor a usable traceback.
**Fix:** preserve both causes, e.g.
`raise CommandError(cmd, 127) from retry_exc` → attach the first as context:

```python
except OSError as retry_exc:
    retry_exc.__context__ = exc  # keep why the wrapped launch failed
    raise CommandError(cmd, 127) from retry_exc
```

or simply chain from `exc` and record `retry_exc` in the message.

### WR-10: `_is_python_child` silently disables the stdbuf rung for any binary named `python*`

**File:** `installer/run.py:122-133`
**Issue:** The heuristic returns True for any argv whose `Path(argv0).name` starts with
`"python"`. The docstring admits the false *negative* direction (`uv run python` presents as
`uv` and gets wrapped, harmlessly) but not the false *positive* one: a real non-Python binary
named `pythonpy`, `python-lsp-server`, `pythonic-cli`, or a wrapper script named `python-tool`
matches the prefix and is excluded from `stdbuf -oL` even though `PYTHONUNBUFFERED` does
nothing for it — i.e. the tool this phase exists to unblock would silently keep bursting.
Line `:131` (`return False` for an empty `cmd`) is also uncovered by the full suite.
**Fix:** tighten to the interpreter shapes that actually honour `PYTHONUNBUFFERED`, and
document the residual gap:

```python
name = Path(argv0).name
return argv0 == sys.executable or re.fullmatch(r"python(\d+(\.\d+)?)?", name) is not None
```

and add a two-line test for `_is_python_child([])` and for a `python`-prefixed non-interpreter.
