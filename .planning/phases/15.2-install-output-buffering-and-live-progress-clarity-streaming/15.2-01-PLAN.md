<objective>
`StreamingRunner` streams faithfully and still looks frozen. Its own docstring already names why:
`bufsize=1` line-buffers the PARENT's reads and cannot make a child line-buffer its own writes. A
vendor installer that detects a non-TTY stdout — pnpm, SDKMAN's bash launcher, most progress-bar
`curl | sh` scripts — block-buffers on its side and bursts everything at process exit, so the user
watches an empty log for two minutes and then gets 400 lines at once.

This plan makes the parent force the child's hand where a real, safe mechanism exists, as a
best-effort ladder that never fails an install when a rung is unavailable (D-01):

- Rung 1, unconditional: `PYTHONUNBUFFERED=1` in every streamed child's environment (D-02). Safe,
  Python-specific, a no-op for a non-Python child.
- Rung 2, opt-in and availability-gated: wrap argv in `stdbuf -oL` when the caller asked for it and
  the binary is on PATH, skipping a child rung 1 already covers (D-03, D-05).

Both rungs live in `installer/run.py` as a generic capability behind one `unbuffer` knob — no
manager-name branching anywhere in the runner (D-04) — and `ExecuteScreen._execute_worker`, the
project's one live streaming call site, opts in.

Purpose: a user running an install in the TUI sees output as the installer produces it, not as a
burst at the end.
Output: in `installer/run.py`, two module-level constants (`UNBUFFER_ENV_VAR`, `STDBUF_FLAG`), three
module-level helpers (`unbuffered_env`, `_is_python_child`, `unbuffered_argv`), two keyword-only
`StreamingRunner.__init__` parameters (`unbuffer`, `which`) with the `self._stdbuf` they resolve, an
unwrapped-retry branch in `__call__`'s `OSError` handler, and a rewritten class docstring that states
the new guarantee without overclaiming; in `installer/execute_screen.py`, one changed constructor
call; in `tests/test_run.py`, an `env` parameter added to the existing `wrapping_popen` double; and
the tests that fail without each of them.
</objective>
