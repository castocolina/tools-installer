<objective>
Plan 01 makes a buffering child stream where it can. Some children still will not: a statically
linked binary doing its own buffering, a host with no `stdbuf`, a step that is genuinely slow before
it prints anything. In all of those the user sees the same thing they see for a hung process — an
empty log — with no way to tell the two apart.

This plan removes that ambiguity. After 2 seconds with no new line from the in-flight tool's stream
(D-06), `ExecuteScreen` writes one clearly-marked transient line into that tool's own region of the
existing live log (D-07), attributed to that tool and not to the batch (D-08). It is superseded the
moment real output arrives, and it never enters the bounded tail that becomes a failure report.

Purpose: silence stops being ambiguous. A user watching a two-minute `pnpm add -g` knows the
installer is waiting on the child rather than wondering whether to press ctrl+c.
Output: a `now` clock seam on `ExecuteInputs`, a `transient` flag on `InstallLogLine`, four pieces of
silence state and one interval-timer check on `ExecuteScreen`, an architecture note recording both of
this phase's mechanisms, and the tests that fail without each of them.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-15.2-05 | Spoofing | `_WAITING_OUTPUT` rendered inside a tool's log region | low | mitigate | A malicious child could print the same text and appear to be the installer. The indicator carries no authority — it makes no claim a user acts on beyond "keep waiting" — and it uses the same `-- ... --` marker `method_started` already writes, which a child could equally forge today. Bounded by the existing `sanitize_log_line` on every child line, which strips the control characters a convincing forgery would need. |
| T-15.2-06 | Tampering | `InstallLogLine.transient` | low | mitigate | The flag is keyword-only, defaults to False, and is set at exactly one call site inside `_check_output_silence`. No child output and no registry data can reach it, so a child line can never mark itself transient and evade the silence bookkeeping. |
| T-15.2-07 | Denial of Service | the `set_interval` silence timer | low | mitigate | Ticks at a fixed 0.5s and does constant work bounded by early returns; it writes at most one line per silence gap because `_silence_noted` latches, so a permanently silent child cannot grow the log. `on_install_run_finished` stops and drops the timer, and a test asserts it, so no timer outlives the run. |
| T-15.2-08 | Repudiation | the indicator inside a failure report | low | mitigate | The indicator must never be mistaken for something the child said when an operator reads a failure. `StreamingRunner`'s bounded `tail` is fed only from the child's stdout and the indicator is produced on the UI side, so the report cannot contain it; a test asserts the occurrence count stays at 1 for a FAILED install. |
