Write `p25-moved-same.py` in the scratchpad, reused by plans 25-08 and 25-09: arguments `--rev REV --source PATH --target PATH [--target PATH ...] [--rename OLD=NEW ...]`. It parses `git show REV:PATH` and the working-tree source, computes the removed top-level names (defined at REV, not in the working tree), maps each through the renames, and fails when a removed name is not a top-level definition in some target ("lost"). Top-level names are those bound by `FunctionDef`, `AsyncFunctionDef`, `ClassDef`, `Assign` (each `Name` target) and `AnnAssign` (its `Name` target), so moved constants such as `MUTATION_REFUSAL` and `_TIMES_LISTED` are checked like classes. For each removed name it compares `ast.dump` of the REV node and the target node after deleting docstrings from both and applying the renames to the REV node's `Name.id`, `FunctionDef.name`, `ClassDef.name` and `alias.name`; it prints each mismatch. Review R1-25: it also prints a "remains" line for every `--rename` OLD name still present as a `Name.id`, an `Attribute.attr`, an `alias.name` or a top-level binding anywhere in the working-tree source or a target, so a reference left behind in a class that has not moved yet (for example `SchedulesScreen` still calling `_sentence`) fails the check; references to moved names that are not renamed are proven by ruff F821 (undefined name) and pyright strict in `make validate`, because the source no longer defines them. Review R2-15 (a copy left behind, and a vacuous run): it also prints a "remains" line for every name a target defines at top level in the working tree but not at REV (a target absent at REV counts as empty) while the working-tree source still defines that same name at top level, so a class or constant copied into a target but not deleted from the source fails; and it fails when it checked zero names (no removed name was compared), so a run against the wrong revision cannot pass. It prints the number of names checked and exits 1 on any lost, mismatched or remaining name or when that number is 0, 0 otherwise. When to run it: on the working tree before the task's commit, with `--rev HEAD`; once the task's commit exists, run it against the task's parent commit instead (`--rev HEAD~1` while that commit is HEAD), because `--rev HEAD` after the commit compares the commit with itself and now fails with zero names checked.
