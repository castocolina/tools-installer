### Wave 0 disposition — why `wave_0_complete` stays `false`

There is no separate Wave 0 wave in this phase. All three gaps above are covered by the plan's own
TDD tasks, which write the test red before the implementation that turns it green, so no task carries
a `MISSING —` placeholder verify and nothing is executed against an unsampled requirement. The flag
records a fact about the tree, not about the plan: the three tests do not exist yet, and reporting
`true` now would assert coverage that cannot be collected. It flips to `true` — with every box above
checked — the moment all five selector counts in the table above reach their required values, which is
the same condition the plan's `<verify>` gates already enforce per task. `nyquist_compliant` is
independently `true` because the *strategy* is complete: every requirement has an automated command,
no requirement is manual-only, and no gap is left to a later wave.
