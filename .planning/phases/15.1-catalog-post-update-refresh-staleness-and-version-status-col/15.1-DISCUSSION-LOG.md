## Post-update refresh scope

| Option | Description | Selected |
|--------|-------------|----------|
| Refrescar toda la vista del catalog activo | Call `enter_view()`/`_start_version_refresh()` on the whole active tab after `ExecuteScreen` closes — re-probes all visible tools, not just the ones touched. | ✓ |
| Refrescar solo las tools que participaron en la corrida | More precise/faster (fewer probes) but requires threading the affected tool-id list back from `ExecuteScreen` into the close callback. | |

**User's choice:** Refrescar toda la vista del catalog activo (recommended option)
**Notes:** Simpler and more robust against edge cases like a dependency drag-in that also changed state.

---

## Gray-state disambiguation

| Option | Description | Selected |
|--------|-------------|----------|
| Texto distinto por caso | Different stable text label per case (e.g. "(unmanaged)", "…"/"(unknown)") — the legend explains each label, no new colors. | ✓ |
| Colores/símbolos adicionales distintos por caso | More visual, but adds more color states to learn and requires verifying legibility across dark/light themes and constrained terminals. | |

**User's choice:** Texto distinto por caso (recommended option)
**Notes:** Avoids growing the color palette; a legend for text labels is simpler to build and keep accurate.

---

## Legend placement

| Option | Description | Selected |
|--------|-------------|----------|
| Siempre visible, línea fija en el footer/status bar | Always-on, one line, present across System/User/AI views, no discovery action needed. | ✓ |
| Toggle con una tecla | Doesn't occupy space by default, but the user has to discover/remember the shortcut — same discoverability problem as the colors already have. | |

**User's choice:** Siempre visible, línea fija en el footer/status bar (recommended option)
**Notes:** Discoverability was the entire original complaint — a toggle just relocates the same problem.
