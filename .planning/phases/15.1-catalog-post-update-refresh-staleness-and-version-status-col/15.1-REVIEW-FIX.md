## Fixed Issues

### CR-01 (BLOCKER): `_install_closed` narrowed every catalog's installed map to one tier

**Files modified:** `installer/wizard_app.py`, `tests/test_wizard_app.py`
**Commit:** `caabe9e`

`UnifiedApp` now keeps the whole catalog as `self._catalog_tools` and
`_install_closed` derives ONE map over it, handing the identical map to all three
tier screens. The previous per-screen derivation from `screen.tools` dropped every
cross-tier id, and `set_installed` is a plain replacement, so
`deps.missing_requires` / `selection.unstaged_recommends` (which resolve against
the full catalog via `installed.get(dep_id, False)`) silently read an installed
cross-tier dependency as missing.

**Regression test:** `test_install_closed_keeps_cross_tier_ids_in_every_installed_map`
— two tiers, a cross-tier `requires` (`mmdc`(user) -> `pnpm`(system)). Asserts the
behavioural symptom first (marking `mmdc` after the close must NOT announce "also
needs pnpm") and the structural invariant second (both tier screens hold the same
whole-catalog map). Confirmed failing pre-fix with the review's exact string:
`'mmdc also needs pnpm - added automatically at install time...'`.

### CR-02 (BLOCKER) + WR-05: the legend collapsed the catalog table at 80x20

**Files modified:** `installer/tool_browser.py`, `installer/catalog_tui.py`, `tests/test_catalog_tui.py`
**Commit:** `58d4fda`

`#browser-legend` is capped at `max-height: 3`, and `_LEGEND` was cut from 466 to
221 plain characters — the three-row budget at 80 columns is 234. The four dim
markers are now listed rather than re-glossed (they already say what they mean by
D-02's design, and re-glossing them is what produced both the 7-row legend and
WR-05's stuttering "checking… still checking" / "no version no version could be
read"). All four now carry the `dim` style the cells render them in, matching what
the two colored entries already did.

Measured before/after, `app.run_test(size=...)`:

| size | legend rows (before -> after) | DataTable rows (before -> after) |
|------|------|------|
| 80x20 | 7 -> 3 | 3 -> 7 |
| 100x30 | 5 -> 3 | 15 -> 17 |
| 120x30 | 4 -> 2 | 16 -> 18 |

**Regression tests:**
- `test_legend_keeps_the_catalog_table_usable_at_the_minimum_size` — at 80x20
  specifically, asserts every marker is still painted AND `table.size.height >= 6`
  AND `legend.size.height <= 3`. Confirmed failing pre-fix (`assert 7 <= 3`).
  Both halves are asserted together because either alone is satisfiable in a way
  that breaks the other (capping clips markers; shortening alone re-opens the
  collapse).
- `test_legend_widget_paints_every_marker_at_full_width` gained a dim-style
  assertion for WR-05. Confirmed failing when a marker's `[dim]` wrapper is
  removed.
- `_painted_legend` now reassembles the wrapped lines with a space rather than edge
  to edge. The pre-existing edge-to-edge join reported a false miss for a marker
  split across a wrap boundary (`(no\ncomparison)`), which surfaced as soon as the
  legend wrapped differently — a latent bug in the review-era test, fixed not
  bypassed.

### WR-01 + WR-02: silent `invalidate` failure, and comments describing absent code

**Files modified:** `installer/wizard_app.py`, `tests/test_wizard_app.py`
**Commit:** `3717219`

`contextlib.suppress(Exception)` is replaced by a real `try/except Exception` with
`# noqa: BLE001`, matching the cited `UpdateService` precedent in BOTH directions:
the failure never downgrades an already-recorded run, and it is never swallowed.
The message is held on `self._invalidate_warning` and written to the catalog's
status line by the following `_install_closed`, because `InstallRunFinished`
arrives while `ExecuteScreen` is still on top and there is no catalog status line
to write to yet. `import contextlib` is now unused and removed.

This also makes WR-02's comments true again — they described a `try/except` and a
`# noqa: BLE001` that the SIM105 rewrite had removed. Rather than deleting the
sentences, the code they describe is restored, which is the option the review
itself offered.

**Regression test:**
`test_a_failed_post_run_cache_invalidation_is_reported_not_swallowed` — a service
whose `invalidate` raises. Asserts the app is still running and the summary merge
still ran (non-fatal), AND that both the symptom and the cause reach
`app.catalog.status_text`. Confirmed failing pre-fix
(`assert 'version cache invalidation failed' in ''`).

### WR-03: unguarded `KeyError` on `self._catalogs[self.current_view]`

**Files modified:** `installer/wizard_app.py`, `tests/test_wizard_app.py`
**Commit:** `ede166c`

Changed to `.get()` + early return, with the reason recorded in-code: `_catalogs`
is keyed by tier only while `current_view` ranges over all six `VIEWS`, and the
"only a catalog tier pushes ExecuteScreen" property is one call site's behaviour,
not an enforced invariant. A `KeyError` raised inside a Textual screen-result
callback takes the message pump down instead of degrading. The half that does not
need a visible catalog (the installed-map replacement) still runs, and a pending
warning stays pending for the next close that has a status line.

**Regression test:**
`test_install_closed_degrades_when_the_active_view_is_not_a_catalog_tier` —
invokes the callback with `current_view == "doctor"`. Confirmed failing pre-fix
with `KeyError: 'doctor'`.

### WR-04: the live presence predicate was called unguarded from the callback

**Files modified:** `installer/wizard_app.py`, `tests/test_wizard_app.py`
**Commit:** `520c001`

The sweep now goes through `ui_common.run_live`, the seam
`.claude/architecture.md` rule 3 mandates for every live core call a screen
triggers. A failed read leaves the previous map in place and reports itself on the
same status line the WR-01 fix uses — one guarding story for both post-run side
effects rather than two, which is the consistency WR-04 asked for.

**Regression test:**
`test_install_closed_reports_a_failed_presence_sweep_and_keeps_the_old_map` — the
predicate starts working (so `ExecuteScreen`'s own read on mount is unaffected) and
starts raising `OSError` only once the run has finished, so the sweep is the only
caller that sees the failure. Asserts the app survives, the previous map is intact,
and both symptom and cause reach the status line. Confirmed failing pre-fix with an
uncaught `OSError: stale file handle: /Volumes/nfs/bin`.
