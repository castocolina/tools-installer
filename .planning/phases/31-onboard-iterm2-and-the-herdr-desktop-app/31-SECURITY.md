## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| installer -> a file under the user's home | A whole file (iTerm2 Dynamic Profile) or two-level keys (herdr-app `keys.json`) are written where foreign content, a symlink or another process may be | JSON text |
| installer -> removal of owned content | Strip deletes a created file or removes keys the user may have changed | file, keys |
| installer -> `/usr/bin/defaults` | A GUID read from preferences or the record file becomes an argv element of a command that writes iTerm2 preferences | argv |
| exported preferences -> generated profile | The parent profile's key map (plist) is parsed and copied into the profile | plist text |
| network -> repository data | Two vendor default files were downloaded once and committed | JSON files, sha256 |
| vendor `install.sh` -> user's home | The herdr-app vendor script (nested `curl \| sh`) writes under the user's data folder | script, files |
| harness / driver -> container runtime and host | One PID-named container (and maybe the base image) is created and removed; the driver mutates a home | container name, run args |
| orchestrator record -> published evidence | The registry comment and skill row state what a container run proved | text |

## Notes (informational, non-blocking, not counted)

- Planned test names that do not exist verbatim: `test_strip_deletes_a_file_it_created_when_only_the_seed_remains`, `test_a_deleted_key_stays_deleted_through_two_reconfigures_and_returns_on_reinstall`, `test_recorded_ownership_is_resolved_before_the_user_binding_check`. Equivalent tests exist under the names cited in T-31-06 and T-31-17; the behavior is pinned.
- The real `iterm2_defaults` body (installer/iterm2_profile.py:226) is never executed by a test: the autouse `no_iterm2_defaults` stub (tests/conftest.py:136-144) replaces it for every test, and tests assert the argv given to the seam. The argv-list and absolute-path property rests on that one line; a regression to a shell string would not fail a test. Suggest a unit test that patches `run_output` and asserts `["/usr/bin/defaults", ...]` with `timeout=20`.
- `_strip_whole_file` deletes the iTerm2 profile file on marker plus GUID proof; if the user appended a second profile to the installer's file, it is deleted with it (`delete_if_unchanged` still guards against concurrent change). Only a parent-directory symlink is not refused (a symlink at the file path is). Both are below the plan's declared mitigation; low impact.
- The vendor-script supply chain (AR-31-02) is the only external code the phase makes the installer run on the user's machine; consider recording the script digest or version in the registry if the vendor publishes one.
