Decisions recorded for this plan (Claude's discretion):
- Waiters live on the app: `_publication_waiters: list[Callable[[str | None], None]]`. `await_publication(callback)`: no service -> `callback(None)` at once; otherwise append, then `request_refresh()` unless a pass is running (a running pass is joined, as the service's single flight was). `on_refresh_finished` serves and clears the waiters only when no follow-up pass is pending, so a waiter never reads a state older than the newest mutation.
- `RefreshFinished` gains `error: str | None`: the first error of the pass (the tool refresh, else the skills refresh). The worker starts from `state check did not complete` and replaces it only when both calls returned; an exception that escapes `run_live` is caught in the worker and becomes its first line through `session.first_line` (21-02). This is the body of the deleted `_wait_worker`, moved, so the fail-closed contract does not change. The status copy of 21-06 (`on_refresh_published`) is unchanged.
- `ExecuteScreen` gets the same `TYPE_CHECKING` `app` property `UninstallScreen` uses, typed as `UnifiedApp` (import under `TYPE_CHECKING` only, so no runtime cycle). The callback posts the existing `StateSettled(token, error)`, so `on_state_settled` and the token rule are untouched.
- `tests/test_execute_screen.py::_host` passes `version_refresh=inputs.version_refresh` to `UnifiedApp`, because the app is now the only thing that refreshes. Held tests keep `calls == [frozenset({"rg"})]`: the launch pass is that call and the review joins it.
</context>
