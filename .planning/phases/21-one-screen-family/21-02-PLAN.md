Decisions recorded for this plan (Claude's discretion):
- `Disposition.REMOVE = "remove"` is declared after `BLOCKED`. Declaration order is the review order, so `_REVIEW_ORDER` places it before `WAIT` and `summary_counts` lists `removed` after `blocked`. `"remove_failed"` goes last in `summary_counts`' explicit result tuple (after `crashed`).
- REMOVE never joins `RUNNABLE` (P11). The review word `will remove` exists only because `Words.review` is required; no screen shows a REMOVE review row in this phase.
- The private first-line helper becomes public `first_line` by rename, not by a wrapper. Every caller in `installer/session.py` is updated in the same commit.
- REUSE 02-1: `outcome_detail_text` gets no new branch. Its `failed` test becomes a membership test over `{"failed", "remove_failed"}`; a removal outcome has `install is None` and `update is None`, so that branch already returns the sanitized first line of `detail`. Its `"no method succeeded"` fallback is unreachable for a removal, because the removal worker (21-13) always fills `detail` with `first_line(...)`.
- The REMOVE boundary is pinned on `build_plan` itself, not only on `RUNNABLE` (review 21-02 LOW): a parametrized test runs `build_plan` over every `Health` value, an unpublished state and a reinstall request, and asserts no row carries `Disposition.REMOVE`.
</context>
