Decisions recorded for this plan (Claude's discretion; CONTEXT leaves the API names open):
- Names: `mark_pending(tool_ids: Collection[str]) -> None`, `record_evidence(tool_id: str, *, broken: tuple[str, ...] = (), notes: tuple[str, ...] = ()) -> bool`. The pending set is `self._pending_ids: set[str]` (`_pending_writes` is already taken by the write queue). The evidence store is `self._evidence: dict[str, tuple[tuple[str, ...], tuple[str, ...]]]` (broken, notes).
- `mark_pending` assigns a new `_states` dict without the ids (the existing one-swap rule: the UI thread reads `_states` unlocked). The skills rebuild in `refresh_skills` only rebuilds ids still present in `_states`, so it needs no change.
- `invalidate` clears `_pending_ids` right after the epoch bump, inside the lock and before the cache write, so a failed write still leaves no id pending.
- The missing-command fact is a third map passed to `_merge_facts` in `_pass`, built by a new `_pnpm_missing_facts(tools, packages, which)` that reuses `pnpm_globals.node_globals(tools)` and the pass's own `which` (no new probe). It rides the `misconfigured` channel, which `tool_state` already turns into a note for an absent tool, so such a row is MISSING with the reason (RESEARCH A4).
- Smoke and split evidence are recorded by Doctor in 21-19; this plan only provides the store and its reading in the pass.
</context>
