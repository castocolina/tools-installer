A confirmed removal marks its tools pending, takes the app's mutation lock, runs the remover on a worker, and on completion writes the Phase 20 count line and asks the app for the follow-up pass. Navigation still works."` lives in `installer/wizard_app.py` beside the lock. The nouns are the members of `MutationHolder(StrEnum)` in `installer/enums.py` (the house module for `StrEnum`s, importable from `installer/catalog_tui.py` without a cycle). This plan adds `REMOVAL = "A removal"`; 21-15 adds `UPDATE`, `POLICY_TOGGLE`, `DAEMON_DEFAULT`; 21-16 adds `GLOBALS_REINSTALL`, `INSTALL_RUN`. Each member is added by the plan whose holder uses it, so no member is ever unused.
- Lock API on `UnifiedApp`: `_mutation_holder: MutationHolder | None`; `mutation_in_flight` (property, true while a holder is set); `begin_mutation(holder)`; `end_mutation()`; `refuse_if_mutating(screen) -> bool`, which, when a holder is set, writes `MUTATION_REFUSAL.format(holder=...)` as warn on that screen's status, posts `RefreshRequested()` from that screen (SPEC R2: a refused mutation still ends with one pass; reuses 21-07's message, so the lock needs no reference to `request_refresh` and 21-16 can move it to a plain base class), and returns true. 21-15 and 21-16 fold the other in-flight flags into this lock and add the check to every other mutating key.
- The invalidate stays on the existing `UninstallInputs.invalidate` seam in this plan, now called inside the worker right after the remover (only when the decision names a tool): it is blocking cache I/O, and a quit that waits for the worker then knows the invalidate already ran. 21-14 replaces the seam with the app's service. The `RemovalFinished` message carries `swept`, the remover's `error` and the `invalidate_error`. A remover that raises outside `run_live` is caught in the worker and becomes `first_line(exc)`.
- The finish handler order: `end_mutation()` first (a later failure in the handler can never leave the lock held), then the status summary, then the terminal sync as today, then `self.app.request_refresh()` (21-14 makes this unconditional except while quitting, W2).
- Per-tool words reuse the Phase 20 path: the summary is `summary_counts` over `RowOutcome(PlanRow(id, Disposition.REMOVE, ""), "done" | "remove_failed", detail=line)` (21-02). The status summary drops the old `Removed N tool(s).` sentence (the count line replaces it) and keeps every environment sentence of `_applied_summary`.
- `HeldRemover` (in `tests/screen_family.py`) reuses the `HeldRefreshService` shape from `tests/state_doubles.py` (a `threading.Event` release and a bounded wait): a callable `UninstallDecision -> SweepResult` with `started` and `release` events, a `calls` list and a configurable `result`; it waits at most 10 seconds and raises `TimeoutError` instead of hanging the suite. No existing double removes on command, so it is new.
