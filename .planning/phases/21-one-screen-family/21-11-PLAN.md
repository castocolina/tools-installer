This plan now carries only the prerequisites that keep the rows predicate as the row source: the Health column, the section merge, the removes cell, the always-render rule, the `pass_state` extension and the proof-test rewrites. 21-12 performs the switch-over and every deletion it makes possible in one plan.
- `UninstallScreen(inputs, *, version_refresh=None)`, the same optional keyword `CatalogScreen` takes. `UnifiedApp` passes the `version_refresh` it already holds. With no service every Health cell reads `…`; the direct-construction tests that do not assert Health pass nothing.
- The Health cell is `health_cell(state)` where `state` is the service's `state_of(row.tool.id)`, or None with no service. Header `Health`, between `Tool` and `Cat` (UI-SPEC A2).
- `_render()` rebuilds `_entries` and `_by_key` and calls `self._browser.reload(self._adapter())`. The re-derivation stores changed values as it does today and then always calls `_render()`. The `changed` comparison keeps its two other jobs: clearing `applied` on a nav entry and writing the standing status. A repaint therefore never touches the status line, as 21-01's status lifecycle requires. `ToolBrowser.reload` keeps the selection and prunes only ids that are no longer selectable (21-03), so an unchanged row set keeps every mark.
- `_STATE_TITLES` maps REMOVABLE to `removable here`, MANAGED to `managed elsewhere`, and both ABSENT and UNAVAILABLE to `nothing to do`. `_groups` merges members by title in that order (absent rows first, then unavailable rows) and drops an empty section.
- `What gets removed` per REUSE 11-2: `Text(", ".join(paths), style=style)` followed by `.truncate(_REMOVES_CELL_MAX, overflow="ellipsis")`, the house form at `installer/tool_browser.py:90`. No hand slicing and no hand-appended `…`. Every non-removable row reads `—`. `_REMOVES_CELL_MAX` is the largest value for which the 80x20 backstop passes with the Health column present; `ConfirmUninstall` still lists every path before anything is deleted.
- The `_VIA_*` constants and the `installed_via` table stay in this plan, because the row-based builder still writes the `Installed via` cell. They go in 21-12 with that builder (REUSE 11-1).
- Proof tests (REUSE "21-11 (outside 11-1/11-2)"): `pass_state` gains `removable: RemovalPlan | None = None` and `receipt: Receipt | None = None`, passed through to `tool_state`. `None` keeps today's empty plan, so every existing caller is unchanged. The two proof tests build the state with `removable=plan_removal(...)` over the planted tree and assert `uninstall_group(state)`. The five other tests replace the classification step with a direct `plan_removal` call. The other `test_classify_*` tests stay, because their subject is still live until 21-12.
