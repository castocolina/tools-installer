<objective>
One screen family: Textual's empty default screen becomes the neutral root, all six views are installed once and reached through one `show_view` order (clear, pop, push, enter), and `AppScreen` owns the lifecycle defaults. Views build widgets in `on_mount` and render content and status only from `enter_view`, so a status written during the first entry survives it and every view clears its status on leave.

Purpose: UI-01's precondition (every view goes through the same entry path, so later plans can render published state from `enter_view`/`state_refreshed`) and UI-02 (status lifecycle) in full.
Output: `AppScreen` defaults in `installer/ui_common.py`; the new root, `show_view`, `_navigable` and `on_mount` in `installer/wizard_app.py`; Doctor/Catalog/Uninstall `on_mount` reduced to widget building; `tests/test_screen_family.py` (new).
</objective>

Decisions recorded for this plan (Claude's discretion):
- `current_view` starts as the empty string `""` (the root sentinel, RESEARCH P1/A9) so `on_mount`'s `await self.show_view(self._initial_view)` is never an early-return no-op. Post-mount reads are unchanged.
- The pending-warning flush moves BEFORE `target.enter_view()` (RESEARCH P8): a status written during entry wins over a queued warning. Uninstall's standing status (`Nothing to uninstall.`) is written by its entry only when the status line is still empty after the flush, so a flushed warning is never replaced by an `ok` line.
- The new pilots live in `tests/test_screen_family.py` with a module-local `_family_app(**overrides)` builder (a `UnifiedApp` with two fake tools, empty uninstall/policies inputs and no state service). `tests/test_wizard_app.py::_app` is private to that module (pyright strict forbids the private import), and only this file needs the builder, so no shared helper module is created here (21-06 creates `tests/screen_family.py` for helpers several files share).
- Task 1 touches six files. They must land in one green commit: the stack-order change makes Doctor's and the catalog's `on_mount` starts duplicates of their `enter_view` starts, and it breaks the burst test's depth and the five `app.query_one` sites in `tests/test_catalog_tui.py` (RESEARCH P12). The test edits are mechanical.
- `tests/test_ui_common.py` uses its own `App` hosts, not `UnifiedApp`; it needs no change.
- Policies' content move to `state_refreshed` belongs to 21-17 (it needs the live predicates of 21-04); here Policies only inherits the new `AppScreen` defaults.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| keyboard -> App priority bindings | rapid key bursts reach `show_view` while a pop/push is in flight |
| a view's status line -> the user | a stale status shown after a leave reads as a claim about the current state |

| T-21-SC | Tampering | npm/pip/cargo installs | high | accept | no package installs in this plan; `pyproject.toml` and `uv.lock` unchanged |
</threat_model>
