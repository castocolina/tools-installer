Move Alacritty's keys lifecycle into one table keyed by registry tool id, so install, reconfigure, the `≈` fact and removal all go through `TERMINAL_KEYS`, then add the completeness guard and the runtime backstop for a declarer with no row.

Task 1 is the phase's tracer: it wires the one existing row through every layer the phase changes. Most of the work is moving code, so the file count overstates the effort.
Output: `installer/terminal_keys.py`; table-driven dispatch in `post_install.py`, `version_status.py` and `app.py`; the keys code removed from `terminal_shell.py`; four import lines in `tests/test_terminal_shell.py`; new tests in `tests/test_terminal_keys.py`.

Decision record for this plan:
- D-01 says `apply_terminal_keys(row, platform_os, home, environ, *, skip_recorded)` and also that the record path comes from the dict key. So the three generic functions take the key too, right after the row: `(row, tool_id, platform_os, home, environ, ...)`. The row still does not repeat its id.
- D-12 says the four import lines change to import from `installer.terminal_keys`. A production `apply_alacritty_keys` wrapper there would have zero production callers, which `.claude/architecture.md` rule 5 forbids (no orphan helpers). So the bound helper `apply_alacritty_keys(home, environ, *, skip_recorded)` lives in tests/test_terminal_keys.py, and the four lines import it from there. That keeps D-12's intent: only those four lines change, no call line or assertion changes, and nothing is re-exported from terminal_shell. Importing a helper from another test module is house practice (`from tests.test_docs import link_targets` in tests/test_docs_only.py).
- D-04 writes `TERMINAL_KEYS[tool.id]` for the install site. The owner's rule 5 overrides it with `TERMINAL_KEYS.get(tool.id)` and a refusal line, because `apply_install_tuning` has no try/except and a KeyError would crash reconfigure; the completeness test is the real guard.
- This plan keeps today's pending and skip-recorded semantics exactly. The D-06 drift change is plan 28-03.
