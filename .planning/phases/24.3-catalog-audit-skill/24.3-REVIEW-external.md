## MEDIUM

- **M-01 (lane A, reported HIGH)** `installer/catalog_audit.py:162`: `run_dir` refuses a symlink only at `root` and at `root/<date>`. A symlinked component above `root`, such as `.planning/audits`, passes the check. Every run-file write then lands outside the checkout. `_refuse_symlink_leaf` guards only the leaf.
  Fix: walk every component from the `.planning` ancestor down to `run` and refuse any symlink. Or compare `run.resolve()` with the resolved `.planning` before writing.
- **M-02 (lane A, reported HIGH)** `installer/catalog_audit.py:676-692`: `_state_refusal` is a denylist. It refuses only the default HOME state, a path inside the checkout, and an existing non-JSON file. `verify --state ~/.config/x/settings.json` is accepted, and so is a symlink to that file. verify-registry's `_save_state` then rewrites the file through `atomic_write_bytes`, which follows a leaf symlink (`atomic.py:42`). The rewrite keeps only the file's string-to-string pairs.
  Fix: refuse a symlinked `--state`, and refuse an existing file outside a temporary or scratch directory. For example, accept the path only when it is absent or lies under `tempfile.gettempdir()`.
- **M-03 (lane A)** `installer/catalog_audit.py:1557` (`scan` command): running `scan` again for the same date rewrites `scripts.md` whole. `_model` rebuilds script drift only from the current `scripts.md` and `findings.toml`, so a scan drift row fixed between scans disappears without a disposition. That breaks the sticky-drift rule of the D-04 cycle-3 amendment. The SKILL runs `scan` only when `scripts.md` is missing, which limits the exposure.
  Fix: refuse to overwrite an existing `scripts.md`, the way a complete report is refused.
- **M-04 (lane A, confirmed by the orchestrator)** `installer/catalog_audit.py:1280-1293`: `_Row.effective` cannot raise a report `n/a` row. In `current or "unknown"`, the `n/a` string is truthy. The `ok` branch needs `current is None` or `current == "unknown"`. So an `unknown` finding, or an `ok` finding sourced from a container transcript, leaves the row at `n/a`. That contradicts the D-04 rule "worst status wins (drift > unknown > ok > n/a), so a late finding can raise a row".
  Fix: rank the statuses and take the maximum. Keep the cycle-3 narrowing: `unknown` becomes `ok` only through a `container:` source, and `drift` stays sticky.
- **M-05 (lane A)** `installer/catalog_audit.py:1373-1425` (`_script_findings`): a script key shows only its first scan pattern, or else its first finding source. The Entries section excludes script keys. A later semantic finding or a container result on that key is therefore never listed, against the D-04 cycle-2 amendment ("every finding ... is listed in file order").
  Fix: render each finding and its status in file order under the script row.
- **M-06 (lane A)** `installer/catalog_audit.py:546-560` (`_installed_line`): when a version probe times out, exits non-zero or prints nothing, the facts say `not installed`. A broken or slow binary then looks the same as an absent one.
  Fix: when the binary resolves but the probe fails, write `unknown: version probe failed`.
- **M-07 (lane A)** `installer/catalog_audit.py:551`: on macOS, `gnu-bash` (`cmd = "gnu-bash"`, real binary in `detect_path`) is probed as `gnu-bash --version`, so a Homebrew bash reads as `not installed`.
  Fix: probe the `detect_path` executable when the method declares one.
- **M-08 (lane A)** `installer/catalog_audit.py:219`: `_check_rows` copies the whole offending row into its refusal message, and `main` prints that message to stderr. A row with a secret-shaped token and a bad status therefore prints the token, even though `_hygiene` flags it. The secret was already in the caller's own input, so this is close to LOW.
  Fix: name a refused row by its check name or row number, not by its text.
- **M-09 (lane C, reported HIGH)** `.claude/skills/catalog-audit/SKILL.md:40-41`: on resume, steps 4 and 5 run only when `scripts.md` is missing. A run that stops after `scan` but during the step 5 container checks therefore skips the remaining checks. Those rows stay `unknown` or `drift`, and drift stays gated, so the summary is not falsified. The missing checks are simply never reported as missing.
  Fix: on resume, run step 5 for every `drift` or `unknown` install, update, removal or script key that has no `container:` finding and no `container check not run` row.
- **M-10 (lane C)** `.claude/skills/catalog-audit/SKILL.md:57-62`: the short path writes `ok` for skipped rows that cite only `facts <id>`. Those facts show what the registry declares, not what the vendor does today, so a deprecated tuning key or a changed update argv is marked `ok`.
  Fix: on the short path, write a non-downloadable row that was not re-read as `unknown` with `reason: short path, not re-read`, which the SKILL already allows as an option.
- **M-11 (lane C)** `tests/e2e_landing_driver.py:647-664`: the driver logs the `service restart` exit code only as an `INFO` line. A failed restart that leaves the old serve process running can still pass `update_while_running_verdict` when the binary was replaced in place, because `/proc/<pid>/exe` then has no `(deleted)` suffix.
  Fix: make a non-zero restart exit fail the verdict, and check that the observed PID changed.
- **M-12 (lane C)** `scripts/container-e2e-verify.sh:2734,2772`: stage and step output goes into `landing-transcript.log` without redaction. The SKILL makes `container: <transcript path>` evidence for the audit, and `_hygiene` covers only report and finding text, not the transcript.
  Fix: pass the output through the existing log sanitizer, with the home path and secret patterns, before the `tee`.
- **M-13 (lane C)** `.claude/skills/catalog-audit/SKILL.md:37` and `scripts/detect-container-runtime.sh:101-103`: on macOS, the prescribed runtime detection runs `colima start` when Colima is stopped. That is a host state change during an audit that promises not to mutate the host. The detector already behaved this way before the phase. The SKILL's new call is what makes it part of the audit.
  Fix: give the detector a probe-only mode and use it from the SKILL, or say in the SKILL that the user must confirm before Colima starts.
- **M-14 (lane B)** `installer/registry.toml:1574-1577`: the comment says an OpenCode 1 receipt that was upgraded outside the installer stays without `opencode2` "until an installer update rewrites the receipt". The lane says an update does not fix it: `preexisting_paths` (`receipts.py:563`) snapshots the shim that already exists, and `record` does not claim it. The receipt then never proves `opencode2`, and removal skips the `service stop` recipe. The orchestrator did not trace `_proven_before` to the end. At minimum, the comment overstates what an update fixes.
  Fix: check `_proven_before`. Either correct the comment to say the limit is permanent, or let a v2 re-run claim the shim it overwrites.
- **M-15 (lane B)** `installer/postinstall.py:217`: the Pi gate gets `which("codegraph")`. When codegraph sits in the managed bin directory but that directory is not on PATH, the binary is `None`, the gate drops `pi` without probing, and no Pi registration is offered.
  Fix: resolve the gate's binary the same way registration resolves it, from the receipt-proven or managed path.

## LOW

The directory is gitignored, sits inside the developer's own checkout, and every other target uses the same `ensure_phase_dir` pattern. Exploiting it needs a symlink planted in the checkout.

- **L-02 (lane C, reported HIGH)** `scripts/container-e2e-verify.sh:2688,2711-2715`: the fixed container name and the teardown `rmi fedora:latest` (without `-f`) follow the per-target convention of the script. Podman refuses `rmi` while another container uses the image, and the comment says so. All the teardown can lose is a cached image that can be pulled again. It destroys no user data.
  Fix (optional): skip the `rmi` when the image existed before the run.
- **L-03 (lane B)** `installer/agent_settings.py:898-919` (`_retired_block`): when the ledger owns the retired `permission` and the user has also added a `permissions` array, `permissions` is reported as `already` with the installer's allow-all value. The user's array is kept, and only the label is wrong.
  Fix: look at a current key that exists before letting the retired key classify the group.
- **L-04 (orchestrator)** `installer/catalog_audit.py:1112,1155-1161`: `_CONTAINER_RE` (`container: \S+`) accepts any token as runtime evidence. The transcript path is never checked to exist, so `container: yes` lifts an `unknown` to `ok`.
  Fix: require a path to an existing file under the run directory or `.e2e-artifacts/`.
