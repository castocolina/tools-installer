# Phase 24.3 Plan 01: npm latest-version source Summary

An installer-owned script tool that declares `latest_npm = "<package>"` now shows that package's npm `latest` dist-tag in the catalog (`source="npm"`), read through an explicit `resolve_npm` seam that is budgeted, cached and backed off exactly like the GitHub source, while every GitHub download seam is unchanged.

## What was built

- `installer/versions.py`: `NPM_PACKAGE_RE` and `resolve_npm_latest(package, fetch=urlopen_fetch)`. An invalid name raises `VersionError` before any fetch; the URL is `https://registry.npmjs.org/-/package/<quote(package, safe="@")>/dist-tags`; fetch errors, non-JSON, non-object, and a missing, empty or non-string `latest` all raise `VersionError` naming the package.
- `installer/model.py`: `latest_npm` in `METHOD_PARAMS["script"]`, validated with the shared regex (`tool '<id>': method 'script' key 'latest_npm' must be an npm package name such as @scope/name`). It is an unknown key on every other kind.
- `installer/version_status.py`: `npm_package`, `_latest_status` (the old `resolve_github_release_status` body, parameterised by `read_release` and `source`; the old function is a thin wrapper with its signature unchanged), the npm branch in `resolve_status`, `resolve_npm` on `VersionRefreshService`, and `npm_package` in the refresh loop's `would_fetch` so npm reads count toward `MAX_FETCHES_PER_REFRESH`.
