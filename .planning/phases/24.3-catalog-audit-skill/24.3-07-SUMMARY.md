# Phase 24.3 Plan 07: OpenCode 2 permissions rule Summary

OpenCode's auto-approve tuning now writes the v2 `permissions` allow-all rule array, the deprecated `permission` key stays in a `RETIRED_KEYS` revert table, and a pre-24.3 recorded `permission` reads as already tuned while a user's own value is never touched.

## Commits

- `bac1682e` feat(24.3-07): write OpenCode 2's permissions rule and keep reverting the retired key
- `53d2438a` feat(24.3-07): recognise the retired permission key as ours or the user's

## What changed

- `_KEYS[("opencode", "auto-approve")]` writes `permissions = [{"action": "*", "resource": "*", "effect": "allow"}]`; group name unchanged.
- `RETIRED_KEYS` (next to `DYNAMIC_KEYS`) holds `permission = "allow"`; `_revert_file` merges it into its revert table, so old ledger entries still revert.
- `_retired_block(agent, setting, doc, ours)`: a retired key present in the file skips the group's current keys; result `already` when the ledger records it with the file's value, otherwise `set_by_you`. `_apply_once` passes its skip paths next to `recorded` and prepends its results.
- `setting_facts`: a present retired key reports no absent key for the group (no `≈`).
- Pins migrated: `permissions` rule at the two jsonc pins, a root-anchored user key in the revert test, `("permissions",)` in the ledger summary, the `cannot remove permissions` line, and the tweaks alias notice.
