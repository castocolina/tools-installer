## Accomplishments

- The opencode script method points at `https://opencode.ai/v2/install` with `paths` for both `opencode` and `opencode2`, and has no `update` key (an update re-runs the v2 script).
- opencode's `remove` recipe `opencode2 service stop` is bound by `_recipe_argv` to the receipt-proven `opencode2` leaf: a v2 receipt runs it before deletion, and a pre-24.3 OpenCode 1 receipt skips it.
- opencode reads its latest version from npm `@opencode/cli` (`latest_npm`), so the catalog cannot show GitHub's v1.19.5 as latest; the brew method moves to homebrew/core `opencode`.
- Pi's `desc` and `# Verified` text describe built-in MCP, `pi mcp`, `pi update`, the vendor installer's sudo use and the Node 22.19.0 floor; its method stays the pnpm host-setup handoff.

- drawio-desktop's two macOS `app` pins move from 32.6.1 to 32.6.10 with new sha256 digests, produced by `make verify-registry --write` against a scratch copy and ported as the drawio block only.

## Decisions Made

- The recipe head is the v2-only `opencode2` shim, so `_recipe_argv` binds it only when a receipt proves that leaf. This is the smallest form that keeps an OpenCode 1 removal from running `service stop` on v1.19.5, which has no `service` command (CONTEXT D-08 amendment, review R1-03).
- No new removal mechanism was added; the existing L3 recipe path carries the change.
- The tap formula stays brew-owned on 1.19.5 on a host that holds it; the ownership code reads a tap formula by its last segment. Recorded in the `# Verified` block as a limit, not fixed here.
- A user who upgraded OpenCode 1 to 2 outside the installer keeps a receipt without `opencode2`, so the recipe is skipped there until an installer update rewrites the receipt. Recorded as a limit.
- v2's own `uninstall` is not used: it deletes `~/.cache/opencode` and may edit shell rc files.
- Pi's method change is not made here (Backlog 999.13); codegraph's copilot target and Pi gate are implemented by 24.3-08, and this plan only documents them.
