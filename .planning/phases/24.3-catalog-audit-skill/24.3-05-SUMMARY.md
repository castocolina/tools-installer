## Deviations from Plan

**1. Container granularity: one pass per distro instead of one container per entry**
- **Found during:** Task 2 step 7
- **Issue:** the plan calls for one disposable container per flagged entry.
- **Fix:** one `all` pass per distro (fedora, debian, arch), run against the untouched registry, which covers install, rerun, uninstall, leftover and reinstall for every Linux entry in the 6 h budget. Each pass ran in a fresh container that was removed afterwards.
- **Impact:** the per-entry isolation the plan asked for is replaced by per-distro isolation. The transcripts are split across `pass1` (clean install marker and exit) and `pass2` (rerun through teardown markers) per distro. Container ok findings were recorded against the same keys, so the merge rule in 24.3-03 still applies.

**2. Imperfections recorded, not fixed**
- Complete reports are immutable, so these stay as written; none changes a verdict:
  - wrong citation line numbers in `jq`, `fd`, `brew`, `springbootcli`, `codegraph` and `drawio-desktop` (verdicts unaffected);
  - two unverified claims in `hyperfine` and `bottom`.
- The java, groovy, springbootcli and gradle removal rows describe SDKMAN's designed handoff (the installer prints `sdk uninstall <candidate> <version>`). The user pointed out that SDKMAN can uninstall. These rows will be dispositioned as no change in 24.3-11.

**Total deviations:** 1 structural (container granularity) and 2 recorded imperfections.
**Impact on plan:** the first run is complete and committed; the deviation does not weaken the R5 host-safety claim, which rests on the fingerprint comparison and the clean `git status`.
