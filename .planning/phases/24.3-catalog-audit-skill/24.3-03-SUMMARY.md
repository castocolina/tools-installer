# Phase 24.3 Plan 03: verify record, script scan, late findings and the disposition-gated summary Summary

`python -m installer.catalog_audit` now closes out a run directory: `verify` records one verify-registry run against a scratch `--state`, `scan` flags mechanical unsafe patterns (elevation heads, `--target auto|all`, stray hook target keys, argv-rewriting shim `exec` lines including f-string templates, deprecated or disallowed tuning keys against a vendor schema), `add-finding` appends validated late findings, and `summarize` rebuilds `SUMMARY.md` deterministically from reports, `scripts.md`, `verify-registry.md`, `findings.toml` and a committed `dispositions.toml`, with `--require-disposition` gating the landing set.

## What was built

- `verify` (D-03, T-24.3-09): `--state` is mandatory; refused with exit 64 when it resolves to verify-registry's default HOME state (also through a symlink), lies inside the checkout (`--repo`, default the checkout) or names an existing non-JSON file. A warm HOME state is copied (read-only on HOME) to an absent scratch path first. `verify_registry.main` (injectable `verify_main`) runs once with `["--state", PATH]`, stdout captured, written whole to `verify-registry.md` as `# verify-registry - <date>`, `exit: <code>`, blank line, report (home shown as `~`). Exit 0: the recorded code is data.
- `scan` (SPEC R3, T-24.3-10/11): Python surfaces parsed by `ast` (docstrings skipped, f-strings rendered with `{…}` placeholders); shell surfaces by command position with quoted words blanked. Rows `| path[:line] | entry | ok|finding | pattern |`, sorted by path then line, entry named per surface (`(installer)`, `(maintainer)`, `cursor-agent`, a `_KEYS` agent, the tools whose `postinstall` names the hook). Patterns carry a backticked token that is a literal fragment of the cited line, so the stale check can find it. `--schema AGENT=PATH` walks `_KEYS` rows through `properties` (local `$ref`s, bounded) and prints only the part and the verdict, never a value or default.
- `add-finding` + `findings.toml` (R1-05, R2-03/04): validated row (registry id, or `(installer)`/`(maintainer)` for `script`; check in `CHECKS` or `script`; `cite` for `script` only; cited `ok`/`drift` source or `container: <path>`; `reason: ` for `unknown`; secret, absolute-home and control-character guards), appended by whole-file atomic rewrite; every refusal exits 73 and leaves the file byte-identical.
- `summarize` (R3, R4, R10, D-04 amended): header (`complete k/N`, `missing`, `orphan`), `## Proposed changes` (or `no proposed changes`), `## Drift` (entry, check, status, source, disposition), `## Entries` (per entry: check, merged status, report value, findings in file order), `## verify-registry`, `## Script scan`, `## Script findings` (`location | entry | status | pattern | state | disposition`, `current`, `stale` or `stale (resolved by <disposition>)`). Merge rule (R2-03, R3-02): key is (entry, check[, cite]); `drift` sticky from any of report, `findings.toml`, `scripts.md`; `unknown` becomes `ok` only through a same-key `container:` `ok`; a later `unknown` never lowers an `ok`. `dispositions.toml` is validated (exit 73, one stderr line per problem, `SUMMARY.md` untouched). `--require-disposition IDS` exits 1 naming each unmapped key of those entries over the union of drift sources.
- `main` gained the keyword-only `verify_main` seam.

## Deviations from Plan

**1. [Rule 3 - Blocking] `codegraph sync` run once, `codegraph explore` not**
- The plan's first executor rule says start with `codegraph sync`, while its own never-mutate rule forbids any `codegraph` command, and the global instructions ask for `sync` in indexed repos. I ran `codegraph sync` once (it only refreshes the worktree's own `.codegraph/` index, which is untracked) and read the code directly with Read/grep instead of `explore`.

**2. [Plan wording] stale citation and script findings landed across Tasks 2 and 3**
- `summarize` needs the stale check to honour the Task 2 f-string test (`summarize` right after the scan reads both findings as current), so the `## Script findings` section with `current`/`stale` arrived in Task 2 and gained the disposition column and the findings.toml and report-row merge in Task 3. Task 1's `summarize` had no `repo` argument (vulture flags an unused argument at 100% confidence); it was added in Task 2.

**3. [Rule 1 - Bug found by the offline f-string test] a formatted value ending in a newline hides the `exec` line**
- `guards.py`'s npx template is `f"...{_NPX_TRANSLATE}" f'exec {...} {...} "$@"\n'`; the render is `{…}exec {…} {…} "$@"`, so a plain "line starts with `exec `" test missed the shim at `installer/guards.py:218`. Leading placeholders are now stripped before the test.

**4. [Plan wording] extra surface and CLI details**
- `verify` also takes `--repo` (default: the checkout) so the "inside the repo" refusal is testable. `summarize` takes `home=None` (the process home, for re-running the findings hygiene). The gate is the separate `unmapped_drift`, not part of `summarize`'s return value, so `summarize` keeps its `-> str` signature.
- On the shipped tree the scan also reports `installer/guards.py:260` (`exec {…} "$@"`, placeholder as the command) and `:333` (`exec {…} install "$@"`) next to the two designed rewrites the plan names (`guards.py:218`, `cursor_shim.py:65`); both are real "placeholder as the command / extra word" rewrites by the plan's rule and are left for the audit loop to judge.

**5. [Rule 2 - hardening] `--require-disposition` refuses an unknown id**
- An id that is neither a registry id nor `(installer)`/`(maintainer)` exits 64: a typo such as `opencde` would otherwise silently gate nothing.
