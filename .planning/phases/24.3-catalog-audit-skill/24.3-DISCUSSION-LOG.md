## Live facts that changed the plan

- **The registry still installs OpenCode 1.** `https://opencode.ai/install` is v1-only and points to `https://opencode.ai/v2/install`, which also writes `~/.opencode/bin/opencode2`. GitHub `releases/latest` = v1.19.5, while v2.2.6 is newest. npm `@opencode/cli` latest = 2.2.6. (SPEC R6, D-07, D-10)
- **v2 deprecates `permission`.** `permissions` is a rule array, and allow-all is `{"action":"*","resource":"*","effect":"allow"}` (schema and v2 docs). (SPEC R7, D-11)
- **v2 runs a background `opencode serve --service`** parented by `systemd --user`, with no unit file. (D-08)
- **The Homebrew tap's `opencode` formula is 1.19.5.** Core `opencode` is 2.2.6. (D-09, SPEC R6 amended)
- **codegraph 1.6.2 has no `pi` target.** `main` has one (`~/.pi/agent/mcp.json`, `exposure: "direct"`, `AGENTS.md` block). (SPEC R8, D-12)
- **Pi 1.3.0 has built-in MCP (since 0.99.0) and `pi update`.** Its README leads with `pi.dev/install.sh`. The host's Pi is a bun global install. (D-14, 999.13; 24.2 D-16 amended)
- **verify-registry writes its state into HOME by default.** (SPEC Background amended, D-03)
- **The installer-owner latest-version branch reads only `github_release` methods**, so an installer-owned script tool shows no latest version today. (SPEC R6 amended, D-10)
