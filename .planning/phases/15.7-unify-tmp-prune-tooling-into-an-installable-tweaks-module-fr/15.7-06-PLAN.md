Write tests FIRST in tests/test_doctor.py.

- `run_doctor` called without the new closure produces byte-identical output to today — pinned
  so existing callers and tests are provably unaffected.
- `run_doctor` given a closure reporting an inactive daemon and a filesystem below the free-space
  threshold prints the finding's title, and the rendered text carries the emphasised style.
- The same call with a healthy filesystem prints nothing extra.
- A closure that raises OSError leaves `run_doctor` completing normally with no disk section,
  rather than aborting the report — the Doctor view is diagnostic and must not be the thing that
  breaks.
- On a macOS-shaped platform the /tmp threshold is not consulted: a /tmp at 95% used with ample
  root free space produces no finding.
  </behavior>
  <action>
In `installer/app.py`, add a `disk_pressure` parameter to `run_doctor`, typed as an optional
zero-argument callable returning a `DiskPressure`, defaulting to None. When it is None, render
exactly what is rendered today — that default is what keeps every existing caller and test
untouched. When it is given, call it inside a guard that swallows OSError and yields no section
on failure, pass the result to `disk_pressure_guidance`, and print the items through the same
`guidance_text` path every other Doctor finding already uses, so the emphasis style reaches the
console with no second render path.

Do NOT widen `doctor_data`'s return tuple: it is destructured positionally at several call sites
and a fourth element would ripple for no benefit. The disk probe is a separate, independently
optional input.

In `setup.py`, build the probe closure once and pass it at every `run_doctor` call site. The
closure composes `diskusage.probe_disk_pressure` with: the daemon-active answer taken from the
policy `_build_daemon_policy` returns (its live `is_active` when present, its `active` field
otherwise, and False when no daemon policy exists for this platform), and a `check_tmp` flag
that is True only when the detected platform is not macOS — the /tmp rule is the Linux
tmpfs-quota case D-03 names, and deriving the flag here keeps the branch in the composition root
rather than inside the pure layer.
  </action>

  </verify>
