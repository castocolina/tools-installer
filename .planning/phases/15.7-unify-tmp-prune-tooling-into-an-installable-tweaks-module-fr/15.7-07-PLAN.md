<objective>
Collapse the duplicated halves of the two prune scripts onto one shared, shellcheck-clean core,
behind characterization tests that prove the macOS script's behavior did not move.

Purpose: the source todo's explicit engineering requirement — "don't just copy-paste ai-kit's
Linux scripts and `prune-user-tmpdir.sh`'s macOS logic side by side — build a single
cross-platform module ... rather than one script per OS with duplicated logic". Plan 15.7-01
delivers a working Linux script; this plan is what stops the phase from shipping the very
side-by-side duplication its own source rejects (review MEDIUM 15.7-01).

Output: `scripts/lib/prune-tmp-common.sh`, both platform scripts reduced to wrappers over it, a
new characterization suite for the macOS script, and a widened `make validate` shellcheck gate.

**Why this is its own plan rather than a fourth task in 15.7-01 (resolved during replanning round
2).** `scripts/prune-user-tmpdir.sh` is 266 lines, has no test of its own today, and is the
executable the SHIPPED macOS daemon already invokes on a schedule. Refactoring it is the riskiest
single change in this phase. Plan 15.7-01 is the phase's tracer: putting this on the tracer's
critical path would mean the end-to-end Linux path could not land until the macOS script had been
rewritten. Splitting it out keeps the risk isolated, lets the characterization tests come first,
and costs only a wave.

**Decision D-01d — share the engine, parameterise the patterns (resolved during replanning).**
The reviewer's suggestion was to extract "shared filename matching, safety checks, and summary
output into one reusable implementation". Two of those three are unconditionally shareable and are
shared here. Filename MATCHING is shared as a mechanism but not as data: the Linux target is one
regex family (`.{16 hex}-{8 digit}.{so,node}`), while the macOS target set is four unrelated
families including two directory shapes. Forcing both into one pattern expression would produce a
parameter that is really just "the whole matching rule", which is duplication wearing an
abstraction. So the core owns the traversal, the depth limit, the age filter, the refusal guard,
the age validation, the human-readable byte formatting and the summary emission; each wrapper owns
its own pattern set, its own default age and its own help text. That is one implementation of every
piece of LOGIC, with the per-platform DATA where it belongs.
</objective>
