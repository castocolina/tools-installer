# Phase 15.7 Plan 04: Cache Redirect Summary

**Reusable cache-redirect mechanism with Bun's `BUN_RUNTIME_TRANSPILER_CACHE_PATH` pointed at `~/.cache/bun/transpiler-cache`, written as an environment.d conf on Linux and an exported rc block on macOS, toggled by one Policy.**

## Accomplishments

- One `CacheRedirect` declaration drives both platform writers. The Bun entry's target is exactly `<home>/.cache/bun/transpiler-cache`, pinned by resolved path and by its three home-relative components.
- The macOS block exports the variable, so Bun's child process inherits it; the conf file stays a bare assignment because systemd's grammar has no `export`. A test named for the asymmetry pins both lines.
- `linux_applied` and `remove_linux_redirect` share one ownership predicate, so nothing can read active that the remover would refuse to remove. Both predicates ignore `os.environ`.
- `cache_redirect_policy` reports a competing environment.d file and leaves it on disk, and its Linux reload hint says the change takes effect at the next login.
- The declaration's coverage caveat — the redirect only reaches invocations that inherit the variable, and the daemon remains the fallback — is composed verbatim into the Policy description.

## Decisions Made

- `write_linux_redirect` refuses to overwrite a same-named file lacking the ownership sentinel. The closing review deferred this as a known limitation and asked for it only if it fell out cheaply; the shared predicate made it a three-line check, so it is in.
- The Linux reload hint does not mention a shell at all. The plan said it must not imply a new shell is sufficient; stating only the next-login requirement is the stricter reading.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing Critical] Apply-time refusal for a foreign conf file**
- **Found during:** Task 1 (the redirect writers)
- **Issue:** The plan required the remover to refuse a same-named file without the sentinel, but not the writer. Overwriting such a file would destroy another tool's content that the remover would then decline to restore.
- **Fix:** `write_linux_redirect` raises `OSError` and writes nothing when the target exists and lacks the sentinel, using the same `_owned` predicate as removal.
- **Files modified:** installer/env_redirect.py
- **Verification:** the refusal is the same predicate `test_unowned_same_named_file_is_neither_applied_nor_removable` exercises on the removal side; `make test` passes.
- **Committed in:** `2e9cdbe`
