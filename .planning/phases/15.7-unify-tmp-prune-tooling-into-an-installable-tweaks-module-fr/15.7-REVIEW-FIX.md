## Fixed

### CR-01 — uninstall skipped an installed-but-inactive Linux timer
**Commit:** `76fe655`
**Files:** `installer/policy.py`, `installer/systemd_daemon.py`, `installer/uninstall.py`,
`installer/app.py`, `installer/wizard_app.py`

- `Policy` gained an appended optional `owned` footprint predicate; the Linux policy binds
  it to "either unit file, the `timers.target.wants` symlink, or the owned wrapper is on
  disk". `uninstall.policy_owned` (renamed from `_reads_active`) prefers it, so the sweep
  answers "is this ours", not "is it running" — and it spawns no systemctl at all.
- `bootout` no longer re-raises merely because the unit files exist: it re-raises only when
  the timer is provably ACTIVE, and returns whether the user manager was reached.
- `remove_units` also removes the enablement symlink, so an unreachable manager cannot leave
  something that restarts the timer at the next login.
- With the manager unreachable, `remove()` deletes the owned files and warns that
  `daemon-reload` could not run. `SweepResult` now carries per-policy warnings; both the CLI
  (`run_uninstall`) and the TUI uninstall summary print them, so success is never reported
  silently over an incomplete teardown. A provably-running timer that cannot be disabled
  still fails the sweep and keeps the decided marker.
- Tests: `tests/test_app.py::test_run_uninstall_removes_an_installed_but_not_running_linux_timer`
  (parametrized inactive/unreachable, against a fake user manager that really creates and
  removes the wants symlink), `..._keeps_the_linux_marker_when_a_running_timer_cannot_be_disabled`,
  plus four `tests/test_systemd_daemon.py` unit tests.
- Mutation-verified twice: dropping `owned=` and restoring the old `units_present` re-raise
  each make the new tests fail.

disclosure instead of `warning is None`. Mutation-verified.

### WR-01 + IN-05 + IN-04 — exact Linux daemon rollbacks
**Commit:** `e0ddd59` · **Files:** `installer/policy.py`, `installer/systemd_daemon.py`

- Apply rollback runs a best-effort `systemctl --user disable <timer>` before deleting the
  units and removes a wants symlink it created, so a `restart` failure after a successful
  `enable` no longer leaves a dangling link the user manager complains about at each login.
- Remove rollback snapshots the unit bytes before `bootout` and restores them before any
  re-bootstrap, so a failed timer unlink can no longer re-enable a timer whose service file
  was already deleted.
- IN-05: `_restore_units` now returns the directory to exactly the snapshot (prior bytes
  rewritten, only newly created files deleted), so a first apply over a half-removed install
  keeps the pre-existing unit file.
- IN-04: the three rollback restores call the public `installer.atomic.atomic_write_bytes`;
  all `# pyright: ignore[reportPrivateUsage]` suppressions in `policy.py` are gone.

### WR-05 + WR-06 — honest environment.d precedence and ownership
**Commit:** `093ba7a` · **Files:** `installer/env_redirect.py`, `installer/policy.py`, `setup.py`

Precedence is computed, not asserted: a competing file sorting before ours is reported as
overridden, one sorting after as overriding this redirect. The scan covers the read-only
system environment.d directories systemd merges (masking a basename already seen in a
higher-priority directory, as systemd does) and matches an indented assignment. An
unreadable, non-UTF-8 or dangling same-named file is refused instead of being overwritten.

`wizard_app._applied_summary` still emits the "log out and back in" line only when BOTH the

wording finding justifies inside this fix pass.

### IN-08 (a `--global`-enabled user unit may not stay disabled)
The reviewer explicitly marked this **unverified** — confirming it requires mutating a real
systemd installation, which this pass is forbidden to do (and which the zero-sudo invariant
makes untestable here for the `/etc/systemd/user` + `--global` case). The proposed fix
(re-run `is-enabled` after disabling and report the unit as failed with
`sudo systemctl --global disable` wording) would add a user-facing claim about behaviour that
has not been observed on any host. Left for a session that can verify it live; the existing
disclosures (CR-02's takeover line and the user-scope failure warning) already tell the user
which unit was touched and how to undo it.
