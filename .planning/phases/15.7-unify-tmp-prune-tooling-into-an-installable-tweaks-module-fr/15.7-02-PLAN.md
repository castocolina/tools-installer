<objective>
Build D-03's disk-pressure detection and wording as a pure, IO-injected layer: a probe module,
a guidance function covering every threshold combination, and one render-layer emphasis
mechanism.

Purpose: D-03 — a red Doctor warning when the cleanup daemon is inactive AND free disk is below
15% (or, on Linux, /tmp usage is above 70%), with extra visual weight when the daemon-inactive
and low-space conditions coincide.

Output: `installer/diskusage.py`, a `disk_pressure_guidance` function in `installer/guidance.py`,
and an `emphasis` flag on `Guidance` honoured by `render.guidance_text`.

**Decision D-03a — low space with the daemon RUNNING is reported as an ordinary warning
(resolved during replanning; review MEDIUM 15.7-02).** D-03 asks for a red finding on the
daemon-inactive AND low-space conjunction, with "extra visual weight when both are true at once".
Reporting nothing at all when the daemon is running would hide a genuinely nearly-full disk from
`make doctor`, whose whole job is to report what it measured; reporting it at the same red weight
would make the emphasis meaningless. So: low space alone is a plain `warn`, the conjunction is an
emphasised `error`, and no pressure is silence. This is a product decision, not an implementation
detail — it is stated here so a later reader does not have to infer it from a test.

**Decision D-03b — one total probe contract (resolved during replanning; review LOW 15.7-02).**
`probe_disk_pressure` never raises. Every mount read is guarded inside it, and an unreadable or
degenerate mount becomes a None percentage on the returned report. Callers therefore do not each
invent their own exception guard set — plan 15.7-06's render-path guards remain, but as a second,
defence-in-depth layer over a probe that is already total, exactly the way
`installer/wizard_app.py` already double-guards `last_run_summary`. One contract, stated once.
</objective>

Create `installer/diskusage.py`: a pure module whose only IO is an injected callable defaulting
to `shutil.disk_usage`, so every test drives it without touching a real filesystem and pyright
strict mode covers it (architecture rule 4 keeps this out of setup.py for exactly that reason).

Declare `DISK_FREE_WARN_PERCENT` and `TMP_USED_WARN_PERCENT` as named module constants carrying
their D-03 values, with a comment recording that these are deliberately more conservative than
the source todo's original numbers and why (fewer false positives on machines with plenty of
free space where the daemon simply is not running yet).

Declare a frozen `DiskPressure` dataclass holding the root free percentage, the tmp used
percentage (both `float | None`, where None means the probe could not read that mount), and the
daemon-active boolean. Give it read-only properties `low_disk`, `high_tmp`, `under_pressure` and
`at_risk` implementing the comparisons above; a None percentage never satisfies a threshold.

Implement `probe_disk_pressure` taking the daemon-active boolean, a `check_tmp` boolean, the two
paths to sample, and the injected usage callable. Read each mount inside its own guarded
conversion that returns None on OSError, on ValueError or TypeError from a malformed result, and
on a zero total, so one unreadable mount never suppresses the other and never propagates out of a
function the Doctor view calls on every render. Skip the tmp read entirely when `check_tmp` is
False.

Make D-03b explicit in the function's own docstring: this function is TOTAL over mount-read
failure — it returns a report for every readable-or-unreadable mount and raises for none. Say
why, naming the alternative it replaces: the callers are
a console report, a TUI screen refresh and a row-highlight handler, and leaving each of them to
guess which exception set to guard is how three different guard tuples end up in three files and
one of them ends up wrong (review LOW 15.7-02). Catch the concrete exception types named above,
not a bare `Exception`, so a genuine programming error inside this module still surfaces.
