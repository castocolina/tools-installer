<objective>
Build D-03's disk-pressure detection and wording as a pure, IO-injected layer: a probe module,
a guidance function covering every threshold combination, and one render-layer emphasis
mechanism.

Purpose: D-03 — a red Doctor warning when the cleanup daemon is inactive AND free disk is below
15% (or, on Linux, /tmp usage is above 70%), with extra visual weight when the daemon-inactive
and low-space conditions coincide.

Output: `installer/diskusage.py`, a `disk_pressure_guidance` function in `installer/guidance.py`,
and an `emphasis` flag on `Guidance` honoured by `render.guidance_text`.
</objective>

Write tests FIRST in tests/test_diskusage.py; every one must fail before the module exists.

- `DISK_FREE_WARN_PERCENT` is 15 and `TMP_USED_WARN_PERCENT` is 70 — asserted by value, because
  D-03 deliberately chose these over the source todo's original 30 and 50.
- `probe_disk_pressure` with an injected usage callable returning a filesystem that is 90% free
  reports `low_disk` False; at exactly 15% free it reports False (the threshold is "below 15%",
  not "at or below"); at 14.9% free it reports True.
- With `check_tmp` False (the macOS case), a /tmp at 95% used reports `high_tmp` False and the
  tmp percentage is None — the /tmp rule is the Linux tmpfs-quota case only.
- With `check_tmp` True, /tmp at exactly 70% used reports False and at 70.1% reports True.
- An injected usage callable that raises OSError for the root path yields a report whose root
  percentage is None and whose `low_disk` is False, and the same independently for the tmp path
  — an unreadable mount is "unknown", never a warning and never an exception.
- `under_pressure` is `low_disk or high_tmp`; `at_risk` is `under_pressure and not daemon_active`.
- A zero-total filesystem (a degenerate mount) yields None rather than a division error.
  </behavior>
  <action>
Create `installer/diskusage.py`: a pure module whose only IO is an injected callable defaulting
to `shutil.disk_usage`, so every test drives it without touching a real filesystem and pyright
strict mode covers it (architecture rule 4 keeps this out of setup.py for exactly that reason).

Declare `DISK_FREE_WARN_PERCENT` and `TMP_USED_WARN_PERCENT` as named module constants carrying
their D-03 values, with a comment recording that these are deliberately more conservative than
the source todo's original numbers and why (fewer false positives on machines with plenty of
free space where the daemon simply is not running yet).

Declare a frozen `DiskPressure` dataclass holding the root free percentage, the tmp used
percentage (both `float | None`, where None means the probe could not read that mount), and the
daemon-active boolean. Give it read-only properties `low_disk`, `high_tmp`, `under_pressure` and
`at_risk` implementing the comparisons above; a None percentage never satisfies a threshold.

Implement `probe_disk_pressure` taking the daemon-active boolean, a `check_tmp` boolean, the two
paths to sample, and the injected usage callable. Read each mount inside its own guarded
conversion that returns None on OSError or on a zero total, so one unreadable mount never
suppresses the other and never propagates out of a function the Doctor view calls on every
render. Skip the tmp read entirely when `check_tmp` is False.
  </action>

  </verify>

tests, and the module performs no IO except through its injected callable.
  </done>

- Daemon inactive + /tmp above the threshold (Linux): one item, severity error, `emphasis` True,

  severity error, `emphasis` True, and its meaning names both measurements.
