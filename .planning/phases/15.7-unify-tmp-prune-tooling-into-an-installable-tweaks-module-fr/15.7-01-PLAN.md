- A first-ever apply whose enable call fails leaves NO unit file, NO wrapper and NO log file
  behind when none of the three existed before, and re-raises.
- A first-ever apply whose write half fails (simulated by making the unit directory
  unwritable) still removes a wrapper that this call created, and leaves one that predated the
  call alone.
- A re-apply whose restart call fails restores the PREVIOUS unit-file bytes and makes a
  best-effort re-bootstrap, so `is_active()` is not left as a false positive.
- A remove whose disable call fails leaves the unit files in place and re-raises, so the
  caller can never treat the daemon as removed while it may still be registered.
- A remove whose unit-file unlink fails makes a best-effort re-bootstrap and re-raises.
- A successful apply whose marker write fails returns a PolicyResult with a non-None warning
  naming the failure, and does NOT roll back the registration.
- The marker write is retried once after a failure before giving up, on both apply and remove.
- After apply, `installer.systemd_daemon.decided(state_path)` is True and
  `installer.daemon.decided(state_path)` is False on that same file.

  <action>
Rewrite `linux_daemon_policy`'s `_apply` and `_remove` to carry the identical transactional
envelope `daemon_policy` already proved. `_apply` snapshots, before any mutation: the prior
bytes of each unit file (or their absence), whether the wrapper was already present, and
whether the log file already existed. It then performs validate-and-write plus bootstrap inside
one try, catching (CommandError, OSError) — DaemonScheduleError is an OSError subclass raised by
the pure validation half before any write, so catching OSError here is safe and the rollback is
a no-op against artifacts that were never created. On failure: when a prior registration
existed, restore the snapshotted unit bytes through an atomic write and make a best-effort
re-bootstrap, suppressing CommandError on that recovery call; when this was a first-ever apply,
unlink the unit files, remove the wrapper only if it did not pre-exist, and unlink the log only
if it did not pre-exist. Re-raise in both cases. The rollback must cover the write half, not
only the systemctl half — the macOS equivalent's CR-01 comment explains exactly why an
orphaned wrapper left by a failed first apply is the bug this guards.

`_remove` calls bootout first and lets a real CommandError propagate; then unlinks the unit
files inside a try that, on OSError, makes a best-effort re-bootstrap before re-raising, so a
failed teardown never reports success while the timer is still enabled. Wrapper removal and the
marker write each degrade to a collected warning string rather than aborting the teardown,
joined into PolicyResult.warning exactly as `daemon_policy._remove` already does.

Generalise `_record_decided_durably` so it takes the zero-argument recording callable instead of
hardcoding `daemon.record_decided`, keep its existing docstring rationale, and have both the
macOS and the Linux factory pass their own module's recorder. This keeps one retry policy for
both daemons rather than a second copy.

Add `scripts/prune-tmp-linux.sh` to the Makefile validate target's shellcheck invocation, beside
the existing install.sh argument, so the new shell artifact is covered by the same gate every
other shell file this project owns goes through. Leave the pre-existing
scripts/prune-user-tmpdir.sh out of that change: widening the gate to a file this phase does not
touch is a separate concern.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| this process -> systemd user manager | argv this module builds crosses into the user's init system via `systemctl --user` |
| this process -> unit files on disk | text this module renders is later parsed and executed by systemd as root-less but privileged-to-the-user configuration |
| scheduled service -> user temp directory | the oneshot service deletes files under the temp root on a timer, unattended |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-15.7-01 | Tampering | `systemd_daemon.render_service` | high | mitigate | Every rendered value is double-quoted and validated to reject `"`, `\`, `%`, newline and carriage return before any write; `%` specifically because systemd expands `%`-specifiers inside unit values, so an unvalidated path could resolve to a different target than intended |
| T-15.7-02 | Tampering | `systemd_daemon.write_units` | medium | mitigate | Unit files are written through `installer.atomic.atomic_write_bytes` at an explicit mode 0o644, so a crash or full disk mid-write cannot leave a truncated unit that systemd silently re-reads on the next daemon-reload |
| T-15.7-03 | Tampering | wrapper executable install path | medium | mitigate | Reuses `installer.daemon.install_wrapper`, whose sentinel ownership check refuses to overwrite a same-named file this project does not own |
| T-15.7-04 | Elevation of Privilege | every systemctl call | high | mitigate | Every argv this module builds is `systemctl --user ...`; the module imports no `subprocess` and issues no privilege-escalation command, preserving this project's userspace-only install model |
| T-15.7-05 | Denial of Service | `scripts/prune-tmp-linux.sh` | high | mitigate | The broad-path refusal case guard ported from `prune-user-tmpdir.sh` rejects `/`, `$HOME` and `/var` as temp roots; the regex matches only Bun's own leading-dot hex-dash-digit cache names at maxdepth 1; `-mmin +N` refuses to touch a file still being written |
| T-15.7-06 | Repudiation | scheduled run outcomes | low | accept | The wrapper's capped append-only log is the existing, already-shipped audit trail; no new record is warranted for a per-user cleanup job |
| T-15.7-SC | Tampering | npm/pip/cargo installs | high | mitigate | Not applicable to this plan: it introduces no package-manager install task and no new external dependency (RESEARCH "Package Legitimacy Audit": not applicable) |
</threat_model>
