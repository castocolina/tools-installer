# Phase 15.7 Gap Closure — the D-03 probe measured the wrong filesystem

Closes the single gap in `15.7-VERIFICATION.md` (status `gaps_found`, 61/63).
No other verification finding was reopened or touched.

## What the gap was

`setup.py:478` — `_DiskProbe.__call__` passed a hardcoded `Path("/")` as
`probe_disk_pressure`'s root free-space mount.

On an ostree/composefs host — Bazzite and Silverblue, the exact host class this
phase's ROADMAP entry, CONTEXT.md and RESEARCH.md name as the target, and the
machine this phase was verified on — `/` is not the user's disk. Ground truth
from this host:

```
Filesystem      Size  Used Avail Use% Mounted on
composefs        45M   45M     0 100% /
/dev/nvme0n1p9  806G  401G  402G  50% /var
/dev/nvme0n1p9  806G  401G  402G  50% /var/home
```

`/` is a ~45 MB read-only composefs overlay that is 100% used and 0 bytes free
**by construction**. So `DiskPressure.low_disk` was permanently True
(`0.0 < 15`), which with the daemon off made `at_risk` permanently True, which
made `disk_pressure_guidance` emit a `Severity.ERROR`, `emphasis=True` red
finding on **every** `make doctor` run and every Doctor-screen entry, forever,
on a machine with 402 GB free. Enabling the daemon never silenced it; it only
downgraded it to a permanent ordinary warning.

That inverted D-03's own stated rationale — the user chose 15%/70% over
30%/50% *specifically* to reduce false-positive noise — and falsified three
things verbatim:

| Falsified | Source |
|---|---|
| "An inactive daemon on a machine with plenty of space produces nothing at all" | 15.7-02 `must_haves.truths` (truth 5) |
| "A machine with healthy free space sees no new Doctor output at all, on either surface" | 15.7-06 `must_haves.truths` (truth 10) |
| "`make doctor` prints no disk finding on this host's healthy free space" | 15.7-06 `<human-check>` claim 6 |

The pure layer (`installer/diskusage.py`) was **not** at fault: it takes the
mount as a parameter and faithfully reports what it is handed. The defect was
entirely the composition root's choice of which mount to hand it.

## Why 2901 passing tests and 95.69% coverage missed it

The "healthy machine is silent" truth was only ever exercised at the pure
layer, with synthetic percentages injected through the `usage` callable. No
test ever asked the composition root **which mount it chose**, so any mount
choice — including a wrong one — passed the entire suite. The verifier
recorded this as `coincidental_reliance`: the low-space assertions passed, but
on an immutable host they passed for the wrong reason (the overlay is always
at 0%), and a passing assertion could not distinguish "correctly detected
pressure" from "measured the wrong filesystem".

## The decision, and why

**Chosen: resolve the mount from `Path.home()` — the filesystem holding the
user's home directory — on every platform.**

**Rejected: gate on `Platform.immutable` and measure `/var` there, `/`
elsewhere.**

The verification report suggested the `Platform.immutable` branch, and the
ingredient is already there (`installer/platform.py:23,52`, off the
`/run/ostree-booted` marker). The home-based rule was chosen instead because
it is strictly more robust and strictly less surprising:

1. **It needs nothing to exist.** The immutable branch has to name a writable
   mount — `/var` or `/sysroot` — and then answer "what if it is not a separate
   mount on this host?". Resolving a *path* (home) and letting the kernel map
   it to its containing filesystem has no such case: `statvfs` on home always
   lands on whatever filesystem actually holds it.
2. **It is the same measurement on a stock host.** On ordinary Linux and macOS
   home is under `/`, so this moves no number there — the change is a no-op on
   every host that was already correct. Pinned by
   `test_the_disk_probe_measures_the_root_mount_on_a_single_root_host`.
3. **It fixes a second, unreported false negative.** On a host with a separate
   `/home` partition, `/` can be roomy while the user's disk is full. The
   immutable-gated rule still reads `/` there and stays silent through a real
   emergency; the home-based rule warns.
4. **macOS has the same shape as ostree, in milder form.** `/` is a read-only
   signed system volume with the user's data on `/System/Volumes/Data`.
   "Measure `/` for the user's free space" is not a portable idea on *either*
   supported platform any more; "measure where the user's data lives" is.
5. **It measures the filesystem this installer actually fills.** Every artifact
   this project writes — `~/.local/opt`, `~/.local/bin`, `~/.cache` (including
   D-04's Bun transpiler-cache redirect target) — lives under home. The warning
   exists to predict exhaustion of the disk this tool consumes.
6. **No detection to keep correct.** Correctness no longer depends on a marker
   file being present, so a future atomic distro that boots differently cannot
   silently regress this.
7. **One notion of home in the composition root.** `Path.home()` is what every
   other path constant in `setup.py` is built from (`_MYSHELLRC`,
   `_DAEMON_PLIST_PATH`, `_LINUX_DAEMON_UNIT_DIR`, …), all resolved at import
   time — so by the time the probe runs it is already known to resolve, and no
   local fallback rule had to be invented for it.

D-03's own text says "general disk space is below 15% free" — it never said
"root". No decision was reversed or reinterpreted to make this fit.

### Naming and wording

Keeping a field called `root_free_percent` while it holds home's number is the
mismatch that made `Path("/")` look obviously right at the call site, so the
names were corrected with the behaviour, in the same commit (no intermediate
tree where an identifier contradicts what it holds):

| Before | After |
|---|---|
| `DiskPressure.root_free_percent` | `DiskPressure.home_free_percent` |
| `probe_disk_pressure(..., root_path, ...)` | `probe_disk_pressure(..., home_path, ...)` |
| `"Free space is at {x}%, below the 15% threshold."` | `"Free space on the filesystem holding your home directory is at {x}%, below the 15% threshold."` |
| `"Current root filesystem free space: {x}%"` | `"Current home filesystem free space: {x}%"` |

The pure layer's *contract* is unchanged — it still measures whatever path it
is handed and stays free of platform knowledge. Its docstring now records that
`home_path` is a path whose containing filesystem is measured (not a mount
point), and why no caller may pass `/`.

## The fix

`installer/diskusage.py` — renames + docstrings only; no behaviour change.

`setup.py`:
- `_DiskProbe.__call__` passes `Path.home()` instead of `Path("/")`.
- `_DiskProbe.__init__` / `_disk_pressure_probe` gain a real-defaulted
  `usage: diskusage.UsageProbe = shutil.disk_usage` seam, the same convention
  `_build_daemon_policy`'s `which`/`run`/`read_output` already follow, so this
  file's own tests can pin the mount choice against a fake mount table instead
  of against however the developer's machine happens to be partitioned.
- The class docstring records the decision above at the point the choice is
  made.

`installer/guidance.py`, `installer/wizard_app.py` — the two user-facing
strings now name the filesystem that was actually measured.

## Tests added (the coverage whose absence let this survive)

All in `tests/test_setup.py`, at the composition root, driven by `_mount_table`
— a `shutil.disk_usage`-shaped fake reader that resolves a path the way a
kernel does (longest mount point that is a prefix of the path wins) over three
fake host layouts. **No test reads this machine's real mounts.**

| Test | Pins |
|---|---|
| `test_the_disk_probe_measures_the_users_filesystem_not_a_read_only_root` | The immutable-host case: composefs `/` at 0 free + `/var` at 50% free, daemon **INACTIVE** (the worst case — the one state that produces the red finding). Asserts the measured path is `/var/home/u` and never `/`, that `low_disk` is False, and that `disk_pressure_guidance(...) == []` — the must-have truth, asserted literally. |
| `test_the_disk_probe_still_reports_a_full_user_filesystem` | The inverse layout: roomy `/`, data mount at 3% free. Asserts the emphasised `Severity.ERROR` finding is still produced, so the fix cannot degenerate into "never warn". |
| `test_the_disk_probe_measures_the_root_mount_on_a_single_root_host[stock-linux]` `[macos]` | A stock single-root host on both platforms: home under `/`, same 50% number as before — proof this change moves no number where the old code was already right. |

TDD order, all verified by running: the fake-reader seam was added first with
`Path("/")` still in place, so the new tests failed on **behaviour**, not on a
missing argument —
`AssertionError: assert PosixPath('/') == PosixPath('/var/home/u')` — before
the one-line fix turned them green.

**Mutation-verified:** reverting only `Path.home()` → `Path("/")` fails all
four new tests (and only those); restoring it makes them pass again.

`_pressure`/`fake_probe` helpers in `tests/test_app.py`,
`tests/test_diskusage.py`, `tests/test_guidance.py`, `tests/test_render.py`
and `tests/test_wizard_app.py` follow the field rename; no existing assertion
was weakened, skipped or deleted.
