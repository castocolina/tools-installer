# Phase 15.7 Plan 07: Unify the macOS/Linux prune scripts onto a shared shellcheck-clean core Summary

Extracted `scripts/lib/prune-tmp-common.sh` -- one implementation of the broad-path refusal
guard, root/age validation, fd-preferred/find-fallback depth-1 traversal, byte formatting, and
the `deleted: N` summary line -- and reduced both platform prune scripts to thin wrappers over
it, behind a new macOS characterization suite that pinned the script's exact contract before any
line of it changed.

## What Was Built

**Task 1** wrote `tests/test_prune_user_tmpdir_sh.py`, the macOS prune script's first-ever test
suite, against the script exactly as it stood (30 tests covering flag grammar, the seven-entry
broad-path refusal list, age validation, all five target families, depth-1 traversal, and the
`deleted: N` contract), and ran it green before touching a single line of
`scripts/prune-user-tmpdir.sh`. Writing that suite surfaced two pre-existing behaviors the plan
had not anticipated (see Deviations): `--tmpdir /` does not actually hit the refusal guard, and
the shipped `--apply` path's `deleted: N` line has always read 0 regardless of real work done.
Both were pinned as frozen characterizations of the CURRENT script, with the second marked as a
second licensed exception (alongside D-01f) for Task 2 to change.

**Task 2** created `scripts/lib/prune-tmp-common.sh` and reduced both
`scripts/prune-tmp-linux.sh` and `scripts/prune-user-tmpdir.sh` to wrappers over it: the core owns
`_prune_common_require_nonempty`, `_prune_common_strip_trailing_slash`,
`_prune_common_require_directory`, `_prune_common_refuse_broad_path`,
`_prune_common_validate_positive_int`, `_prune_common_escape_dots`, `_prune_common_human`,
`_prune_common_bytes_free`, `_prune_common_emit_deleted`, and the
`_prune_common_find_matches`/`_prune_common_find_matches0` traversal pair; each wrapper supplies
only its own match patterns, default age, refusal-list extras, and help text. The Linux wrapper's
find-only traversal is preserved exactly (passing an empty fd pattern so it never touches `fd`
regardless of what's on `PATH`); the macOS wrapper's five families are five separate traversal
calls reusing its original `find -name` globs and `fd` regexes verbatim. `Makefile`'s `validate`
target now shellchecks all three shell files (`-x` plus a `# shellcheck source=` directive in each
wrapper resolves the dynamic `source` path). Both pre-existing test suites pass with exactly the
two licensed assertion changes (D-01f's age-semantics convergence, the counter-bug fix) plus new
shared-core proof assertions (identical refusal message from both scripts against `$HOME`, the
library doing nothing when executed directly).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `deleted: N` always read 0 in `--apply` mode (pipeline-subshell counter bug)**
- **Found during:** Task 1, while writing the characterization suite -- a fixture that
  demonstrably had 5 items removed (verified via `.exists()` checks) still reported
  `deleted: 0` in stdout.
- **Root cause:** `scripts/prune-user-tmpdir.sh`'s `--apply` path fed matches into `delete_stream`
  through a pipe (`{ list_fd0 ...; } | delete_stream`). Bash runs every pipeline stage, including
  the last, in its own subshell unless `shopt -s lastpipe` is set, which the script never did, so
  `delete_stream`'s own `deleted=$((deleted + 1))` mutated a copy that was discarded the instant
  the pipeline exited. The deletions themselves were real (`rm`/`rm -rf` ran for real); only the
  reported count was wrong. Because `installer.daemon.last_run_summary` parses exactly this line
  for the Policies "last run" detail, that detail has always shown 0 in production regardless of
  actual prune activity.
  - **Note:** `scripts/prune-tmp-linux.sh` (plan 15.7-01) never had this bug -- its deletion loop
    is a plain `for` loop over an array, not a pipeline.
- **Fix:** In the extracted wrapper, `delete_stream` now reads its NUL stream via input
  redirection from a process substitution (`delete_stream < <(...)`) instead of a pipe. Input
  redirection does not fork a subshell, so `delete_stream` runs in the wrapper's own shell and its
  counters are real.
- **Files modified:** `scripts/prune-user-tmpdir.sh`, `tests/test_prune_user_tmpdir_sh.py`
- **Commit:** `756d816`
- **Why this was in-scope despite the plan's "exactly one licensed exception" language:** the
  must_haves text names D-01f as the one exception because the plan's authors were unaware of this
  separate bug (their own text assumes the counter already works: "so the Policies 'last run'
  detail keeps rendering"). Reproducing a known, silently-discarded counter on purpose inside a
  NEW shared core -- one Linux also uses, and whose own tests assert an accurate count -- would
  have been actively worse than fixing it. Documented as a second licensed exception at both the
  module docstring and the specific test's own docstring in `tests/test_prune_user_tmpdir_sh.py`.

### Deviations from the plan's illustrative test text (not code changes)

**2. `--tmpdir /` does not reach the refusal guard on the unmodified macOS script**
- **Found during:** Task 1, live-testing the plan's assumption that all seven refusal-list
  entries (including `/`) print "refusing broad path".
- **What's actually true:** `TMP_ROOT="${TMP_ROOT%/}"` (unconditional, no `/`-special-case) turns
  `/` into an empty string before the case-statement refusal check ever runs, so `--tmpdir /` is
  rejected by the "not a directory" check instead. Verified reproducibly with a standalone bash
  trace. This is a pre-existing quirk of the current script, not something this plan introduced --
  the exit code is still non-zero and nothing is deleted, so the safety property the refusal guard
  exists for (T-15.7-46) is intact; only the message text differs from the other six entries.
- **Handling:** Pinned exactly as observed in `test_refuses_root_via_not_a_directory_quirk`
  (frozen, unchanged by Task 2 -- `_prune_common_strip_trailing_slash` is deliberately "dumb" so
  the macOS wrapper reproduces this quirk exactly). The plan's own new must-have ("compare the
  refusal line from `--tmpdir /` on both scripts") was re-targeted at `$HOME`, which both scripts'
  refusal lists share unconditionally and is guaranteed to exist as a real directory on every
  host -- see `test_refusal_message_is_identical_in_shape_from_both_scripts`.
- **Why not a code fix:** must_haves explicitly permits exactly D-01f (plus the counter bug above,
  reasoned separately) as licensed behavior changes; unifying `/`'s handling was not requested and
  would be a third, unlicensed change to a script whose contract this plan exists to preserve.

**3. Three of the seven refusal-list entries do not exist on this Linux worktree**
- **Found during:** Task 1, confirming each refusal-list path's real existence before writing the
  parametrized test.
- **What's actually true:** `/private/var`, `/var/folders`, and `/private/var/folders` are
  macOS-only paths; none exist on this Fedora/Bazzite host. Since the unmodified script's
  is-a-directory check runs BEFORE its refusal check, a `--tmpdir` pointing at a nonexistent path
  is rejected via "not a directory", never reaching the refusal guard at all -- host-dependent,
  not something a Linux-run characterization suite can assert against.
- **Handling:** The parametrized refusal test (`test_refuses_broad_paths`) skips any entry that
  is not a real directory on the CURRENT host, mirroring the plan's own precedent for skipping the
  fd-present half of the age-divergence tests on a host that legitimately lacks the tool.
  `$HOME/Library`, being relative to the test's own fixture `$HOME`, IS created and exercised for
  real regardless of host.

None of the above required a `checkpoint:human-verify` -- both are testing-scope discoveries about
the pre-existing (unmodified) script's actual behavior, not architectural decisions, and are fully
reversible by re-running the now-documented characterization suite against any future change.
