Decisions for this plan:
- D-06 extension (recorded): D-06 says only `_receipt_proof` branches on the retired flag. Two more branches are required by D-08 and the SPEC R3 edges, both narrow: `plan_removal` lists a retired receipt's unproven, still-existing recorded paths in `yourself` (the catalog formula that normally names them is empty for `methods=()`), skipping manager kinds whose recorded paths belong to the manager; and `removal_plan` gives a retired tool with nothing removable and nothing listed the new level `receipt` (receipt-only removal), so `run_uninstall`'s `level != "none"` filter and `remove_tool` can retire it. No other module branches on the flag.
- D-07: `_placement_shape(kind: str, artifact: receipts.ReceiptArtifact, bin_dir: Path) -> bool` exactly as in the truths; the name check rejects `""`, `.`, `..`, a `/` or a NUL. `_receipt_proof` for a retired tool keeps the `receipt is None or receipts.drifted(receipt, rehash=verify)` early return, then returns the receipt artifacts that pass `_placement_shape(receipt.method.kind, artifact, default_bin_dir)`. It never adds a home-wide rule and never trusts a recorded type beyond these shapes.
- D-08: `retired_manager_package(tool_id: str) -> tuple[str, str] | None` returns `(receipt.method.kind, receipt.package)` for a readable receipt of a manager kind with a package. `removal_plan` for a retired manager-kind tool sets `hint="remove it yourself: {manager} {package}"`; `_manager_argv` already returns nothing because the tool declares no method, so no command is ever built.
- `RemovalLevel` gains `"receipt"`. `remove_tool`: when the fresh plan's level is `receipt`, refuse as changed if the preview carried paths or argv; otherwise `receipts.delete(tool.id)` and return `ToolRemoval(tool.id, True, <sentence>)` with `Retired the {id} receipt; {manager} {package} stays installed — remove it yourself.` (manager kind) or `Retired the {id} receipt; there was nothing to delete.`. Everything else in `remove_tool` is unchanged.
- `run_uninstall`: retired tools (`tool.retired`) are kept out of the aggregate catalog `paths` and `yourself` lists; after the catalog `render_remove_yourself` call it prints, when any retired tool has `level != "none"` or a non-empty `yourself`, the heading `retired — no longer in the catalog` and per tool (sorted by id): `{id} (retired)`, then two-space indented lines: each proven path, `remove it yourself: {comma-joined yourself paths}` when any, `remove it yourself: {manager} {package}` for a manager kind, or `nothing to delete; confirming retires the receipt`. Every line goes through `console.print(..., markup=False, soft_wrap=True)` with ids and paths passed through `sanitize_log_line`. The "nothing to uninstall" early return also requires that no retired tool has such a row.
- The CLI never offers an install, update or reinstall line for a retired id.
