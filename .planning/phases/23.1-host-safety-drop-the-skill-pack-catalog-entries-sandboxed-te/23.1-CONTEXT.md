The installer and its tests can no longer install or remove anything on the developer's machine by accident. The eight catalog entries the user dropped (rtk, matt-pocock-skills, opengsd, ponytail, superpowers, softaworks-agent-toolkit, openspec, spec-kit) and the whole skill-pack machinery go; the `npx` guard shim translates or refuses npx options; unit tests run under a subprocess allowlist, a sandboxed PATH/env, a socket block and a widened real-HOME fingerprint; real installs happen only in the container e2e.

### npx shim (R4, R5)
- **D-11: `redirect_shim_script("npx", target)` becomes an npx-only POSIX-sh translator.**
  - `REDIRECT_SENTINEL` stays on line 2; the rotate idiom from `global_redirect_shim_script` (`guards.py:152-271`) is reused (take `$1`, shift, append what is kept; every branch ends in `exec` or `exit`).
  - Until the first token not starting with `-`: `-p X`, `--package X`, `--package=X` → `--package=X`; `-y`/`--yes` dropped; any other `-*` token → stderr message, exit `EXIT_CODE`; no command → usage, exit `EXIT_CODE`.
  - The body ends in one `exec '<target>' dlx --package=… "$@"` line, so `exec_targets` / `_stale_target_message` (`:643-670`) still read the target as `words[1]`. `Redirect.args`, the label text and `guard_status` copy stay.
  - Analyzer, Confident.
- **D-12: A bare `--` before the command is refused like any other untranslated option** (fail closed).
  - choice 0.97 (refuse).
- **D-13: "Outdated" = the whole body differs byte for byte from the current body rendered with the target already baked into the old body (`exec_targets(old)[0]`), never a pnpm re-resolved at launch.**
  - **jev overridden** (re_resolve 0.99): PATH differs per launch route (`setup.py:1513-1515`), so re-resolving flip-flops the file and breaks "a second launch writes nothing"; a launch with pnpm briefly missing would turn a live redirect into a hard block, which SPEC R5 says is left alone. Second opinion baked_target 0.98.
- **D-14: The rewrite is a `guards.py` function returning `(text, severity)` lines like `LegacyStrip.launch_lines` (`tweaks.py:290-360`).**
  - It touches only `shim_dir / "npx"`, only when that is a regular file (`lstat`, not a symlink) containing `REDIRECT_SENTINEL`. The `GLOBAL_REDIRECTED` npm/pnpm wrappers share the sentinel and are never touched; a hard-block body (only `SHIM_SENTINEL`) is skipped.
  - `atomic_write_text(..., mode=0o755)`; `OSError` → one warn line.
  - Notice (ok severity, one line, names the path), e.g. "Rewrote the npx redirect at ~/.local/bin/npx: the old one could run a package's default bin." Final wording is Claude's discretion.
  - Analyzer, Likely; taken with D-15.
- **D-15: One `_launch_repairs()` composition in `setup.py` runs the legacy-alias strip and the shim rewrite for every route**, replacing the three separate `strip_legacy_aliases` calls (`setup.py:930`, `:1336`, `:1464`) and also covering `--doctor`, `--fix` and `--guard`, which run neither today.
  - choice 0.88 (single_launch_step).

Second opinion pre_collection_and_per_test 0.91.
- **D-17: Interpreters stay runnable through a per-worker `<basetemp>/interpreters/` link dir, matched by resolved path.**
  - Links only for `sh`, `bash`, `zsh` that the stripped PATH no longer finds (on this host: `zsh`, whose only copy is `/home/linuxbrew/.linuxbrew/bin/zsh`; nothing on CI or macOS). Prepended once.
  - Allowlist by realpath: the host's sh/bash/zsh, `realpath(sys.executable)` (it resolves under the real HOME: `.venv/bin/python3` → `~/.local/share/uv/python/cpython-3.12.12-…/bin/python3.12`), and named system utilities found by running the suite: known so far `stdbuf` (`tests/test_run.py:742`) and `systemd-environment-d-generator` (`tests/test_env_redirect.py:25-30`).
  - `python3` is not exposed by name (a symlink would lose the venv; tests use `sys.executable`).
  - choice 0.99 (link_dir).
- **D-18: The `sh -c` / `bash -c` / `zsh -c` parser is strict and function-aware.**
  - `shlex.shlex(posix=True, punctuation_chars=True)`; split on `&&`, `||`, `;`, `|`, newlines; leading `VAR=value` words skipped.
  - Allowed command words: a small builtin set (`echo`, `printf`, `test`, `[`, `true`, `false`, `cd`, `export`, `unset`, `set`, `exit`, `return`, `.`, `source`, `command -v`, `type`), function names defined in the script itself (`name() {`) or in a checkout file the script sources (`. "<repo>/install.sh"`), and words resolving on the child's own PATH to an allowlisted program.
  - Refused: `$(`, backticks, `<(`, `eval`, unknown compound keywords and lexer errors. A shell run with `-n` executes nothing and is allowed.
  - Tests whose scripts still use refused constructs (the `bash -c` e2e function bodies in `tests/test_container_e2e_receipts.py:171-189`) move them to a file under `tmp_path` run as `bash <file>`.
  - choice 0.94 (function_aware).
- **D-19: The two `with-fd` tests in `tests/test_prune_user_tmpdir_sh.py:479-530` become expected skips on hosts whose only `fd` is under the real HOME** (SPEC R7 amended). They need the real `fd` (`~/.local/bin/fd` is the only copy here, live `type -ap fd`); the allowlist may not name it, and a stand-in built on `find` would empty the comparison. The plan records their exact skip reason and excludes them from the baseline compare.
  - choice 0.99 (amend_baseline).
- **D-20: "A script inside this checkout" means explicit roots only: `<checkout>/scripts/`, `install.sh` and `setup.py`, by resolved path.** `.venv/` (ruff, pyright, pre-commit) and `.claude/gsd-core/bin` are excluded.
  - choice 0.89 (explicit_roots).
- **D-21: `os.system` (parsed like `sh -c`), every `os.exec*`, `os.spawn*` and `os.posix_spawn` / `posix_spawnp` present on the platform are wrapped with the same check, and the check is idempotent** (`subprocess` may call `os.posix_spawn` after `GuardedPopen` already passed). `tests/test_screen_family.py:3683-3692` stops running `git ls-files` and walks `installer/` in Python, since `git` is not allowlisted. Analyzer, Confident.
- **D-22: The socket guard refuses `AF_INET`/`AF_INET6` at `socket.socket.__init__` (including the default family when no fileno is given) and replaces `socket.getaddrinfo`;** both errors name the test (`request.node.nodeid`, autouse fixture). `socketpair()` and asyncio's self-pipe keep working. No new dependency (pytest-socket is not installed).
  - Scratch check (venv Python 3.12): `socketpair()` returned family 1 and `asyncio.run` worked; `create_connection(("127.0.0.1", 9))` and `urlopen("https://example.com")` raised at `getaddrinfo`, before any DNS query left the host. xdist 3.8.0 / execnet 2.1.2 popen gateways use pipes.
  - **jev overridden** (connect_only 0.96): SPEC R8 says creating or connecting must raise, and a connect-only block lets the DNS query leave first. Second opinion create_and_resolve 1.0.
- **D-23: The first plan wave records the skipped-test count and reasons on the pre-phase tree** (`uv run pytest -n auto -q -rs -p no:cacheprovider`) before any guard change; that number is R7's baseline.   - choice 0.89 (count_only).
