# Phase 23.1 — UI Design Contract

> Visual and interaction contract for: the catalog views without the eight dropped entries, the retired-receipt removal rows (Uninstall view and `--uninstall`), the launch notice when an old `npx` guard shim is rewritten, the `npx` shim's stderr messages, and the old-cache and corrupt-receipt warnings.
> Generated by gsd-ui-researcher (no user questions: every answer is in SPEC/CONTEXT or the Phase 21-23 contracts). To be verified by gsd-ui-checker.

This is a **Textual terminal UI** plus a headless Rich console, not a web frontend. Units are terminal **cells** and **rows**. The design system is the Phase 21 contract as extended by Phases 22 and 23 (`22-UI-SPEC.md`, `23-UI-SPEC.md`). This file **extends them and never contradicts them**: house chrome (`AppScreen`, `StatusLine`, `VIEWS`), the glyph set `… ! ≈ ↑ ✓ ○ –`, Rich named ANSI styles, the 78-cell line budget at `size=(80, 20)`, no motion, sentences with an em dash, `show_result`, the one mutation-lock template, the Phase 22 detail-bar clause order (proof, config, `remove it yourself`, `required by`), and the Phase 20 vocabulary (`WORDS`, `RESULT_WORDS`, `RowOutcome`).

**Binding minimum:** `size=(80, 20)` with `NO_COLOR=1`. Every state is a word or a glyph first; color is redundant.

**Sources (locked, none re-asked):** `23.1-SPEC.md` R1-R5 (R6-R10 have no user-visible surface), `23.1-CONTEXT.md` D-05, D-06..D-10, D-11..D-15, `22-UI-SPEC.md` (Uninstall rows, `remove it yourself`), `23-UI-SPEC.md` (launch notice lines, environment pseudo-rows, report width rule).

**Scope.** No new screen, view, key, widget class, flag or glyph. R6-R10 (test allowlist, PATH/env sandbox, socket block, fingerprint, container e2e) are test and script internals: their only output is pytest failure text and the e2e `TRACER_GSD_*` lines, which are developer logs outside this contract (they follow the existing `TRACER_*` line pattern). The visible changes are:

1. Eight ids vanish from every catalog view; nothing replaces them (section 1).
2. Retired receipts become Uninstall rows and `--uninstall` lines (section 2).
3. One launch notice line for the `npx` shim rewrite, plus the shim's own stderr text (section 3).
4. Two warning lines for unreadable or corrupt receipts (section 2).

## 1. Catalog views after the drop (R1, R2)

- The eight ids (`rtk`, `matt-pocock-skills`, `opengsd`, `ponytail`, `superpowers`, `softaworks-agent-toolkit`, `openspec`, `spec-kit`) appear in no row, no detail bar, no search result, no `--all` plan, no `recommends` hint.
- The `codex`, `claude`, `opencode` and `cursor-agent` detail lines read `pairs well with codegraph, graphify` (the existing `recommends` sentence form with two ids; no `rtk`).
- A category left with no tools renders no heading and no empty section (SPEC edge, R1 empty). Remaining order is unchanged (priority, then id).
- The skill-pack status wording (pack present/absent per host, `skill_install` / `plugin_enable` step texts) is removed with its code. No handoff, notice or uninstall line offers a reinstall command for a dropped id (SPEC prohibition); a `pnpm dlx @opengsd/gsd-core` text appears nowhere.
- A `kind = "skill_pack"` registry entry is a developer-facing load error, not a UI state: `unknown method kind 'skill_pack'` (existing error form, D-05); a leftover `[tool.skill_lifecycle]` table: `skill_lifecycle was retired in 23.1; remove the [tool.skill_lifecycle] table`. These print as the registry error, not in any screen.
- An old version cache with a `skills` key loads silently: no warning, no line.

## 2. Retired receipts: Uninstall view and CLI (R3; D-06..D-10)

A retired tool is a receipt whose id is not in the catalog. It is **never** offered for install, update, repair or in any catalog view or `--all` plan (D-09); it exists only as a removal row.

### Where it appears

In the Uninstall view, in its own section **after** the catalog rows and after the environment pseudo-rows are unaffected (the section follows the catalog tool rows; the environment section keeps its Phase 22/23 place). Section heading row (disabled, `bold`): `retired — no longer in the catalog` (35 cells). Rows are sorted by id, stable. With no retired receipts the heading and rows do not render (nothing changes from today).

Columns follow the existing Uninstall table. The Tool cell is the receipt id; the mark and the What-gets-removed text follow Phase 22 rules unchanged.

| Column | Retired row |
|--------|-------------|
| Tool | `{id}` (bold, as for catalog rows) plus a dim suffix ` (retired)` |
| Mark | the Phase 22 removal mark for the row's state (`✓` removable, `—` nothing to remove) |
| What gets removed | the Phase 22 text: the receipt-proven paths (`{path}` list, same truncation); empty when only a manager package is recorded |

### Detail bar (3 rows of 78 cells; Phase 22 clause order)

| Case (receipt kind / proof outcome) | Detail bar |
|-------------------------------------|------------|
| download-kind, placement shape and hash proven (D-07) | `retired: {id} is no longer in the catalog · recorded files re-checked before deletion` |
| some recorded path drifted or fails the shape proof | the line above, then ` · remove it yourself: {paths}` (drifted and unproven paths; they are kept) |
| `app` kind | same first line; paths are the `.app`-style dir under the applications dir plus an optional bin link |
| manager kind (`brew`, `cask`, `uv-tool`, `node`) (D-08) | `retired: {id} is no longer in the catalog · remove it yourself: {manager} {package}` — confirming retires the receipt and leaves the package installed |
| `script` tree or leaf, or any kind never proven | `retired: {id} is no longer in the catalog · remove it yourself: {paths}` |
| receipt with zero artifacts | `retired: {id} is no longer in the catalog · nothing to delete; confirming retires the receipt` |

`{manager} {package}` is a display string, never executed. No row offers a reinstall or update command (negative acceptance).

### Keys

Unchanged. `space` selects, `enter` reviews, `c` is refused with the existing `This row has no config to delete.` (a retired row has no config). The mutation lock and the preview/confirm re-check ("changed since the preview") are the Phase 22 ones.

### ConfirmUninstall (reuses Phase 22 blocks; no new block)

A retired row adds lines to the existing blocks only:

| Block | Retired-row line |
|-------|------------------|
| What is removed | the proven paths, one per line, `2`-cell hanging indent (as Phase 22) |
| What runs | none for a retired tool (no manager command, no hook undo) |
| remove it yourself | `{id}: {paths}` or `{id}: {manager} {package}` (manager kind) |

### Results (status line, existing `show_result` path)

| Situation | Status line | Severity |
|-----------|-------------|----------|
| retired tool removed and receipt retired | the Phase 22 removal result (`removed {id}`) | ok |
| manager-kind or nothing-to-delete: receipt retired only | `Retired the {id} receipt; {manager} {package} stays installed — remove it yourself.` (manager kind) or `Retired the {id} receipt; there was nothing to delete.` | ok |
| a recorded file changed between preview and confirm | the Phase 22 changed-since-preview refusal; the file is kept and listed under `remove it yourself` | warn |

### Corrupt or unreadable receipts (D-10)

Never a row, never deleted, never a crash. One warning line each through the startup-warning path (TUI: first-view status at `warn`; headless: printed first with `markup=False, soft_wrap=True`):

| Case | Line |
|------|------|
| `receipts.read() is None` for an id not in the catalog | `Ignored the corrupt receipt {path}: it is kept; remove it yourself if it is stale.` |
| the receipts dir cannot be listed | `Could not read the receipts folder {path}: {first error line}.` |

The corrupt-receipt line is printed once per launch per file. A corrupt receipt for a **catalog** id keeps today's handling (unchanged).

### CLI `--uninstall` and `--uninstall --yes`

- Retired rows join the existing preview after the catalog tools, under the same heading text `retired — no longer in the catalog`, each as the Phase 22 preview lines (what is removed, `remove it yourself`) with `{id} (retired)` as the tool name. `--all` and `--categories` never include them.
- `--uninstall --yes` removes proven paths and retires receipts exactly like catalog tools; a drifted file stays and is listed under `remove it yourself`.
- A second `--uninstall --yes` after the receipt is gone prints no retired section and exits 0.
- Output uses `markup=False, soft_wrap=True`; every fixed string is ≤ 78 cells.

## 3. `npx` shim: launch notice and stderr text (R4, R5; D-11..D-15)

### Launch notice (one line, one launch)

Emitted by `_launch_repairs()` for every route (TUI, headless install, `--uninstall`, `--doctor`, `--fix`, `--guard`) when an installer-written `npx` redirect with an outdated body is rewritten. Severity `ok` when written, `warn` when it cannot be.

| Case | Line | Severity |
|------|------|----------|
| rewritten | `Rewrote the npx redirect at {path}: the old one could run a package's default bin.` (78 cells with `~/.local/bin/npx`; longer paths wrap) | ok |
| bin dir or file not writable | `Could not rewrite the npx redirect at {path}: {first error line}.` | warn |
| already current, absent, foreign (no sentinel), hard-block body, or symlink | no line | — |

- TUI: shown through the existing launch status warning path (shown at `warn` display, as the Phase 23 alias notice; the `ok`/`warn` severity decides only the headless color). Headless: printed first, before the plan or preview. A second launch prints nothing.
- `{path}` is sanitized with `sanitize_log_line` and printed as data, never markup.
- The notice is printed in the same block as any Phase 23 alias-removal line, after it (alias lines first, then the shim line); nothing else is added.

### Shim stderr messages (shell script, plain text, no color; command-line surface)

The generated POSIX `sh` body prints one line on stderr and exits `EXIT_CODE` (the existing guard exit code) without running pnpm. Wording follows the existing guard messages' form (`npx: …`):

| Case | stderr |
|------|--------|
| untranslated option, e.g. `--no`, `-c`, `--frobnicate`, `--` | `npx: option {opt} is not supported by this redirect (it runs pnpm dlx); nothing was run.` |
| no command (`npx`, `npx -y`) | `npx: missing command. Usage: npx [-y] [-p package]... command [args]` |
| `-p` / `--package` without a value | `npx: option {opt} needs a package name; nothing was run.` |

`{opt}` is the token as typed, single-quoted by the shell (`'%s'` via `printf`), so a hostile token cannot inject. The translated options (`-p X`, `--package X`, `--package=X` to `--package=X`; `-y` / `--yes` dropped) print nothing. Each message is a fixed sentence plus the token; the fixed part is ≤ 78 cells. `guard_status` copy, the `Redirect.args` label and the doctor wording for the redirect stay byte for byte as today.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | none new. Uninstall keeps `enter` review and the existing confirm; no install, update or reinstall CTA for a retired id |
| Retired section heading | `retired — no longer in the catalog` |
| Retired detail (proven) | `retired: {id} is no longer in the catalog · recorded files re-checked before deletion` |
| Retired detail (manager kind) | `retired: {id} is no longer in the catalog · remove it yourself: {manager} {package}` |
| Retired detail (nothing to delete) | `retired: {id} is no longer in the catalog · nothing to delete; confirming retires the receipt` |
| Empty state | No retired receipts: no heading, no rows, no line. The catalog views list no empty category after the drop. `--uninstall` with none prints nothing extra |
| Error state (receipts) | `Ignored the corrupt receipt {path}: it is kept; remove it yourself if it is stale.` · `Could not read the receipts folder {path}: {first error line}.` |
| Error state (shim rewrite) | `Could not rewrite the npx redirect at {path}: {first error line}.` |
| Shim rewrite notice | `Rewrote the npx redirect at {path}: the old one could run a package's default bin.` |
| Shim stderr | `npx: option {opt} is not supported by this redirect (it runs pnpm dlx); nothing was run.` · `npx: missing command. Usage: npx [-y] [-p package]... command [args]` · `npx: option {opt} needs a package name; nothing was run.` |
| Destructive confirmation | Retired removal: `ConfirmUninstall` (Phase 22) unchanged; the receipt row's paths are the only deletions, re-hashed at deletion time. Confirming a manager-kind or empty retired row only retires the receipt: `Retired the {id} receipt; {manager} {package} stays installed — remove it yourself.` |
| Removal result (receipt only) | `Retired the {id} receipt; there was nothing to delete.` |

Register: lowercase fragments in detail bars and cells; status and notice sentences capitalized with a period. Fixed strings ≤ 78 cells except the rewrite notice, which is exactly 78 with the default path and wraps otherwise (`StatusLine` is `height: auto`).

**Data, never markup.** Ids, paths, packages, managers, option tokens and first error lines are sanitized with `sanitize_log_line` and appended as `Text` or printed with `markup=False`. A `[` or an ANSI escape in a receipt filename, a receipt field or an error renders literally. The shim prints `{opt}` through `printf '%s'`, never as a format string.
