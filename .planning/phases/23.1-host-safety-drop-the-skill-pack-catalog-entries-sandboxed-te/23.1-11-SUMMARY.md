# Phase 23.1 Plan 11: Retired-receipt scan and the Tool.retired flag Summary

**Receipts whose tool id left the catalog are listed as synthetic retired tools sorted by id; unsafe names are ignored; corrupt receipts and an unreadable folder give warnings and never cause a deletion.**

## Performance

- **Tasks:** 2 (both TDD, one green commit each)
- **Files modified:** 3
- **Commits:** 2 (`38e10df`, `4598176`)

## Accomplishments

- `Tool` gained `retired: bool = False` as a dataclass field and `__init__` keyword; every registry tool keeps `retired=False`.
- `receipts.RetiredScan(tools, warnings)` and `receipts.scan_retired(catalog_ids)` list receipts whose id is outside the catalog as synthetic `Tool(id=stem, name=stem, cmd=stem, methods=(), retired=True)`.
- Corrupt receipts for unknown ids produce `Ignored the corrupt receipt {path}: it is kept; remove it yourself if it is stale.`, with the file left byte-identical.
- An unreadable receipts folder produces one `Could not read the receipts folder {path}: {reason}.` warning and an empty scan; a missing or empty folder gives nothing.
- A receipt that vanished between the listing and the read is skipped silently.
