## Priority-area findings

**npx translator and launch repairs.**
- Injection is closed. The shim's own output uses a fixed `printf` format with the token as `%s`. Packages are re-emitted only as `--package=` entries. The command and its arguments are rotated through untouched after the first positional.
- The rewrite bakes the target of the first `exec` line of the old body and re-quotes it with `shlex.quote`, so a hand-edited old body cannot inject shell into the new one.
- A foreign shim is never overwritten when it lacks the sentinel, is a symlink (`lstat` and `O_NOFOLLOW`), is over 8192 bytes, is not UTF-8 or has no `exec` line. A file that changes identity or bytes after the read is also skipped.
- Residuals R-1 and R-2 are the only ways around those gates. Both need a hostile writer in the user's own bin dir.

**Retired-receipt removal.**
- A path can be deleted only when all of these hold: the receipt is readable and undrifted; the path has the installer's placement shape; no other readable receipt records it (C-02); and the re-hash at deletion time still matches.
- No manager or recipe command is built for a retired tool. A retired receipt that deletes nothing retires the receipt only.
- Receipt-derived text is sanitized in the CLI preview, the TUI detail bar, the confirm review and the result sentences.
- The one path that shape-proof alone cannot separate from a legitimate one is another catalog tool with no receipt, as in T-23.1-33 (accepted).

**Unit-test guard.**
- No real toolchain: Popen, os.system, exec*, spawn* and posix_spawn* are all allowlisted by resolved real path.
- No socket or DNS: the two internet families and six resolvers refuse, and the child Python guard covers launches only (R-4).
- Refusals are never swallowed: every wrapper records before it raises, and teardown fails the test.
- Gaps: R-3 and R-4.

**Zero sudo.**
- `git diff a30bb2f..HEAD` over `installer/`, `setup.py`, `install.sh`, `scripts/` and `Makefile` adds no `sudo`, `pkexec`, `doas`, `os.system`, `shell=True` or `eval`.
- Every `sudo` string in production code is text handed to the user (`installer/systemd_daemon.py:846-848`, `installer/executors.py:613-615`).
- `installer/model.py:483` `ELEVATION_COMMANDS` is the registry-side refusal.
- The sudo tests passed, e.g. `tests/test_plan.py::test_no_sudo_argv_on_the_plan_path`.
- The only `sudo` use is inside the disposable e2e container.
