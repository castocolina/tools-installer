# Phase 23.1: Host safety: drop the skill-pack catalog entries, sandboxed tests, container-only e2e — Specification

**Created:** 2026-11-07
**Ambiguity score:** 0.14 (gate: ≤ 0.20)
**Requirements:** 10 locked

## Goal

The installer and its test suite can no longer install or remove anything on the developer's machine by accident: the eight dropped catalog entries and the skill-pack machinery are gone, the `npx` guard shim can never run a package's default bin, unit tests cannot launch a real toolchain or open a network socket, and real installs happen only in the container e2e.

## Background

- **Root cause (audit 2026-11-07, read-only).** The repo's gitignored `.opencode/opencode.json` (written by GSD 1.17 `--opencode --local`) declared MCP `gsd` = `npx -y -p @opengsd/gsd-core gsd-mcp-server --no-prompts`. The installer's redirect shim `~/.local/bin/npx` (`installer/guards.py:145-149`, `REDIRECTED` at :55) is `exec <pnpm> dlx "$@"`. pnpm 11.18 `dlx` has no `-y` and spells the package option `--package` (verified live: `pnpm dlx --help` lists `--allow-build`, `--package`, `-c/--shell-mode`, reporter flags), so it ran the package's default bin, GSD's `install.js`, which defaults to a global Claude install in a non-interactive terminal. That happened 10 times since 2026-10-28, each at an `opencode run` in this repo. The host's shim still carries the old body (`exec /home/bazzite/.volta/bin/pnpm dlx "$@"`, verified live); the MCP entry was disabled on the host the same day. A shim is only rewritten when the guard policy is applied (`installer/app.py:529`, `installer/policy.py:351`).
- **Other GSD paths.** `installer/skill_lifecycle.py:505-526` builds `project_pack_install` / `project_pack_global_uninstall` steps that run `sh -c 'cd <repo> && exec pnpm dlx @opengsd/gsd-core@1.16.0 --<runtime> --local …'`; `installer/session.py` runs them on an approved `make run` row.
- **Catalog.** Seven `kind = "skill_pack"` entries (`ponytail`, `openspec`, `superpowers`, `softaworks-agent-toolkit`, `matt-pocock-skills`, `opengsd`, `spec-kit`; `installer/registry.toml:3066-3720`) are the only users of the skill-pack kind; `rtk` (`registry.toml:1829`) is a `github_release` + `brew` binary entry. Skill packs are receiptless (`installer/receipts.py:41`); rtk writes a receipt. The skill-pack code is about 1,000 lines in `installer/skill_lifecycle.py` plus its use in `version_status.py`, `catalog_tui.py`, `session.py`, `engine.py`, `model.py`, `resolve.py`, `enums.py`, `version_cache.py` (`skills` key) and `tests/test_skill_lifecycle.py`. Only `present_harnesses` is shared with a non-pack feature (`installer/postinstall.py:24`, hook registration).
- **Uninstall** is driven by the catalog's `Tool` list (`installer/uninstall.py:170` `plan_removal`, `wizard_app.py:1190` `UninstallScreen._build_entries`), so a receipt whose id leaves the catalog becomes invisible and unremovable.
- **Unit-test guard.** `tests/conftest.py:52-105`: `GuardedPopen` checks only `argv[0]` against a nine-name deny set (`node npm npx pnpm corepack volta bun yarn brew`), so `sh -c '…'` and `uv`, `curl`, `gh`, `claude`, `git` pass. PATH loses real-home and `/run/user` dirs, but linuxbrew stays (`conftest.py:208`: this host's `zsh` and `python3` live there; `copilot` and `brew` do too). Only `ZDOTDIR ZSH PNPM_HOME VOLTA_HOME XDG_CONFIG_HOME XDG_DATA_HOME` are cleared. No socket block. The real-HOME fingerprint (`conftest.py:125-178`) watches six dotfiles, the backup glob, and the receipts / `environment.d` / config-ledger listings. About 10 tests run `zsh -n` and skip when zsh is not on PATH. Production code launches processes only through `subprocess` (no `os.system` / `os.exec*` / `os.posix_spawn`, verified by grep).
- **e2e.** `make e2e` runs `scripts/container-e2e-verify.sh all` in a disposable Fedora container (podman/docker); there is no other e2e target. `scripts/e2e-residue-allowlist.txt:38-39` allow `.config/rtk` and `.local/share/rtk` residue.

## Requirements

1. **Catalog drop**: The catalog no longer offers rtk, matt-pocock-skills, opengsd, ponytail, superpowers, softaworks-agent-toolkit, openspec or spec-kit.
   - Current: the eight entries are in `installer/registry.toml` and appear in the catalog views; opengsd's steps run `pnpm dlx @opengsd/gsd-core`.
   - Target: none of the eight ids is in `registry.toml` or in any catalog view, no file under `installer/` or `setup.py` contains `@opengsd/gsd-core` or a `pnpm dlx` of a GSD package, and the rtk lines in `scripts/e2e-residue-allowlist.txt` are gone.
   - Acceptance: a test loads `registry.toml` and asserts none of the eight ids is present; a test greps `installer/` and `setup.py` for `@opengsd/gsd-core` and finds nothing; the catalog views built over the shipped registry list none of the eight ids.
   - *Amended 2026-11-07 (23.1 D-03):* the `recommends` lists of `codex`, `claude`, `opencode` and `cursor-agent` name `rtk` (`registry.toml:1473,1528,1562,1626`); the loader checks only `requires` ids, so those `rtk` items are removed too, or the catalog keeps suggesting rtk.

2. **Skill-pack machinery removed**: The `skill_pack` method kind and all skill-pack and project-pack support code are deleted; only the agent-host detection that hook registration uses is kept.
   - Current: `skill_lifecycle.py` (about 1,000 lines), the `skill_pack` kind in `model.py` / `resolve.py` / `engine.py` / `receipts.py`, the pack status probes, `SkillHostStatus`, the `skills` key in the version cache, the project-pack reconfigure steps and their tests exist with no catalog entry left to use them.
   - Target: the registry loader rejects `kind = "skill_pack"` and `[tool.skill_lifecycle]` as unknown; no module imports pack status, project-pack or skill-lock code; `present_harnesses` (or its replacement) still serves `postinstall.py`; a version cache file written by the previous version (with a `skills` key) loads without error and the key is ignored.
   - Acceptance: a registry fixture with `kind = "skill_pack"` fails to load with an error naming the kind; the codegraph hook-registration tests still pass; a test loads an old-format cache with a `skills` key and gets the version entries back; `make validate` (vulture included) is green.

3. **Retired receipts stay removable**: A receipt whose tool id is not in the catalog is shown as a retired tool that can be removed through its receipt, and is never offered for install.
   - Current: uninstall plans and the Uninstall view iterate the catalog's tools only, so a leftover `rtk.json` receipt is invisible and its files can never be removed by the installer.
   - Target: the Uninstall view and `--uninstall` list every receipt whose id is not in the catalog as a retired row; its receipt-recorded artifacts are removed after the same deletion-time re-hash proof as a catalog tool (drifted or unproven paths go to "remove it yourself"), and the receipt is retired once its proven paths are gone; no install, update or catalog view lists the id.
   - Acceptance: with a scratch HOME holding a valid receipt for an id absent from the registry and its recorded files, `--uninstall --yes` removes the files and the receipt; with one recorded file modified, that file is listed as "remove it yourself" and kept; a corrupt receipt for an unknown id is reported, never deleted blindly, and never crashes the launch; the catalog views and `--all` never include the id.

4. **npx shim translates or refuses**: The `npx` redirect shim maps npx's package options onto `pnpm dlx` and refuses every npx option it cannot honour, so a flag mismatch can never run a package's default bin.
   - Current: the shim is `exec <pnpm> dlx "$@"`, so `npx -y -p pkg bin args` reaches pnpm as `dlx -y -p pkg bin args`.
   - Target: before the first positional (the command), `-p X`, `--package X` and `--package=X` become `--package=X` (repeatable, order kept), `-y` / `--yes` are dropped, and any other option token, including `--no`, `--no-install`, `-c` / `--call`, `-w` / `--workspace` and `--`-less unknown flags, exits non-zero with a message on stderr and runs nothing; everything from the command on is passed through unchanged, and pnpm's exit code is returned.
   - Acceptance: tests in `tests/test_guards.py` run the generated shim against a fake pnpm that records its argv: `npx -y -p pkg bin a b` records `dlx --package=pkg bin a b`; `npx --package=a -p b cmd` records `dlx --package=a --package=b cmd`; `npx pkg@1 x` records `dlx pkg@1 x`; `npx -c 'echo hi'`, `npx --no pkg` and `npx --frobnicate pkg` exit non-zero and the fake pnpm is never invoked; a fake pnpm exiting 3 makes the shim exit 3; `sh -n` passes on the generated body.
   - *Amended 2026-11-07 (23.1 reviews, orchestrator decision; the user may reverse it):* the interactive guard alias block (`ban_alias_block`) wrote `alias npx='pnpm dlx'`, so an interactive `npx -y -p pkg bin` reached pnpm untranslated and "a flag mismatch can never run a package's default bin" did not hold in interactive shells (review R1-19; live in this host's `~/.myshellrc:21`). The block no longer aliases `npx`: the translating PATH shim is the only npx layer, as it already is for the npm/pnpm wrappers. Acceptance: `ban_alias_block()` holds no `alias npx=` line (tests/test_guards.py).

5. **Outdated shim rewritten at launch**: An `npx` redirect shim this installer wrote with an older body is rewritten with the current body on the next launch, with a one-line notice.
   - Current: a shim is rewritten only when the user re-applies the guard policy, so the host's vulnerable shim stays until then.
   - Target: at launch (TUI and headless routes), a file in the managed bin dir that carries the redirect sentinel and whose body differs from the body the current code would write is atomically rewritten; one notice line names the path; a file without the sentinel, or a hard-block body written because pnpm was unresolvable, is left alone; an unwritable bin dir produces a warning, not a crash.
   - Acceptance: in a scratch HOME, an old-body sentinel shim is replaced by the current body at launch and the notice is printed once; a second launch writes nothing and prints nothing; a foreign `npx` without the sentinel is byte-identical after launch; a read-only bin dir yields a warning line and the launch continues.
   - *Amended 2026-11-07 (23.1 reviews, orchestrator decision; the user may reverse it):* the same launch repair also rewrites an existing, marker-delimited guard alias block in `~/.myshellrc`, the zshrc or `~/.bashrc` whose lines differ from the current block (the old block still aliases `npx` to `pnpm dlx`), with one notice line per file; it never adds a block to a file without one and never changes a line outside the markers. Acceptance: in a scratch HOME, an old block between user lines is rewritten once at launch with every byte outside the markers unchanged, a second launch is silent, and an rc file without the block is byte-identical (tests/test_guards.py, tests/test_setup.py).

6. **Subprocess allowlist in unit tests**: Unit tests can launch only allowlisted programs; any other launch, direct or through a shell script, fails the test before the process starts.
   - Current: the guard denies nine names by `argv[0]` only; `sh -c` scripts, `uv`, `curl`, `gh`, `claude`, `git` and linuxbrew binaries pass.
   - Target: every process launch in a test (`subprocess.Popen` and so `run` / `check_output`, plus `os.system`, `os.exec*`, `os.spawn*` and `os.posix_spawn`) is refused unless its program is an executable under pytest's base temp dir, a script inside this checkout, or a named allowlisted interpreter or utility; for `sh -c` / `bash -c` / `zsh -c` the script's command words are checked by the same rule, and a script the guard cannot parse is refused.
   - Acceptance: tests in `tests/test_sandbox.py` show `["uv", "--version"]`, `["curl", "-V"]`, `["sh", "-c", "uv --version"]`, `["bash", "-c", "true && gh --version"]` and a linuxbrew binary by absolute path each raise before launch; a fake under `tmp_path`, `["sh", "-n", file]` and `sys.executable -c pass` run; the full suite passes under the new guard.

7. **Sandboxed test PATH and environment**: Linuxbrew and real-home bin dirs are off the test PATH, agent and toolchain variables are cleared, and allowlisted interpreters stay runnable so no test starts skipping.
   - Current: linuxbrew stays on the test PATH; only six location variables are cleared; zsh tests depend on linuxbrew's zsh on this host.
   - Target: the test PATH holds no entry under the real HOME, `/run/user` or the linuxbrew prefix; `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, `OPENCODE_CONFIG*`, `XDG_CACHE_HOME`, `XDG_STATE_HOME`, `npm_config_*`, `UV_*`, `HOMEBREW_*`, `GH_TOKEN` and `GITHUB_TOKEN` are unset in every test unless the test sets them; the allowlisted interpreters (`sh`, `bash`, `zsh`, the running Python) still resolve by name when they exist on the host, even when their only copy lives in a removed dir.
   - Acceptance: a test asserts the PATH has no real-home, `/run/user` or linuxbrew entry and none of the listed variables is set; `shutil.which("zsh")` succeeds in a test on a host whose only zsh is under linuxbrew; the suite's skipped-test count on this host does not rise against the count before the phase.
   - *Amended 2026-11-07 (23.1 D-19):* the two `with-fd` tests in `tests/test_prune_user_tmpdir_sh.py` need the real `fd`, whose only copy on this host is `~/.local/bin/fd` (live `type -ap fd`); the allowlist may not name it and a stand-in would empty the comparison, so they are recorded as expected new skips (exact reason text) and excluded from the baseline compare.

8. **Network sockets blocked in unit tests**: A unit test that opens an internet socket fails.
   - Current: no socket guard; tests rely on monkeypatching `urlopen`.
   - Target: creating or connecting an `AF_INET` / `AF_INET6` socket in a test raises an error naming the test; `AF_UNIX` sockets and `socket.socketpair()` keep working (asyncio's self-pipe in Textual tests needs them).
   - Acceptance: a test shows `socket.create_connection(("127.0.0.1", 9))` and `urllib.request.urlopen("https://example.com")` raise the guard's error; a Textual app test (`run_test`) still passes.

9. **Widened real-HOME fingerprint**: The session fingerprint also watches the agent, toolchain and service directories and fails the run on any change.
   - Current: six dotfiles, the backup glob and three listings are watched.
   - Target: the fingerprint also covers `~/.claude/{gsd-core,.gsd-source,gsd-file-manifest.json,agents,commands,hooks}`, `~/.gsd`, `~/.agents`, `~/.codex`, `~/.cursor`, `~/.config/opencode`, `~/.local/bin`, `~/.local/opt`, the uv tools dir, the pnpm global dir, Volta's tools dir, `~/.config/systemd/user` and `~/.oh-my-zsh`, by existence, entry listing and mtime only (never file contents); the failure message names each changed path and the entries added or removed.
   - Acceptance: a test drives the fingerprint function against a scratch "real home": creating `~/.claude/gsd-core`, adding a file to `~/.local/bin`, or touching `~/.config/systemd/user` each yields a diff naming that path and entry; an unchanged tree yields no diff; a missing directory is recorded as absent, not as an error.

10. **Real installs only in the container e2e**: Every check that installs or removes real packages runs only inside the container e2e, which also proves no global GSD tree appears.
    - Current: `make e2e` is container-only, but nothing asserts the GSD trees stay absent, and nothing pins that the verification targets never run a real install.
    - Target: the container e2e asserts after the install pass, the uninstall pass and the reinstall pass that `~/.claude/gsd-core` and `~/.claude/.gsd-source` do not exist in the tester's home and prints a tracer line for it; a host test pins that the `test` and `validate` recipes never invoke `setup.py`, `install.sh` or the e2e script (the user-facing `setup` / `run` / `uninstall` targets stay as they are), and that `scripts/container-e2e-verify.sh` exits non-zero and touches nothing when no container runtime is detected.
    - Acceptance: the host-side e2e script tests (`tests/test_container_e2e_receipts.py`) show the new tracer printed when the trees are absent and a failure when a planted `gsd-core` dir is present; the Makefile pin test passes; `make e2e` in a container prints the GSD-absent tracer three times.

## Boundaries

**In scope:**
- Deleting the eight registry entries, the skill-pack/project-pack machinery, their tests and the rtk residue allowlist lines
- Retired-receipt removal for any receipt whose id is not in the catalog
- The `npx` shim translation and the launch-time rewrite of an outdated shim
- The unit-test subprocess allowlist, PATH/env sandbox, socket block and widened fingerprint
- The container e2e GSD-absence assertion and the Makefile/e2e-script pins

**Out of scope:**
- Editing the repo's gitignored `.opencode/opencode.json` or any developer config — host-specific, already disabled on 2026-11-07; the installer never writes it
- Uninstalling a global GSD install the user already has — the installer never wrote it; HOST-01's handoff covers only receipts
- The `pnpm` / `npm` global-redirect shims (`GLOBAL_REDIRECTED`) — unrelated to the `npx` flag mismatch; their argv rules stay as they are
- Install-time tuning, Policies trimming and the progress indicator — Phase 23.2
- Adding copilot to the catalog — Phase 23.2 (TUNE-06)
- The wider dead-code sweep — Phase 25 (Lean); this phase deletes only what the dropped entries leave unused
- Blocking processes started by an allowlisted program's own children (a shell script's subcommands beyond its parsed words, a child `python -c`) beyond the PATH and env sandbox — the guard lives in the pytest process; the PATH strip and cleared variables are the net there

## Constraints

- Zero sudo; no test or code path installs, removes or downloads anything on the host; real installs only in `make e2e` containers (AGENTS.md).
- The shim body stays POSIX `sh` (`sh -n` clean) and keeps the redirect sentinel line, so `is_our_shim` and `guard_redirect_warning` keep working.
- Linux and macOS: the test PATH sandbox must work where linuxbrew is absent (CI ubuntu, macOS) and where zsh is at `/bin/zsh` (macOS).
- The guard must not slow `make test` noticeably: no per-launch subprocess of its own.
- `make validate && make test` green with the 90% coverage gate.
