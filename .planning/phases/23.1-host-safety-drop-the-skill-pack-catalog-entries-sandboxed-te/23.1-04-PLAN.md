- `LaunchPolicy` (frozen dataclass): `allowed_root: Path` (resolved base temp), `checkout: Path` (resolved repo root), `interpreters: frozenset[Path]`, `utilities: frozenset[Path]` (all resolved real paths).
- `build_launch_policy(allowed_root: Path, *, path_value: str, checkout: Path = CHECKOUT) -> LaunchPolicy`: interpreters are the realpaths of `sh`, `bash`, `zsh` found with `shutil.which(name, path=path_value)`, plus `/bin/sh`, plus `os.path.realpath(sys.executable)`; utilities are the realpaths of each name in `UTILITY_NAMES = ("stdbuf", "systemd-environment-d-generator")` found on `path_value`, plus the generator file in the three libdirs when it exists and is executable. No subprocess is run to build it (SPEC constraint: no per-launch subprocess).
- `FORBIDDEN_PROGRAM_NAMES`: a frozenset of real toolchain and network names that may never be allowlisted: uv, uvx, pip, pip3, python3 (by name), curl, wget, gh, git, claude, codex, opencode, cursor-agent, copilot, brew, node, npm, npx, pnpm, corepack, volta, bun, yarn, cargo, rustup, go, docker, podman, flatpak, dnf, apt, systemctl, launchctl.
- `check_launch(args: object, *, env: Mapping[str, str] | None, cwd: object, policy: LaunchPolicy, shell: bool = False, executable: object = None, missing_ok: bool = True) -> None` raises `AssertionError`:
  - `shell=True` with a `str` command is checked as the argv `["/bin/sh", "-c", command]`; any other non-list/tuple argv, an empty argv, or an element that is neither `str` nor `os.PathLike` is refused with `the guard needs a non-empty argv list`.
  - The program is `executable` when given, else `argv[0]`. A program containing `/` resolves against `cwd` (or `os.getcwd()`) and then `os.path.realpath`, whether or not it exists; a bare name resolves with `shutil.which` on `env["PATH"]` (or `os.environ["PATH"]`); a bare name found nowhere is allowed when `missing_ok` (nothing can run; Popen raises FileNotFoundError) and refused otherwise.
  - Allowed when the resolved path is under `allowed_root`, under `checkout/scripts/`, equal to `checkout/install.sh` or `checkout/setup.py`, or in `interpreters` or `utilities`. Otherwise refuse with the existing wording: `the suite tried to run the host's {name} at {resolved}; plant a fake under tmp_path instead` (tests match `host's <name>`).
  - When the resolved program is an interpreter whose basename is one of sh, bash, zsh, dash, the remaining argv is checked by the shell rules below.
- Shell rules (D-18): scan leading option tokens (a short cluster such as `-f`, `-ec`, `-lc`; long options such as `--norc` are skipped; a cluster ending in `o` consumes the next token; a bare `--` ends the options). A cluster containing `n` means no-exec: allowed. A cluster containing `c` means the first remaining argument is the script: `check_script` it (missing script: refused). Neither: the first remaining argument is a script file that must resolve under `allowed_root` or the checkout roots; no file argument (a script on stdin) is refused.
- `check_script(script: str, *, env, cwd, policy) -> None`: refuse an empty or blank script; refuse when the text contains `$(`, a backtick, `<(` or `>(`; tokenize as in the interfaces (a `ValueError` is refused); split into commands on tokens made only of `;`, `&`, `|` and newline characters; per command skip leading redirection operators with their target and `NAME=value` words; the keywords `{ } ( ) ! if then elif else fi while until do done` are skipped and the next word is the command word, `for` skips the rest of its command, any other compound keyword (`case`, `select`, `function`, `coproc`, `[[`) and `eval` are refused; a `name ()` or `name ( )` definition records `name`; `command -v` / `command -V` / `type` are lookups and pass; `command`, `builtin` and `exec` are dropped and the next word is checked; `.` and `source` take a file that must resolve under `allowed_root` or the checkout roots, and a sourced checkout file adds the function names it defines (lines matching a `name()` or `function name` header); words in `SHELL_BUILTINS` pass; any other command word, with the rest of its command as arguments, goes through `check_launch(..., missing_ok=False)` recursively (so a nested `sh -c` is parsed too and an unresolvable or `$`-word is refused).
- `SHELL_BUILTINS` starts as: echo, printf, test, [, true, false, cd, export, unset, set, exit, return, ., source, command, type, local, shift, :, alias, unalias, read, wait, trap, hash, typeset, declare, readonly, print, whence, setopt, unsetopt, emulate, autoload, builtin. Only shell builtins that run no external program may ever be added.
- Script refusal wording: `the suite tried to run a shell script the guard cannot check ({reason}); move it into a file under tmp_path and run it as bash <file>: {script!r:.200}`; never include environment values in any message (GH_TOKEN canon).
