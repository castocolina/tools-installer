## Summary

All design decisions are locked, so the work is an ordered refactor across three independent tracks: (A) catalog and machinery deletion plus retired receipts, (B) the npx shim and launch repair, (C) test-infrastructure hardening plus e2e/Makefile pins. Track C is the riskiest because widening the guard will fail existing tests that today silently launch `uv`, `git`, `sh -c` scripts, and linuxbrew `zsh`; those must each get a fake under `tmp_path` (SPEC prohibition), never an allowlist widening.

Key facts verified this session: the pre-phase suite (`uv run pytest -n auto -q -rs -p no:cacheprovider --no-cov`, 6 workers) finishes with no failures and exactly **4 skips** (baseline, see below). The `with-fd` tests currently run (they are not in the skip list), so D-19 adds exactly two new expected skips on this host. The existing guard (`GuardedPopen`, `conftest.py:~52-105`) only checks `argv[0]` against nine names; `redirect_shim_script` is still `exec <target> dlx "$@"` (`guards.py:145-149`).

**Primary recommendation:** Sequence as: Wave 0 baseline + fingerprint/sandbox primitives with their own unit tests; then deletion (A) and shim (B) in parallel; then switch the guard on and fix fallout test-by-test; finish with e2e/Makefile pins. Land the guard switch last among test-infra changes so earlier waves are not blocked by fallout.

## Architecture Patterns

### Dataflow

```
registry.toml --load--> model.parse (kind tuple, no skill_pack) --> Tools
receipts dir --list_retired_receipts (ids not in Tools, TOOL_ID_RE)--> retired Tool(synthetic, methods=())
        --> UninstallInputs predicate --> UninstallScreen section / run_uninstall headless
        --> removal_plan -> _receipt_proof(retired shape proof) -> remove_paths -> receipt retire

setup.py launch --> _launch_repairs(): strip_legacy_aliases(rc) + rewrite_outdated_npx(shim_dir) --> notice lines
npx argv --> shim (sh): option loop -> --package=X / drop -y / refuse other -* --> exec <pnpm> dlx --package=.. cmd "$@"

pytest_configure: strip PATH(linuxbrew+home+/run/user), clear env, build interpreters link dir
 per test: autouse fixture re-applies via monkeypatch; GuardedPopen/os.* wrappers -> allowlist check
          (checkout roots | basetemp execs | interpreters by realpath | sh -c parser)
 socket guard (AF_INET*, getaddrinfo) ; session: fingerprint(real_home) before/after -> diff on fail
```

### Recommended structure
- `tests/sandbox.py` (recommended over growing `conftest.py`, which is already 411 lines): pure functions `check_launch(argv, env, cwd, ...)`, `parse_shell_script(...)`, `fingerprint(home, overrides)`, `fingerprint_diff(a, b)`, `socket_guard`. conftest only wires fixtures. This also lets `tests/test_sandbox.py` test them with a scratch home.
- `installer/guards.py`: `npx_shim_script(target)` replaces the REDIRECTED body path; `rewrite_outdated_npx(shim_dir, target?)` returns `((text, severity), ...)`.
- `installer/receipts.py`: listing helper; `installer/uninstall.py`: retired-aware `_receipt_proof`.

### Anti-Patterns to Avoid
- Widening the allowlist to `uv`/`git`/`curl`/`gh`/`brew` to make a test pass: forbidden by SPEC; plant a fake under `tmp_path`.
- Re-resolving pnpm when deciding "outdated" (D-13): flip-flops the file per launch route.
- Typing a receipt's own recursive deletes or a home-wide proof rule (D-07).
- Opening files in watched dirs in the fingerprint (credentials live there).

## Common Pitfalls

### Pitfall 1: Guard fallout order
**What goes wrong:** Turning on the allowlist first produces dozens of failures mixed with real defects.
**Avoid:** Record baseline first (done below), land helpers with their own tests, enable the guard last; fix each failing test with a `tmp_path` fake. Known launchers to handle: `bash`/`sh`/`zsh` (14+10 call sites), `sys.executable` (resolves into real HOME uv python, so realpath allowlist, not a PATH rule), `stdbuf` (`tests/test_run.py:742`), `systemd-environment-d-generator` (`tests/test_env_redirect.py:25-30`), `git ls-files` in `tests/test_screen_family.py:3683-3692` (walk in Python), `node` in two `test_sandbox` cases (already expecting a raise), `launchctl` (macOS-only, skip stays).
**Warning signs:** a failure message that says "plant a fake" for a name like `uv` or `git`.

### Pitfall 2: `pytest_configure` env strip vs. import-time captures
`tests/test_prune_user_tmpdir_sh.py:67,74`, `test_shellrc.py`, `test_tweaks.py:360` read PATH at import (D-16). Strip in `pytest_configure` before collection, AND capture overrides (`UV_TOOL_DIR`, `PNPM_HOME`, `VOLTA_HOME`) at conftest import before clearing. Under xdist each worker runs `pytest_configure`, so state must be per-process (no shared files).

### Pitfall 3: Python `subprocess` bypasses `Popen` on some paths
`subprocess` may call `os.posix_spawn` after `GuardedPopen` already checked, so wrappers must be idempotent (D-21). Wrap `posix_spawnp` only if present on the platform (macOS has it, so does Linux; guard with `hasattr`).

### Pitfall 4: Socket guard breaks asyncio/Textual/xdist
Block only `AF_INET`/`AF_INET6`, including the default family when none is given. `socketpair()` returns `AF_UNIX` and asyncio self-pipe works (verified in CONTEXT D-22 scratch check). The guard must also apply in Textual worker threads (patching the class applies process-wide; do not use thread-local state).

### Pitfall 5: Fingerprint false failures
D-25 keeps "any change" failing; message must name path + entries so a concurrent agent writer (systemd `ai-kit-session-wake-*` units, `~/.cursor`, `~/.local/bin`) is recognizable. Surface the open confirmation to the user at the plan-checker/verify step. Compare listings as sets of raw `str` (non-UTF-8 names included), directories also by `st_mtime_ns`; absent -> `None`; absent -> created is a change.

### Pitfall 6: Shim rewrite touching foreign files
Rewrite only if `lstat` says regular file AND body contains `REDIRECT_SENTINEL` AND is the npx redirect (not the npm/pnpm `GLOBAL_REDIRECTED` wrappers, which share the sentinel, `guards.py:231`). Hard-block bodies carry only `SHIM_SENTINEL` (`guards.py:116-117`). Compare to the body rendered with `exec_targets(old)[0]` (`guards.py:642-655`) so a second launch writes nothing.

### Pitfall 7: Receipts as untrusted input
A hand-edited receipt must never authorize deletes beyond the D-07 placement-shape rules; corrupt (`receipts.read() is None`) is reported and never deleted; unreadable dir yields a warning not a crash; ids must match `TOOL_ID_RE` (`receipts.py:37,102`).

### Pitfall 8: Dead code after deletion trips vulture
`make validate` runs vulture over `installer/`; every symbol only used by pack code (labels, scopes, enums, `RECONFIGURE` consumers listed in D-02 "Kept") must go in the same commit as its last user. Keep `HARNESS_MARKER_DIRS` and `RECONFIGURE`.

npx translator sketch (POSIX sh; verify with `sh -n` and a fake pnpm):
```sh
#!/bin/sh
# tools-installer-redirect-shim
pkgs=''   # build via set -- rotate to preserve quoting; do not use a flat string
while [ "$#" -gt 0 ]; do
  case "$1" in
    -y|--yes) shift ;;
    -p|--package) [ "$#" -ge 2 ] || usage; set -- ...  # append --package=$2
    --package=*) ...
    -*) echo "tools-installer: npx option $1 is not supported through pnpm dlx" >&2; exit 127 ;;
    *) break ;;
  esac
done
[ "$#" -gt 0 ] || { echo usage >&2; exit 127; }
exec '<target>' dlx --package=... "$@"
```
Implementation note: collecting kept options requires rotating the remaining command args behind them; the simplest correct form is two passes (first pass validates and counts, second builds `--package=` list into positional params with a marker), or accumulate packages in a loop that `set --`s a prefix list and then re-appends the rest after the loop. Test with args containing spaces, quotes, `$x`, and `--package` given twice (SPEC encoding/adjacency edges). Final line must start with `exec ` so `exec_targets` still yields `words[1]` (D-11).
