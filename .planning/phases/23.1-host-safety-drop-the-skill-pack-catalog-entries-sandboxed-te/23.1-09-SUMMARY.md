# Phase 23.1 Plan 09: launch-time npx redirect and guard alias repair Summary

An installer-written `npx` redirect with an older body and an old guard alias block (`alias npx='pnpm dlx'`) are rewritten on the next launch of any route, each with one notice, through one `_launch_repairs()` composition; the docs and AGENTS.md no longer call `make doctor` safe.

## What was built

- `installer/guards.py::rewrite_outdated_npx(shim_dir)`: touches only `shim_dir/npx`; own `os.lstat` must say regular file, own `read_capped(..., follow_symlinks=False)`, `REDIRECT_SENTINEL` and an `exec` target required, equal bytes skip, otherwise `atomic_write_text(path, body, mode=0o755)`. An `OSError` becomes the warn line. It never calls `is_our_shim` and never raises.
- `setup.py::_launch_repairs()` returns `(strip_legacy_aliases(_MYSHELLRC), (*rewrite_outdated_ban_aliases(all_ban_rc_paths()), *rewrite_outdated_npx(_DEFAULT_BIN_DIR)))`. `_print_repairs(console, legacy, repairs)` prints the legacy launch lines then the repair lines (`markup=False, soft_wrap=True`). Call sites: `_build_app` (into `startup_lines`), headless install in `main`, `_run_uninstall` headless (after the existing uninstall/failure lines), `_run_doctor` and `_run_fix` non-TTY, `_run_guard` (both directions). `strip_legacy_aliases(` now appears once in setup.py (baseline 3).
- Docs: AGENTS.md doctor line, Makefile `doctor` help, README command tables and the "PATH doctor & fix" paragraph; the AGENTS.md "Never mutate the developer's host" bullet names all six targets with the reason.
