### Recorded rule for C-06 (decision 4: the stricter consistent rule)

D-20's blanket roots (`scripts/`, `install.sh`, `setup.py`) are replaced by a reviewed table.
`tests/sandbox.py::CHECKOUT_SCRIPTS` lists each checkout file a test may run or source, with the
toolchain names it may reach:

- `install.sh`: curl, wget, git, uv
- `scripts/prune-user-tmpdir.sh`, `scripts/prune-tmp-linux.sh`, `scripts/lib/prune-tmp-common.sh`: none

Each name must resolve, on the PATH the child sees, to a fake under the base temp or to nothing. The
rule is the same for a direct run, a shell's script argument and a `.`/`source` target, which closes
X-01's sourced route along with WR-03's direct route. `setup.py`, `container-e2e-verify.sh`,
`detect-container-runtime.sh` and any new script are refused until someone reviews them into the
table. D-18's function collection from a sourced checkout file still applies, but only after this
check passes. This is the "existing sandboxed contract the plan allowed": the install.sh tests run
against stubs (now with a fake-only PATH), and the prune tests run against a tmp TMPDIR. The
no-runtime e2e pin keeps copying its script under `tmp_path`.

### Recorded refinement for C-02 (decision 2)

Decision 2 says "anything not proven is listed as `remove it yourself`". That holds for shape and
pairing failures. A path that another readable receipt records is neither proven nor listed on the
retired row. Listing a live tool's link or opt dir as "remove it yourself" would tell the user to
break that tool. It would also leave the retired row stuck at level `none` for good, because a
non-empty `yourself` blocks the receipt-only retire. With the path left out, a renamed id's stale
receipt retires alone, and the live receipt is not drifted. This is pinned by
`test_a_retired_receipt_never_removes_what_a_live_receipt_records`. When two retired receipts share a
path, the first retires its receipt. The second's post-confirm re-plan then sees the path as proven,
and it is refused as "changed since the preview". The next run removes it through the remaining
receipt. Nothing is deleted while the claim is shared.

## Residuals and not-fixed rows

### C-14: IN-01, a refusal from a leftover thread can fail the wrong test (residual)

**File:** `tests/sandbox.py` (`_REFUSALS`), `tests/conftest.py` (`refusals_fail_the_test`)
**Reason:** Tagging each refusal with a node id needs the running test's identity in every guard
wrapper, including the os launchers and Popen, which have no request object. Then setup has to fail
on leftovers instead of discarding them, and `refused()` needs a registry-only mode. That is a larger
redesign of the registry. It fixes a test-blame problem, not a host-safety hole: a late refusal still
fails some test, and the launch is still refused. No current test leaves a launching thread behind.
Upgrade if a flaky "wrong test failed" report ever points here.

### C-12 part 2: IN-05, `_retired_leftovers` may list any recorded path, `/etc/passwd` included (residual)

**Reason:** No binding decision covers it. The path is only printed, sanitized, as "remove it
yourself" and is never deleted. Limiting the list to HOME would hide a stale receipt's real non-HOME
leftovers from the user. Revisit along with any receipt-signing work.

### C-13 part 2: `_build_app` startup lines drop the warn/ok severity (residual)

**Reason:** Cosmetic: the TUI startup banner shows warnings and notices in one style. No binding
decision covers it, and it changes the startup widget contract. Defer to the next UI pass.

### C-17: PT-05, three near-copies of the retired wording (residual)

**File:** `installer/app.py::_print_retired_preview`, `installer/wizard_app.py::_retired_detail`, `::_retired_review_lines`
**Reason:** Not a small consolidation. The three outputs differ by design under UI-SPEC section 2.
The detail bar is one line, returns early on a manager hint and adds the "re-checked before
deletion" note. The CLI preview is a multi-line block with the hint after the paths. The confirm
review uses `<id>: deletes ...` lines. One shared clause function would change wording that
`test_retired_preview_lines_cover_every_case` and the TUI tests pin.

### C-18: PT-06, the receipt is read up to five times per retired plan (residual)

**Reason:** Not a small consolidation. The reads happen in `plan_removal` (via `receipt_exists`,
`_receipt_proof` and `_retired_leftovers`) and in `removal_plan`/`remove_tool`, and `plan_removal`
is the shared public prover. Passing one `Receipt` through it changes its signature for every caller.
The reviewer marked this as harmless at the expected load ("Nothing breaks"). C-02 adds one more scan
(`recorded_elsewhere`) for retired tools only.

**Reason:** Decision 8. Locked D-01 moved the full 17-host table, and Phases 24 and 24.3 add hooks
