# Phase 23.1 Plan 16: Retired receipts wired into the composition root Summary

**`--uninstall --yes` removes retired receipts with their proven files and is idempotent, corrupt receipts are named at launch and kept, and the Uninstall view gets a live `retired` predicate for 23.1-17**

## Accomplishments

- Headless `--uninstall --yes` passes the retired receipts to `run_uninstall`, so a retired download's bin file and receipt are removed through the shared remover, and a second run prints no retired section (SPEC R3, edge R3 idempotency).
- A corrupt receipt for an absent id prints one `Ignored the corrupt receipt ...` line before the preview and is never deleted; an unreadable receipts folder prints one `Could not read the receipts folder ...` line and the launch still exits 0 (T-23.1-39).
- The TUI startup warning carries the same corrupt-receipt lines once per launch. `UninstallInputs.retired` re-lists retired receipts on every call and never adds a warning (review R1-55).
- Install routes never receive a retired id: the headless `run_wizard` and the TUI catalog both get the catalog list only (T-23.1-40).

## Decisions Made

- The installed map and the daemon policy stay catalog-only; retired tools join the teardown list only.
- One launch scan supplies the startup warnings; the predicate's scan discards its warnings. A cheaper single scan was rejected by the plan because the predicate must re-list on every publish (D-09).
- The unreadable-folder test uses `chmod 0` with a root skip, per the plan. The existing `deny_receipts_dir` helper wraps only `stat`, `lstat` and `open`, so it does not simulate a failed directory listing.
