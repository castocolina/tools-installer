## Critical Issues

### CR-01: Guard approves any bare program name when the launch `env` has no `PATH`; Popen then runs it from `/bin:/usr/bin`

**Severity:** BLOCKER
**File:** `tests/sandbox.py:471` (also reached through `tests/conftest.py:81-88` GuardedPopen and `tests/conftest.py:136-141` os launchers)
**Evidence:**
```python
found = shutil.which(program, path=(env if env is not None else os.environ).get("PATH", ""))
literal = Path(found) if found is not None else None
...
if resolved is None or not resolved.exists():
    if missing_ok:          # default True for the top-level argv
        return
```
`shutil.which(..., path="")` returns `None`. But CPython's POSIX `_execute_child`, and `os._execvpe`, search `os.get_exec_path(env)`. When `env` has no `PATH`, that function falls back to `os.defpath` (`:/bin:/usr/bin`). The guard reads that launch as "exists nowhere", step 3 allows it, and the child runs the real host binary. Bytes environments such as `os.environb` slip through the same way, because `.get("PATH")` misses the `b"PATH"` key.
**Reproduction (scratch, under the real conftest):** `test_env_without_path_runs_a_host_program` passes. `subprocess.run(["true"], env={"HOME": "/nonexistent"})` returns 0 from `/usr/bin/true`, and the same call with the inherited env is refused (`test_same_program_with_path_is_refused`). With the pure check, `git`, `curl`, `systemctl` and `flatpak` are all `ALLOWED` with `env={"HOME": "/tmp"}`.
**Failure scenario:** A test isolates a child with the common idiom `env={"HOME": str(tmp_path)}`, as `tests/test_shellrc.py:489` already does for a bash child. If code under test, or the test itself, then launches `git`, `systemctl --user ...` or `flatpak`, the real host binary runs with no refusal recorded. That breaks SPEC R6 and the "never mutate the developer's host" rule. The same hole covers `os.execvpe` and `os.posix_spawnp` with a PATH-less env.
**Fix:** Search exactly what the exec layer searches:
```python
search = os.pathsep.join(os.get_exec_path(env))  # PATH-less env -> os.defpath; bytes keys handled
found = shutil.which(program, path=search)
```
Add a `test_sandbox` case asserting that `check_launch(["true"], env={"HOME": "/x"}, ...)` raises.

## Warnings

### WR-01: Shell functions are collected up front, so a call before (or without ever running) its definition skips the check

**Severity:** WARNING
**File:** `tests/sandbox.py:323-325`, `tests/sandbox.py:382`
**Evidence:** `_ScriptChecker.run` adds every `name ( )` in the script to `self.functions` before checking any command. `word()` then skips any word in that set. Position and control flow are ignored.
**Reproduction:** `check_launch(["/bin/sh", "-c", "git --version; git() { :; }"], ...)` returns ALLOWED, and the real git runs first. So does `if false; then uv() { :; }; fi; uv sync`.
**Failure scenario:** A test stubs a tool as a shell function but defines it after the first use, or only in one branch. The real binary runs, and the guard advertises that every command word is checked (D-18).
**Fix:** Register a function only when the parser reaches its header, in order. `command()` already sees `name ( )` at `:350`, so add the name there and drop the up-front pre-scan. Refuse any function definition that is nested inside `if`/`while`/`{`, or treat such names as unknown.

### WR-02: `check_shell_args` lets `bash -s <path>` and `bash --rcfile/--init-file <f> -c '<cmd>'` through unchecked

**Severity:** WARNING
**File:** `tests/sandbox.py:416-448`
**Evidence:** A `--long` option skips one word, so `--rcfile f` treats `f` as the script. The `-c` after it is never seen, and `_file_allowed(f)` passes for any name under tmp. A `-s` cluster is neither `c` nor `n`, so the next argument is judged as a script path, and that path does not even need to exist. The real script then comes from stdin and is never checked.
**Reproduction:** All three print `ALLOWED`: `[bash, "-s", str(root / "x")]`, `[bash, "--rcfile", rc, "-c", "git status"]` and `[bash, "--init-file", rc, "-c", "curl x"]`.
**Failure scenario:** `subprocess.run(["bash", "-s", str(tmp_path)], input="curl ...")` runs a host program.
**Fix:** In the option loop, refuse `s` in any cluster. Treat `--rcfile`, `--init-file` and `-O`/`+O` as taking a value (skip 2), and keep scanning for `-c` after them. Refuse any long option that is not known.

### WR-03: The allowlist launches `install.sh` and every `scripts/*` file directly, yet R10 forbids `make test` from running them

**Severity:** WARNING
**File:** `tests/sandbox.py:150-159`, `tests/sandbox.py:500`, `tests/sandbox.py:446-448`
**Evidence:** `_under_checkout_roots` allows `install.sh`, `setup.py` and everything under `scripts/` as launch targets. A script file is judged by its location only, never by its content. `install.sh` is `#!/bin/sh`, executable, and bootstraps uv and the wizard.
**Reproduction:** `check_launch([CHECKOUT/"install.sh"])` and `[bash, "scripts/container-e2e-verify.sh", "all"]` are both `ALLOWED`.
**Failure scenario:** A test runs `bash install.sh` or the e2e script with the inherited, sandboxed PATH. That PATH still holds `/usr/bin/curl`, `podman` and `systemctl`. The script's children run unguarded: a real bootstrap, or real containers. `tests/test_makefile.py` only pins the Makefile recipes, not tests.
**Fix:** Allow these files only as `.`/`source` targets, which is the one shape the suite uses for them (`tests/test_sandbox.py:526` sources `install.sh` for `detect_os`). Allow direct execution only for named, reviewed scripts that the tests already fake around (for example `prune-user-tmpdir.sh` with a tmp TMPDIR). Refuse `install.sh`, `setup.py` and `container-e2e-verify.sh` as launch programs. `test_e2e_script_refuses_without_a_container_runtime` copies the script under tmp_path, so it keeps working.

### WR-04: An allowlisted interpreter skips its argv check unless its realpath basename is a shell name; Python children run unguarded

**Severity:** WARNING
**File:** `tests/sandbox.py:476-485`, `tests/sandbox.py:100`
**Evidence:** In step 1, a member whose `resolved.name` is not in `_SHELL_NAMES` returns with nothing checked. `sys.executable` is such a member, so `[sys.executable, "-c", "import subprocess; subprocess.run(['git', ...])"]` is allowed. That child is a fresh interpreter: no conftest, no GuardedPopen, PATH still containing `/usr/bin`. Separately, the shell detection keys off the basename of the realpath. A bash whose realpath is `bash5.2`, or a busybox-backed `sh` (where `wget` and every applet resolve to the same allowed binary), skips the script check entirely.
**Reproduction:** `test_python_child_is_unguarded` runs `true` from a `sys.executable -c` child under the real conftest, and nothing is refused.
**Failure scenario:** One of the 33 `sys.executable` launch sites in `tests/` grows an `-c` body or a helper script that calls a toolchain. It runs for real.
**Fix:**
- Store the shell members as their own set: `LaunchPolicy.shells` comes from the sh/bash/zsh lookups in `build_launch_policy`. Check args by membership in that set, not by `resolved.name`.
- For Python children, export `PYTHONPATH=<a tmp dir with sitecustomize.py>` in the sandboxed environment. That `sitecustomize.py` installs `check_launch` around `subprocess.Popen` and the os launchers. Alternatively, require `-c` bodies to come from files under tmp_path and refuse `-c`/`-m`.

### WR-05: The socket guard leaves `gethostbyname`, `gethostbyname_ex`, `gethostbyaddr` and `getnameinfo` unpatched, despite the "no name lookup" claim (SPEC R8)

**Severity:** WARNING

### WR-06: Retired-receipt proof ignores paths owned by a live catalog tool's receipt, so retiring a stale receipt can delete a current install

**Severity:** WARNING
**File:** `installer/uninstall.py:167-179` (`_receipt_proof`, retired branch), `installer/uninstall.py:262-275` (`plan_removal`), `installer/app.py:922-932`
**Evidence:** A retired tool is proven from its own receipt alone: shape plus drift check. `removal_plan(tool, ...)` calls `plan_removal([tool])` with just that tool. Neither `scan_retired` nor the removal checks whether a catalog tool's readable receipt records the same `~/.local/bin/<n>` link or `~/.local/opt/<n>` dir.
**Failure scenario:** A registry id is renamed (`foo` becomes `foo-cli`) while the binary name stays the same. Or an old receipt survives a reinstall under a new id. If the installed version matches, the key-file digest matches, so the old `foo.json` re-proves cleanly. The Uninstall view offers `foo (retired)`. Confirming it unlinks `~/.local/bin/<n>` and rmtrees `~/.local/opt/<n>`, which belong to the live `foo-cli`. The live receipt is then left drifted ("changed since install"). This is data loss that the "MUST NOT delete a path that is not recorded" rule does not cover: the path is recorded, but by both receipts.
**Fix:** Pass the catalog's receipt claims into the retired proof. Build `claimed = {a.path for tid in catalog_ids if (r := receipts.read(tid)) for a in r.artifacts}` and drop any retired artifact in `claimed`. Show those paths under "remove it yourself", or leave them out. Add a test with two receipts that claim the same link and dir.

### WR-09: GSD-absent tracer fails open on any exec error and checks a narrower set than the unit-test net

**Severity:** WARNING
**File:** `scripts/container-e2e-verify.sh:341-354`
**Evidence:** `if exec_tester "test -e ... || test -L ..."` treats every non-zero exit as "absent". A stopped container (`podman exec` exit 125), a failed `su`, or a broken `ct` therefore prints `TRACER_GSD_ABSENT_OK`. The tracer also checks only `.claude/gsd-core` and `.claude/.gsd-source`. `tests/home_fingerprint.py:25-31` watches `.claude/gsd-file-manifest.json`, `.claude/agents`, `.claude/commands`, `.claude/hooks` and `.gsd` as well. Separately, `TRACER_GSD_PRESENT path=%s` prints the literal string `$HOME/...`, because the argument is escaped.
**Failure scenario:** After the uninstall pass, the container dies or `su` breaks. The tracer still reports GSD absent, so the R10 gate passes on no evidence. A global GSD install that writes only `~/.gsd` or `~/.claude/commands/gsd` is never caught either.
**Fix:** Run one probe that must print a completion token, and fail when the token is missing:
```bash
out=$(exec_tester 'for p in .claude/gsd-core .claude/.gsd-source .claude/gsd-file-manifest.json .gsd; do
  if [ -e "$HOME/$p" ] || [ -L "$HOME/$p" ]; then echo "PRESENT $HOME/$p"; fi; done; echo PROBE_DONE') || return 1
grep -qx PROBE_DONE <<<"$out" || return 1
```
Report each `PRESENT` line, which then carries the expanded path.

## Info

### IN-01: The refusal registry can blame the wrong test or drop a refusal, and `refused()` cannot consume a refusal that was caught

**Severity:** WARNING (test reliability)
**File:** `tests/sandbox.py:510-551`, `tests/conftest.py:144-154`
**Issue:** `_REFUSALS` is process-wide, with no test identity attached. A refusal raised by a thread that outlives test A is recorded during test B and fails B. The scratch pair `test_refusal_from_late_thread_is_lost` and `test_next_test_absorbs_the_late_refusal` shows B failing on A's launch. A refusal that lands between A's teardown check and B's setup `take_refusals()` is silently dropped. Also, `refused()` fails with "none was raised" when the code under test catches the AssertionError. So a test cannot assert a refusal that a broad `except` swallowed. That is exactly the case the registry exists for.
**Fix:** Record `(nodeid, message)` using the `describe()` hook that the socket guard already has. At setup, fail on leftovers instead of discarding them. Give `refused()` a mode that checks only the registry, without requiring a raise.

### IN-02: `rewrite_outdated_npx` replaces whatever is at `npx` at rename time, not what it read

**Severity:** WARNING (narrow race)
**File:** `installer/guards.py:726-741`
**Issue:** Between `read_capped` and `os.replace`, a real npx dropped into `~/.local/bin` (an npm or Volta install running at the same moment) is overwritten. That breaks "a foreign npx is never modified" for that window. `installer/atomic.py` already has `read_snapshot`/`snapshot_matches`, built for this compare-before-replace pattern.
**Fix:** Take a `FileSnapshot` with the read and check `snapshot_matches` right before `atomic_write_text`. Skip silently on a mismatch.

### IN-03: The guard-alias rewrite normalizes newlines and decodes with the locale everywhere in the rc file

**Severity:** WARNING (user lines changed)
**File:** `installer/guards.py:651-656` (`write_ban_aliases`, reached from `rewrite_outdated_ban_aliases` at `:699`)
**Issue:** `rewrite_outdated_ban_aliases` reads the file as UTF-8 bytes and finds the block. It then calls `write_ban_aliases`, which re-reads with `Path.read_text()`. That read uses universal newlines, so every `\r\n` or `\r` in user lines outside the block becomes `\n`, and the decoder is the locale's. A file with mixed endings, whose block lines are LF, therefore gets user lines changed by a "marker-owned only" launch repair. The repair now runs on every launch route, so this is newly reachable without any user action.
**Fix:** Pass the bytes already read to `apply_block` and write them back. Or read with `open(..., newline="", encoding="utf-8")` in `write_ban_aliases`.

### IN-04: Repair notices print on routes that undo the repair right away

**Severity:** WARNING (misleading output)
**File:** `setup.py:1401` (`_run_guard`, including `--unguard`), `setup.py:1362-1369` (`_run_uninstall`)
**Issue:** `--unguard` prints "Rewrote the guard aliases in ~/.zshrc: npx now runs through its redirect.", then removes that block. `--uninstall --yes` prints "Rewrote the npx redirect at ~/.local/bin/npx…", then `remove_shims` deletes it. The `_build_app` startup lines also drop the `warn`/`ok` severity.
**Fix:** Skip `rewrite_outdated_*` when the route is going to remove guards (`remove=True` or uninstall), or suppress their `ok` lines there. Keep severity when building `startup_lines`.

### IN-05: Text taken from a hand-edited retired receipt reaches the console without sanitizing and with markup on

**Severity:** WARNING
**File:** `installer/app.py:1072`, `installer/app.py:1097`, `installer/uninstall.py:225-234`
**Issue:**
- `console.print(line)` prints `changed since the preview; not removed: <path>` with Rich markup enabled and no `sanitize_log_line`. The same holds for `remove failed — {outcome.detail}`. A retired receipt's proven paths can carry any byte except `/` and NUL in their name, including ESC and `[...]` markup.
- `_retired_leftovers` lists any recorded path that exists, `/etc/passwd` included, as "remove it yourself". So a hand-edited receipt can make the installer advise deleting a system file.

The new retired preview sanitizes. These two pre-existing lines are newly fed with receipt-originated paths.
**Fix:** Print both lines with `markup=False` through `sanitize_log_line`. Limit `_retired_leftovers` to paths under HOME, or under `bin_dir`, `opt_dir` and `applications_dir`.
