Interfaces this plan creates:
- `MARKER = "# tools-installer: pre-push gate (installed by make dev-setup; do not edit)"`
- `PRE_COMMIT_HEADER = "# File generated by pre-commit"`: the second line of pre-commit's own hook template (`pre_commit/resources/hook-tmpl`). A regular `pre-commit` hook holding it is pre-commit's own; one without it is foreign (D-29).
- `SHIM`, the exact shim text, five logical parts in this order: `#!/bin/sh`; MARKER; `if ! command -v uv >/dev/null 2>&1; then`; `echo "pre-push: uv not found on PATH; install uv (see README) or push from a shell that has it" >&2` then `exit 1` then `fi`; `exec uv run python -m devtools.push_gate "$@"`. It ends with a newline.
- `Runner = Callable[[Sequence[str]], subprocess.CompletedProcess[str]]`, which receives the full argv. The default runner sets `LC_ALL=C` in the child environment (`{**os.environ, "LC_ALL": "C"}`), so git's messages are untranslated and the not-a-repository check reads the same text in every locale.
- `def install(*, run: Runner | None = None, which: Callable[[str], str | None] = shutil.which) -> int`
- `def main(argv: Sequence[str] | None = None) -> int`: accepts exactly the verb `install`, and anything else is an argparse usage error with exit 2. Plus `if __name__ == "__main__": sys.exit(main())`.

Facts (RESEARCH Pattern 4, verified live):
- `git rev-parse --path-format=absolute --git-common-dir` prints the absolute common dir: `<repo>/.git` in the main checkout and in a linked worktree alike. `--git-dir` prints `<repo>/.git/worktrees/<name>` in a worktree. Outside a checkout it exits 128 with `fatal: not a git repository (or any of the parent directories): .git`. Other fatal errors exit 128 too (for example `fatal: detected dubious ownership in repository`), so the exit code alone cannot tell "not a checkout" apart from a broken one (review M4).
- `git config --get core.hooksPath` exits 1 with empty output when the key is unset. With the key set, `pre-commit install` prints "Cowardly refusing to install hooks with `core.hooksPath` set." and exits 1. The installer checks the key itself first, so its own message names the key and the fix.
- `pre-commit install` moves a foreign hook to `<hook>.legacy`, prints "Running in migration mode…", exits 0, and leaves its own hook byte-identical on a rerun. It bakes `INSTALL_PYTHON` (the python that ran it) into the hook (Pitfall 3).
- The migration is unsafe in two cases (`pre_commit/commands/install_uninstall.py`, 4.6.0, review C2-H2): `:75-77` runs `shutil.move(hook_path, legacy_path)` whenever the hook exists and is not pre-commit's, and on Unix that renames over an existing `pre-commit.legacy`; `:56-61` `is_our_script` follows a symlink and `:93` `open(hook_path, 'w')` writes through it. pre-commit recognizes its own hook by an ID hash; its template's header line `# File generated by pre-commit` sits next to that hash, so the installer uses the header (no import of pre-commit internals, which have no type stubs). A hand-edited hook that keeps the header but drops the hash is the accepted residual (T-26-41).
- bandit skips only B404, B603 and B310. B607 (partial executable path) is avoided by passing absolute paths from `shutil.which`. B103 flags a chmod that grants group or other exec or write, so the shim mode is 0o744.
- The existing ci.yml step `Install dependencies` runs the old bootstrap target. Branch protection's required contexts are the job names, which this plan does not touch.
