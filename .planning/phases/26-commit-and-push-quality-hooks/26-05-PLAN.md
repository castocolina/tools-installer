Interfaces this plan creates:
- `MARKER = "# tools-installer: pre-push gate (installed by make dev-setup; do not edit)"`
- `SHIM`, the exact shim text, five logical parts in this order: `#!/bin/sh`; MARKER; `if ! command -v uv >/dev/null 2>&1; then`; `echo "pre-push: uv not found on PATH; install uv (see README) or push from a shell that has it" >&2` then `exit 1` then `fi`; `exec uv run python -m devtools.push_gate "$@"`. It ends with a newline.
- `Runner = Callable[[Sequence[str]], subprocess.CompletedProcess[str]]`, which receives the full argv.
- `def install(*, run: Runner | None = None, which: Callable[[str], str | None] = shutil.which) -> int`
- `def main(argv: Sequence[str] | None = None) -> int`: accepts exactly the verb `install`, and anything else is an argparse usage error with exit 2. Plus `if __name__ == "__main__": sys.exit(main())`.

Facts (RESEARCH Pattern 4, verified live):
- `git rev-parse --path-format=absolute --git-common-dir` prints the absolute common dir: `<repo>/.git` in the main checkout and in a linked worktree alike. `--git-dir` prints `<repo>/.git/worktrees/<name>` in a worktree. Outside a checkout it exits 128 with `fatal: not a git repository`.
- `git config --get core.hooksPath` exits 1 with empty output when the key is unset. With the key set, `pre-commit install` prints "Cowardly refusing to install hooks with `core.hooksPath` set." and exits 1. The installer checks the key itself first, so its own message names the key and the fix.
- `pre-commit install` moves a foreign hook to `<hook>.legacy`, prints "Running in migration mode…", exits 0, and leaves its own hook byte-identical on a rerun. It bakes `INSTALL_PYTHON` (the python that ran it) into the hook (Pitfall 3).
- bandit skips only B404, B603 and B310. B607 (partial executable path) is avoided by passing absolute paths from `shutil.which`. B103 flags a chmod that grants group or other exec or write, so the shim mode is 0o744.
- The existing ci.yml step `Install dependencies` runs the old bootstrap target. Branch protection's required contexts are the job names, which this plan does not touch.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| installer → `.git/hooks` | The hooks directory may hold a user's own hooks; overwriting them is data loss |
| git config → installer | `core.hooksPath` can silently route hooks elsewhere |
| shim → uv | The shim runs whenever git pushes, from any checkout or worktree |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-26-11 | Tampering | `<common>/hooks/pre-push` | high | mitigate | Refuse a file without MARKER (exit 1, untouched, checked before any write); rewrite a marked file only when bytes differ |
| T-26-12 | Elevation of Privilege | `core.hooksPath` bypass | medium | mitigate | The installer checks the key at every scope first and exits 1 naming it and the unset command |
| T-26-13 | Denial of Service | shim without uv | medium | mitigate | The shim prints the cause and exits 1, so git aborts the push (fails closed, never `|| true`) |
| T-26-14 | Denial of Service | commit hook bound to a worktree's venv (Pitfall 3) | medium | mitigate | Warning when git-dir differs from common-dir; docs say to run from the main checkout; agents never run it (D-22) |
| T-26-15 | Tampering | file mode of the shim | low | mitigate | mode 0o744: owner-executable, no group/other write or exec |
| T-26-SC | Tampering | dependency installs | low | accept | This plan installs no package |
</threat_model>
