Facts (RESEARCH Patterns 1-3, verified live with git 2.56.0 and pre-commit 4.6.0):
- stdin lines: an update looks like `refs/heads/main <sha> refs/heads/main <sha>`. A new remote ref has a remote sha of zeros. A deletion looks like `(delete) 000… refs/heads/x <sha>`. A tag line carries the tag object sha, so peel it with `rev-parse --verify <sha>^{commit}`. A `HEAD:feat` refspec gives local ref `HEAD`. Empty stdin happens when nothing needs pushing.
- pre-commit keeps its stash on whenever neither `--all-files` nor `--files` is given (`run.py:344`). It restores on SIGINT only. On SIGTERM, SIGHUP or SIGKILL it dies with the tree reverted and the edits left in `$PRE_COMMIT_HOME/patch*`.
- Hooks share pre-commit's process group (pre-commit never calls setsid), so `os.killpg(child.pid, SIGINT)` also reaches `make` and `pytest`.
- tests/sandbox.py refuses real git, make, uv and pre-commit in pytest. A `sys.executable` child is allowed and is guarded by tests/child_guard/sitecustomize.py. The editable install puts the checkout on sys.path, so a child can import `devtools`.
- bandit skips B404, B603 and B310 only, so programs must be absolute paths from `shutil.which` (B607).

Git queries the gate runs (argv after `git`, all through `GitRunner`):
- unmerged paths: `diff --name-only --diff-filter=U -z`
- staged changes: `diff --cached --name-only -z`
- untracked files: `ls-files --others --exclude-standard -z` (no pathspec), then drop every name that starts with `.planning/` (D-25). git runs `pre-push` from the work tree root, so every name is root-relative, like the other queries.
- gate-read files, ignored or not (D-28): `--glob-pathspecs ls-files --others -z -- <every entry of GATE_READ_PATHSPECS>`. `--glob-pathspecs` is git's global option, placed before the subcommand. With no exclude option git applies no ignore rules, so the result holds every untracked match. `**/` matches zero or more directories, so `tests/**/*.py` also matches `tests/conftest.py`. Verified in a scratch repo with git 2.56.0 on 2026-11-16: ignored and non-ignored matches are both listed, `.venv/conftest.py` is not, the traversal visits 5 directories against 608 for an unbounded listing, and `GIT_LITERAL_PATHSPECS=1` or `GIT_NOGLOB_PATHSPECS=1` makes git exit 128.
- unstaged config: `diff --name-only -z -- .pre-commit-config.yaml`
- HEAD: `rev-parse --verify HEAD`
- a pushed commit: `rev-parse --verify <local sha>^{commit}`

Why refusal 3 covers the whole tree (D-25, review H1): pytest's rootdir is the repo root, so it loads an untracked root `conftest.py`, and an untracked root `pytest.ini`, `.pytest.ini`, `tox.ini` or `setup.cfg` overrides `[tool.pytest.ini_options]`. Likewise `.coveragerc`, `pyrightconfig.json`, a `ruff.toml` in any parent directory, `typings/*.pyi`, a `GNUmakefile` that shadows `Makefile`, `.shellcheckrc`, an installer data file and a doc link target a test resolves all change what the gates see. For non-ignored files a fixed list would miss the next one, and a miss is a green push of a HEAD that fails in CI, which SPEC R3 forbids. `.planning/` stays exempt: SPEC R5 treats it as docs and no gate reads it, apart from the SKILLJUDGE glob of `tests/test_catalog_audit_skill.py:401`. That test checks each file it finds, so an extra untracked file can only add failures and can never hide one.

Why gate-read files count even when ignored (D-28, review C2-H1): pre-commit stashes only tracked edits (`pre_commit/staged_files_only.py:50-82`), so an ignored root `conftest.py`, `pytest.ini` or `GNUmakefile` still changes what pytest or make runs. pytest and pyright do not read `.gitignore`, so an ignored module under the source trees is still collected, type-checked and importable. Ignored files as a whole cannot be refused, because `.venv/` and the tool caches are always present, so `GATE_READ_PATHSPECS` names the two classes that change what runs: config and plugin files the gates load, and the gated sources. An ignored file outside the list (an unlisted config, a data file) is the accepted residual; CI on the pushed commit stays the binding gate. The old advice to ignore any untracked file through `.git/info/exclude` would have turned refusal 3 into a bypass for exactly these files, so the advice now applies only to files no gate reads.
