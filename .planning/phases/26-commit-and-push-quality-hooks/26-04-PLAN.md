Interfaces this plan creates (26-05, 26-06 and the tests rely on these names):
- `RefUpdate`, a frozen dataclass with `local_ref`, `local_sha`, `remote_ref`, `remote_sha` and the property `is_deletion` (local sha is all zeros, whatever its length, so SHA-256 repos work too).
- `GitRunner = Callable[[Sequence[str]], subprocess.CompletedProcess[bytes]]`: it receives the arguments after `git`.
- `PRE_PUSH_ARGS: tuple[str, ...] = ("run", "--hook-stage", "pre-push", "--fail-fast", "--from-ref", "HEAD", "--to-ref", "HEAD")`.
- `def parse_updates(text: str) -> list[RefUpdate]`
- `def refusal(git: GitRunner, updates: Sequence[RefUpdate]) -> str | None` returns the refusal message, or None.
- `class Child(Protocol)` with `pid: int` and `def wait(self) -> int` (what `subprocess.Popen` already satisfies).
- `def run_forwarding_signals(argv: Sequence[str], *, spawn: Callable[[Sequence[str]], Child] = _spawn, killpg: Callable[[int, int], None] = os.killpg) -> int`, where the private `_spawn(argv)` is `subprocess.Popen(list(argv), process_group=0, stdin=subprocess.DEVNULL)`. The two keywords exist so a test can deliver a signal inside the spawn window deterministically (review M3); production callers pass only `argv`.
- `def main(*, stdin: BinaryIO | None = None, git: GitRunner | None = None, run: Callable[[Sequence[str]], int] = run_forwarding_signals, which: Callable[[str], str | None] = shutil.which) -> int`, plus `if __name__ == "__main__": sys.exit(main())`. git passes the remote name and URL as argv; the gate ignores them.

Facts (RESEARCH Patterns 1-3, verified live with git 2.56.0 and pre-commit 4.6.0):
- stdin lines: an update looks like `refs/heads/main <sha> refs/heads/main <sha>`. A new remote ref has a remote sha of zeros. A deletion looks like `(delete) 000… refs/heads/x <sha>`. A tag line carries the tag object sha, so peel it with `rev-parse --verify <sha>^{commit}`. A `HEAD:feat` refspec gives local ref `HEAD`. Empty stdin happens when nothing needs pushing.
- pre-commit keeps its stash on whenever neither `--all-files` nor `--files` is given (`run.py:344`). It restores on SIGINT only. On SIGTERM, SIGHUP or SIGKILL it dies with the tree reverted and the edits left in `$PRE_COMMIT_HOME/patch*`.
- Hooks share pre-commit's process group (pre-commit never calls setsid), so `os.killpg(child.pid, SIGINT)` also reaches `make` and `pytest`.
- tests/sandbox.py refuses real git, make, uv and pre-commit in pytest. A `sys.executable` child is allowed and is guarded by tests/child_guard/sitecustomize.py. The editable install puts the checkout on sys.path, so a child can import `devtools`.
- bandit skips B404, B603 and B310 only, so programs must be absolute paths from `shutil.which` (B607).

Git queries the gate runs (argv after `git`, all through `GitRunner`):
- unmerged paths: `diff --name-only --diff-filter=U -z`
- staged changes: `diff --cached --name-only -z`
- untracked files: `ls-files --others --exclude-standard -z` (no pathspec), then drop every name that starts with `.planning/` (D-25). git runs `pre-push` from the work tree root, so every name is root-relative, like the other queries.

Why refusal 3 covers the whole tree (D-25, review H1): pytest's rootdir is the repo root, so it loads an untracked root `conftest.py`, and an untracked root `pytest.ini`, `.pytest.ini`, `tox.ini` or `setup.cfg` overrides `[tool.pytest.ini_options]`. Likewise `.coveragerc`, `pyrightconfig.json`, a `ruff.toml` in any parent directory, `typings/*.pyi`, a `GNUmakefile` that shadows `Makefile`, `.shellcheckrc`, an installer data file and a doc link target a test resolves all change what the gates see. A fixed list would miss the next one, and a miss is a green push of a HEAD that fails in CI, which SPEC R3 forbids. `.planning/` stays exempt: SPEC R5 treats it as docs and no gate reads it, apart from the SKILLJUDGE glob of `tests/test_catalog_audit_skill.py:401`. That test checks each file it finds, so an extra untracked file can only add failures and can never hide one.
- unstaged config: `diff --name-only -z -- .pre-commit-config.yaml`
- HEAD: `rev-parse --verify HEAD`
- a pushed commit: `rev-parse --verify <local sha>^{commit}`
