- `.pre-commit-config.yaml`: six static hooks (`make lint`, `make format-check`, `make typecheck`, `make security`, `make dead-code`, `make shellcheck`) at `[pre-commit, pre-push]`, then `make test` at `[pre-push]`.
- `python -m devtools.hooks install` (devtools/hooks.py) resolves `git` and `pre-commit` on PATH, writes the shim into `<common dir>/hooks/pre-push`, and prints `dev-setup:` lines.
- The shim runs `exec uv run python -m devtools.push_gate "$@"`. The gate resolves `pre-commit` on PATH and runs `pre-commit run --hook-stage pre-push --fail-fast --from-ref HEAD --to-ref HEAD`.
- pre-commit exports `PRE_COMMIT_FROM_REF` and `PRE_COMMIT_TO_REF` to hooks during that run.

Design of the scratch repo, settled here per D-15. Keep it as written, because 26-07's CI step relies on it:
- `SCRATCH=$(mktemp -d "${TMPDIR:-/tmp}/hooks-e2e.XXXXXX")`, so a leftover dir is easy to spot. `ROOT` is the checkout the script lives in. Before `env -i`, resolve the absolute paths of `pre-commit`, `uv` and `python` with `command -v`. `make hooks-e2e` runs under `uv run`, so the dev `.venv/bin` is first on PATH. If any of the three is missing, print `hooks-e2e: run make dev-setup first` and exit 1.
- `run_isolated` wraps every git, uv and pre-commit call in `env -i` with exactly: `PATH=<dir of pre-commit>:<dir of uv>:/usr/bin:/bin`, `HOME=$SCRATCH/home`, `PRE_COMMIT_HOME=$SCRATCH/pre-commit`, `XDG_CACHE_HOME=$SCRATCH/cache`, `UV_CACHE_DIR=$SCRATCH/uv-cache`, `UV_PYTHON=<resolved python>`, `UV_OFFLINE=1`, `GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_TERMINAL_PROMPT=0`, `GIT_AUTHOR_NAME=hooks-e2e`, `GIT_AUTHOR_EMAIL=hooks-e2e@example.invalid`, the matching `GIT_COMMITTER_*`, and `LANG=C`.
- `new_repo <name>` creates, under `$SCRATCH/<name>`:
  - a `git init -q -b main` work tree holding `pyproject.toml` (`[project]` name `hooks-e2e-scratch`, version `0`, `requires-python = ">=3.11"`, and `[tool.uv]` `package = false`);
  - a `.gitignore` with `.venv/`, `uv.lock` and `__pycache__/`;
  - `cp -R` of `$ROOT/devtools` without `__pycache__`, and a copy of `$ROOT/.pre-commit-config.yaml`;
  - a scratch Makefile whose six gate targets each touch `$SCRATCH/marks/<name>/<target>.ran`. `lint` also fails when a tracked file `LINT_FAIL` exists. `test` runs `sh tests/check.sh`;
  - `tests/check.sh`, which touches `test.ran`. When `tests/slow` exists it touches `started` and sleeps in 0.1 s steps, up to 300 of them, until `$SCRATCH/stop` exists. It then fails when any `tests/*.py` contains `FAIL`;
  - `tests/test_a.py` with `print("ok")`;
  - an initial commit, a bare `$SCRATCH/<name>.git` added as `origin`, and `main` pushed there before any hook is installed.
- `install_hooks <name>` runs `uv run python -m devtools.hooks install` in the work tree through `run_isolated`.
- Each case prints `ok <case>` or `FAIL <case>: <reason>`. The script counts failures and exits 1 if there is any, after the EXIT trap has cleaned up.
- Portability: bash 3.2 (macOS). No associative arrays, no `mapfile`, no `${var,,}`, no `setsid`, no `sha256sum`. Compare bytes with `cmp -s`. Start a background push in its own process group with `"$PY" -c 'import os, sys; os.setpgid(0, 0); os.execvp(sys.argv[1], sys.argv[1:])' git push …`, record its pid, and signal the group with `kill -<SIG> -- "-$pid"`. Collect a background exit status with `wait "$pid" || rc=$?`, so `set -e` does not abort.
