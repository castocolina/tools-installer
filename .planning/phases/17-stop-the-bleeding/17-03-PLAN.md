Hazard H7 (SAFE-07): a vendor install or update script that prompts on `/dev/tty` blocks the TUI because children share the installer's session. Per D-10, `StreamingRunner.popen_with_env` adds `start_new_session=True` (stdin is already DEVNULL). RESEARCH Pitfall 4 showed updates run through `run_captured -> run_output`, which inherits stdin and the session; SPEC R7 covers "install and update children", so `run_output` gets `stdin=subprocess.DEVNULL, start_new_session=True` too.

Purpose: a prompting child fails fast instead of hanging the app.
Output: two kwargs in each runner and tests that discriminate a new session from the old behaviour.

The codex registry `env = { CODEX_NON_INTERACTIVE = "1" }` half of D-10 is in plan 17-05 (it edits installer/registry.toml).
</objective>
