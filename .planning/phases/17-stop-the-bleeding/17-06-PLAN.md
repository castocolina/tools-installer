Hazard H5 (SAFE-04): ban-alias, tweak and shim writes use `Path.write_text`, so a crash or full disk mid-write truncates the user's rc; `clean_rc_duplicates` applies line indices computed before the confirm prompt to whatever the file holds afterwards. Per D-05 every rc/shim write goes through the existing `atomic.atomic_write_text` (symlink-through, unique temp, cleanup on error); per D-06 the duplicate cleanup keeps the previewed bytes and refuses a file that changed.

Purpose: no write can leave a half-written shell config, and no cleanup can strip the wrong line.
Output: 10 call sites switched (6 chmod(0o755) lines deleted: guards.py:389,393,426,453,473 and tweaks.py:255), one recheck, two rc-level guard tests, one atomic concurrency test, the clean_rc tests.

Test economy (ponytail reuse pass): the atomic properties themselves (failure keeps the original, symlink write-through, missing file, explicit mode) are already proven once in tests/test_atomic.py (:59, :46, :23, :40); routing every writer through `atomic_write_text` is enforced by the `.write_text(` = 0 and `mode=0o755` count greps. So this plan adds one failure and one symlink test at the rc level (guards), keeps the D-06 clean_rc tests, puts the concurrency test on `atomic_write_text` itself, and does not re-prove the same properties per call site.
</objective>
