Output: `executors.link_executable` used by the three sites; tests rewritten from shelled-argv assertions to filesystem assertions through one shared test runner.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| downloaded archive -> ~/.local/opt and ~/.local/bin | upstream archive layout decides what the member path is |
| existing ~/.local/bin entry -> reinstall | a pre-existing link may point anywhere, including a directory |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-17-03 | Tampering | `ln -sf` onto an existing link-to-directory writes inside the opt dir (H1) | high | mitigate | `link_executable` replaces the link itself via `replace_symlink` (os.replace on the link path, never followed); byte-identical reinstall test |
| T-17-04 | Tampering | directory member linked as the tool binary | high | mitigate | `is_file()` check raises `ExecutorError` before any chmod/link; ladder falls through |
| T-17-05 | Tampering | member that is itself a symlink pointing outside the opt dir (chmod follows it) | low | accept | Registry is the only argv source and archives come from the registry URL; containment check is listed as optional hardening in RESEARCH and not required by the SPEC; Phase 18 adds digests |
| T-17-SC | Tampering | npm/pip/cargo installs | high | accept | No package installs; `pyproject.toml` and `uv.lock` unchanged |
