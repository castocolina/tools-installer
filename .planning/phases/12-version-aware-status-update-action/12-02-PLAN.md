<objective>
Introduce ownership resolution as a real, separate, tested concept, and use it — not install-preference ranking — to decide where each catalog tool's version comes from. Then resolve current-and-latest versions for brew-, cask-, pnpm-, and uv-owned tools using each manager's own report, queried once per manager per refresh pass through a single bounded runner.

Purpose: REQ-manager-version-resolution, and the correctness precondition Plan 12-03's mutating update action depends on. Without ownership, a brew-installed `rg` is queried (and later upgraded) as a GitHub download, because `rg` declares `github_release`, native, and `brew` methods and `_RANK` puts `github_release` (20) ahead of `brew` (40) — see `installer/registry.toml`'s `rg` entry and `installer/resolve.py:12-26`.
Output: `installer/ownership.py` (new), `installer/manager_versions.py` (new), `installer/run.py::run_query` (new), and a Ver column whose source for each row is that row's real owner.

  <behavior>
    - `installer.manager_versions.ManagerVersion(current: str | None, latest: str)` (frozen dataclass).
    - `installer.manager_versions.OutdatedReport(brew: Mapping[str, ManagerVersion] | None, cask: Mapping[str, ManagerVersion] | None, pnpm: Mapping[str, ManagerVersion] | None, uv: Mapping[str, ManagerVersion] | None)` (frozen dataclass). Each field is independently `None` when that manager's own query failed; one failure never blanks another map. Because `brew` and `cask` come from the same call, a failed brew call sets BOTH to `None`, and that shared fate is stated in the field docstring.
    - `parse_brew_outdated_json(raw: str) -> tuple[dict[str, ManagerVersion], dict[str, ManagerVersion]] | None`: parses the v2 payload into `(formulae, casks)` as two SEPARATE maps — never merged, because a formula and a cask may share a name. Per entry: `current` is the last element of `installed_versions` when that key is a non-empty list of strings, else `None`; `latest` is `current_version` when it is a non-empty string. An entry missing `name` or `current_version` is skipped, not fabricated. A payload that is not a JSON object, or whose `formulae`/`casks` values are not lists, returns `None`. A payload missing one of the two keys yields an empty map for that side (brew genuinely reports `"casks": []`), which is different from `None`.
    - `parse_pnpm_outdated_json(raw: str) -> dict[str, ManagerVersion] | None`: parses `{"<pkg>": {"current": "...", "latest": "...", ...}}` into `{pkg: ManagerVersion(current, latest)}`.
