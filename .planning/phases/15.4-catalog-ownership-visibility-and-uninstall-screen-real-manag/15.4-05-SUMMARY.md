# Phase 15.4 Plan 05: Uninstall Screen Real Manager Attribution Summary

**The Uninstall screen's "Installed via" cell now names the real manager (dnf/apt/pacman/rpm-ostree/pnpm/uv/Homebrew-cask/SDKMAN/OS-package) instead of a four-value enum string, fed by the catalog's own ownership map, and a removal command never names the wrong package because native probes now capture and propagate the verified package name.**

## Accomplishments
- Native ownership probes (`_dnf`/`_apt`/`_pacman`/`_rpm_ostree`, plus `_brew`/`_pnpm`/`_sdkman`) capture the package name each one actually matched onto a new `Ownership.package` field, and `_native_owner` propagates it onto the resolved record — preferring the manager's own inverse file query (`path_owner_package`) over the probe's declared-name match, so a split package like `rg`/`ripgrep` or `git`/`git-core` resolves to the real name.
- `removal_hint(ownership, fallback_name)` in `installer/ownership.py` builds the complete per-owner removal phrase (brew/cask byte-identical to today's, dnf/apt/pacman/rpm-ostree/pnpm/uv each with their own command, OS-package naming the package with no command) and structurally refuses to emit a backticked command unless the record carries a resolved package name — a command-less record degrades to a description-only sentence instead of guessing from the tool's own cmd.
- `classify_tools` gained an `owner_hint` seam (a plain `Callable[[Tool], str | None]`, never `ManagerOwnership`) consulted only on the managed branch, and the registry-derived fallback `_manager_hint` now scans `resolve_methods(tool, platform)` instead of raw `tool.methods` — closing the Round-2 review HIGH where a macOS-only cask (codex) could name a Homebrew command on Linux — plus a new SDKMAN branch naming the candidate from its own registry method.
- `UninstallScreen._tool_entry`'s "Installed via" cell now renders `row.hint` verbatim for removable and managed rows (D-03); absent/unavailable rows keep their existing short dash label, and the "What gets removed" cell is untouched.
- `setup.py` binds `owner_hint` to `removal_hint` over `VersionRefreshService.ownership_of`, reusing the catalog's already-computed ownership map rather than running a second probe pass (D-05) — freshness is inherited from 15.4-04's epoch-gated map, post-removal invalidate seam, and `OwnershipRefreshed` completion signal with no new plumbing required.

## Decisions Made
- `removal_hint`'s cask phrase hard-codes "Homebrew" (not `owner_label`'s "Homebrew cask") to stay byte-identical to the pre-existing cask sentence; the label-agreement rule every other owner satisfies carries a declared, bespoke-tested exemption (`_LABEL_AGREEMENT_EXEMPT`) rather than a silent skip.
- Package-name resolution order in `_native_owner`: the manager's own inverse file query (`path_owner_package`, when an active path exists) first, then the probe's captured name, then `None` — never invented.
- `OwnerHint` is a plain `Callable[[Tool], str | None]`; `installer/uninstall.py` imports nothing from `installer.ownership` or `installer.install_ownership`, keeping the dependency direction ownership-to-uninstall only.
