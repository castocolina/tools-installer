# Phase 15.4 Gap Closure: vscode Linux cask naming mismatch

**Commit:** 593f225

## Gap

`15.4-VERIFICATION.md` flagged `vscode` as a second, unfixed instance of the exact
Linux-cask naming mismatch that Plan 02 already fixed for `jetbrains-toolbox`
(commit `dda9814`). `vscode` is actually installed via the linuxbrew cask
`visual-studio-code-linux` (confirmed live: present in this host's
`ManagerInventory.brew_casks` / `brew list --cask`, with the real binary at
`/home/linuxbrew/.linuxbrew/Caskroom/visual-studio-code-linux/.../bin/code`),
but `installer/registry.toml`'s vscode entry only declared the macOS-gated
cask name `visual-studio-code` (`os = ["macos"]`). Without a Linux-gated cask
row, ownership resolution had no cask evidence to attribute against, so the
Owner column blanked and the Uninstall cell fell back to the generic "package
manager" phrase for vscode on Linux -- violating the phase's own rule that a
blank cell means "genuinely don't know", never "didn't bother".

## Fix

Replicated Plan 02's exact shape for vscode:

- **`installer/registry.toml`**: added a second, Linux-gated `cask` method row
  (`cask = "visual-studio-code-linux"`, `os = ["debian", "arch", "fedora"]`)
  to the vscode entry, with the same dated-verification-comment style stating
  it is ownership evidence only -- `installer/resolve.py`'s cask branch
  remains macOS-and-brew-only, so this row can never install anything. The
  Linux install path for vscode remains the existing tarball methods.
  `installer/resolve.py` was left untouched, matching D-02a's narrower fix.
- **`tests/test_registry.py`**: added
  `test_vscode_declares_two_distinct_linux_and_macos_cask_names` and
  `test_vscode_linux_cask_row_records_dated_verification`, mirroring
  jetbrains-toolbox's equivalent pair exactly (behavioral proof that
  `resolve_methods` still returns no cask method on Linux and exactly one on
  macOS, plus a dated-verification-comment presence check).
- **`tests/test_ownership.py`**: added
  `test_real_registry_vscode_resolves_linux_cask_ownership`, mirroring
  jetbrains-toolbox's `test_real_registry_jetbrains_toolbox_resolves_linux_cask_ownership`
  -- loads the real registry, resolves ownership for vscode on a Linux
  platform against a fake cask inventory naming `visual-studio-code-linux`
  with a live binary under the fake linuxbrew prefix, and asserts
  `owner == "cask"`, `package == "visual-studio-code-linux"`,
  `confidence == "direct"`.

No changes were needed to `installer/ownership.py`: its cask-ownership-evidence
path already reads any `cask` method regardless of `resolve.py`'s macOS-only
install gate (the same mechanism Plan 02's task 1 built), so it required no
tool-specific wiring.
