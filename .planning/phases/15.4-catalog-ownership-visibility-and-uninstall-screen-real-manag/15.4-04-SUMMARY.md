# Phase 15.4 Plan 04: Live Uninstall Rows, Epoch-Tagged Ownership, and the Completion Signal Summary

**`UninstallInputs.rows` becomes a live callable predicate (D-06) migrated across all 13 real construction sites, `VersionRefreshService._ownership` collapses to one epoch-tagged map so a superseded background refresh can never publish a torn or stale record, and a new `OwnershipRefreshed` message repaints a mounted Uninstall screen after a background refresh commits — with a written failure > change > no-change `_resync` precedence and a same-session removal invalidate seam (D-05).**

## Accomplishments

- **Live `rows` predicate (D-06):** `UninstallInputs.rows` is now `Callable[[], list[ToolRow]]`, evaluated through `run_live` at both construction time and inside `_live_state()`, joining `ban_names`/`has_path_block`/`tweak_ids` as a fourth element in the same tuple comparison `enter_view()` already used — no second refresh mechanism.
- **Written `_resync` precedence:** a predicate-read failure always wins the status line and never clears `applied`; otherwise a changed comparison rebuilds and (only on a nav entry) clears `applied`; otherwise an unchanged comparison returns early and leaves the standing message untouched.
- **Pre-mount status preservation:** a `_pending_status`/`_set_status()` mechanism stops `on_mount()`'s unconditional `_show_standing_status()` call from silently overwriting a construction-time warning written before the screen was ever mounted — found and fixed during this plan's own test-writing, not pre-existing.
- **Applied-summary preservation during background repaint:** the changed-branch's repaint guard became `if self.is_mounted and not self.applied`, so `ownership_refreshed()` (`clear_applied=False`) can update the row list under a standing applied removal summary without ever overwriting the sentence describing what the user just did — found and fixed before the corresponding test was written, by re-reading the plan's own precedence requirement.
- **All 13 `UninstallInputs(...)` construction sites migrated** to callables across `setup.py` and 6 test files — re-confirmed by grep at execution time (`13`, not the `12` a stale reference might claim).
- **Production `rows` closure measured:** 89-tool catalog, ~5.01ms per call, well under the plan's 250ms stop-and-report threshold.
- **`invalidate` seam wired into `_apply_removal`** after a successful sweep, closing the second hole (removal, after install/update) in "every mutation this app performs calls invalidate" (D-05).
- **`VersionRefreshService._ownership` collapsed** from a plain `dict[str, ManagerOwnership]` to `dict[str, tuple[int, ManagerOwnership]]`: `ownership_of` does one dict lookup and compares the paired epoch, so a torn read (record and epoch from different passes) is structurally unrepresentable. The raced-refresh branch no longer calls `.update(...)` with stale records at all — proven by a two-pass, `threading.Event()`-synchronized interleaving test using deterministic alternating checkpoints (not `sleep()`), plus a single-threaded deterministic case.
- **`OwnershipRefreshed` message** posted by `CatalogScreen.on_version_status_refreshed`'s commit path only; `UnifiedApp.on_ownership_refreshed` forwards it to a mounted Uninstall screen's `ownership_refreshed()` only when that view is current — no new coupling from `_install_closed`, no second navigation trigger.
- `make validate` (ruff check/format, pyright, bandit, vulture, shellcheck) and `make test` both pass on the full tree: 2342 passed, 1 skipped, 95.66% coverage against a 90% floor.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Pre-mount status writes were silently overwritten by `on_mount()`**
- **Found during:** Task 1, while writing `test_uninstall_construction_rows_failure_yields_a_usable_screen_that_self_heals`
- **Issue:** `enter_view()` runs before `push_screen()`, and Textual's `on_mount()` only fires on first push. A construction-time or pre-mount `_resync` warning was being unconditionally overwritten by `on_mount()`'s call to `_show_standing_status()`.
- **Fix:** Added `self._pending_status: tuple[str, str] | None` and a `_set_status()` helper that stashes the message when `not self.is_mounted`; `on_mount()` now checks and applies the stash first.
- **Files modified:** `installer/wizard_app.py`
- **Verification:** `test_uninstall_construction_rows_failure_yields_a_usable_screen_that_self_heals` passes; asserts the stale-file-handle message survives to `screen.status.text`.
- **Committed in:** `f7bd2c1`

**2. [Rule 1 - Bug] A background ownership repaint could overwrite an applied removal summary**
- **Found during:** Task 1, while re-reading the plan's precedence requirement before writing the standing-summary preservation test
- **Issue:** The changed-branch's `if self.is_mounted: self._show_standing_status()` was unconditional even when `clear_applied=False` and `applied` remained `True`, which would have overwritten the applied removal summary during a background `ownership_refreshed()` repaint — violating the plan's explicit precedence requirement.
- **Fix:** Guard changed to `if self.is_mounted and not self.applied:`, with an explanatory comment, fixed proactively before the corresponding test was run.
- **Files modified:** `installer/wizard_app.py`
- **Verification:** the standing-summary preservation test passed cleanly on first run.
- **Committed in:** `f7bd2c1`
