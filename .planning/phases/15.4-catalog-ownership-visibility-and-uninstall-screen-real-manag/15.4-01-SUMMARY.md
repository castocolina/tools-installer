# Phase 15.4 Plan 01: OS-Package Owner Tracer + Update Refusal Summary

**A new inverse package-database query (`path_owner_package`) lets `resolve_ownership` answer for a base-image tool like `/usr/bin/git` — resolving to the real `os-package` owner (`git-core`) instead of `unknown` — wired end-to-end through a new Owner column, the focused-row detail bar, and an explicit update refusal that names the real package.**

## Accomplishments

- **Probe layer** (`installer/install_ownership.py`): `path_owner_package(os_family, path, probe)` — the INVERSE of the pre-existing `package_owns_path` — asks "whatever owns this live path, name it" with no declared candidate. Covers fedora (`rpm -qf`), debian (`dpkg-query -S`), arch (`pacman -Qoq`); macOS issues no query at all. Fails closed on a raising probe, zero names, 2+ names, or a name that fails a new package-name guard (`_PACKAGE_NAME_RE`). `installer/model.py::OWNER_PROBES` and `installer/registry.toml` are untouched — confirmed by `git diff --name-only`.
- **Resolver layer** (`installer/ownership.py`): widened `Owner` to 11 values with `os-package`; `OS_PACKAGE_OWNER` and `UNMANAGEABLE_OWNERS` (the shared set both this module's semantics and `update.py`'s refusal read); `_os_package_owner` — the adapter, placed immediately after `_native_owner` and immediately before the active-path-unknown branch, on the identical complete-negative-evidence gate, and deliberately NOT gated on `platform.immutable` (pinned by a parametrized `immutable=True/False` test asserting an identical record from both).
- **Label layer**: `OWNER_LABELS` (the column register, exhaustive over `Owner` minus `unknown`), `_INSTALLER_KIND_LABELS`, `owner_label(ownership)` — `None` only for `unknown`, the resolved method-kind label for an installer-owned record, `OWNER_LABELS["installer"]` as fallback.
- **Render layer** (`installer/catalog_tui.py`): `Owner` column at `_COLUMNS` index 7 (non-sorting, like `sel`/`ver`/`desc`); an owner cell in both `_row_cells` branches (dimmed in the unavailable branch like the Ver cell); an `os-package` placeholder sentence added to `_version_detail`'s existing local `labels` dict, explicitly handed off in a comment to 15.4-03.
- **Update refusal** (`installer/update.py`, TDD): `_perform`'s pre-ladder refusal now reads `UNMANAGEABLE_OWNERS` instead of restating `NATIVE_OWNERS`; a distinct `_OS_PACKAGE_DETAIL` names the real package via `ownership.package` rather than reusing the native template (which would tell the user to "update it through os-package yourself" — not a real command).
- Mutation-tested three load-bearing pieces: (1) removing the `_os_package_owner` call site in `resolve_ownership` — the pinned tracer test fails with `unknown` instead of `os-package`; (2) loosening the package-name guard regex to `.*` — 4/5 guard-rejection parametrizations fail; (3) narrowing the update refusal condition back to a bare `{"dnf","apt","pacman","rpm-ostree"}` set — the os-package refusal tests fail with `status="failed"` (a raised `UpdateError`) instead of `"unsupported"`. All three reverted cleanly and the full suite re-verified green.
- Updated two pre-existing tests in `tests/test_ownership.py` to reflect the INTENDED new behavior rather than leaving them broken by the new capability: a base-image package on an immutable Fedora host now correctly resolves to `os-package` (this plan's whole point) rather than the old `unknown`, while the underlying CR-02 guarantee (the dnf-specific CONFIRM probe never runs on that host) is preserved and re-asserted via the recorded probe-call list.
- `make validate && make test` pass on the full tree after each task: 2242 passed / 1 skipped (Task 1), 2250 passed / 1 skipped (Task 2), 95.59% coverage against the 90% floor.
