**A linuxbrew-cask-owned tool (`jetbrains-toolbox`) now resolves to `owner="cask"` instead of `unknown`, via a narrow ownership-only evidence path plus the registry's real Linux cask name — while `installer/resolve.py`'s install-time cask gate stays byte-for-byte untouched, so Linux install behaviour is provably unchanged.**

## Accomplishments

- **Ownership-only evidence path** (`installer/ownership.py`): `_method_targets_platform` mirrors `resolve.py::_applies`'s os/arch/min_os_version gate using the identical `meets_minimum` comparison; `_OWNERSHIP_ONLY_KINDS` declares, as a data table rather than a hard-coded check, exactly one eligible kind (`cask`) and which `_applies` dimensions its bypass mirrors; `_ownership_only_methods` reads that table, gated on `platform.has_brew and platform.os != "macos"` so macOS and no-brew hosts contribute nothing.
- **Wired into both consuming surfaces**: `resolve_ownership`'s candidate path now sees `resolve_methods(tool, platform)` followed by the ownership-only methods, and `competing_owners` builds its method list the same way — so `_unreadable`'s guard and the candidate list can never disagree about which owners are in play.
- **Registry fix** (`installer/registry.toml`): a second, Linux-gated cask row on `jetbrains-toolbox` naming the real linuxbrew cask (`jetbrains-toolbox-linux`, confirmed live via `brew list --cask` in 15.4-RESEARCH.md and re-verified this session), with a dated verification comment stating the row is ownership evidence only and can never install anything, naming the exact `resolve.py` gate that keeps it inert.
- **`installer/resolve.py` left completely untouched** — confirmed by `git diff --name-only` across both commits — resolving 15.4-RESEARCH.md's Open Question 2 as option (b): install behaviour on Linux is unchanged, pinned by a behavioural (not source-substring) three-point truth table over `_applies`'s cask branch.
- **Applicability-drift closed**: a table-driven 288-cell parity gate proves `_method_targets_platform` agrees with `resolve._applies` over every combination of declared/platform os, arch, and `min_os_version` for a `kind = "script"` method — the kind `_applies` accepts unconditionally once its three dimension checks pass, making the two functions directly comparable without reimplementing the kind ladder.
- Both surfaces of the evidence rule are asserted together for every exclusion case (excluded `os`, excluded `arch`, unmet `min_os_version` including a `None` `os_version`): a method that fails one of these enters neither `candidates` nor `competing_owners`, never one without the other.
- `make validate && make test` pass on the full tree after each task: 2263 passed / 1 skipped (Task 1), 2266 passed / 1 skipped (Task 2), 95.62% coverage against the 90% floor.
