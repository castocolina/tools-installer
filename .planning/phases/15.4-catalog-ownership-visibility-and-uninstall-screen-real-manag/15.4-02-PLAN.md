<objective>
Close the second half of D-01's dated correction: a tool Homebrew installed as a cask on a
Linux host stops resolving to `unknown`, without changing what this installer offers to
install on Linux.

Purpose: 15.4-RESEARCH.md proved the Linux-cask gap is blocked at two independent layers —
a declared cask name that does not match the installed one, and `resolve.py`'s categorical
macOS-only cask gate that drops every cask method before ownership code ever sees it.
Fixing either alone changes nothing, so this plan fixes both while deliberately leaving
install-time behaviour alone.
Output: a narrow, ownership-only evidence path plus the registry data it reads.
</objective>
