<objective>
Stop `UninstallScreen` from showing a tool list frozen at app construction. Make the whole
row list a live predicate re-evaluated on every entry, using the exact conditional-rebuild
shape the same method already uses for the three environment rows.

Purpose: `UninstallScreen._rows` is assigned once in `__init__` from a `classify_tools` call
`setup.py` makes at startup, and `enter_view` re-checks only `ban_names`/`has_path_block`/
`tweak_ids`. An install performed elsewhere in the session therefore never appears here, and
a removal performed here is never reflected on a later entry — D-06, which the user
explicitly pulled into this phase rather than deferring. The same screen's removal action
is also the one mutation in this app that never calls `invalidate`, so the shared
version/ownership data it just falsified stays believed — D-05's second half, which names
uninstall alongside install and update.
Output: one more predicate, one revised guard, every construction site migrated, the
post-removal invalidation, the epoch gate that makes it observable, and the freshness proof.
</objective>
