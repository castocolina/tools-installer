# Phase 23.2: Install-time tuning instead of Policies knobs — Specification

**Created:** 2026-11-07
**Ambiguity score:** 0.14 (gate: ≤ 0.20)
**Requirements:** 12 locked

## Goal

Installing a tool finishes its setup in one go: the agent co-authoring-off and auto-approve keys, the shell init of the six shell tools, the Oh-My-Zsh plugins and the VS Code lean keys are written at install with no question and reverted with the tool; Policies shrinks from 23 rows to the 7 that are not part of any install; the Phase 23 run options are gone; the GitHub Copilot CLI joins the catalog with the same tuning; a dependency found present but missing from the session PATH no longer fails the tool that needs it; and a silent step shows a live spinner with elapsed time plus a timestamped "still running" line every 10 s.

## Requirements

1. **Agent tuning at install**: Installing claude, codex, opencode, cursor-agent or copilot writes that agent's tuning keys at once, with no question, on every route (TUI, headless, `--yes`).
   - Current: the keys are written only when the user turns on a run option (default off, never under `--yes`) or a Policies row.
   - Target: a row that ends done writes, only where absent: claude `permissions.defaultMode = "bypassPermissions"`, `skipDangerousModePermissionPrompt = true`, `attribution.commit` and `attribution.pr` set to the empty value; codex `approval_policy = "never"`, `sandbox_mode = "danger-full-access"`; opencode `"permission": "allow"`; cursor-agent `approvalMode = "unrestricted"`, `attribution.attributeCommitsToAgent = false`, `attribution.attributePRsToAgent = false`; copilot `defaultPermissionMode = "allow-all"`, `includeCoAuthoredBy = false` in `$COPILOT_HOME/settings.json` (default `~/.copilot/settings.json`). A key the user holds with another value stays and is reported "set by you"; every written key is recorded in the agent's config-write ledger; pi gets nothing written. The run summary names the file and keys written per agent.
   - Acceptance: in a scratch HOME with a fake runner, a headless `--yes` install of each of the five agents leaves exactly its keys in its file and its ledger; a pre-existing `permissions.defaultMode = "acceptEdits"` stays and is reported "set by you"; comments and unrelated keys survive; no prompt or review option is shown.

2. **Present but untuned agents show a pending step**: An agent that is present but lacks tuning keys the ledger never recorded shows `≈` with the step "apply install tuning", and RECONFIGURE writes them.
   - Current: a present agent (installed by hand or before this phase) never gets the keys unless the user turns on a Policies row.
   - Target: the state pass adds one `ConfigStep` per present agent whose absent tuning keys are not in its ledger; selecting the row plans RECONFIGURE, which writes them under requirement 1's rules. A key the ledger records but the file no longer has counts as the user's choice: no `≈`, and RECONFIGURE does not write it again (an explicit reinstall does). A key "set by you" never raises `≈`.
   - Acceptance: scratch HOME with claude present and an empty `settings.json` → claude reads `≈` with the step; RECONFIGURE writes the four keys and the next pass reads `✓`; deleting one recorded key by hand → still `✓` and a RECONFIGURE writes nothing; a user value on every key → `✓`.

3. **Removal reverts the tuning**: Removing an agent reverts exactly the recorded keys that still hold the installer's value, including keys written before this phase by a Policies row or a run option.
   - Current: removal already reverts ledger keys (Phase 23 R8); Policies "off" also reverted them.
   - Target: with no Policies row left, removal is the only revert path; a file whose only change was the installer's keys returns byte-identical; a key the user changed after the write is kept and named; ledger entries written by the retired Policies rows or run options are honoured unchanged (no migration rewrite at launch).
   - Acceptance: in a scratch HOME, install then remove each of the five agents → every settings file is byte-identical to its pre-install bytes; a ledger fixture written by the Phase 23 `agent:codex:auto-approve` row is reverted by codex removal; a hand-changed `sandbox_mode` survives removal and is named.

**Out of scope:**
- A heartbeat for the headless CLI — child output goes straight to the terminal there and no "waiting for output" line exists
- Moving the tmpdir-cleanup daemon or the bun redirect into Schedules — Phase 24.2 (SCHED-01..05)
- Copilot updates on a schedule and the cursor-agent shim — Phase 24.2

- Rewriting existing files at launch to migrate former Policies state — ledger entries, OMZ records and tweak blocks are honoured as they are
