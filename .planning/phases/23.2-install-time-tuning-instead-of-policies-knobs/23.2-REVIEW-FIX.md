## Fixed

### C-01 (e57cc02): PATH repair skips our own shim
- Changed: `installer/session.py` `_put_present_bin_dir_on_path` asks `guards.real_binary(tool.cmd, shim_dir=bin_dir(None), path_value=PATH)` instead of `shutil.which`.
- RED: `test_path_repair_ignores_the_installers_own_pnpm_redirect_shim` (redirect-sentinel `~/.local/bin/pnpm`, real pnpm in its declared dir) failed with `IndexError` (the runner was never called). GREEN after the fix.
- Test helpers adjusted, not weakened: five `fake_which(cmd)` doubles in `tests/test_session.py`, `tests/test_app.py` and `tests/test_execute_screen.py` now accept `path=None`, because they patch the global `shutil.which` and `real_binary` calls it with `path=`.
- Fixed: yes.

### C-02 (5edeb5c): facts and writer agree on a non-object parent
- Changed: `agent_settings.setting_facts` skips a key whose parent exists but is not an object.
- RED: `...non_object_parent...` asserted `absent == ("skipDangerousModePermissionPrompt",)` and got both keys. GREEN after the fix.
- Note: C-07 later reduced `SettingFacts` to `path` and `absent`, so the test lost its `set_by_you` assertion there.

### C-03 (cfb9366): a blank settings file reverts byte for byte
- Changed: `ConfigLedger` gains an optional `blank_files` field of (file, original text), read leniently and rejected when malformed; `_apply_once` records a whitespace-only original; `_revert_once` writes it back when only a bare `{}` remains; the record is released with the file's last entry. Older ledgers without the field still read.
- RED: 9 cases (claude, copilot, codex x `b""`, `b"\n"`, `b"  \n\n"`) failed with `{\n}\n` or the equivalent. GREEN after the fix. Four cases cover a malformed `blank_files` field.
- Residual: a blank file the user edits during the install keeps the normal path (the new content is theirs).

### C-04 (8ca41f6): per-action isolation
- Changed: `run_post_install` wraps each action; a crash becomes `<action> crashed: <first line>` on a new `PostInstallOutput.warning`, which the engine carries to `postinstall_warning`. `_store_shell_init_record` raises a plain `OSError` for non-UTF-8 bytes instead of a `UnicodeDecodeError`, and never rewrites them.
- RED: `test_one_crashing_action_keeps_the_chsh_handoff_and_the_other_actions` (real non-UTF-8 `.zshrc`, three actions) and the record test raised the decode errors. GREEN after the fix.
- The two existing engine tests for a raising action still pass unchanged (the warning text still names the cause).
- Residual: `apply_install_tuning` (RECONFIGURE) is not isolated per action; it was not in the finding.

### C-05 (af93593): settings notes only for rows that tuned
- Changed: `render._settings_lines` counts a row as done only for INSTALL, REPAIR and REINSTALL dispositions.
- RED: `test_settings_notes_stay_silent_for_rows_that_wrote_no_settings` failed on the UPDATE case. GREEN after the fix.

### C-06 (e3106aa): refused plugin write fails the step

- RED: `test_install_tuning_step_fails_when_the_omz_plugin_write_is_refused` got `done`. GREEN after the fix.
