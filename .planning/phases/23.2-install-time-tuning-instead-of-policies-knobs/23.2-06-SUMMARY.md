## Deviations from Plan

### Auto-fixed issues

### Notes and small divergences

1. **The fresh-install record lists `docker`, not `git docker`.** The plan's tracer behavior says the `~/.myshellrc` record lists `git docker`. In the shipped order (`set_login_shell`, `set_omz_theme`, `set_omz_plugins`) the theme action runs `ensure_zshrc_template` first, which writes `plugins=(git)`, so `git` is already in the array and is correctly never recorded as added (the R4 adjacency rule). The end `.zshrc` is the required `plugins=(git docker)`; `test_omz_install_writes_plugins_and_theme_end_to_end` asserts the record is `("docker",)`. Calling `write_plugins` on a missing `.zshrc` directly still records `git docker` (existing test).
2. **`_tune_omz_plugins` catches `OSError`, not only `OmzPluginsError`.** `OmzPluginsError` subclasses `OSError`, so every refusal the plan names still becomes the `Plugins not changed: <first line>` line; a failed atomic write does too instead of reaching the engine's crash isolation.
3. **`_omz_tuning_fact` checks the record before the refusal** (see key-decisions); the plan listed the refusal first. For a never-tuned host both orders give the same result, and a tuned host is never flagged.
4. **R8 ordering.** The registry order is locked (`set_login_shell` first), so the handoff's `chsh` lines come first inside the row's `after install` block, before the theme and plugin lines. The test asserts the block, that the `chsh` line appears once, and that the other tuning lines share the block; it does not assert chsh is last.
5. **The full-uninstall record clear is in `installer/app.py`** (`run_uninstall` after `remove_managed_block`, `perform_uninstall` right after `sweep_tweaks`), not `installer/uninstall.py`, because those are the teardown sites; `test_a_full_uninstall_clears_the_shell_init_record` is in tests/test_app.py (next to the `run_uninstall` helpers) instead of tests/test_uninstall.py, which got `test_omz_plugins_full_uninstall_restores_the_users_list`.
6. **Plan-head ledger.** See Commits.
7. **`FakePrompter.sensitive_confirm` in tests/test_app.py is now unused** (no confirmation is requested any more); it is left as a harmless parameter.
