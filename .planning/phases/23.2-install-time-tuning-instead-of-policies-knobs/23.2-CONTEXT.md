<domain>
## Phase Boundary

Installing a tool finishes its setup in one go. The agent keys (auto-approve/bypass, co-authoring off), the VS Code keys, the shell-init block of the six shell tools and the Oh-My-Zsh plugins are written at install, with no question, on every route. They are reverted with the tool. A present tool that never got its tuning shows `≈` "apply install tuning", and RECONFIGURE applies it. Policies drops from 23 rows to the 7 that are not part of any install. The Phase 23 run options are deleted. The login-shell handoff prints without asking. GitHub Copilot CLI joins the catalog with the same tuning. A dependency that is present but missing from the session PATH runs for the tools that need it. A silent step shows a live spinner and writes a timestamped heartbeat every 10 s.

This phase assumes Phase 23.1 has landed: `skill_lifecycle.py` is gone, `present_harnesses` lives in `postinstall.py`, the skill-pack `ConfigStepKind` values are gone, there is one `_launch_repairs()`, and the unit-test sandbox is in place.
</domain>

## Implementation Decisions

### Dispatch, ledger and the pending step (R1, R2, R3)
- **D-01: Every tuning kind runs through the engine's plural `post_install` dispatcher.** Today the dispatcher runs once per row, right after the row succeeds (`engine.py:333-351`, and `:233-247` for the `refuses_existing` OMZ reinstall), on every route.
  - A new action (name at Claude's discretion, e.g. `apply_agent_tuning`) is declared in `registry.toml` on claude, codex, opencode, cursor-agent, copilot and vscode. It returns its instruction lines plus the `FileResult`s it wrote.
  - `InstallOutcome` carries those `FileResult`s, and `RowOutcome.settings` reads them, so the existing "Agent and editor settings" summary block keeps working.
  - `_apply_run_options` is deleted (D-10). A run halted after claude's row still has claude's keys, because they were written by that row.
  - choice 0.73 (post_install_actions).
- **D-02: The setting group names in `agent_settings._KEYS` stay unchanged** (`auto-approve`, `no-attribution`, `vscode-lean`, `vscode-ai-off`, `vscode-ext-updates-off`). "Install tuning" for a tool means every group `setting_keys(tool, …)` returns. Copilot adds `("copilot", "auto-approve")` → `defaultPermissionMode = "allow-all"` and `("copilot", "no-attribution")` → `includeCoAuthoredBy = false`.
  - Ledger entries store the group name (`agent_settings.py:660-664`), and revert rebuilds the key table from it (`:859`, `:991-1003`). Renaming the groups would leave the keys written by the old Policies rows behind on removal (SPEC R3). Analyzer, Confident.
- **D-03: RECONFIGURE uses one new `ConfigStepKind` `"install_tuning"`, with the step text "apply install tuning".**
  - The `_run_step` branch (`session.py:398-402` closed set) calls the same tuning functions as D-01.
  - `_StepResult` / `_run_reconfigure` (`:513-534`) carry the `FileResult`s, so the summary shows what was written.
  - `apply_setting` gains a `skip_recorded` flag that drops keys the ledger records. RECONFIGURE passes it. Install and reinstall do not, so an explicit reinstall rewrites a key the user deleted (SPEC R2).
  - **Own reasoning** (jev low 0.65, writer_flag): one writer keeps the conflict, retry and compare-before-commit logic in one place (23 D-06). A pre-filtering caller would need a second, lower-level writer. Ledger.
- **D-04: The pending fact is computed per tool inside the state-pass loop, next to `_hook_fact` (`version_status.py:1962-1964`), and only when the tool is present.**
  - Agents and VS Code: pending = absent keys that the ledger does not record. Keys recorded and then deleted (`setting_facts.drifted`, `agent_settings.py:950-955`), keys "set by you", and keys already holding our value are excluded.
  - OMZ: pending when its plugin record is `None` (never touched; `omz.py:292-325`). A `()` record ("touched, nothing added") is not pending.
  - Shell init: see D-08.
  - Each pending tool gets one `ConfigStep(kind="install_tuning")`.
  - `tool_state` moves an absent tool's facts into notes (`:885-888`), so computing the fact for all agents up front would show "apply install tuning" on absent rows.
  - choice 0.97 (per_tool_in_loop).
- **D-05: A present agent whose settings file does not parse shows the O7 reason (`≈`, no step), whether or not its ledger has entries.**
  - Today `_settings_facts` (`version_status.py:693-716`) reads only agents that have a ledger ("not the installer's business until the user opts in"). Every present agent now has pending tuning, so the unparsable case needs a visible reason instead of a step that would only be refused.
  - The untrusted-ledger handling stays as it is.
  - **Own reasoning** (jev none): this settles the analyzer's edge-table gap (SPEC R1 "an invalid file is refused with `≈`"). Ledger.
- **D-06: A cursor-agent key holding the CLI's own default value (`cli_default`) does not raise `≈` on its own.** SPEC R2 raises `≈` only for absent keys. When install, reinstall or a RECONFIGURE triggered by another pending key runs, the default is still replaced, as `_apply_pass` does today (`agent_settings.py:668-673`).
  - choice 0.79 (already_configured).

### Silent-step indicator (R10)
- **D-16: The live indicator is a one-line widget directly under `#execute-log`, shown only while the in-flight step is silent. Heartbeats are transient `InstallLogLine`s appended to the RichLog.**
  - RichLog only appends, so a separate widget is the only way to update a line in place without private API.
  - The heartbeat reuses the transient/generation mechanism (`execute_screen.py:218-245`, `:795-802`, `:878-897`): it stays in the log, does not count as output, and a stale one is dropped.
  - The self-re-arming one-shot `_check_output_silence` becomes a 1 s tick while silent. Its "one pending timer" invariant (`:804-851`) is kept.
  - `_silence_noted` becomes a "heartbeats written this silence" counter.
  - The indicator appears at `SILENCE_SECONDS` (2 s) and reads `<frame> <tool> running · Ns`. A heartbeat line `HH:MM:SS <tool> still running (Ns)` is written at each further 10 s of silence (10 s, 20 s, …), measured from the last output.
  - Output, an open prompt or the row's end hides the indicator. `_WAITING_OUTPUT` is deleted.
  - choice 0.98 (widget_under_log).
- **D-17: `ExecuteInputs` gains an injected wall clock (`time.time`, for `HH:MM:SS` via `time.localtime`) and an `ascii_spinner` flag.** The composition root sets the flag once, from the output stream's encoding (not UTF-8 → `-\|/`; otherwise Braille frames). Elapsed time is whole seconds from the existing monotonic `now` (`:349`).
  - Tests drive both frame sets and the 25 s scenario with fake clocks, as `tests/test_execute_screen.py:1862-1909` already does.
  - Open point for planning: confirm which stream's encoding is truthful while Textual owns the terminal.
  - choice 0.98 (startup_flag).
