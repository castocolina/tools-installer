## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] The offline version-service double read the developer's real bun tree**
- **Found during:** Task 1 (full-suite run)
- **Issue:** `tests/state_doubles.py::offline_service` never injected `bun_versions`, so `VersionRefreshService` used the default reader of `$BUN_INSTALL`. With pi now carrying a bun method, a host whose bun tree lists pi made every catalog TUI and layout test resolve pi as bun-owned and attempt `registry.npmjs.org` (the network guard rejected it, failing about 25 tests in `test_layout_80x20`, `test_catalog_tui`).
- **Fix:** `offline_service` takes a `bun_versions` argument defaulting to a new `no_bun_globals()` empty reader.
- **Files modified:** tests/state_doubles.py (not in the plan's `files_modified`)
- **Commit:** 80331678

**2. [Rule 1 - Bug] `test_installing_mmdc_runs_pnpm_add_global_no_bare_npm` let a developer's bun answer**
- **Found during:** Task 1
- **Issue:** with a bun method first, the test passed only on a host with no `BUN_INSTALL`; with one set, `resolve_bun()` found the real bun and the ladder never reached pnpm.
- **Fix:** the test clears the three bun environment variables; its docstring says it exercises the bun-absent fallthrough.
- **Files modified:** tests/test_node_install_e2e.py
- **Commit:** 80331678

**3. [Rule 3 - Blocking] Extra files that pinned the old shape**
- **Found during:** Task 1 full-suite run (RESEARCH's list came from reading, not a run)
- **Files beyond the plan's `files_modified`:** tests/state_doubles.py (above); tests/test_ownership.py (`_FROZEN_REMOVAL` gains the `bun` row: `bun remove --global {}`, since the shipped registry now has bun methods); tests/test_version_status.py (`test_constant_probe_service_keeps_mmdc_available` expects `["bun", "node"]`).
- **Commit:** 80331678
