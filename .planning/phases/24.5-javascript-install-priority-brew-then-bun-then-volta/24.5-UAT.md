### 3. Script-installed bun without Homebrew on PATH

Steps:

1. Start `ti-uat-24.5-fedora` (`--init`, `fedora:latest`, dnf prerequisites plus the system `nodejs` 22.23.1, `chromium`
   and `zsh`, user `tester` with passwordless sudo, repo streamed to `~/workspace`, uv). No Homebrew
   (`command -v brew` empty, no `/home/linuxbrew`).
2. Install bun through the catalog (`install_one(tool_by_id("bun"))`).
3. Install mmdc with `setup.py --categories diagram --yes` as tester.
4. Check the receipts, the bun manifest, and fresh login shells (bash and zsh, with and without an inherited PATH).
5. Uninstall mmdc through the installer, then re-check the manifest, the bin dir and the command.

Expected: mmdc is installed by the bun method and `~/.bun/install/global/package.json` lists
`@mermaid-js/mermaid-cli`; `~/.bun/bin` is on PATH in a fresh login shell (`bash -lc 'command -v mmdc && mmdc
--version'` exits 0, same with `zsh -lc`); after the uninstall the entry leaves the manifest and `mmdc` is gone.

- Result: pass
- Notes: agent-run 2026-11-15 in `fedora:latest` (`ti-uat-24.5-fedora`, removed afterwards). Captures under
  `.../uat/24.5/`: `03-setup.log`, `03-pre-state.txt`, `03-install-bun.txt`, `03-after-bun-state.txt`,
  `03-profiles-after-bun.txt`, `03-setup-mmdc.txt`, `03-state-after-install.txt`, `03-login-shells.txt`,
  `03-login-isolated.txt`, `03-uninstall-mmdc.txt`, `03-state-after-uninstall.txt`; scripts `t3_*.sh`, `t3_*.py`.
  - bun: `BUN_INSTALL installed script` (method kind `script`), `~/.bun/bin/{bun,bunx}`, receipt `bun.json` kind
    `script`. The plan for the mmdc run read `bun skipped - already present`.
  - mmdc install ran `bun add` twice: first `puppeteer@25.17.0` (the required tool), then `@mermaid-js/mermaid-cli@12.2.0`
    with `puppeteer`. Receipts: `mmdc bun @mermaid-js/mermaid-cli`, `puppeteer bun puppeteer`, `bun script`,
    `drawio-desktop github_release`.
  - Manifest: `{"dependencies": {"@mermaid-js/mermaid-cli": "^12.2.0", "puppeteer": "^25"}}`; no
    `trustedDependencies` key (grep count 0); `~/.cache/puppeteer` holds `chrome` and `chrome-headless-shell`.
  - PATH: the managed block in `~/.myshellrc` now has `/home/tester/.bun/bin`, and `~/.bashrc` and `~/.zshrc` each
    source `~/.myshellrc`. Without the installer's wiring bun would still be on PATH, because bun's own install
    script wrote `export PATH="$BUN_INSTALL/bin:$PATH"` into `~/.bash_profile`. To prove the installer's wiring
    alone, I removed those two lines (restored afterwards, diff clean) and ran `env -i HOME=$HOME bash -lc ...`:
    exit 0, `/home/tester/.bun/bin/mmdc`, `12.2.0`.
  - Literal expected commands (`su - tester -c 'bash -lc ...'` and `zsh -lc ...`): both print
    `/home/tester/.bun/bin/mmdc` and `12.2.0`, exit 0. `env -i bash -lic` and `env -i zsh -lic` also exit 0.
  - Observation, not an issue: `env -i HOME=$HOME zsh -lc 'command -v mmdc'` (non-interactive login zsh with no
    inherited PATH) exits 1. The installer wires `~/.zshrc`, which a non-interactive zsh never reads, so the literal
    `zsh -lc` pass relies on the PATH the `su -` bash login shell already exported. A real fresh zsh terminal is
    interactive (`zsh -lic` passes), so no phase requirement fails; the owner may want to know that a script run as
    `zsh -lc` from a bare environment would not see `~/.bun/bin`.
  - Uninstall: `bun remove v1.4.4 ... - @mermaid-js/mermaid-cli`, `UNINSTALL removed= ('mmdc',) failed= ()`.
    Afterwards the manifest is `{"dependencies": {"puppeteer": "^25"}}`, `~/.bun/bin/mmdc` is gone, the mmdc
    package dir is gone, the `mmdc.json` receipt is gone, and `command -v mmdc` exits 1 in a fresh `bash -lc` and
    `zsh -lic`. `puppeteer` stays, as a separately receipted tool the installer put there.
  - No jev call: every check is an exit code or a literal match.

### 4. Docs claims

Owner sign-off item, delegated. Check: README and `.claude/architecture.md` never claim that bun-installed CLIs run
without node, or that bun is stricter than pnpm.

- Result: kept (owner delegated 2026-11-14)
- Notes: agent check 2026-11-15 against HEAD f660e361.
  - `grep -n -i "without node\|no node\|stricter\|safer\|without a node\|run under bun\|bun runs"` over both files
    matches only `README.md:200` and `README.md:203` (both the negated, correct statements below) and
    `.claude/architecture.md:400` ("Bun runs a dependency's lifecycle scripts only for its default allowlist...").
  - `README.md:197-199`: "Bun-installed CLIs run under node, not under bun. Their bins start with
    `#!/usr/bin/env node`, so a node must be on PATH. Volta stays the Node runtime; there is no `volta install`
    method."
  - `README.md:200-203`: bun runs lifecycle scripts only for its default allowlist or the user's
    `trustedDependencies` (which replaces the allowlist); "pnpm also blocks such scripts by default, so bun is
    comparable to pnpm, not stricter."
  - `README.md:204-206`: the installer never passes a trust flag nor writes `trustedDependencies`; the failure line
    names `bun add -g --trust puppeteer@^25`.
  - `.claude/architecture.md:398-402`: "Bun-installed CLIs run under node, not under bun, so they need a node on
    PATH; volta stays that Node runtime." and the same allowlist and `trustedDependencies` wording, no stricter-than-pnpm
    claim.
  - `.claude/architecture.md:468-470` and `README.md:154-157` describe the order brew, bun, pnpm, then the old
    order; `grep -n "last resort" README.md` finds no Homebrew line.
  - Test 3 backs the node claim in practice: mmdc ran under the system node 22.23.1 (`mmdc --version` printed
    `12.2.0`); the 24.5-09 container run covers the no-node failure.
