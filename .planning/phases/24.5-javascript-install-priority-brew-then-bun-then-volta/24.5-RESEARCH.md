## Summary

All seven requirements are an additive extension of patterns that already exist at HEAD: `bun` is a second "manager kind" shaped exactly like `node`/`uv-tool` (a package param, an executor, an `Owner`, an inventory field, an uninstall argv row). The resolver change is a three-number edit to `_RANK`. The only genuinely new mechanics are (1) file-based inventory for bun (no usable CLI), (2) an `update` route that cannot reuse the install executor, and (3) a bin/tree directory helper read by about eight sites instead of one declared `bin_dir`. CONTEXT's symbol list is almost entirely still valid; every symbol it cites exists at HEAD (the 24.4 retirement only moved `real_pnpm` to `installer/legacy_guard.py:232`). The one CONTEXT name that is not a function: `app.perform` is `app.remove_tool` (`installer/app.py:745`).

The riskiest finding is not in bun at all: `brew`-first changes the first method of **50 tools on macOS+brew, 57 on mutable Fedora+Linuxbrew, 48 on immutable Fedora+Linuxbrew and 0 on Debian without brew** (computed below against the real resolver, registry of 86 tools). It also removes the plan-time `MANUAL` handoff for 9 dnf-first system tools (docker, git, glab, jq, podman, unzip, watch, zip, zsh) on Fedora hosts that have Linuxbrew, and it routes `claude` and `codex` to their Homebrew casks on macOS even though SPEC Out of Scope says the vendor-installed agent CLIs "do not change". The code path in PRIO-01 is correct as specified; the owner-visible consequence is large and is flagged for confirmation (Assumptions A5, Open Question 3).

Two design traps need an explicit plan decision: after a bun method's post-install smoke fails, `engine.install_tool` falls through to the next method, so a blocked-puppeteer bun install would be followed by a pnpm install carrying `--allow-build=puppeteer` (Pitfall 2); and `tests/test_registry.py:2059` (`test_shipped_node_tools_require_pnpm`) contradicts D-19's `requires` change and must be rewritten in the same commit as the registry edit.

**Primary recommendation:** land the phase as ordered, each commit green: (1) model + resolver + `_bun` executor + engine/status/shellrc dir readers with unit tests and no registry change; (2) ownership/inventory/version-status/update/remove/Doctor for bun with seeded-tree tests; (3) registry migration of mmdc/puppeteer/pi together with every registry/dep/e2e test it breaks; (4) the `_RANK` change last (or together with its golden table) because it rewrites 45 existing tests; (5) docs; (6) the container acceptance verb.

### Pattern 1: Manager kind = param + executor + owner + inventory + uninstall row
**What:** every manager kind (`brew`, `cask`, `uv-tool`, `node`) is one row in `KIND_PACKAGE_PARAM` (`model.py:109-119`), one `EXECUTORS` entry (`executors.py:684-691`), one `_KIND_TO_OWNER` entry (`ownership.py:149-155`), one inventory field, one `MANAGER_UNINSTALL_ARGV` row (`uninstall.py:111-116`). `ownership._REMOVAL_COMMANDS` (`ownership.py:1540-1546`) and `manager_kind_label` (`:1700-1706`) are generated from the argv table, so the hint and the removal cannot drift.
**When to use:** the whole bun lifecycle. Add `bun` to each, nothing bespoke.

### Pattern 2: Fail closed on unreadable inventory
**What:** an inventory `None` is "could not ask", never empty (`ownership.py:386-392` docstring; `_unreadable` `:1185-1198`). For bun: missing tree -> `{}`; invalid/unreadable manifest -> `None`.

### Anti-Patterns to Avoid
- **Reusing the install executor for update:** `bun add -g semver@^7` over 7.5.0 kept 7.5.0 (CONTEXT D-13 live). Use `bun update -g`.
- **Mapping bun into the brew/pnpm outdated branch** (`version_status.py:596-631`): "absent from the outdated map" means current there; `bun outdated -g` lists nothing, so every bun tool would read current forever.
- **Passing `--trust` or writing `trustedDependencies`:** replaces bun's default allowlist when the key is absent.
- **Putting `"bun"` in `catalog_tui._detail_text/_health_block`:** `tests/test_catalog_tui.py:1995-2003` fails if any quoted owner literal appears in their source.

## Common Pitfalls

### Pitfall 1: `_RANK[m.kind]` KeyError for a new kind
**What goes wrong:** a `bun` stanza in the registry before `"bun"` is in `_RANK` raises `KeyError` inside `sorted()` for every resolve call, including `load_tools` consumers.
**How to avoid:** the commit that adds the kind adds the `_RANK` entry and `METHOD_PARAMS` row together; the registry edit comes after.
**Warning signs:** `tests/test_ownership.py:1618` (iterates `resolve._RANK`), `tests/test_model.py:1368`.

### Pitfall 2: ladder fall-through after a bun smoke failure
**What goes wrong:** `engine.install_tool` catches `ExecutorError` from the executor (`engine.py:320-321`) and tries the next method. A blocked puppeteer postinstall (D-21) raises from `_bun` after `bun add -g` already installed both packages; the ladder then runs the `node` fallback, i.e. `pnpm add -g --allow-build=puppeteer`, a second install carrying exactly the grant PRIO-06 refuses to widen, and leaves two copies (bun's, which the failed run already left on PATH). The engine's "left installed after its smoke run failed" note (`engine.py:300-313`) covers only `_run_manager_smoke`, not the executor's own smoke.
**Why it happens:** one exception type means both "this method could not start" and "this method ran and left state".
**How to avoid (recommend, needs a planner decision):** make a post-install smoke failure terminal for the ladder, e.g. a dedicated `ExecutorError` subclass that the engine records and then stops on (as `ChecksumMismatch` already does under `checksum_policy == "fail"`), with the leftover/remove-hint text. Pre-install failures (bun missing, node floor) stay fall-through, as SPEC R2 requires. The alternative (accept the fall-through) must be a conscious owner call because it contradicts the PRIO-06 intent.
**Warning signs:** a test with a `trustedDependencies = ["esbuild"]` manifest that shows a `pnpm add` call after the bun failure.

### Pitfall 3: bun bin dir is not wired by existing machinery
**What goes wrong:** every bin-dir reader (`engine.py:54,297`, `status.py:104`, `version_status.py:449,506`, `shellrc.py:85`) reads `method.params["bin_dir"]`; a bun stanza has no such param (D-05 params list) so mmdc installs fine but is not on PATH for this run's dependents or for a fresh login shell.
**How to avoid:** D-07's helper must be called in `engine._manager_smoke_target`, the engine prepend, `status.present_bin_dir`, `collect_bin_dirs`, `version_argv` (`:449` loop) and the owner dir; add a test per site (Validation map). `collect_bin_dirs` wires only an existing directory (`require_exists=True`), and `~/.bun/bin` does not exist after a brew-installed bun until the first global install, so the wiring step must run after the install, which `app.py:220` / `setup.py:1160` do at the end of the run. Container acceptance "fresh login shell" proves it.

### Pitfall 4: `SMOKE_CHECKS` zero-arg contract
**What goes wrong:** D-08 wants an owner-first puppeteer root, but `SMOKE_CHECKS` callables and the `launch_puppeteer` seam take no arguments and ~8 tests replace them with zero-arg lambdas (`tests/test_executors.py:1082,1089`, `tests/test_version_status.py:5499`, `tests/conftest.py:65,401,446`).
**How to avoid (two shapes, pick one in planning):** (A) widen to `Callable[[str | None], None]` and edit those tests in the same commit; (B) keep zero-arg callables and carry the preference as a keyword on `run_smoke_check(name, *, prefer=None)` and `_bun`'s direct call, resolved inside `_puppeteer_module_roots(prefer)` while `launch_puppeteer` becomes `Callable[[str | None], str | None]`. Both touch the conftest seam; A is the more explicit design.

### Pitfall 5: `requires` drops pnpm, so the fallback has no provider
**What goes wrong:** D-19 sets `requires = ["bun", ...]`. If the bun method fails (node below floor is plan-gated, but a missing node reads "could not be read" and fails at run time), the ladder falls to the pnpm `node` method on a host where pnpm was never installed, which then fails with "pnpm not found". The live bun runs all had node (22.23.1); `bun` does not provide node, and the catalog has no node tool (`rg '^id = "(node|nodejs|fnm|nvm|mise)"'` finds only `fnm`; no `requires` names `fnm`, `volta` or `node`). That is the same gap that exists today for pnpm, but with bun-first it is now reachable on machines that have bun and no node.
**How to avoid:** accept and document, or add the node provider as an explicit open question for the owner (Open Question 2). The executor's floor message already names the fix.

### Pitfall 6: `ManagerInventory` constructors
**What goes wrong:** 33 call sites build `ManagerInventory(...)` with five required fields; a sixth required field turns one commit into an 11-test-file edit.
**How to avoid:** add `bun_globals` as the last field with default `None` (reads as "unknown", the safe default) and pass it explicitly only in `read_inventory`, `_merge_inventory`, `_decode_inventory`, `_EMPTY_INVENTORY`.

### Pitfall 7: the manager snapshot is cached on disk
**What goes wrong:** `version_cache` persists the inventory (`version_cache.py:325-340`) and `_merge_inventory` backfills a failed field from the last good snapshot (`version_status.py:148-163`). A bun tree is a cheap file read; caching it makes freshly installed or removed bun packages read stale until the snapshot ages out, and a merged-from-previous `bun_globals` would hide an unreadable manifest.
**How to avoid:** read `bun_globals` live in `_pass` (never persisted, never backfilled), or persist and make `_partial_manager_failure` (`version_status.py:1705`) treat `bun_globals is None while the manifest exists` as a failure. The first is simpler and keeps fail-closed semantics; note `_decode_inventory` of an old cache then needs no new key.

### Pitfall 8: removal ordering and bun's peer behaviour
**What goes wrong:** removing puppeteer while mmdc stays keeps the package and bin link (live). `removal_order` (`app.py:512`) removes dependents first, so a joint run removes mmdc first, and puppeteer's own removal then finds it gone or kept; a naive "command succeeded" reports removed.
**How to avoid:** the post-command tree check from D-14, in both the ALREADY_REMOVED shortcut and after `runner(command)`.

### Pitfall 9: `host_setup` pi leftovers
**What goes wrong:** dropping pi's `host_setup` method leaves `owner_probes = ["host-setup"]`, `HOST_SETUPS["pi"]`, `update._perform`'s `method is None` pnpm branch and `update_refusal`'s host-setup refusal (`update.py:332-341`) with no registry user. They are intentionally kept for Phase 25, but vulture/pyright will not flag them (they are reachable from tests), so remove only the registry's `owner_probes` and `desc` wording; leave the code.

def bun_dirs(environ: Mapping[str, str], home: Path) -> tuple[Path, Path]:
    install = environ.get("BUN_INSTALL")

### `_bun` skeleton (mirrors `_node`, `executors.py:463-555`)
```python
def _bun(method: Method, runner: Runner) -> None:
    npm_pkg = require_str(method, "npm_pkg")
    co_install = _opt_pkg_list(method, "co_install")
    versions = _opt_version_map(method, "versions")
    smoke = _opt_smoke_name(method)          # shape validation BEFORE the bun probe, as _node does
    bun = _resolve_bun()                      # PATH first, then bun_dirs bin dir; raise ExecutorError with one fix line
    min_node = method.params.get("min_node")
    if isinstance(min_node, str) and min_node:
        _require_minimum("node", ["node", "--version"], min_node)   # before bun add: no half-installed package
    members = list(dict.fromkeys([npm_pkg, *co_install]))
    specs = [f"{n}@{versions[n]}" if n in versions else n for n in members]
    runner([bun, "add", "-g", *specs])        # one argv element per spec; never --trust
    if smoke is not None:
        SMOKE_CHECKS[smoke]()                 # see Pitfall 2 for what a failure here means to the ladder
```

| Brew-first replacing checksum-verified downloads with brew bottles | Tampering | accepted trade (brew verifies bottle SHA); recorded as a behaviour change for the owner |
| Removing another manager's copy | Denial | removal runs only for a receipt of kind `bun` naming the declared package (`uninstall._manager_argv`, `uninstall.py:329-340`) |

## Project Constraints (from AGENTS.md / .claude)

- **uv only** for environment and dependencies; never pip, poetry, conda.
- **Never bypass a quality gate**; no skip/xfail; fix root causes. `make validate && make test` must pass on the exact tree before any commit.
- **Coherent commits**: one self-contained, valid change each (amend/squash, no "fix review comment" piles). Every intermediate commit green.
- **Never mutate the developer's host**: no `make setup/fix/uninstall/doctor/guard/unguard`, no mutating `systemctl --user`, no edits to real shell rc or agent settings; tests use a scratch HOME; real installs only in disposable containers (`scripts/detect-container-runtime.sh`), removed afterwards.
- **Zero sudo**: no `sudo`/`pkexec`/`doas` code path; privileged steps are handed off as text.
- **English only** in every identifier, comment, docstring, log line and commit message.
- Architecture rules (`.claude/architecture.md`): one view registry, one nav path, one apply workflow, wiring-only `setup.py` (so the Doctor/bun wiring in `setup.py:958` stays a thin closure).
- pyright strict, ruff, bandit, vulture (`make validate`); a new function with no caller fails vulture.
- Testing: deterministic and offline; `-n auto` never dropped or raised; xdist-safe tests; no fixed shared paths.
- Open GSD rule in the user's global instructions: GSD is installed per project only; use the project-local `.claude/gsd-core/bin/gsd-tools.cjs` (used here for the legitimacy check).
