# Phase 24.5 Plan 09: the bun-lifecycle container verb and its two real runs Summary

A `bun-lifecycle` verb in `scripts/container-e2e-verify.sh` proves, in a disposable Fedora container, that mmdc installs through a Homebrew-installed bun with a working browser and login-shell PATH, that pi is owned by bun, that a hidden bun falls back to a real pnpm, that the node floor and the user trust list refuse correctly, and that removal against real receipts works. The first real run passed all twelve verdicts, and the unchanged `audit-landing` verb passed once after the landing driver refactor.

## Performance

- **Duration:** about 6 hours wall clock, almost all of it waiting on container bootstraps (a dnf download of about 520 packages ran at 100 to 400 KiB/s on this host; one bootstrap took 50 minutes). The start time was not captured, so this is an estimate.
- **Completed:** 2026-11-15
- **Tasks:** 3 of 3 (Tasks 1 and 2 committed; Task 3 is the two real runs, which the plan says need no commit)
- **Files modified:** 6 (two new, four edited)

## Accomplishments

- `bun-lifecycle` verb: `cmd_bun_lifecycle` names its container `tools-installer-e2e-bun-$$`, sets `CONTAINER_NAME`, `IMAGE` and `DISTRO` itself, reuses the landing bootstrap and step helpers through a new `LANDING_DRIVER_MODULE`, and traps `landing_teardown` on EXIT. The dispatcher entry and usage text name it.
- `landing_teardown` builds its verdict once, prints it, and appends it to `${LANDING_TRANSCRIPT:-}` (tolerating an unset variable and a missing directory), so both transcripts end with the verdict.
- `tests/e2e_bun_driver.py`: nine verbs (`install-mmdc`, `idempotent-mmdc`, `strict-loader`, `pi-owner`, `kept-peer`, `remove-both`, `fallback`, `floor`, `trust`) over `installer`'s own code, each ending in a pure verdict function with a host test. Negative steps check that mmdc is absent first (`absent_detail`); removal steps check the expected bun or node receipt first (`receipt_detail`).
- The landing driver's shared helpers are public, `install_one` passes `read_inventory_fn=read_inventory` as `setup.py` does (so bun and node installs write their receipts), and a new `uninstall_tools` lets `remove-both` remove two tools in one Uninstall decision.
- Two real container runs passed (below), the receipts probe was confirmed with herdr (below), and every container was removed.

### Receipts probe with herdr (orchestrator override 2)

24.5-07 moved the receipts probe from yq to herdr (`RECEIPT_PROBE_TOOL=herdr`, `RECEIPT_PROBE_CATEGORY=terminal`) because brew-first now installs yq through Homebrew. The route that runs the assertions is `pass1`. A chunked `pass1 --categories terminal` runs `assert_receipt_present`, but `pass2`, which holds the removal-side assertions, refuses after a chunked pass1 (it reruns `--all`, a full-catalog install I did not run). So I ran, in one real container named `tools-installer-e2e-fedora`: `bootstrap --replace`, then `pass1 --categories terminal`, then, from a scratch script that loads the harness functions without `main`, `assert_receipt_ready_for_removal`, `setup.py --uninstall --yes` as the tester, and `assert_receipt_removed`.
