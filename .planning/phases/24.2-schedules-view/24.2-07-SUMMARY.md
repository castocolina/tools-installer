# Phase 24.2 Plan 07: Cross-process run lock in MutationLock Summary

**The TUI's install, update, removal and pnpm-reinstall work now takes the same flock as every scheduled run, refusing with "A scheduled run is running; ..." instead of overlapping a timer.**

## What was built

- `MutationLock.begin_mutation(holder, *, screen=None) -> bool`: for the four cross-process holders it calls `runlock.try_acquire(run_lock_path(), "installer")`; a lost race sets `SCHEDULED_RUN_REFUSAL` on the screen, posts `RefreshRequested`, and returns False holding nothing. `end_mutation` releases the `RunLock` before clearing the holder.
- `refuse_if_mutating(screen, *, cross_process=False)`: in-app check first, then (when asked) `runlock.holder(...)` only, never a flock probe.
- `MutationHolder.SCHEDULE_CHANGE = "A schedule change"`; `"A scheduled run"` is a refusal constant, not a member (R1-05). `tests/test_screen_family.py` `_NOUNS` gained the new member.
- Call sites: catalog `u` and batch accept, Uninstall `_apply_removal`, Doctor pnpm reinstall (`cross_process=True` plus the `begin_mutation` answer), and the install run in `ExecuteScreen._begin_run`.
- Toggles and schedule changes are untouched (in-app lock only), so a toggle during a scheduled run lets the run finish.

## Deviations from Plan

None in kind. Two small implementation notes:

- The `UpdateService.begin` latch now comes after `begin_mutation` in the catalog update key (the plan's "before any worker starts or `UpdateService.begin` latches"); the bare-guard failure branch calls `end_mutation()` so a lost latch never leaves the run lock held.
- The INSTALL_RUN take moved to `_begin_run` as the plan preferred; no existing test needed the take to stay in the app handler. `test_run_in_flight_flag_lifecycle` calls the handler directly and only checks `run_in_flight`, so it passes unchanged.

Test-side note: `tests/test_mutation_runlock.py` reuses the family helpers from `tests/test_screen_family.py` through `vars(importlib.import_module(...))["_x"]`, per the private-name rule.
