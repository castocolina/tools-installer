# Phase 24.2 Plan 11: The handover switch Summary

**Schedules now owns the tmp cleanup: Policies lists 6 rows (Linux) or 4 (macOS), undecided schedules turn on at launch, after each install run, after the headless install and after every removal, and the uninstall sweeps one `schedule:<id>` adapter per owned schedule behind the shared run lock.**

## What was built

Task 1 (0063010)
- `ScheduleDefaultWarnings` and `SCHEDULE_DEFAULT_WAIT_SECONDS` moved from `installer/policy.py` to `installer/schedules.py` (same body); `policy.DaemonDefaultWarnings` is gone.
- `setup.py`: the daemon left the Policies list only (the policy object is still built for the uninstall until Task 3). `_schedule_context(platform, present)` is the one context builder; `_reconcile_headless` runs `ensure_schedule_defaults` and prints each `reconcile_lines` text with `markup=False, soft_wrap=True`.
- Headless `--all/--categories`: `runlock.try_acquire` before `run_wizard`; held means `A scheduled run is running; try again when it finishes.` (new `runlock.BUSY_MESSAGE`) and exit 1; the lock is released in `finally` after the reconcile.

Task 2 (da16b5b)
- `MutationHolder.DAEMON_DEFAULT` became `SCHEDULE_DEFAULTS = "A schedule setup"`. `UnifiedApp(schedule_defaults=...)` replaces `daemon_default`/`daemon_default_policy_id`; the constructor takes the holder, `_apply_schedule_defaults_worker` (same `try/finally`, `exit_on_error=False`) posts `ScheduleDefaultsApplied(report)`, and `on_install_run_finished` starts the same worker after `end_mutation()` of the run.
- `on_schedule_defaults_applied` releases the lock first, routes `reconcile_lines` to the visible view's status (or the pending-warning queue), repaints Schedules and the visible view, and moves a deferred first-run link pick.
- `setup._build_app(apply_schedule_defaults=, schedule_default_warnings=)`: the closure runs the reconcile, feeds each warning once to `ScheduleDefaultWarnings` (the post-`app.run()` console print is unchanged) and always `finish()`es.
- Disk-pressure copy points at Schedules (see New copy).

Task 3 (ef01041)
- `SweepResult.schedule_lines`; `_after_removal(schedule_removed=...)`; `_merge` and `removal_result_lines` carry it; `run_uninstall` and `perform_uninstall` thread the keyword.
- `setup.py`: both uninstall inputs and the CLI teardown pass `daemon_policy=None`, `extra_policies` with `schedules.sweep_adapters(ctx)` (read when a sweep starts, before any removal), and `schedule_removed`. `_run_uninstall` takes the run lock around the whole CLI teardown (`_teardown_cli`).
- Uninstall copy keys off `schedule:` ids (`has_schedule_id`, `schedule_phrase`): `the background maintenance job` / `jobs`, or `the schedule state and logs` when only `schedule:state` is left; the tweak row's timer sentence follows `UninstallInputs.platform_os` (only `== "macos"` is compared).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] An rc file that is not valid UTF-8 crashed the sweep adapters**
- **Found during:** Task 3 (`test_every_route_survives_a_non_utf8_myshellrc`)
- **Issue:** `schedules._tmp_decided` called `daemon.decided`/`systemd_daemon.decided`, which `read_text()` the rc; `sweep_adapters` and the reconcile raised `UnicodeDecodeError` on `~/.myshellrc` bytes that are not UTF-8 (a 24.2-08 gap that only surfaced once the sweep was wired into the teardown).
- **Fix:** `_tmp_decided(ctx, *, unreadable=True)` returns `unreadable` on `OSError`/`UnicodeDecodeError`: the reconcile treats an unreadable marker as decided (never turns tmp on over a decision it cannot see), `_state_leftovers` passes `unreadable=False` (the sweep never touches a marker it cannot prove). Covered by `test_a_non_utf8_rc_breaks_neither_the_sweep_nor_the_reconcile`.
- **Files modified:** installer/schedules.py, tests/test_schedules_handover.py
- **Commit:** ef01041

### Judgment calls

- **TUI reconcile context.** The plan said bind the closure "to the same context the view uses". The view's `present` is `version_refresh.installed_or(launch)`, which falls back to the launch snapshot after an install run invalidates the cache, so the reconcile that follows an install would not see the new tool. The reconcile closure uses `_schedule_context` with a live `is_installed(tool)` probe; the view and the sweep keep `installed_or`. The headless route uses `refresh.installed_or(launch)` computed after `run_wizard`.
- **Shared predicates.** `has_schedule_id` and `schedule_phrase` are public in `installer/app.py` and imported by `wizard_app.py` (one copy, not the mirrored pair the plan implied). The acceptance grep (`_has_daemon_id` 0) holds; the PoliciesScreen detail branch that used the old predicate now tests `policy.id.startswith("daemon:")` inline, because 24.2-12 deletes that branch and its tests.
- **`UninstallInputs`.** It carries `platform_os` (Linux/macOS wording) but not `schedule_removed`; the hook is bound in setup's `_do_uninstall` closure, so the screen never needs it.
- **Collector warnings.** `ScheduleDefaultWarnings` receives each reconcile warning once (a set in the closure), because the reconcile now runs at mount and after each install run; warnings also appear in the first view's status (UI-SPEC section 8) as well as in the post-exit console print.
- **Sweep ids on the TUI route.** The plan's `test_full_uninstall_sweeps_schedules` expects `schedule:update-claude` among the swept ids on both routes. On the TUI route `sweep_tweaks` re-filters adapters by `owned` at sweep time, and the removal hook has already taken claude's files, so that id is reported by the hook line ("Removed the claude update timer because claude is gone.") instead; the CLI route builds its policy list before the removal and sweeps all three. The test asserts that split.
- **Migrated, not carried over.** `test_on_by_default_treats_an_existing_installation_as_fresh` (a daemon-D-01 pin with no schedule equivalent) became `test_schedule_defaults_run_once_per_launch`; the `refresh_daemon_state` pins became schedule-repaint tests. `PoliciesScreen.refresh_daemon_state`/`live_state`, `ensure_daemon_default`, `_build_daemon_policy` and the `daemon_policy=` parameters stay, unused by production wiring, for 24.2-12.
