# Phase 24.2 — UI Design Contract

> Visual and interaction contract for: the seventh view, Schedules (table, detail panel, note line, keys), its two modals (when it runs, cursor-agent model), the status, startup and headless lines it adds, the `--run-schedule` result line and the run-log line form the view reads, and the Policies view after the tmp-cleanup row leaves.
> Generated by gsd-ui-researcher in an autonomous run (no user questions: answers come from `24.2-SPEC.md`, `24.2-CONTEXT.md` and the Phase 21-23.1 contracts; open points are decided and listed under **Provisional decisions**). To be verified by gsd-ui-checker.

This is a **Textual terminal UI** plus a headless Rich console, not a web frontend. Units are terminal **cells** and **rows**. The design system is the Phase 21 contract as extended by Phases 22, 23 and 23.1 (`23-UI-SPEC.md`, `23.1-UI-SPEC.md`). This file **extends them and never contradicts them**: house chrome (`AppScreen`, `WayfindingHeader`, `ModeBadge`, `StatusLine`, `FooterBar`, all driven by `VIEWS`), the glyph set `… ! ≈ ↑ ✓ ○ –` and the Policies marks `●` / `○`, Rich named ANSI styles, the 78-cell line budget at `size=(80, 20)`, no motion, sentences with an em dash, `run_live` as the only apply path, `UnifiedApp.show_view` as the only navigation path, the one mutation-lock template `{Holder} is running; wait for it to finish. Navigation still works.`, and data rendered as `Text`, never markup.

**Binding minimum:** `size=(80, 20)` with `NO_COLOR=1`. Every state is a word or a glyph first; color is redundant.

**Sources (locked, none re-asked):** `24.2-SPEC.md` R1-R9 (amended R3, R4, R6, R7, R8), `24.2-CONTEXT.md` D-01..D-26 (UI-bearing: D-04, D-05, D-09, D-12, D-13, D-14, D-17, D-18, D-20, D-21, D-22, D-23, D-24; Claude's Discretion: column widths, row and modal wording, the logged-in / power-off note), `.claude/architecture.md` (five rules), `23-UI-SPEC.md` (Policies State column, detail panel rules, status width rule), `23.1-UI-SPEC.md` (format, launch-notice path). ## 3. Table columns and cells (R1, R3, R4, R8; D-13)

Rows in the fixed order of SPEC R2, whatever their state; always seven rows (a host with nothing installed still shows all seven).

| # | Row label (status copy) | Schedule cell | Target cell |
|---|-------------------------|---------------|-------------|
| 1 | `tmp cleanup` | `tmp cleanup` | `$TMPDIR` |
| 2 | `cache cleanup` | `cache cleanup` | installed managers, space-joined in the order `uv pnpm brew npm`; `none` (dim) when none resolves |
| 3 | `claude update` | `update` | `claude` |
| 4 | `opencode update` | `update` | `opencode` |
| 5 | `pi update` | `update` | `pi` |
| 6 | `cursor-agent update` | `update` | `cursor-agent` |
| 7 | `copilot update` | `update` | `copilot` |

The Schedule cell names the job and the Target cell names what it acts on, so no cell repeats another; status, headless and log copy use the full row label (`claude update`). *(provisional — P3)*

**Columns, left to right, with fixed content widths** (DataTable `cell_padding` 1 adds 2 cells per column: 64 + 14 = 78 cells):

| Column header | Width | Cell content | Style |
|---------------|-------|--------------|-------|
| `Schedule` | 13 | as above | `bold` |
| `Target` | 12 | as above; longer text is cut with a trailing `…` (`uv pnpm brew…`) | regular |
| `State` | 9 | `● [on]`, `○ [off]`, `! [drift]`, `– [n/a]`, `…` | see Color |
| `Every` | 9 | `6h 00:00` (interval + start, the default); `8h 01:30`; `24h 23:30`; Linux tmp cleanup `10 min`; macOS tmp cleanup `24h 03:30` | regular; `dim` when off or n/a |
| `Next` | 5 | `HH:MM` local, from D-04's slot function (always within 24 h); `–` when off, n/a, drift or `…` | regular; `dim` for `–` |
| `Last` | 7 | `✓ HH:MM` ok, `– HH:MM` skipped, `! HH:MM` failed (incl. interrupted), `running`, `never`; a result from an earlier day shows days ago instead of the time: `✓ 2d` (`>99d` cap) | see Color |
| `Script` | 9 | basename of the file the timer executes: `runner.py` (D-10, every timer runs the copied runner); a longer name is cut from the left with a leading `…` | `dim` |

Rules:

- **State words.** `on` = decided on and every recorded file present and matching. `off` = decided off, or undecided with the target present on a host where the default pass has not run yet. `drift` = decided on, but a recorded file is missing or its sha256 no longer matches. `n/a` = unavailable; the literal SPEC reason `unavailable: <reason>` is the detail panel's first line and the refusal text (section 5). `…` = still unknown (manager probe running, or the target's tool state not yet published). *(the short `– [n/a]` cell is provisional — P2)*
- **Unavailable reasons (literal):** `unavailable: {tool} not installed` (rows 3-7 when the target is absent from the published tool state); `unavailable: no user timer manager` (every row, D-24). tmp cleanup and cache cleanup have no target tool, so only the second reason applies to them.
- **Last cell from the log (D-13).** The newest `start` / `ok:` / `skipped:` / `failed:` line for the row's id wins. No line: `never`. A trailing `start` with no result: `running` while the run lock is held, else `! HH:MM` (the start time) with `failed: interrupted` in the detail panel. Times are local to the minute; a result under a minute old shows its own time, never a future one.
- **Next cell** uses the same slot function as the unit file (D-04); for Linux tmp cleanup it is the last result time + 10 min, or `–` if it never ran.
- **Refresh.** The screen re-reads `schedules.json`, the `~/.myshellrc` tmp markers and the log on `enter_view`, on every app publish while it is on top, after every mutation, and every 30 s while Schedules is the top screen (a Textual `set_interval` paused when another view is pushed), so `running` and `Next` do not go stale. These reads are file reads and one non-blocking `flock` probe; render never spawns a process. *(30 s refresh is provisional — P5)*
- **Encoding.** Every cell is a sanitized `Text` measured with `rich.cells.cell_len`; a path or id with spaces, non-ASCII or `[red]` renders literally and never widens a column past its fixed width.

Example at 80x20, Linux, `NO_COLOR=1` (copilot not installed, opencode pacman-owned):

 update         claude        ● [on]     6h 00:00   18:00   ✓ 12:00  runner.py

## 4. Detail panel (`#schedule-detail`) (R1, R2, R4, R7, R8; D-05, D-13, D-21)

Describes the highlighted row. Lines in this order, most important first, so a 6-row panel at 80x20 clips only the tail; each fixed part ≤ 78 cells, longer interpolated lines wrap:

1. **State line**
   - on: `{label} is on — {what}.`
   - off: `{label} is off — {what}.`
   - drift: `Drift: its timer files are missing or changed. space writes them again.` (72)
   - n/a: `unavailable: {reason}` (literal SPEC string), then on the next line `{what}.`
   - `{what}`: tmp cleanup `deletes orphaned Bun runtime files from the temp dir` · cache cleanup `runs each installed package manager's prune command` · updates `runs {tool}'s update the way the catalog's u does`
2. **Last:** `last: {ISO-8601 local with offset} {result}` — the full result text from the log (e.g. `last: 2026-11-13T12:00:04+01:00 skipped: pacman owns opencode`), `last: never`, `last: running since HH:MM`, or `last: {ts} failed: interrupted`.
3. **Times:** `times: 00:00, 06:00, 12:00, 18:00 (local)`; with more than 8 slots: `times: 00:30, 01:30, 02:30 … 23:30, every hour (local)` (interval 1) or `… every 2 hours (local)` (interval 2); Linux tmp cleanup `times: every 10 min, first run 2 min after login`; macOS tmp cleanup `times: daily at 03:30 (local)`.
4. **Row-specific lines**
   - cache cleanup: `prunes: uv cache prune · pnpm store prune · brew cleanup · npm cache verify` (only the managers that resolve), or `prunes: nothing — no uv, pnpm, brew or npm found`.
   - cursor-agent update: `model: {model} — press m to change`; then at most one of `! {model} is not in your model list; the shim passes arguments through.` (D-20 pass-through) or `model unverified: could not read the cursor-agent model list; using {model}.`; and, when present, `your own ~/.local/bin/cursor-agent is kept: it has no installer sentinel.`
   - tmp cleanup: the lines moved byte for byte from Policies (D-21): the Linux linger sentence (`The timer runs while you are logged in. For always-on operation, run \`loginctl enable-linger $USER\` yourself; …`), the temp-usage line (`_temp_usage_line`) and the competing-unit line (`_competing_line`, `Also installed system-wide: …`). The `Press t to set the daily run time; press l to view the run log.` and `The daily time picker does not apply to this row.` sentences are dropped (their keys are gone).
5. **Runs:** `runs: uv run --no-project --script {runner path} {job args}` with `$HOME` shown as `~` (e.g. `runs: uv run --no-project --script ~/.local/share/tools-installer/schedules/runner.py update claude`). Shown for off and n/a rows too, as "what it would run".

All values (paths, ids, model ids, result text) are sanitized with `sanitize_log_line` and appended as `Text`. The panel is a `Static`; at 80x20 a row's lines 1-4 fit in 6 rows for the default fixtures; a taller terminal shows everything.

## 7. `CursorModelScreen` — default model (R7; D-18, D-20)

`ModalScreen[str | None]`, `align: center middle`, width 64, height 16, `border: round $accent`. Opened with `m` on the cursor-agent update row.

| Part | Widget | Content |
|------|--------|---------|
| Title | `Label` (bold) | `Model cursor-agent uses when no --model is given` (48) |
| Field | `Input` | prefilled with the configured model (default `gpt-5.6-sol-xhigh`); filters the list below by substring and is also the free-text value |
| List | `OptionList` (`1fr`) | ids from `cursor-agent --list-models`, read on a thread worker when the modal opens; the configured id is prefixed `● `, others `  ` |
| Loading | `Label` (dim) in place of the list | `Reading your cursor-agent models…` (33) |
| List failure | `Label` (`yellow`) in place of the list | `Could not read the model list: {first error line}. Type a model id.` |
| Error | `Label` (`red`) | empty until a rejected value |
| Keys | `Label` (dim) | `enter use \| esc cancel` |

- `enter` on an option returns that id; `enter` in the `Input` returns the typed text. `esc` returns `None`. Dismissing cancels the list worker's result (an answer that lands after dismissal is dropped).
- Validation (D-18): the closed character set `[A-Za-z0-9._-]` plus `[ ] = ,`; anything else → `Model ids use letters, digits and . _ - [ ] = , only.` (53), modal stays open. An unlisted but valid id is accepted (offline editing must work) and leads to the pass-through warning in section 5.
- The default model `gpt-5.6-sol-xhigh` **needs confirmation** (upstream D-20: the user asked for `gpt-6.1-sol`, which the live list lacks). *(P7)*

## 8. Startup, headless and run-log lines (R3, R6, R8, R9; D-09, D-11, D-14)

### Default-on reconcile (D-09) — TUI first-view status and headless console

Emitted once per pass that changes something; nothing is printed when nothing changed. TUI: through the existing startup-warning path (first view's status); headless: printed after `run_wizard` with `markup=False, soft_wrap=True`.

| Case | Line | Severity |
|------|------|----------|
| schedules turned on by default | `Turned on schedules: {labels}. Change them in Schedules.` (78 with two labels; a longer list wraps) | ok |
| target gone, files removed (decision kept) | `Removed the {label} timer because {tool} is gone.` (67 for cursor-agent) | ok |
| default apply failed | `Could not turn on {label}: {first error line}.` | warn |
| competing-mechanism notice | the existing text, byte for byte (moves from the Policies daemon worker) | warn |

A user's `off` is never reported or changed (SPEC prohibition).

### `--run-schedule <id>` (D-14) — machine-facing, one line

Prints exactly one line to stdout and sets the exit code to match: `ok: up to date` · `ok: updated {a} → {b}` · `skipped: {owner} owns {tool}` · `failed: {reason}` (including `failed: installer not found at {path}`). No color, no markup.

### Run log (`schedules.log`, D-11) — the lines the view parses

```
2026-11-13T12:00:01+01:00 update-claude start
2026-11-13T12:00:04+01:00 update-claude ok: up to date
2026-11-13T12:00:01+01:00 cache-cleanup start
2026-11-13T12:00:02+01:00 cache-cleanup ran: uv cache prune (exit 0)
2026-11-13T12:00:09+01:00 cache-cleanup ran: pnpm store prune (exit 0)
2026-11-13T12:00:09+01:00 cache-cleanup ok: pruned uv, pnpm
```

- Result words are exactly `ok: …`, `skipped: …`, `failed: …` (`skipped: busy`, `ok: nothing to clean`, `failed: interrupted` is shown by the view, never written). Per-manager lines use the word `ran:` so the view's result parser ignores them; a failing manager gives `failed: brew cleanup exited 1 (uv, pnpm ok)`.
- Schedule ids in the log: `tmp-cleanup`, `cache-cleanup`, `update-claude`, `update-opencode`, `update-pi`, `update-cursor-agent`, `update-copilot` (also the `tools-installer-schedule-<id>` unit and `com.tools-installer.schedule.<id>` label suffix, D-03). *(id spelling and the `ran:` word are provisional — P4)*
- Child output reaching a reason is sanitized (ANSI and non-UTF-8 stripped) before it is logged.

### Full uninstall

The sweep receives one `schedule:<id>` adapter per owned schedule (D-23); its output uses the existing sweep lines with those ids. No new line format.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `space toggle` (turn a schedule on/off now); secondary `e time`, `m model`. Modals: `enter save` / `enter use`, `esc cancel` |
| View label / palette / hint | `Schedules` · `Schedules - cleanup and tool updates on a timer` · `space turns a schedule on or off now; e sets when it runs` |
| Note line | Linux `Timers run while you are logged in; a missed run catches up once at login.` · macOS `Missed during sleep: runs once at wake. Missed while shut down: skipped.` |
| Empty state | Designed, not missing: there is no empty table. A host with no target installed shows all seven rows, rows 3-7 reading `– [n/a]` with `unavailable: {tool} not installed`; a schedule that never ran reads `never`; cache cleanup with no manager reads Target `none` and `prunes: nothing — no uv, pnpm, brew or npm found`, and its run logs `ok: nothing to clean` |
| Error state (no timer manager) | Note `unavailable: no user timer manager — nothing is scheduled on this machine.`; every row `– [n/a]`; `space` → `Cannot turn on {label}: unavailable: no user timer manager.` |
| Error state (apply) | `Could not turn on {label}: {first error line}.` — the row repaints from a fresh read |
| Error state (validation) | `Interval must be 1, 2, 3, 4, 6, 8, 12 or 24 hours.` · `Start must be HH:MM from 00:00 to 23:59, for example 01:30.` · `Model ids use letters, digits and . _ - [ ] = , only.` |
| Error state (reads) | `Could not read schedules.json ({first error line}); using defaults.` · `Could not read the schedule log: {first error line}.` · `Could not read the model list: {first error line}. Type a model id.` |
| Drift | `Drift: its timer files are missing or changed. space writes them again.` |
| cursor-agent warnings | `! {model} is not in your model list; the shim passes arguments through.` · `model unverified: could not read the cursor-agent model list; using {model}.` · `your own ~/.local/bin/cursor-agent is kept: it has no installer sentinel.` |
| Destructive confirmation | none. Turning a schedule off deletes only its recorded files and is undone by turning it on again (LIVE, reversible); the cursor-agent off restores the symlink. No action in this view deletes user data |
| Lock refusals | `A schedule change is running; wait for it to finish. Navigation still works.` · `A schedule setup is running; …` · `A scheduled run is running; wait for it to finish. Navigation still works.` |

Register: lowercase fragments in cells and detail lines (`last:`, `times:`, `prunes:`, `runs:`, `model:`); status, note and notice sentences capitalized with a period (lines that begin with an id such as `cursor-agent now defaults …` keep the id's lowercase). Every fixed string is ≤ 78 cells; lines that interpolate a label list, path, model id or error may exceed it and wrap.

**Data, never markup.** Labels, ids, tool names, paths, model ids, log results and first error lines are sanitized with `sanitize_log_line` and appended as `Text`; a `[` or an ANSI escape in a log line, a model id or a HOME path renders literally.

## Keyboard and accessibility

- **New keys only on Schedules:** `space`, `e`, `m`; `7` navigates here from every view. Policies loses `t` and `l`. No other view's keys change.
- **Word first.** `on`, `off`, `drift`, `n/a`, `running`, `never`, `unavailable:`, `last:`, and glyphs `● ○ ! – ✓ …` carry every state without color.
- **No motion.** The 30 s refresh repaints cells in place; no spinner, no blinking; `running` is a word.
- **Focus.** Table focused on entry; modals focus their first field; `esc` always closes a modal with no write; `tab` cycles modal fields.
- **Refusals name the reason and the next step** (install the target, move to the cursor-agent row, wait for the run).
- **80x20 todo** (`2026-11-03-fix-80x20-layout-gaps-found-by-the-phase-21-tui-check.md`): item 1 (tab bar clipped) is fixed for the seven-tab bar by the gap change; items 2-7 are not touched and not worsened.
