# Phase 24.2 Plan 08: Lifecycle Summary

**A default-on reconcile that never overrides a user's off, in-place adoption of the old tmp units, a removal hook for gone targets, and one uninstall adapter per schedule that leaves nothing but the lock files.**

## What was built

- `ensure_schedule_defaults(ctx)` walks the seven rows under `schedules.reconcile.lock`. Undecided rows turn on; a decided on row with no files (a reinstall) turns on again; a decided off row is never touched; a gone target's recorded files are removed with the decision kept; a stale on row is rewritten in place with one restart; a drifted row is left for the view. No reachable manager writes nothing.
- A damaged or unreadable `schedules.json` (including the sticky `.damaged` copy) turns nothing on and reports the load's warning or the pinned sticky sentence. Each default `turn_on` is preceded by a re-read of that row's decision under the state lock (the `~/.myshellrc` marker for tmp cleanup).
- `reconcile_lines` gives the three UI-SPEC section 8 lines (`Turned on schedules: ...`, `Removed the {label} timer because {tool} is gone.`, each warning as `warn`).
- `after_target_removed(ctx, tool_id)` takes the timer files of every row targeting that tool, keeps its decision, and removes our cursor-agent shim; it needs no reachable manager.
- `_remove_timer` is the shared core of `turn_off`, the removal hook and the sweep. `_linux_texts`/`_macos_plist` were extracted from `_apply_*` so the stale check renders exactly what an apply would write.
- Adoption: legacy tmp units found by name are refreshed in place (reload, enable, one restart, never disable), the wrapper goes afterwards, and on macOS the record's start is seeded from the old plist (`05:15` survives).
- `sweep_adapters(ctx)` returns `schedule:<id>` policies for every schedule with a footprint, or one `schedule:state` ("Schedules state and logs") when only state files remain. The last removal deletes the shared runner and scripts, `schedules.json`, `.damaged`, the schedule log, the launchd log, `prune-daemon.log` and tmp's marker. The three lock files stay.

## Deviations from Plan

### Auto-fixed / judgment calls

**1. [Rule 2 - Correctness] A load that warned counts as damaged**
- **Found during:** Task 1
- **Issue:** `LoadedState.damaged` is only the `.damaged` copy; an unreadable state (OSError) returns defaults with a warning and no copy, which would let the pass record fresh defaults over a file it could not read.
- **Fix:** the pass treats `loaded.damaged or loaded.warning is not None` as damaged.

**2. [Rule 2 - Correctness] tmp cleanup's off also honors a recorded `decided=False`**
- **Issue:** `turn_off` records the marker best effort; if that write fails, a marker-only rule would re-enable the row.
- **Fix:** tmp is undecided only when there is no marker and the record's decision is None; refresh never touches a recorded off.

**3. [Rule 2 - Correctness] `schedule:state` and the last removal also clear tmp's marker**
- **Issue:** with tmp turned off, the marker is the only thing left and nothing else would clear it at uninstall.
- **Fix:** `_cleanup_if_last` clears it (idempotent; never reached while a tmp unit was refused).

**4. [Judgment] `_remove_timer` signature beyond the plan**
- Added `restore_cursor_link` and `forget` keyword arguments (defaults keep `turn_off` identical) and a `_Removal` result instead of raising on kept files, so `turn_off` keeps its raise-after-record order, the hook turns kept files into a warning and the sweep turns them into an `OSError`. The tmp marker and legacy wrapper stay with the callers. Warning order inside `turn_off` shifted (unreachable, cursor, shared, wrapper, decision); no engine test depends on it.

**5. [Judgment] Extra warnings** `Could not refresh {label}: ...` and `Could not remove the {label} timer: ...` for refresh and removal failures in the pass; the plan named only the turn-on warning.

None of these changed a file outside `installer/schedules.py` and `tests/test_schedules_lifecycle.py`. The shared fakes are imported from `tests/test_schedules_engine.py` (no new helper module).

## Known gaps (not stubs)

- The stale check compares unit text only. A newer runner or prune script in the checkout is not refreshed by the reconcile (it is on the next `turn_on`); adding a shared-asset comparison would make a user-edited script raise on every pass, so it was left out.
- A damaged state still leaves recorded shared assets unprovable, so `schedule:state` can leave the data dir's scripts behind in that corner.
