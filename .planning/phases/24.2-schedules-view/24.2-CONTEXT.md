**Gathered:** 2026-11-07 (assumptions mode, after 24.2-SPEC.md)

<domain>
## Phase Boundary

A seventh view, Schedules, owns every recurring per-user job the installer writes:
- tmp cleanup, adopted from the Policies daemon row;
- cache cleanup through the package managers' own prune commands;
- 6-hourly updates of claude, opencode, Pi, cursor-agent and copilot through the ownership-first update path.

Each job is a systemd user timer or a launchd agent. A small runner copied into the user's data dir runs the job, writes one shared capped log, and takes one lock shared with the installer's own mutations. The cursor-agent schedule keeps a model-defaulting shim in place of the `cursor-agent` symlink. No sudo anywhere.

This phase assumes 23.1 (test sandbox), 23.2 (copilot entry; Policies at 7/5 rows) and 24.1 have landed.
</domain>

### Module and data shape
- **D-01: The seven built-ins are a closed Python table in a new `installer/schedules.py`, not `registry.toml`.** Each row holds id, label, target tool id (or none), job kind, default interval and start, and platforms. A registry test checks every target id against the catalog.
  - SPEC edge R1: "an eighth built-in is a code change". Code-owned closed tables are the house pattern (`host_setup.py:27-43` `HOST_SETUPS`, `ui_common.py:121-187` `VIEWS`), and a registry edit must never supply a command (`.claude/architecture.md`).
  - **Own reasoning** (jev low 0.94, closed_python_table). Ledger.
- **D-02: `installer/systemd_daemon.py` and `installer/daemon.py` take a unit basename / launchd label instead of the hard-coded names, and the Linux renderer gains an `OnCalendar=` + `Persistent=true` timer form next to today's monotonic form.**
  - The hard-coded names are threaded through every verb today (`systemd_daemon.py:101-103`, `:303-409`, `:436-453`, `:562-602`; `daemon.py:28`, `:246-278`).
  - `daemon_policy` / `linux_daemon_policy` (`policy.py:1151-1730`) are deleted. Their apply, rollback, snapshot and competing-takeover logic moves into `schedules.py` and keeps its error handling.
  - A parallel module would duplicate `_quote`/`_REJECTED_CHARS`, atomic writes and bootout classification (the drift trap at `policy.py:61-66`).
  - **Own reasoning** (jev low 0.91, parameterize_existing). Ledger.
- **D-03: Unit names.** New units are `tools-installer-schedule-<id>.{service,timer}`, and new launchd labels are `com.tools-installer.schedule.<id>`. The adopted tmp cleanup keeps `tools-installer-prune-tmp` and `com.tools-installer.prune-tmpdir`. Analyzer, Confident (SPEC edge R5).
- **D-04: One pure slot function turns (interval, start) into the sorted daily (hour, minute) list.**
  - It renders `OnCalendar=*-*-* H1,H2,…:MM:00` with `Persistent=true` on Linux, and an array of `{Hour, Minute}` dicts in `StartCalendarInterval` on macOS. The view's next-run cell uses the same function.
  - The `start/step` hour form is never used. Live, systemd 259: `systemd-analyze calendar '*-*-* 23/6:30:00'` fails "Invalid argument", while the explicit list `05,11,17,23:30:00` works.
  - `read_schedule` (`daemon.py:221-243`) learns the array form.
  - Analyzer, Confident.
- **D-05: macOS power-off catch-up is a launchd limitation, and the SPEC says so** (SPEC R4 amended).
  - launchd coalesces slots missed during sleep into one run at wake. A slot missed while powered off is not run, and the view's note states it.
  - Linux `Persistent=true` catches up once at the next login.
  - Plan-time research confirms both: the exact launchd wording, and that the stamp under `~/.local/share/systemd/timers/` survives an in-place rewrite.

### cursor-agent shim
- **D-17: The shim is a bash file carrying `# tools-installer-helper: cursor-agent-shim`.**
  - It bakes the absolute path of `~/.local/bin/agent` and resolves it on every call with `realpath` (falling back to `readlink -f`). A missing or dangling link exits non-zero with a message naming the link.
  - Dispatch:
    - `exec "$target" "$@"` when any argument is `--model` or starts with `--model=`;
    - `exec "$target" --model '<model>' "$@"` otherwise;
    - a pass-through shim (D-20) always uses the first form.
  - It must **not** use `exec -a "$0"`. The launcher finds `node` via `realpath "$0"`, which would resolve to `~/.local/bin`. Execing the absolute target keeps `CURSOR_INVOKED_AS` = `cursor-agent`.
  - Writes use `atomic_write_bytes(..., mode=0o755)`. A `mode=None` write would `copymode` through the symlink onto the launcher. Restore uses `atomic.replace_symlink(cursor_agent, os.readlink(agent))`.
  - A regular `cursor-agent` without the sentinel is never touched (`guards.is_our_shim` pattern, `guards.py:276-296`).
  - Analyzer, Confident: the launcher was read live, and the shim itself was not executed.
  - *(amended 2026-11-13, 24.2 research F1: `atomic_write_bytes` resolves a symlink before its `os.replace`, so the write above would overwrite the release launcher that `cursor-agent` points to. The shim is written by a new entry-replacing atomic write in `installer/atomic.py`: a sibling temp in `~/.local/bin`, `chmod 0o755`, then `os.replace` onto the link path itself, never following it. A test asserts that the launcher bytes and the `agent` link are unchanged, needs confirmation)*
- **D-18: Model ids are checked against a closed character set before they are written: `[A-Za-z0-9._-]` plus `[ ] = ,` for bracket overrides. The value is single-quoted in the script.** The listed ids are offered by the picker (D-20). Accepting only listed ids would break the SPEC's offline "model unverified" case.
  - **Own reasoning** (jev low 0.55 for list_only, rejected): offline editing must work, and the charset is the safety boundary (`_quote` precedent, `systemd_daemon.py:163-181`). Ledger.
  - *(amended 2026-11-13, 24.2 research F6: a model id must also start with a letter or digit and is at most 128 characters long, so a value such as `--foo` can never be read as a flag, needs confirmation)*
- **D-19: Every shim write and every restore re-fingerprints the `~/.local/bin/cursor-agent` leaf in cursor-agent's install receipt, through a small receipts helper under `_WRITE_LOCK`** (SPEC R7 amended).
  - Without it, `_leaf_matches` fails a regular file where a symlink was recorded (`receipts.py:801-809`). `broken_drift` then makes `UpdateService.run` refuse (`update.py:587-599`), and removal loses proof (`uninstall.py:130-131`), so the next cursor-agent update and the uninstall would both break.
  - A host with no receipt (this one: no `cursor-agent.json`) relies on the sentinel alone.
  - **Own reasoning** (jev low 0.38/0.36 split, refingerprint_leaf vs sentinel_exception): widening the integrity gate weakens every tool's tamper check. Ledger.
- **D-20: `cursor_default_model` lives in `schedules.json` (default `gpt-5.6-sol-xhigh`, **needs confirmation**: the user asked for `gpt-6.1-sol`, which `cursor-agent --list-models` lacks).**
  - A pass-through shim keeps the configured value.
  - The view edits it with a picker filled by `cursor-agent --list-models` on a thread worker, with free text when the list cannot be read. The `PoliciesScreen._probe_competing_worker` pattern is at `wizard_app.py:2089-2104`.
  - **Own reasoning** (jev low 0.88, picker_with_fallback). Ledger.
