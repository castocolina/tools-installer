## Findings

**F-1 (medium): a dependency reported as `already present` then fails as `not found on PATH` in the same session.**

- Repro: in a shell opened before pnpm existed, run headless
  `setup.py --categories pkg-mgr --yes` (pnpm installs), then, in the same shell, launch the TUI and install mmdc.
- Actual: `✓ pnpm skipped — already present` and `✖ puppeteer failed — pnpm not found on PATH — install pnpm
  (or, if this installer's pnpm wrapper is the only pnpm on PATH, re-apply the package-manager policy)`, then
  `○ mmdc dependency failed — puppeteer`.
- After `source ~/.myshellrc` the same install succeeds.
- Detection finds pnpm by path, but the executor resolves `pnpm` from the launching shell's PATH. The
  advice it prints (install pnpm) is wrong for this case.
- Expected: run the detected pnpm by its absolute path, or say "open a new terminal / source ~/.myshellrc".
- This is the normal flow for a first-time user: install a manager, then a tool that needs it.
