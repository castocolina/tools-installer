## Warnings

### WR-01: "pnpm not found" error tells the user to re-apply a package-manager policy that no longer exists

**File:** `installer/executors.py:488-491` (pinned by `tests/test_executors.py:1244-1250`)
**Issue:** `_node` raises `pnpm not found on PATH — install pnpm (or, if this installer's pnpm wrapper is the only pnpm on PATH, re-apply the package-manager policy)`.

Failure scenario: a host has no real pnpm and a leftover wrapper that could not be removed (read-only bin dir). The user runs a node-kind install and is told to re-apply the "package-manager policy". Phase 24.4 deleted the Policies row, `make guard` and `--guard`, so there is nothing to re-apply. Re-applying the guard would also re-create the shim that causes the problem. The advice is a dead end, and the real remedy (delete the leftover named in the launch warning, see `docs/TROUBLESHOOTING.md`) is not mentioned. `test_node_reports_an_absent_pnpm_with_todays_message` pins the stale text, so a fix has to change the test too.

**Fix:**
```python
raise ExecutorError(
    "pnpm not found on PATH — install pnpm (a leftover guard shim named in the launch "
    "warning does not count; see docs/TROUBLESHOOTING.md)"
)
```
Update the string in `tests/test_executors.py:1247-1250` to match, and rename the test (it no longer asserts "today's message").

### WR-02: Home-path `~` collapsing in Policy layer details lost its only test

**File:** `installer/policy.py:344,355,359,374,381` (test deleted from `tests/test_policy.py`)
**Issue:** `test_apply_collapses_home_paths_to_tilde` was removed with `ban_policy`. It was the only test that applied a policy under a `HOME` sandbox and asserted that `PolicyLayer.detail` shows `~/.myshellrc` and `~/.local/bin` instead of the absolute path. `tweak_policy` still builds its layer details through `_display_path` (lines 344, 355, 359, 374, 381). The surviving tweak tests use paths outside `HOME`: `tests/test_policy_tweaks.py:70` asserts `str(rc) in detail`, and `tests/policy_doubles.py:43` joins `str(p)`. Dropping `_display_path` from those lines would break no test, yet the user-facing Policies feedback would then show absolute paths and pytest temp dumps. This is generic Policies coverage that was incidental to the ban and not replaced.

**Fix:** Add a `tweak_policy` test with `HOME` set to `tmp_path` and `rc_path=Path.home()/".myshellrc"`. Assert that `apply()` and `remove()` layer details contain `~/.myshellrc` and do not contain `str(tmp_path)`.

### IN-01: Prose still describes the retired pnpm wrapper and the volta redirect as live

**File:** `installer/pnpm_globals.py:8-18` and `:763`; `installer/executors.py:473-477` and `:505-507`; `installer/registry.toml:2262-2275`

### IN-03: `_is_leftover` docstring claims the checks "can never disagree", but the schedule runner has its own copy

**File:** `installer/legacy_guard.py:38-44`, `installer/helper_assets/schedule_runner.py:362-380`
**Issue:** The runner cannot import `legacy_guard`. It skips any file with a sentinel in its first 8192 bytes, including non-UTF-8 files and files over 8 KiB. `_is_leftover` accepts only valid UTF-8 of at most 8192 bytes. So `real_binary` can resolve a file that `_resolve` skips (a >8 KiB file whose head carries a sentinel). The runner's comment documents this as the "safe direction", but the `legacy_guard` docstring overclaims. `test_runner_sentinels_match_legacy_guard` pins the strings only.
**Fix:** Reword the docstring to "the in-process lookups share this; the schedule runner mirrors it conservatively". Optionally pin `_SHIM_HEAD_BYTES == _SHIM_MAX_BYTES` in that test.

### IN-04: The no-guard test's identifier denylist will reject unrelated future names

**File:** `tests/test_setup.py:4873-4906`
**Issue:** `_GUARD_IDENTIFIERS` includes generic names such as `shell_path`, `exec_targets` and `BANNED`, and the regex runs over every `installer/**/*.py` file. A future legitimate function called `shell_path` fails the suite with a message about guard writers. The sentinel-literal scan (`needles`) is the real guard and stays valid; the identifier list is the brittle part.
**Fix:** Keep the sentinel and marker literal scan. Trim the denylist to guard-specific names (`ban_alias_block`, `write_ban_aliases`, `*_shims`, `ban_policy`, `run_guard`) and drop `shell_path` and `exec_targets`.

### IN-05: A race during the shim check yields a misleading "fix its permissions" warning

**File:** `installer/legacy_guard.py:132-146`
**Issue:** `lstat` passes (regular file, at most 8 KiB), then the file is swapped for a symlink or FIFO before `read_snapshot`. `read_snapshot` raises `OSError` (ELOOP, or "not a regular file"), which maps to the generic warning "Could not check ...: <reason>; fix its permissions, then relaunch". The file is not a permissions problem, and the next launch is silent. This is rare and harmless, but TROUBLESHOOTING promises that a changed file is skipped silently.
**Fix:** Treat `ELOOP` and the non-regular `OSError` from `read_snapshot` as the silent re-check case. For example, re-`lstat` in the `except` and return `None` when the file is no longer a regular file.
