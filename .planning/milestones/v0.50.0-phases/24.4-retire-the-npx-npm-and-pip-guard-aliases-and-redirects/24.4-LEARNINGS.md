# Phase 24.4 Learnings: Retire the npx, npm and pip guard aliases and redirects

## Decisions

### A local marker matcher replaces `strip_block` for the ban block
`legacy_guard._strip_ban_blocks` removes every well-formed block: a later begin supersedes an open one, one trailing CR is ignored, line terminators are kept, and orphan begin or end lines stay.

**Rationale:** `shellrc.strip_block` pairs only the last begin marker and compares exact LF-split lines, so a CRLF block or a valid block followed by an orphan begin stayed active. That contradicted the amended SPEC R2 (plan review H2).
**Source:** 24.4-01-SUMMARY.md, 24.4-REVIEWS.md (Cycle 1 H2), 24.4-SECURITY.md (T-24.4-04)

---

### Identity re-check right before unlink, with the residual race documented, not claimed closed
`snapshot_matches` (O_NOFOLLOW re-open, device, inode and bytes) is the last call before `os.unlink`. The remaining window is a `shortcut:` comment, and GUARD-03 and SPEC R3 (Target, acceptance, edge row) were reworded in place to a re-check guarantee.

**Rationale:** No userspace unlink is atomic against a swap, and the unconditional "never deleted" wording could not be kept honestly (review H3 verified, H-03 verified).
**Source:** 24.4-01-SUMMARY.md, 24.4-REVIEWS.md (H3, H-03), 24.4-SECURITY.md (T-24.4-02 accepted residual)

---

### One leftover definition (`_is_leftover`) for every path that runs or counts a binary
`is_our_shim`, `real_binary`, `look_through_shim`, `real_pnpm`, the status presence check, the engine smoke target, `version_argv`, the ownership probe runner and the schedule runner mirror all use it. The lookups moved into `installer/legacy_guard.py`.

**Rationale:** The review found the schedule runner's 4 KiB head read, the smoke target, the version probe and Pi's host-setup `pnpm list` probe each ran a leftover by name. Removing the writer without this would leave a leftover pnpm wrapper runnable.
**Source:** 24.4-03-SUMMARY.md, 24.4-REVIEWS.md (H5, H6, C3-2), 24.4-SECURITY.md (T-24.4-10, -12, -24)

---

### Vendor install shells inherit PATH unchanged (`shell_path` and `_path_prefix` deleted)
The PATH demotion that existed only for the shims is gone. An unremovable leftover `npm` can be hit by a vendor script's own `npm`; the launch warning names the file.

**Rationale:** The demotion never covered the no-real-pnpm case either, and the SPEC locked D-03 as an accepted edge.
**Source:** 24.4-03-SUMMARY.md, 24.4-SECURITY.md (T-24.4-11 accepted risk)

---

### Link-mode coverage survives through a test-local `block_policy` double
`tests/policy_doubles.py::block_policy` is link-mode aware, so every `move_link_mode` test keeps its assertions after `ban_policy` is deleted. Assertions match the old ones line for line.

**Rationale:** That coverage is generic and has nothing to do with the guard (D-15); deleting the only real fixture must not delete the tests.
**Source:** 24.4-04-SUMMARY.md, 24.4-REVIEWS.md (H-06), 24.4-SECURITY.md (T-24.4-14)

---

### Keep `all_ban_rc_paths` by name; keep `legacy_guard.py` out of `_PY_SURFACES`
Only the docstrings changed for `all_ban_rc_paths` (D-13). `installer/legacy_guard.py` is not listed as a catalog-audit script surface because it writes no shim or script (D-16).

**Rationale:** The launch cleanup still needs the rc path set, and the audit lists only files that write scripts.
**Source:** 24.4-06-SUMMARY.md, 24.4-02-SUMMARY.md

---

### First-read OSError warns with permission advice only; re-check read failures are silent skips
Any first-read `OSError` other than ENOENT/ENOTDIR is one warn line ("fix its permissions, then relaunch") with no deletion advice. A failure at a re-check read is a documented silent skip that the next launch's first read reports. Docs advise deleting a shim only after "Could not remove the retired pip/npm guard shim", and never delete an rc file.

**Rationale:** A shim whose ownership was not yet verified must never be named for deletion; following the old wording would have deleted `~/.bashrc`.
**Source:** 24.4-01-SUMMARY.md, 24.4-07-SUMMARY.md, 24.4-REVIEWS.md (H-10, C3-1), 24.4-SECURITY.md (T-24.4-23, T-24.4-26)

---

### Wave dependencies enforce the deletion order, not the wave barrier alone
24.4-06 declares `depends_on` for 24.4-01..05 (including 24.4-02), and 24.4-07 depends on 24.4-06. AGENTS.md drops the `make guard`/`make unguard` host-safety prohibition only after 24.4-06 deletes the targets.

**Rationale:** Review H12 showed 07 could remove the prohibition while the targets still existed; 02 had to land before `guards.py` could go because two audit tests read the real file.
**Source:** 24.4-REVIEWS.md (H12, cycle-1 LOW), 24.4-07-SUMMARY.md, 24.4-SECURITY.md (T-24.4-20)

## Lessons

### Three plan-review cycles found real defects, and verifying each HIGH against source paid off
Cycle 1 verified 9 of 12 HIGHs, cycle 2 verified 6 of 10, cycle 3 verified 4 of 5. Several were refuted or downgraded with evidence (H-01, H-02, H-04, H-05, C3-3).

**Context:** The review ran with a single reviewer, so every HIGH counted. The orchestrator checked each one against the code and the plans were revised with a dispositions ledger, which kept the refuted ones from adding scope.
**Source:** 24.4-REVIEWS.md (Orchestrator HIGH Verification, cycles 1-3), 24.4-01-PLAN.md (Review Dispositions Ledger)

---

### Deleting a module means auditing every retained test that quietly uses its helpers
The same defect recurred in each cycle: a deleted helper or import still used by a kept test (H7, H8, H9, H10, H-06, H-07, H-08, H-09, C3-4, C3-5). Examples: `_plant_volta_and_pnpm`, `BAN_BEGIN`, `forwarded[0]["rc_paths"]`, a launcher-line count of six.

**Context:** A plan whose commit gate is `make validate && make test` fails on these. A grep gate must not contradict the plan's own new test (C3-5), and an orphaned local fails ruff F841 (C3-4).
**Source:** 24.4-REVIEWS.md (cycles 1-3), 24.4-06-SUMMARY.md (wizard tests importing `installer.guards`)

---

### Safety wording must match the real guarantee
The unconditional "a file swapped between the read and the delete is never deleted" was not achievable. The SPEC, REQUIREMENTS and plan wording were amended to the re-check guarantee, and the residual became an accepted risk with a `shortcut:` comment.

**Context:** A plan that accepts a window while the requirement promises none fails verification by definition.
**Source:** 24.4-REVIEWS.md (H3, H-03), 24.4-01-SUMMARY.md, 24.4-SECURITY.md (Accepted Risks Log)

---

### `hash -r` does not clear loaded aliases
The remedy text must say to open a new shell, or run `unalias pip pip3` then `hash -r` in the current one.

**Context:** The ban block defined aliases; `hash -r` clears only the command hash.
**Source:** 24.4-REVIEWS.md (H11), 24.4-07-SUMMARY.md

---

### A bare "Could not check" warning is not proof of ownership
The earliest plan text told the user to delete any file a shim warning named, before the regular-file and sentinel checks had run.

**Context:** For an rc file this advice would have deleted `~/.bashrc`. The fix keys the advice on what the launch actually verified.
**Source:** 24.4-REVIEWS.md (H-10, C3-1), 24.4-SECURITY.md (T-24.4-26)

---

### Code review still found stale user-facing text and a lost incidental test after a clean verification
WR-01: the `pnpm not found` error told the user to re-apply a package-manager policy that no longer exists, and a test pinned that text. WR-02: deleting the ban tests removed the only test of `~` collapsing in policy layer details (`_display_path`).

**Context:** Both came from deleting a feature whose tests covered generic behaviour. Fixes landed in db0b78d4..a00b3aae. Five info items covered stale prose and a brittle identifier denylist.
**Source:** 24.4-REVIEW.md (WR-01, WR-02, IN-01..IN-05), 24.4-VERIFICATION.md

### A mirrored copy cannot import its source, so pin the behaviour and word the claim carefully
The schedule runner cannot import `legacy_guard`. It skips any sentinel file in the first 8192 bytes, including non-UTF-8 and over-8 KiB files, which is the safe direction. The `_is_leftover` docstring still overclaimed that the checks "can never disagree", and the pin test compared the strings only.

**Context:** Pins `test_runner_sentinels_match_legacy_guard` and `test_runner_and_installer_agree_on_what_a_leftover_is` cover sentinels, read size and resolution result.
**Source:** 24.4-REVIEW.md (IN-03), 24.4-SECURITY.md (T-24.4-12), 24.4-03-SUMMARY.md

### A harness brief can name an API that does not exist
The UAT brief called `real_binary("pnpm")`, but `path_value` is a required keyword. The agent passed the process PATH and recorded it.

**Context:** Expected behaviour was then confirmed with a control run (the leftover writes its marker when run directly, so absence is meaningful).
**Source:** 24.4-UAT.md (test 3)

### Docs checks found a broken link that predated the plan
The README's `CLAUDE.md` link was already broken. The new link checker resolves each link from its own document's directory, skips fenced code, and checks cross-document `#fragment` links against the target's headings.

**Context:** The README layout text still names `CLAUDE.md` as plain text and was deferred.

## Patterns

### Never-raise launch repair returning (text, severity) tuples
Each remover catches `OSError` and `UnicodeDecodeError` and returns warn lines. `_launch_repairs` composes them, and `_build_app`, `_teardown_cli`, doctor, fix and headless run it first.

**When to use:** Cleanup that runs at every launch and must never block the launch or change its exit status.
**Source:** 24.4-01-SUMMARY.md, 24.4-SECURITY.md (T-24.4-06)

---

### Identity re-check as the last call before a destructive unlink
Open with O_NOFOLLOW, compare device, inode and bytes against the snapshot immediately before deleting. Identical bytes also re-prove size, UTF-8 and the sentinel.

**When to use:** Deleting a file the program once wrote in a user-owned directory, where a swap must not widen the deletion.
**Source:** 24.4-01-SUMMARY.md, 24.4-SECURITY.md (T-24.4-01, T-24.4-02)

---

### Module-attribute reads keep conftest patches effective
Code reads `installer.legacy_guard.x` and `installer.locations.bin_dir` through the module, not through a from-import copy.

**When to use:** After moving helpers between modules, when tests patch the old location.
**Source:** 24.4-03-SUMMARY.md

---

### Test-local double to keep generic coverage when the only real fixture goes
`block_policy` keeps the link-mode tests alive after `ban_policy` is deleted. A related fake in `test_wizard_app.py` was neutralised (`Sample policy`, `sample effect`) so no guard words remain.

**When to use:** Removing a feature that was the only real fixture for a generic mechanism.
**Source:** 24.4-04-SUMMARY.md

---

### Surface-list existence test plus a scan test plus a behavioural route test
`test_every_py_surface_exists` replaces a silent skip. `test_no_guard_writer_or_surface_remains` scans for literals and deleted identifiers. `test_no_route_writes_a_guard_file` proves behaviour on every route. The scan's claim is narrowed to what it can see.

**When to use:** Proving a retired feature cannot return, and guarding a list of paths against renames.
**Source:** 24.4-02-SUMMARY.md, 24.4-06-SUMMARY.md, 24.4-REVIEWS.md (cycle 3 MEDIUM)

---

### Tracer-first tasks with honest RED evidence
Each plan records RED output, or marks a test as a pin when it passed at once. Examples: 24.4-01 Task 2 (37 pins), 24.4-05 Task 3, and the narrow RED of 24.4-04 Task 2.

**When to use:** Any TDD plan where a contract is already satisfied by an earlier task, so a fake RED is never claimed.
**Source:** 24.4-01-SUMMARY.md, 24.4-04-SUMMARY.md, 24.4-05-SUMMARY.md

---

### Agent-run container UAT with byte-exact expectations and a control run
Seed an owner-like scratch user in a disposable container, build the expected rc files from literals and compare with `cmp`, snapshot sha256 and mtime twice to prove idempotency, and run a control to make "marker absent" meaningful. The container is removed afterwards.

**When to use:** Verifying real filesystem and shell behaviour without touching the developer's host.
**Source:** 24.4-UAT.md, 24.4-VERIFICATION.md

---

### Link checker that resolves from the document's own directory
Relative links resolve from the linking document, fenced code blocks are skipped, and GitHub-style slugs are used for `#fragment` checks against the target's headings.

**When to use:** Keeping README and docs links valid after prose rewrites.
**Source:** 24.4-07-SUMMARY.md

`test_the_linux_unit_carries_the_proxy_and_certificate_variables` asserts `"bad" not in text`, and the worktree path `agent-ab02f49badfc71358` contains `bad`. It failed on every `make test` run in that worktree and passed elsewhere.

### Estimates ran far above actuals
Plan estimates sum to 905000 tokens. Summary actuals sum to about 161000, roughly 18 percent. 24.4-02 estimated 50000 and recorded 3344.

**Impact:** Actuals are `chars/4` over the realized diff, not a harness token count, so the ratio overstates the gap. It still feeds the calibration.
**Source:** 24.4-01..07-PLAN.md (estimate), 24.4-01..07-SUMMARY.md (actuals), 24.4-02-SUMMARY.md

### The shared git directory refused the plan-head ledger write
`plan_head_before` came from the spawn brief's base SHA and `commits` from `git rev-list --count`. A `git add` of the tracked `.claude/architecture.md` printed the ignored-path hint and exited 1, although the index already held the change.

**Impact:** No effect on the result; commits were checked with `git diff --cached --stat`.
**Source:** 24.4-01-SUMMARY.md, 24.4-07-SUMMARY.md

Pi's host-setup ownership probe runs bare `pnpm list --global` through the PATH (`installer/host_setup.py`), with no leftover skip. The host-setup retirement itself stays in Phase 25.

**Impact:** `run_probe` now resolves a guard-named argv[0] through the leftover-aware lookup, or raises `FileNotFoundError`.

**Impact:** Same class as the baseline's `all_ban_rc_paths` false positive; no change made.

**Impact:** None blocks the phase (verification passed, security 27 of 27 closed); the host-side proof is left to a real launch.
