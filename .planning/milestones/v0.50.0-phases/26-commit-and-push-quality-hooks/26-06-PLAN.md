- `ahead <name> <label>` makes one unpushed commit with `git commit --allow-empty -q -m <label>` through `run_isolated`, so the push carries a real ref update and the gate runs instead of taking its empty-input exit (review H4). `clear_marks <name>` empties `$SCRATCH/marks/<name>/`. Proof that the gate ran: `test.ran` exists after a pass or a failed suite, or the push output holds `push refused:` for a refusal.
- `expect_edit <name> <file> <case>` copies the file, after the unstaged edit has been made, to `$SCRATCH/expect/<case>`. `assert_restored <name> <file> <case>` succeeds only when `cmp -s` of the file against that copy succeeds and `git diff --quiet -- <file>` exits 1 (the edit is still there). A lost edit fails both; a correct restore passes (review H3).
- Each case prints `ok <case>` or `FAIL <case>: <reason>`. The script counts failures and exits 1 if there is any, after the EXIT trap has cleaned up.
- Portability: bash 3.2 (macOS). No associative arrays, no `mapfile`, no `${var,,}`, no `setsid`, no `sha256sum`. Compare bytes with `cmp -s`. Start a background push in its own process group THROUGH `run_isolated`, from the scratch work tree (`cd "$SCRATCH/<name>"` in a subshell): `run_isolated "$PY" -c 'import os, sys; os.setpgid(0, 0); os.execvp(sys.argv[1], sys.argv[1:])' git push …`, so the wrapper and the `git` it execs get exactly the `env -i` allowlist and never inherit `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE` or any other variable from the caller (review C3-H2). No git, uv or pre-commit process in this script starts outside `run_isolated`; a Task 1 grep pins that every `git push` launch line goes through it. Record its pid, and signal the group with `kill -<SIG> -- "-$pid"`. Collect a background exit status with `wait "$pid" || rc=$?`, so `set -e` does not abort.
- Cleanup (review C2-M2). The gate starts pre-commit in a group of its own (26-04), so killing the recorded push group alone can leave pre-commit, make and the suite running. `trap cleanup EXIT`, plus `trap 'exit 130' INT`, `trap 'exit 143' TERM` and `trap 'exit 129' HUP`, so an interrupted harness still runs `cleanup`. `cleanup`, in this order:
  1. touch `$SCRATCH/stop`, so a slow suite ends by itself;
  2. take one `ps -A -o pid= -o ppid= -o pgid=` snapshot (works on Linux and macOS). For every recorded background pid, collect it and its descendants by following ppid links in the snapshot until no pid is added (space-separated strings and `case` matching), then the distinct process groups of all collected pids;
  3. send INT to each recorded push group (the gate forwards it, and pre-commit restores), then poll every 0.1 s, at most 10 s, until `ps -A -o pgid=` lists no collected group;
  4. send KILL to every collected group that still has a member, ignoring errors, and `wait` each recorded pid so no zombie child lingers;
  5. poll at most 5 s more. If a collected group still has a member, print `FAIL cleanup: process group <pgid> survived`, leave `$SCRATCH` in place for inspection and exit 1. Otherwise `rm -rf "$SCRATCH"`.
  Late children (make, the suite) join pre-commit's group, so signalling groups also reaches processes started after the snapshot.
- Abort self-test knob (review C2-M2). When `HOOKS_E2E_ABORT_PIDS` names a file, the script runs only this scenario: `new_repo abort`, `install_hooks abort`, commit `tests/slow` (the update), start `git push origin main` in its own group, wait at most 30 s for the `started` mark, write one `<pid> <pgid>` line per collected pid (the step-2 walk) plus a `scratch <dir>` line to that file, then `exit 3`. Normal runs never set the variable (the `make hooks-e2e` recipe is pinned to `uv run scripts/hooks-e2e.sh`).
