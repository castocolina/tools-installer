# Phase 24.2 Learnings: Schedules view

## Decisions

### The seven built-in schedules are a closed Python table, not registry.toml
The seven schedules (tmp cleanup, cache cleanup, and updates for claude, opencode, pi, cursor-agent, copilot) live in `installer/schedules.py` as a fixed table. A registry test checks every target id against the catalog.

**Rationale:** The set is code-owned and closed; it needs no user-extensible data file.
**Source:** 24.2-CONTEXT.md (D-01), 24.2-VERIFICATION.md (SC1)

---

### One JSON state file with recorded unit files and sha256 fingerprints
`~/.local/state/tools-installer/schedules.json` holds each schedule's `decided`, interval, start, recorded files and the cursor default model. Off and the uninstall sweep delete only the recorded files, re-hashed through `uninstall.remove_paths`. A damaged file loads as whole-file defaults plus one warning, and the original bytes stay in `schedules.json.damaged`.

**Rationale:** A half-trusted file is worse than none; deleting by recorded fingerprint means the installer never removes a file the user edited.
**Source:** 24.2-CONTEXT.md (D-06, D-07), 24.2-01-SUMMARY.md, 24.2-SECURITY.md (T-24.2-23)

---

### A damaged state file is sticky: no default turns on until a user action clears it
`LoadedState.damaged` (or a load that warned, such as an unreadable file) makes the reconcile turn nothing on. `clear_damage` runs only from a user action in the view.

**Rationale:** A plan-review finding (R1-09, R2-11): a damaged file loads as "undecided" and would otherwise re-enable rows the user had turned off.
**Source:** 24.2-REVIEWS.md (R1-09), 24.2-08-SUMMARY.md, 24.2-13-SUMMARY.md

---

### Every timer runs one stdlib runner copied out of the checkout, under one cross-process flock
Timers run `uv run --no-project --script <data>/runner.py <job>`; the runner is stdlib-only (PEP 723), copied byte for byte into the data dir and refcounted in `state.shared`. One `flock` on `run.lock` serializes scheduled runs and the TUI's install, update, removal and pnpm-reinstall work.

**Rationale:** The units must keep working when the checkout moves, and installs must not overlap a timer.
**Source:** 24.2-CONTEXT.md (D-10, D-12), 24.2-02-SUMMARY.md, 24.2-05-SUMMARY.md, 24.2-07-SUMMARY.md

---

### The running cell reads the lock's holder line, not a flock probe
The view shows `running` from the holder line (pid-checked), never by probing the lock.

**Rationale:** A non-blocking flock probe races a starting runner; the 30 s refresh corrects a stale holder line. This superseded UI-SPEC section 3 through an amendment.
**Source:** 24.2-01-SUMMARY.md, 24.2-13-SUMMARY.md (design readings), 24.2-REVIEW.md (deferred R1-23)

---

### Tmp units are adopted by name and rewritten in place with one restart
The old `tools-installer-prune-tmp` units keep their names and are never disabled and re-enabled. The legacy wrapper is removed and the decided marker recorded only after registration succeeds. An already-on daemon stays on across the upgrade.

**Rationale:** A disable/enable gap would drop a working timer; SPEC R3/R9 changed from "adopted unchanged" to "adopted by name".
**Source:** 24.2-CONTEXT.md (D-08), 24.2-08-SUMMARY.md, 24.2-11-SUMMARY.md (`test_an_on_daemon_stays_on_across_the_upgrade`)

---

### The cursor-agent shim replaces the link entry and leaves `agent` alone
`atomic_replace_entry` swaps `~/.local/bin/cursor-agent` for a sentinel-owned bash shim without following the symlink. The shim injects `--model <default>` only when the caller gave none, runs the realpath of `agent` at call time, and the leaf is re-fingerprinted in cursor-agent's receipt after every write and restore. A foreign regular file is kept untouched.

**Rationale:** Never loosen the receipt gate (D-19); a foreign file or `agent` itself must survive byte for byte.
**Source:** 24.2-03-SUMMARY.md, 24.2-CONTEXT.md (D-17, D-19), 24.2-VERIFICATION.md (SC3, R7)

---

### Model ids are checked against a closed charset and single-quoted in the shim
`validate_model_id` allows `[A-Za-z0-9._-]` plus `[ ] = ,`, a leading alphanumeric, at most 128 characters. Only listed ids are offered by the picker, but a free-text id is accepted.

**Rationale:** Accepting only listed ids would break the offline "model unverified" case; the charset keeps quotes, `$` and leading `-` out of the script.
**Source:** 24.2-CONTEXT.md (D-18), 24.2-SECURITY.md (T-24.2-02, T-24.2-14), 24.2-01-SUMMARY.md

---

### Policies hands tmp cleanup to Schedules and the old daemon path is deleted
The Policies daemon row, `ensure_daemon_default`, the job-state worker, `TimePickerScreen`, the old runner asset and the prune-shaped renderers were removed in a separate delete plan, with a migration ledger that maps every removed test to the test that now asserts the same behavior (or names "no replacement by design").

**Rationale:** One owner for recurring jobs; a ledger keeps deleted-test guarantees from silently disappearing.
**Source:** 24.2-11-SUMMARY.md, 24.2-12-SUMMARY.md (migration ledger)

---

### A scheduled run waits for another scheduled run, and skips only when the installer holds the lock
After code review, a runner that finds the lock held by another scheduled run polls (5 s, at most 2 h) and logs a `waited:` line; it logs `skipped: busy` at once when the installer holds it.

**Rationale:** Six calendar schedules share the same 6 h grid, so they fire together and five used to log `skipped: busy` at every slot (reproduced with three real runners). SPEC R8 and D-12 amended; the owner kept the amendment in the UAT.
**Source:** 24.2-REVIEW.md (F1), 24.2-UAT.md (test 2)

## Lessons

### A planned-for single feature can break a whole test-suite pin set
Adding a seventh `VIEWS` row broke `tests/test_ui_common.py`, `test_wizard_app.py`, `test_screen_family.py`, `test_layout_80x20.py` and `test_catalog_tui.py`, plus the `UnifiedApp.__init__` signature pin the plan's sweep list missed.

**Context:** Plan review found the sweep missing (R1-07) and moved it into the same commit as the row; execution still found one more pin.
**Source:** 24.2-REVIEWS.md (R1-07, R2-02), 24.2-09-SUMMARY.md (deviation 2)

---

### A real-systemd container run found two bugs that 6800 mocked tests did not
The first container run failed: `uv cache prune` waited on the runner's own uv cache lock (the runner now runs with `uv run --no-cache`), and the harness's busy holder did not outlive its exec session (it is now a transient `systemd-run --user` unit).

**Context:** Every unit test uses recording fakes for `systemctl`; only the real manager showed the lock interaction.
**Source:** 24.2-13-SUMMARY.md ("Container checkpoint: runs and the two bugs")

---

### Code review found a convergent set of concurrency and ownership holes
Five HIGHs and seven MEDIUMs survived three plan-review cycles: the same-grid pile-up (F1), macOS `bootout` leaving an orphaned child with the lock released (F2), a reconcile in another process undoing the user's off (F3), shared-asset deletion racing a run (F4), and copied scripts never refreshing after a `git pull` (F5).

**Context:** Deep, ponytail and external lanes agreed. Fixes took F3 into the reconcile lock for every user verb and F4 into a run-idle check under that lock.
**Source:** 24.2-REVIEW.md (F1-F19), 24.2-REVIEW-deep.md, 24.2-REVIEW-external.md

---

### A damaged or unreadable state must never be treated as "undecided"
An OSError read returned defaults with no `.damaged` copy, which would have let a reconcile re-arm defaults over a file it could not read. Related: a failed read inside `update_state` saved defaults (F11), and a damaged state hid live timers from off and from the uninstall sweep (F10, now found by unit name).

**Context:** Three separate paths shared one root cause: defaults returned in place of an error.
**Source:** 24.2-08-SUMMARY.md (deviation 1), 24.2-REVIEW.md (F10, F11)

---

### An rc file that is not UTF-8 crashed code that only read a marker
`schedules._tmp_decided` read `~/.myshellrc` with `read_text()`, so the sweep and reconcile raised `UnicodeDecodeError`. It only surfaced when the sweep was wired into the teardown. The reconcile now treats an unreadable marker as decided; the sweep treats it as no leftover.

**Context:** A 24.2-08 gap exposed by 24.2-11 wiring and a dedicated route-wide test.
**Source:** 24.2-11-SUMMARY.md (deviation 1)

---

### Private attribute names can collide with the framework
A flag called `self._closed` on a Textual modal is Textual's own message-pump flag; setting it froze the app so `escape` never returned. The flag was renamed `_dismissed`.

**Context:** Found by a hanging "list arrives after escape" test.
**Source:** 24.2-09-SUMMARY.md (deviation 1)

---

### Deleting a feature also deletes guarantees nobody listed
Removing the daemon policies dropped the competing-mechanism warm-up, the Doctor's timer-cache invalidation and the render-time validation of HOME/TMPDIR/PATH. Each was restored in the new code only because a migrated test failed or a ledger row asked who now owned it.

**Context:** `test_apply_and_remove_invalidate_the_cache_on_success_and_on_failure` had guarded a guarantee only the deleted code provided.
**Source:** 24.2-12-SUMMARY.md (deviations 2-4)

---

### TDD evidence slipped in several plans and was reconstructed
In plans 03, 06, 08 and 10 the implementation (or the driver) was written before the RED run; the summaries restored the earlier file to produce a genuine RED output, and 24.2-11 says plainly that no standalone red run was kept for Task 1.

**Context:** Honest labeling of partial RED evidence is itself the practice that worked.
**Source:** 24.2-03-SUMMARY.md, 24.2-06-SUMMARY.md, 24.2-10-SUMMARY.md, 24.2-11-SUMMARY.md

---

### macOS launchd behavior cannot be shown by any run available here
`launchctl bootout` on off or re-time stops a running job (Last cell reads `failed: interrupted`); the bootstrap without a GUI session, the sleep catch-up and `realpath` on macOS 13+ were never exercised. The macOS UAT stays deferred.

**Context:** Linux containers cover systemd only; Linux lets a running service finish on off or re-time.
**Source:** 24.2-05-SUMMARY.md, 24.2-13-SUMMARY.md, 24.2-UAT.md (test 8)

## Patterns

### Render first, write second; write before register, disable before delete
Callers render both unit texts before anything touches disk; the engine snapshots before each verb, rolls back on any failure, and records only what is on disk after registration.

**When to use:** Any transactional apply over files plus an external manager (systemd, launchd).
**Source:** 24.2-04-SUMMARY.md, 24.2-05-SUMMARY.md, 24.2-SECURITY.md (T-24.2-22)

---

### One truth table read by the reconcile, the removal hook and the sweep
`(decided, present, recorded, on disk)` decides every default turn-on, removal and sweep, and `_remove_timer` is the one shared core of `turn_off`, the removal hook and the sweep.

**When to use:** When several entry points need the same lifecycle decision and drift between them would be a bug.
**Source:** 24.2-08-SUMMARY.md

---

### Adapters gate removal on a file-read footprint and stay idempotent
No footprint means forget the record only; deletion is by recorded sha256 or by installer-namespaced unit name.

**When to use:** Uninstall sweeps over state that may be partly gone or damaged.
**Source:** 24.2-08-SUMMARY.md, 24.2-SECURITY.md (R3)

---

### Process seams injected as fakes in every engine function
Every engine function takes a `ScheduleContext` whose `run`, probe and path seams are injected recording fakes; tests run under a scratch HOME with `systemctl` and `launchctl` forbidden, and a render-never-spawns test pins the view.

**When to use:** Any code that drives a host service manager.
**Source:** 24.2-05-SUMMARY.md, 24.2-09-SUMMARY.md, 24.2-VALIDATION.md

---

### Host-test a shell harness by extracting its functions into bash with stubs
The container harness functions are extracted from `container-e2e-verify.sh` and run in bash with stubbed `ct`, `exec_root`, the tester and the driver. Every start failure is `TRACER_SCHEDULES_INFEASIBLE step=<step>` with exit 2, so the orchestrator reads it as environmental, and a bash 3.2 test guards array expansion under `set -u`.

**When to use:** Container or shell harnesses that executors may not run (orchestrator-only).
**Source:** 24.2-10-SUMMARY.md

---

### Contract tests between the stdlib runner and the installer
The runner cannot import `installer`, so contract tests prove its child argv parses with `cli.parse_args`, its log lines read back through `read_last_runs`, and its lock content through `runlock.holder`. A pin test is the stated fix for the duplicated cache-manager list.

**When to use:** Code copied out of the checkout that must stay in step with the repo.
**Source:** 24.2-06-SUMMARY.md, 24.2-REVIEW.md (deferred)

---

### Fix a cross-process race by moving the lock, not adding a check
F3 and F4 were fixed by making every user verb take the reconcile lock and by running shared-asset removal under it, with the reconcile re-checking the decision inside the locked change.

**When to use:** Cross-process "undo the user's decision" races.
**Source:** 24.2-REVIEW.md (F3, F4), 24.2-SECURITY.md (T-24.2-34)

## Surprises

### The default cursor model the user named does not exist
The user asked for `gpt-6.1-sol`; `cursor-agent --list-models` does not offer it, so the default is `gpt-5.6-sol-xhigh`, kept by owner delegation in the UAT.

**Impact:** One constant and its tests; flagged "needs confirmation" in four artifacts until 2026-11-14.
**Source:** 24.2-CONTEXT.md (D-20), 24.2-13-SUMMARY.md, 24.2-UAT.md

---

### Six schedules defaulting to one grid fire at the same instant
The default 6 h grid made six calendar schedules fire together, so one won the lock and five logged `skipped: busy` each slot and each catch-up.

**Impact:** HIGH review finding F1 and an amendment to SPEC R8 and D-12.
**Source:** 24.2-REVIEW.md (F1)

---

### `systemctl clean --what=state` refuses an active timer
Re-timing ran it on a loaded, active timer, which systemd refuses.

**Impact:** F13: stop the timer, clean, then start; the clean also removes the `Persistent=` stamp.
**Source:** 24.2-REVIEW.md (F13), 24.2-05-SUMMARY.md

---

### The launching shell's TMPDIR was baked into every unit
The caller's TMPDIR made units look stale whenever it changed.

**Impact:** F17: Linux writes `TMPDIR=/tmp`, macOS the per-user `confstr` directory.
**Source:** 24.2-REVIEW.md (F17)

---

### The Schedules view reads the installed set at launch
A tool planted while the wizard was open (a claude stub) showed only after a restart; 35 s of waiting did not flip the row. The UAT also found the plan text called Policies key 5 when it is key 6.

**Impact:** Informational, not a gap; recorded in VERIFICATION and UAT.
**Source:** 24.2-UAT.md (test 5, 6), 24.2-VERIFICATION.md (Anti-Patterns)

---

### A scheduled cache run beside an open `make setup` logs a skip
`uv cache prune` reports "cache in use" while the wizard (a live `uv run`) is open; the result is `skipped: uv cache in use` and a later run with the wizard closed logs `ok: pruned uv`.

**Impact:** Expected behavior from F6's short `UV_LOCK_TIMEOUT`; the UAT text now notes it as expected.
**Source:** 24.2-UAT.md (test 5 step 4), 24.2-REVIEW.md (F6)
