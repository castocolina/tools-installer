## Focus-area findings

- **bun argv.** Names validated at load with `NPM_PACKAGE_RE` (no leading `-`); bun run by an
  absolute path in install (`executors.py:642`), update (`update.py:453`) and removal
  (`app.py:832`). No bare `npm` argv was added (the one `npm cache verify` entry,
  `wizard_app.py:2601`, predates the phase).
- **Manifest and trust.** No write to bun's manifest; no `--trust` in any argv; byte-identity test.
- **puppeteer confinement.** Strict `own-tree` loader with realpath prefix check, no fallback;
  missing bun copy fails before node starts; pnpm checks never use bun's tree.
- **PATH safety.** `"`, `$`, backtick, backslash, newline and `os.pathsep` refused on both
  spellings for the shell block; `prepend_path` refuses a separator for the process PATH.
- **Ownership fails closed.** Unreadable manifest, invalid key, or a listed package without a
  readable version marks bun unreadable; the engine receipt gate treats unknown as already there.
- **Repair never installs a second copy.** `session.py:706-711` `_other_node_manager_owns`
  makes a broken pnpm or Volta copy BLOCKED ("repair it with <owner>") unless the ladder's first
  method is that owner's (`session.py:770-777`, commit `aa38c1c8`); test
  `test_plan.py:319`. A bun smoke failure halts the ladder (T-24.5-05).
- **Container verb.** PID-scoped name, own `CONTAINER_NAME`/`IMAGE`/`DISTRO`, EXIT-trap teardown
  with a verified verdict, no host mount, no `ti-uat-*`.
- **Test isolation.** `tests/sandbox.py:758-760` clears `BUN_INSTALL`, `BUN_INSTALL_BIN`,
  `BUN_INSTALL_GLOBAL_DIR`; `bun` is a refused launch (`:66`); test `test_sandbox.py:1252`. The run
  above passed with the real `BUN_INSTALL` exported (review CR-01 fixed).
- **Zero sudo.** No `sudo`/`pkexec`/`doas` added in `installer/`, `setup.py` or `Makefile` in the
  phase diff. The e2e tester's passwordless sudo exists only inside the disposable container
  (`container-e2e-verify.sh:257`).
