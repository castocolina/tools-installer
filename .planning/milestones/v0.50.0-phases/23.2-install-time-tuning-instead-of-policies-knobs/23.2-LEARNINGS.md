# Phase 23.2 Learnings: Install-time tuning instead of Policies knobs (INSERTED)

## Decisions

### One writer, one dispatcher for every kind of install tuning
Agent keys, VS Code keys, Oh-My-Zsh plugins and shell init all run through the engine's plural `post_install` dispatcher. The `apply_agent_tuning` action returns a `PostInstallOutput(lines, settings)`, so the existing "Agent and editor settings" summary block keeps working. RECONFIGURE reuses the same writer with a `skip_recorded` flag instead of getting a second, lower-level writer.

**Rationale:** One writer keeps the conflict, retry and compare-before-commit logic in one place. A pre-filtering caller would have needed a second writer (D-01, D-03).
**Source:** 23.2-CONTEXT.md, 23.2-01-SUMMARY.md, 23.2-03-SUMMARY.md

---

### Setting group names in `agent_settings._KEYS` stay unchanged
`auto-approve`, `no-attribution`, `vscode-lean`, `vscode-ai-off` and `vscode-ext-updates-off` were not renamed. Copilot only adds rows under the existing group names.

**Rationale:** Ledger entries store the group name and revert rebuilds the key table from it. Renaming would leave keys written by the old Policies rows behind on removal (D-02).
**Source:** 23.2-CONTEXT.md

---

### A key the user deleted after the installer wrote it is the user's choice
RECONFIGURE writes only keys that are absent and unrecorded. A recorded-then-deleted key is neither flagged `≈` nor rewritten. An explicit reinstall still rewrites it. Shell init gets a written-once record in `~/.myshellrc` so a hand-deleted block follows the same rule.

**Rationale:** SPEC R2 treats a hand-deleted item as the user's choice. The jev suggestion of "presence only" (0.74) was overridden because pending means "never wrote", which needs a record (second opinion 0.96).
**Source:** 23.2-CONTEXT.md (D-03, D-04, D-08), 23.2-03-SUMMARY.md, 23.2-UAT.md (test 3a)

---

### Pending tuning is computed per tool inside the state-pass loop, only for a present tool
`_tuning_fact` runs next to `_hook_fact`, because `tool_state` moves an absent tool's facts into notes. Computing it for all agents up front would have shown "apply install tuning" on absent rows.

**Rationale:** Per-tool-in-loop scored 0.97 and matches the existing `ConfigStep` pattern.
**Source:** 23.2-CONTEXT.md (D-04), 23.2-03-SUMMARY.md

---

### Policies shrinks from 23 rows to 7, and the run options are deleted
Policies keeps ban, the three helper bundles, the daemon, the Bun redirect and the desktop SHELL row. The deletion list was written out deliberately, because vulture runs at `min_confidence = 80` and catches no leftovers. A symbol-absence test (`test_no_run_option_or_settings_policy_symbols_remain`) pins it.
Uninstall keeps the full `BUNDLES` and its own OMZ policy so per-tool removal and the full sweep still remove shell-init blocks and plugins.

**Rationale:** Install-time tuning with no question is the product rule. Removal paths need the old writers and removers as closures.
**Source:** 23.2-CONTEXT.md (D-09, D-10), 23.2-08-SUMMARY.md

---

### Sensitive-action machinery stays wired but empty
`SENSITIVE_POST_INSTALL_ACTIONS` becomes `()` and `SENSITIVE_PROMPTS` becomes `{}`. `set_login_shell` prints the `chsh` handoff text with no question and never runs `chsh`. `ConfirmSensitiveAction`, `SensitiveActionScreen` and the loader field `default_enabled_sensitive_actions` are left for Phases 24.1 and 25 to decide.

**Rationale:** Deleting the machinery before 24.1 decides ONB-09/ONB-10 would pre-empt that phase.
**Source:** 23.2-CONTEXT.md (D-13, D-14), 23.2-06-SUMMARY.md

---

### Copilot's Linux method is a checksummed `github_release` tarball, not npm
macOS uses the `copilot-cli` cask, and Linux gets an ownership-only cask method plus the `github_release` tarball verified against `SHA256SUMS.txt`. The node method was dropped.

**Rationale:** `requires` is tool-level and ignores OS, so `requires = ["pnpm"]` would have pulled pnpm into the macOS cask plan. The npm package states no `engines` floor, so a "Node floor" could not be verified. This amended D-20 at plan time.
**Source:** 23.2-CONTEXT.md (D-20 amendment), 23.2-RESEARCH.md via 23.2-04-SUMMARY.md

---

### PATH repair uses `guards.real_binary`, not `shutil.which`
`_put_present_bin_dir_on_path` asks `guards.real_binary(tool.cmd, shim_dir=..., path_value=...)`, so the installer's own redirect shim never counts as the tool being reachable. The repair applies only to SKIP and done rows, only for a registry-declared `bin_dir`, and only to the process PATH.

**Rationale:** Three review lanes (deep, ponytail, external) independently confirmed that with the pip/npm ban on, `~/.local/bin/pnpm` is the shim, `which` finds it, and UAT finding F-1 returns.
**Source:** 23.2-REVIEW.md (C-01), 23.2-REVIEW-FIX.md, 23.2-07-SUMMARY.md

---

### The silent-step indicator is a separate widget under the log, truncated by CSS
`#execute-silence` sits under `#execute-log`, and heartbeats are transient `InstallLogLine`s. Truncation uses `text-wrap: nowrap; text-overflow: ellipsis` instead of Python width arithmetic. ASCII versus Braille frames follow the stream encoding (`wants_ascii_spinner`), decided once at the composition root.

**Rationale:** RichLog only appends, so a separate widget is the only way to update a line in place without private API. Textual 8.2.7 supports both CSS properties, which is less code.
**Source:** 23.2-CONTEXT.md (D-16, D-17), 23.2-02-SUMMARY.md

---

### Install tuning is written down as a rule in the onboarding skill and architecture
`tool-onboarding` section 7 and `.claude/architecture.md` state that an accepted customization is install-time tuning in the tool's postinstall, applied with no runtime question and reverted with the tool. A Policies row is only for something outside any install. The author still asks which customizations to build, and only the end user is never asked at install. Two pin tests fail if the rule is softened.

**Rationale:** Without the rule, the next onboarding would add a Policies knob by default (T-23.2-15).
**Source:** 23.2-05-SUMMARY.md, 23.2-CONTEXT.md (D-19)

## Lessons

### Review lanes found a real HIGH that the plan review and executors missed
A planted redirect shim reproduced it: the PATH repair returned early, so the runner never got the real pnpm. Plan 07's own tests had no shim on PATH.

**Context:** Code review on the merged phase (deep, ponytail, external) consolidated 15 items. One was HIGH, five were MEDIUM and several were rejected with reasons. Fixes went in with a failing test written first.
**Source:** 23.2-REVIEW.md, 23.2-REVIEW-FIX.md, 23.2-REVIEW-external.md

---

### A reviewer's "dead code" claim needs a caller check before deletion
The deep lane said `omz_plugins_policy` had no production caller. `uninstall._omz_policy` calls it, so the claim was wrong and the function stays.

**Context:** C-07 deleted `setting_state`, `SettingState`, unread `SettingFacts` fields and `TUNING_ACTIONS`, but kept `omz_plugins_policy` after the caller was found.
**Source:** 23.2-REVIEW.md (C-07), 23.2-REVIEW-FIX.md

---

### Plan review tests must prove the schedule, not just the effect
A silence test that drives the check by hand with a fake clock would pass even if the code kept the 2 s re-arm. The fix was to assert the delays recorded from `set_timer` (the `recording_set_timer` pattern). The same applies to the container probe: a probe that re-selects agents by `PATH` after uninstall silently skips copilot, so the plan persists the checked agent list (`.e2e-tuned-agents.json`).

**Context:** Plan-review cycle 1 confirmed R1-03 and R1-04 as MEDIUM. Cycle 2 rejected a tighter pre-threshold clause because an existing kept test already pinned the remainder.
**Source:** 23.2-REVIEWS.md (R1-03, R1-04, R2-01), 23.2-02-SUMMARY.md, 23.2-04-SUMMARY.md

---

### A container e2e run found defects that hosted unit tests could not
The first verification ended `human_needed` because the container e2e had not run on the post-fix tree. The e2e fixes then changed covered files, so the verification went stale and had to be redone.
The fixes were: cursor-agent `approvalMode` declared `cli_default="allowlist"` (the CLI self-repairs a missing key, so install said "set by you" and never wrote it); ledger `created_dirs` so revert does not leave `.config/Code`; `removal_order` puts hook-registering tools first; a created JSON file holding only empty objects and `$schema` is deleted on revert; the probe skips `~/.claude/backups/`.

**Context:** Run #9 on `eb893c0` finished with every tracer green: `TRACER_SETTINGS_INSTALLED_OK agents=6 keys=29`, `TRACER_SETTINGS_REVERT_OK keys=29`, `TRACER_LEFTOVER_OK`.
**Source:** 23.2-VERIFICATION.md, 23.2-UAT.md

---

### Revert has to restore bytes, not only keys
A blank settings file (`b""`, `b"\n"`, `b"  \n\n"`) came back as `{\n}\n` after revert. The ledger now records a blank original (`blank_files`) and revert writes it back when only a bare `{}` remains. A BOM-only or U+00A0-only file still reverts to different inert bytes (security residual R1).

**Context:** C-03 had 9 failing cases (claude, copilot, codex by three blank forms) before the fix.
**Source:** 23.2-REVIEW-FIX.md (C-03), 23.2-SECURITY.md (R1)

---

### One crashing post-install action must not drop the others
The Oh-My-Zsh theme step raising on a non-UTF-8 `.zshrc` lost the earlier `chsh` handoff lines and the later plugin step. `run_post_install` now isolates each action into a `<action> crashed: <first line>` warning, and a non-UTF-8 rc is refused instead of rewritten. RECONFIGURE's `apply_install_tuning` is still not isolated per action.

**Context:** Raised as EX-03 by the external lane and PT-03/WR-05 by the others, then fixed as C-04.
**Source:** 23.2-REVIEW.md (C-04), 23.2-REVIEW-FIX.md, 23.2-REVIEW-external.md

---

### The vendor installer may write rc files that run the tool
fnm's `install.sh` appends a block that runs `fnm env`, so the plan had to pass `--skip-shell` and keep the installer's own `command -v`-guarded block. Volta's `get.volta.sh` runs `volta setup`, which writes only `export` lines. The executor read that as text and recorded it in the registry comment instead of passing a flag. That claim is not test-pinned (security residual R3).

**Context:** A plan-time stop-and-report rule covered the volta check, and it did not trigger.
**Source:** 23.2-06-SUMMARY.md, 23.2-REVIEWS.md (cycle 2), 23.2-SECURITY.md (T-23.2-25, R3)

---

### The same-release checksum defends against corruption, not a compromised release
The copilot `SHA256SUMS.txt` ships beside the asset, so it catches a substituted or corrupted asset but not a compromised upstream release.

**Context:** Logged as residual R4 along with the observation that `remove_plugins` reads then writes `.zshrc` with no compare-before-commit.
**Source:** 23.2-SECURITY.md (R4, T-23.2-12)

## Patterns

### Compare-before-commit with a reserve-then-write ledger
Reserve the ledger entry first, write through a snapshot-bound `write_if_unchanged`, retry once, then report `CHANGED_WHILE_WRITING`. Restore the ledger on `SettingsChanged` or `OSError`. `write_plugins` and `apply_theme` copied the idea with `_snapshot_text` and `_commit_unless_changed`, whose `OmzPluginsError` is an `OSError` subclass, so the existing rollback catches it.

**When to use:** Any installer write to a user-owned file that may be edited concurrently.
**Source:** 23.2-SECURITY.md (T-23.2-01, T-23.2-10, T-23.2-18), 23.2-06-SUMMARY.md

---

### Post-install actions may return lines or a structured output
`run_post_install` merges `PostInstallOutput` and plain tuples in declared order. Existing callers did not need rewriting except where a test compared the result to a tuple (about 48 call sites now read `.lines`).

**When to use:** Adding a structured result to an action registry without breaking the old return type.
**Source:** 23.2-01-SUMMARY.md

---

### Explicit `environ` argument instead of reading `os.environ`
`agent_env` and `agent_settings` take `environ` as an argument, and callers pass `os.environ`. A grep acceptance check (`os.environ` count 0 in both modules) pins it. The copilot adapter honours only an absolute `COPILOT_HOME`.

**When to use:** Any path that depends on an environment variable the sandboxed tests clear (`COPILOT_HOME` joined `CLEARED_ENV_NAMES`).
**Source:** 23.2-01-SUMMARY.md, 23.2-SECURITY.md

---

### Tracer first, then pinning tests, and label which tests are not RED
Plans began with one end-to-end tracer, then added matrix tests. SUMMARYs name tests that passed at once as "pinning/regression guards, not RED", and a mutation was used to show one was not vacuous. Where production code was written first, the RED run was reconstructed from a patch or a `git archive` of the earlier tree and was labelled as a reconstruction.

**When to use:** Plans where the writer already exists and later tasks only add coverage.
**Source:** 23.2-01-SUMMARY.md, 23.2-03-SUMMARY.md, 23.2-06-SUMMARY.md, 23.2-08-SUMMARY.md

---

### Doc rules get pin tests that assert load-bearing phrases
Two `tests/test_docs.py` tests check substrings of the skill and architecture text. The phrases must sit on one line, and text that names Policies stays plain ASCII. Skill-judge was run before and after, with the scores recorded (71.2 to 72.0, grade C).

**When to use:** A written rule that must not be softened later.
**Source:** 23.2-05-SUMMARY.md

---

### A constant copied from the registry gets a pin test
`PNPM_BIN_DIRS` in `executors.py` duplicates the registry's pnpm bin dirs because the executor has no catalog. A test pins the two together.

**When to use:** Where a layering rule prevents importing the source of truth.
**Source:** 23.2-07-SUMMARY.md, 23.2-REVIEW.md (C-15)

---

### Restore a CLI default on revert only while our value is still there
For cursor-agent, tuning replaces a value equal to the CLI's own default, records `replaced_default`, and revert restores the default only if the key still holds our value. Any other user value is kept. The e2e revert probe counts a key as gone when it is absent or equals its `cli_default`.

**When to use:** Agents that self-repair a missing key to a default.
**Source:** 23.2-04-SUMMARY.md, 23.2-VERIFICATION.md (97e8338), 23.2-UAT.md (test 2)

## Surprises

### Plan 08 shrank the test count by 21
Deleting the settings rows, run options and review-problem code removed a whole test file (`test_policy_settings.py`) and many tests. The collected total went 6026 to 6005 against 11 new tests.

**Impact:** A negative net test count was expected and correct. The summary lists every deleted or retargeted test with its reason so the drop is auditable.
**Source:** 23.2-08-SUMMARY.md

---

### The fresh-install OMZ record lists `docker`, not `git docker`
`set_omz_theme` runs first and `ensure_zshrc_template` writes `plugins=(git)`, so `git` is already present and the adjacency rule never records it as added. The final `.zshrc` is still `plugins=(git docker)`.

**Impact:** The plan text said the record lists `git docker`, and the test asserts `("docker",)` instead.
**Source:** 23.2-06-SUMMARY.md (note 1)

---

### The ASCII spinner is not reached under `LANG=C LC_ALL=C`
Python's UTF-8 mode (PEP 540) makes `sys.__stderr__.encoding` `utf-8` in the C locale, so Braille frames show. The ASCII frames appear only with `PYTHONUTF8=0 PYTHONCOERCECLOCALE=0`, and the rest of the TUI is then `\uXXXX`-escaped.

**Impact:** No defect, since the rule is "the stream encoding decides" (D-17), but UAT observed that the fallback is narrower than the plan implied.
**Source:** 23.2-UAT.md (O-1)

---

### The absent-pnpm message cannot be reached through the TUI
With pnpm absent, the dependency pass plans `pnpm will install`, so only an executor-level call shows the message. The same holds for the "installed at ... but not on PATH" message when the session repair did not run.

**Impact:** UAT test 7 checked the absent branch against the real executor code in the container instead of the TUI.
**Source:** 23.2-UAT.md (test 7, O-6)

---

### Real-TTY and container checks found no 23.2 defect
All seven container UAT tests passed with no findings. Nine observations were logged: clock restart after output, a settings block scrolling out at 80x20, `claude` reading `owner unknown` after the native installer, and others.

**Impact:** The defects came from the e2e run (the cursor-agent default and leftover directories) and from code review. UAT could not exercise opencode, pi, VS Code, headless `--yes` or macOS.
**Source:** 23.2-UAT.md

---

### The worktree guard and the shared git dir limited how executors recorded work
Plans 03, 06, 07 and 08 could not write the plan-head ledger file (the shared git dir is outside the worktree), so `commits:` was measured from the base SHA. The guard also refused compound shell commands and any command containing `git` in a URL or the scratchpad path.

**Impact:** Several SUMMARYs record durations as unknown or proxied. Executors fell back to scratch files and simple commands, with no behaviour change.
**Source:** 23.2-03-SUMMARY.md, 23.2-06-SUMMARY.md, 23.2-07-SUMMARY.md, 23.2-08-SUMMARY.md
