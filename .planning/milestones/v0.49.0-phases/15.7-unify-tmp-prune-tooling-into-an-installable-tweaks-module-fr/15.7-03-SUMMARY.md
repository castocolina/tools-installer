# Phase 15.7 Plan 03: Competing-mechanism detection and scope-aware takeover Summary

## Decisions Made

- `system_scope_warning`/`user_scope_failure_warning` are asserted with full string equality in the mechanism-layer tests, not substring/forbidden-word checks — the plan explicitly says these must be "pinned by asserting the exact produced sentences, not by grepping for forbidden words," so a future wording regression that reintroduces an overstated "removes"/"deletes" claim fails the test outright instead of slipping past a loose substring check.
- `_detect_and_take_over_competitors` is a private closure inside `linux_daemon_policy` rather than a standalone `installer/policy.py`-level function, matching the existing `_validate_and_write`/`_restore_units` closure shape that already captures `unit_dir`/`run`/`read_output` from the enclosing factory — introducing a new parameter-threading pattern for a single caller would be a gratuitous structural change.
- The "Competing mechanism" `PolicyLayer`'s detail text joins up to three independent clauses (disabled / disable-failed-still-running / system-scope-left-running) with `"; "` rather than collapsing to one sentence, so a mixed outcome across multiple competitors (e.g. one disabled, one failed) is never reported as a single ambiguous success or failure.
