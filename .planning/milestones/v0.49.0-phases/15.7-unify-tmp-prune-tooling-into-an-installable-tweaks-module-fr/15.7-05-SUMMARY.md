# Phase 15.7 Plan 05: Compose the Linux daemon and cache redirect Summary

**The Linux daemon and the Bun cache redirect are wired into the Policies list, the on-by-default path, and both uninstall routes, and the UI says what each one actually does.**

- **Tasks:** 3
- **Files modified:** 13

## Accomplishments

- A policy carries its own `decided` and `clear_decided` closures. `ensure_daemon_default` no longer names the macOS daemon module, and a Linux uninstall clears only the Linux marker.
- The on-by-default competing-mechanism warning is collected by `DaemonDefaultWarnings`, finished in the auto-apply closure's `finally`, and printed before the abort return. An unarmed collector returns immediately; a timeout prints what was collected plus one line saying the apply had not finished.
- `extra_policies` is required on `run_uninstall` and `perform_uninstall`. Both composition roots pass the same cache-redirect policies, and a full uninstall previews and removes them.
- The Policies detail for the Linux daemon names the ten-minute timer, the login-session limit, and `loginctl enable-linger $USER`, and says this installer does not run that command. The cache-redirect detail carries plan 15.7-04's `coverage_caveat` verbatim and says a Linux redirect takes effect at the next login. The uninstall row names a systemd timer on Linux and discloses the redirect inside the aggregate tweaks row.
