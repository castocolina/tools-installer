## Decisions Made

- Wrapped the first-ever-apply rollback's own `remove_units(unit_dir)` call in `contextlib.suppress(OSError)` after discovering (via live debugging with temporary instrumentation, since reverted) that it could itself raise `NotADirectoryError` and silently mask the original failure being unwound, aborting the rest of rollback. `_remove()`'s own separate `remove_units()` call site was deliberately left unwrapped, since its test contract requires a real failure there to still propagate — a secondary compensating-call failure must never mask the original one, but a primary call's own contract must still hold.
- `_build_daemon_policy`'s `which` parameter defaults to `None`, resolved dynamically via `shutil.which` inside the function body rather than bound at definition time, so the pre-existing `test_build_daemon_policy_is_fail_closed_not_fail_hidden_for_a_bad_environment` test's `monkeypatch.setattr(setup.shutil, "which", ...)` technique kept working unchanged while new call sites can still inject an explicit lookup.
- Extended `tests/test_setup.py`'s `_sandbox` fixture to also patch `_LINUX_DAEMON_UNIT_DIR`/`_LINUX_DAEMON_LOG_PATH`, mirroring the existing macOS `_DAEMON_PLIST_PATH`/`_DAEMON_LOG_PATH` patches — without it, Linux-platform tests would read/write the real dev host's `~/.config/systemd/user`, and the D-01c presence short-circuit (no unit files → INACTIVE without ever calling `read_output`) would incidentally, not genuinely, prevent a real subprocess call.
- Split `test_daemon_policy_is_absent_on_linux` into a pair rather than simply widening its assertion: the absent case re-grounded on the D-01b systemd-availability gate, a new sibling proving the row IS present once systemd is available. ROADMAP SC#2's original "invisible/inert on Linux" framing is deliberately superseded by this phase's D-01a, and the tests now say so explicitly rather than leaving a stale docstring.
