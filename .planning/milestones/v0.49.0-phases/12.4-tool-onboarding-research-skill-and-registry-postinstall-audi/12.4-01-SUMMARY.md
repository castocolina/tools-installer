## Live Verification Transcript

**Binary:** `rtk-x86_64-unknown-linux-musl.tar.gz` from `rtk-ai/rtk` release `v0.49.0`.
**Checksum:** `7278231dfd7e6a730a4ab7f847b195bcf02289c2d57622b0dab75a6411100c8f` — matched the release's own `checksums.txt` exactly.
**Version confirmed:** `rtk 0.49.0` (via `--version`).

1. **Fresh init (claude, `-g --auto-patch`):** in a scratch `$HOME` with a pre-created empty `.claude/` dir, exit 0. `RTK.md` and `settings.json` created with the hook block.
   - *Finding:* rtk does NOT create `~/.claude/` itself — a scratch `$HOME` with no `.claude/` dir at all fails: `Failed to write RTK.md: ... No such file or directory (os error 2)`. Added a defensive `ensure_dir(Path.home() / ".claude")` call before the claude branch fires (not in the plan's original Task 1 skeleton, added based on this session's own live evidence).
2. **Idempotency rerun (same scratch `$HOME`):** exit 0, `settings.json: hook already present`, hook string appears exactly once in `settings.json` (`grep -c` confirmed 1).
3. **Adversarial seeded-content rerun:** fresh scratch `$HOME` seeded with a pre-existing `permissions.allow` entry, an unrelated `PreToolUse` hook on a different matcher, and a custom `statusLine`. After `rtk init -g --auto-patch`: all three survived byte-equivalent (JSON re-serialized but semantically identical), rtk's own hook appended as a second `PreToolUse` entry alongside the pre-existing one.
4. **Pitfall 1 falsification, scenario A (no `.claude/`, only `.cursor/`):** `rtk init -g --agent cursor --auto-patch` — exit 1, same `Failed to write RTK.md ... No such file or directory` error, confirming the cursor branch still unconditionally attempts to write Claude Code's files even when claude was never selected. **Bug persists in v0.49.0.**
5. **Pitfall 1 falsification, scenario B (pre-existing `.claude/` and `.cursor/`):** same command, exit 0 — printed the full "RTK hook registered (global)... Claude... settings.json: hook already present" block, THEN the Cursor-targeted "Cursor hook registered (global)... hooks.json: RTK preToolUse entry added" block. Confirms the coupling: cursor mode always also touches claude's files when they can succeed.
6. **Pitfall 2 falsification:** `rtk init -g --codex --auto-patch` — exit 1, `rtk: --codex cannot be combined with --auto-patch`. `rtk init -g --codex` (no auto-patch) — exit 0, non-interactive, wrote `.codex/RTK.md` and `.codex/AGENTS.md` (codex's own directory WAS auto-created by rtk, unlike claude/cursor).

Based on step 4/5's result (bug persists), `_rtk_register` gates the `cursor-agent` branch: it only fires when `"claude" in present`, silently skipping otherwise (documented in the function's docstring and the registry's `# Verified` comment) — Option (a) from the plan's `<read_first>` (blind-scaffold `~/.claude/`) was never implemented, per the plan's explicit instruction.

Every command above ran with `HOME=$(mktemp -d)` overridden; no command touched this machine's real `$HOME`, `~/.claude/`, or `~/.cursor/`. All scratch directories were deleted after verification.
