## Decisions Made

- `fzf` and `dive` stay `human` despite each having a documented non-interactive flag (`fzf --filter`, `dive --ci`, both verified live during planning). D-02's criterion asks whether an agent would invoke the tool on its own; a flag's existence is not an answer to that question. This reasoning is written into the dated comment above `_INTERACTIVE_ONLY_TOOLS` in `tests/test_registry.py`, not left in PLAN.md, so it ships with the repo.
- The criterion comment states the rule in terms of a tool's default mode and product (interactive session vs. print-and-exit-is-the-product), explicitly saying a batch/filter/CI flag bolted onto an interactive tool does not by itself make it `both`.
- `_PRE_15_3_HUMAN_TOOLS` (the 17 pre-existing human ids) was derived by querying the live registry (`load_tools(REGISTRY)`, filtered to `audience == "human"`, minus `_INTERACTIVE_ONLY_TOOLS`) and reconciled against the plan's `read_first` list before being written as a literal set -- both matched exactly (17 ids, no discrepancy to resolve).
- Falsification was run scoped to each guard's own pytest node id rather than as a whole-file run, per the plan's explicit instruction: the three guards overlap by design (a kept-tool flip also trips the set-equality and distribution tests), so a whole-file run would not show what each guard individually catches.
