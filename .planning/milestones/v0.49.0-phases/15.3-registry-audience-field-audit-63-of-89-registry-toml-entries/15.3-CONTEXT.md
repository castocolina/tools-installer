# Phase 15.3: Registry audience field audit - Context

**Gathered:** 2026-09-15
**Status:** Ready for planning

<domain>
## Phase Boundary

A one-time data-quality pass over `installer/registry.toml`: 63 of 89 entries carry
`audience = "both"` (the class default, `installer/model.py:287`), never individually
reviewed. This phase re-tags genuinely human-only interactive tools to
`audience = "human"`, keeping `"both"` for anything with a plausible non-interactive or
agent-invoked use. No code or schema change — `tier` and `audience` are confirmed
separate, correctly-used fields (see `code_context` below); this phase touches only
`audience` values in `registry.toml`.

</domain>

<decisions>
## Implementation Decisions

### High-confidence re-tag set
- **D-01:** The following 11 tools move from `audience = "both"` to `audience = "human"`
  — no plausible case where an agent invokes them on its own:
  - **shell** (7): `direnv`, `gnu-bash`, `gum`, `oh-my-zsh`, `starship`, `watch`, `zsh`
  - **editor** (2): `sublime`, `vscode`
  - **nav** (2): `broot`, `zoxide`
  — **Reversibility:** reversible — a value in a TOML file, trivially reverted.
  **Rationale (user):** confirmed as-is, no individual review needed — shell
  theming/config, GUI editors, and interactive directory navigation have no
  agent-invoked use case.

### Borderline-category criterion
- **D-02:** Applied criterion: **"human" if the tool is an interactive TUI with no
  plausible non-interactive use; stays "both" if it can be invoked non-interactively
  for a one-shot output** (prints and exits, scriptable). Applying this criterion to
  the borderline set the user selected:
  - **→ `human`:** `gitui`, `lazygit` (git TUIs, no non-interactive mode), `bottom`,
    `dive` (persistent interactive monitors/explorers), `fzf` (inherently interactive
    fuzzy-finder)
  - **→ stays `both`:** `duf`, `dust`, `procs` (all print-and-exit by default — an
    agent can invoke any of them for a one-shot snapshot, same shape as `df`/`du`/`ps`),
    `bat`, `eza` (non-interactive by default, agent-usable like `cat`/`ls` with nicer
    output), `glow` (prints-and-exits when given a file argument), `hexyl`
    (print-and-exit hex dump)
  — **Reversibility:** reversible.
  **Rationale (user):** the "TUI vs one-shot-output" line is the right split —
  matches the user's own framing that an agent wouldn't care about interactive shell
  tooling, but a one-shot CLI with nice formatting is plausibly agent-usable.

### Combined final re-tag list (16 tools, `both` → `human`)
`direnv`, `gnu-bash`, `gum`, `oh-my-zsh`, `starship`, `watch`, `zsh`, `sublime`,
`vscode`, `broot`, `zoxide`, `gitui`, `lazygit`, `bottom`, `dive`, `fzf`

**Everything else currently tagged `both` (47 remaining tools across `data`, `dev`,
`diagram`, `docker` [except `dive`], `git` [except `gitui`/`lazygit`], `pkg-mgr`,
`runtime`, `search` [except `fzf`], `security`, `sysinfo` [except `bottom`], `view`)
stays `both` — no further changes.** These are package managers, runtimes, build
tools, linters/formatters, data-manipulation CLIs, and one-shot CLIs with real
agent-invoked use cases (e.g. `docker`/`podman` build/run commands, `pnpm`/`uv`
dependency installs, `ruff`/`shfmt` formatting, `gh`/`glab` API operations).

### Claude's Discretion
- Exact `git diff`-style presentation of the 16-line change during planning/execution
  (whether the plan does one bulk edit or per-category commits) — this is execution
  shape, not a product decision.
- If, during implementation, a tool turns out to have a non-obvious non-interactive
  flag/mode not considered here (discovered via live doc check, matching the rigor
  Phase 12.4's audit used for `spec-kit`), the planner should apply D-02's criterion
  to that new evidence rather than blindly following this list — but any deviation from
  the 16-tool list above should be called out explicitly in the plan's own notes.

### Folded Todos
None — see Deferred Ideas for the two todos reviewed but not folded.

</decisions>
