### `installer/wizard_app.py` — `_install_closed` (controller, event-driven)

**Analog:** itself (current state) — the fix is a one-line addition, not a rewrite.

**Current code** (`installer/wizard_app.py:1833-1834`, verbatim per RESEARCH.md):
```python
def _install_closed(self, _result: None) -> None:
    self._staged.clear()
```

**Pattern to apply (D-01):**
```python
def _install_closed(self, _result: None) -> None:
    self._staged.clear()
    self._catalogs[self.current_view].enter_view()
```

`self._catalogs` is keyed uniformly by `self.current_view` (a `Tier`/`BASE_VIEW`-typed
string) for **all three** tiers, so no base-vs-non-base branching is needed — do not
mirror `show_view`'s `if name != BASE_VIEW:` asymmetry here (that asymmetry exists only
because `show_view` mutates the screen stack; `_install_closed` does not).

**Cross-file precedent for this bug class (Phase 15 D-01/D-02, `DoctorScreen`):**
read `.planning/phases/15-catalog-accuracy-doctor-refresh-version-parsing-ownership-at/15-CONTEXT.md`
for the shape of "a screen must re-render itself after a background action closes" —
same bug class, different screen/call site; not literally copyable code, but confirms
the "call the existing view-refresh entrypoint from the action-close callback" shape is
this codebase's established idiom for this exact bug class.

**`enter_view()` mechanism being reused** (`installer/catalog_tui.py:264-273`, verbatim,
unchanged by this phase — read-only reference, do not re-implement):
```python
def enter_view(self) -> None:
    if self.is_mounted:
        self._start_version_refresh()

def _start_version_refresh(self) -> None:
    if self._version_refresh is None:
        return
    self._version_refresh_generation += 1
    self.version_refreshing = True
    self._refresh_versions_worker(self._version_refresh_generation)
```
Guards on `is_mounted` internally — safe to call unconditionally from `_install_closed`,
no new guard needed at the call site.

### `installer/catalog_tui.py` — `_ver_cell` (component, transform)

**Analog:** itself (current state) — three of its five return branches are rewritten in
place; two (the `outdated is True` / `outdated is False` branches, and the `~` suffix
assembly) are unchanged.

**Current code** (`installer/catalog_tui.py:299-323`, verbatim):
```python
def _ver_cell(self, tool: Tool) -> Text:
    if not self._installed.get(tool.id, False):
        return Text("")
    status = self._version_statuses.get(tool.id)
    if status is None or status.installed is None:
        return Text("unknown", style="dim")
    if status.latest is None:
        return Text(status.installed, style="dim")
    if status.outdated is True:
        base = f"{status.installed} -> {status.latest}"
        color = "yellow"
    elif status.outdated is False:
        base = status.installed
        color = "green"
    else:
        return Text("unknown", style="dim")
    if status.stale:
        return Text.assemble((base, color), (" ~", "dim"))
    return Text(base, style=color)
```

**Branches to change (D-02) — exact locations:**
- `catalog_tui.py:303-304` (`status is None or status.installed is None`) → "no data
  yet / still probing" — currently literal `"unknown"`. Give it a distinct label (e.g.
  `"…"`).
- `catalog_tui.py:305-310` (`status.latest is None`) → "not tracked for updates"
  (dnf/apt/pacman/rpm-ostree-owned tools) — currently bare `status.installed` with no
  marker. **MUST preserve `status.installed` in the output** (append/prefix a marker,
  do not replace) — this exact regression was already fixed once, per the code comment
  and `test_ver_cell_shows_probed_version_with_no_latest_to_compare`
  (`tests/test_catalog_tui.py:903-931`). Illustrative: `Text.assemble((status.installed,
  "dim"), (" (unmanaged)", "dim"))`.
- `catalog_tui.py:317-318` (final `else`, `status.outdated is None` while
  `status.latest is not None`) → "unparseable version" — currently literal `"unknown"`,
  same text as the first branch (this is the ambiguity D-02 exists to fix). Give it a
  third distinct label (e.g. `"unknown ver."`).

**Unchanged branches** (keep verbatim — do not touch): `outdated is True` /
`outdated is False` color logic (lines 311-316), and the trailing `stale` suffix
assembly (lines 320-323) using `Text.assemble((base, color), (" ~", "dim"))`.

**Constraint:** verify by grep after editing that the literal string `"unknown"` (or
whichever label is kept, if any) appears in only one `_ver_cell` return path — reusing
it for more than one branch reproduces the exact bug D-02 fixes.

**Color-naming constraint:** use `"yellow"` (the actual Rich style token already used at
`catalog_tui.py:313` and in `_PRIORITY_STYLE[P1]`), never `"orange"` — CONTEXT.md's
prose says "orange" but the real rendered/style-matching color is `yellow`.

### `installer/catalog_tui.py` — `_LEGEND` (config, transform)

**Analog:** itself (current state) — in-place string extension, no new widget.

**Current code** (`installer/catalog_tui.py:168-172`, verbatim):
```python
_LEGEND = (
    "[bold red]P0[/] essential · [bold yellow]P1[/] recommended · [blue]P2[/] nice-to-have"
    " · [dim]P3[/] niche  |  for [bold cyan]AI[/] / [magenta]human[/] / both"
    "  |  [green]✓ installed[/] · [yellow]○ missing[/]"
)
```

**Pattern to apply (D-03/D-04):** append a new clause following the existing
`·`/`|`-separator convention, covering: `[green]` up to date, `[yellow]` update
available, each of the three new D-02 gray labels (verbatim text matching what
`_ver_cell` now emits), and the ` ~` stale suffix. Do not build a second `Static` or a
new footer region — `_LEGEND` is rendered via the existing mechanism below and is
already present on all three tiers (System/User/AI), satisfying D-03's "always-on,
present on all three top-level views" requirement automatically.

**Rendering mechanism being reused** (`installer/tool_browser.py:124-129`, verbatim,
unchanged by this phase — read-only reference):
```python
def compose(self) -> ComposeResult:
    yield Tabs(*[Tab(label, id=name) for name, label in self._adapter.views])
    yield DataTable()
    if self._adapter.legend is not None:
        yield Static(Text.from_markup(self._adapter.legend), id="browser-legend")
    yield Static("", id="browser-detail")
```
`_adapter()` is called once per `CatalogScreen` instance (once per Tier), so extending
the single `_LEGEND` string keeps System/User/AI automatically in sync — do not
special-case per tier.
