### 2. Label comprehension

expected: Read the legend at the bottom of the catalog on a real 80-column terminal
  and, without consulting the code or the plan, say what `checking…`, `no version`,
  `(source unknown)`, `(no comparison)` and `~ cached latest` each mean. Each should
  be understandable from the legend alone; the original complaint ("the ambiguous
  grays ... anything else weird that doesn't explain itself") no longer applies.
result: RESOLVED (originally ISSUES; legend format+content fixed across 3
  rounds, each independently re-verified — see follow_up; functional findings
  triaged out of 15.1 into Phase 15.4 / a new Doctor todo) — original user
  feedback (verbatim, lightly reformatted):
  "about the legend, when I use the term legend I expect colors matched to color
  explanations in a footer or similar, per color — that sense is lost in the full
  prose description. But the worst part: jetbrains-toolbox, which resides in
  ...linuxbrew..., does not match any package manager. git, which is distributed by
  the OS and installed into /usr/bin/git, has the same problem. mmdc, which resides
  in pnpm, still says 'no version' and the same 'source unknown' thing."

  Two distinct problems raised:
  (a) Design regression — "legend" should read as a compact per-color/symbol key
      (swatch -> meaning), not a paragraph of prose; the current wording loses that
      at-a-glance quality.
  (b) Functional bugs — real installed tools (jetbrains-toolbox via linuxbrew, git
      via OS package at /usr/bin/git, mmdc via pnpm) are all landing in the
      "(source unknown)"/"no version" bucket despite being genuinely
      owned/attributable — this is a version_status/ownership resolution defect,
      not just a labeling-wording issue, and may extend beyond D-02's original
      scope into ownership attribution (Phase 15.4 territory) — needs investigation
      to determine true root cause and correct phase placement.
follow_up: investigated via subagent (this session), root-caused, and triaged:
  (a) legend format — fixed in 15.1 itself, in three rounds, each caught by an
      independent re-verification subagent pass rather than further manual UAT:
        - commit cc50901: first attempt — 3 explicit per-group lines instead
          of wrapped prose, but collapsed the four dim labels into one "other
          dim: self-explains" note and one forced line overflowed the
          confirmed 78-usable-column budget by 1 character, silently clipping
          at the tested 80x20 minimum. Both regressions caught by re-verify.
        - commit 1b372c5: restored all four dim labels verbatim (D-03/D-04's
          locked per-state requirement) and regrouped the 3 lines by budget
          (each measured <=78 plain columns) instead of strict semantics, but
          silently dropped "latest" from the `~` marker's gloss while
          trimming, and weakened its covering test to match instead of catch
          it. Caught by a third re-verify pass.
        - commit fed6e56: restored "latest" (`~ cached latest`, 77/78 cols)
          and the stricter test assertions. A fourth, adversarial re-verify
          pass independently reproduced every claim (parsed constant, actual
          painted widget against the real 89-tool registry at 80x20/100x30,
          proved the strengthened tests fail against each prior broken
          commit) and found 22/22 must-haves, 0 gaps.
  (b) jetbrains-toolbox/git — real resolver/registry gaps (no "OS base image" owner
      concept exists; Linux cask name mismatch + macOS-only cask method gate).
      NOT a 15.1 defect — 15.1's own D-02 labeling is working correctly (both
      genuinely resolve to owner=unknown today). Folded into Phase 15.4's
      CONTEXT.md as a dated Correction (commit 94b767f) — that phase's D-01
      premise ("no new data plumbing") was disproven and must budget for the
      real fix before planning.
  (c) mmdc — confirmed a dangling pnpm global bin shim (package removed via a
      comma-group coupling, stale shim left on PATH); app's "no version"/
      "(source unknown)" reporting is factually correct for a broken install.
      Filed as a new pending todo (Doctor dangling-shim detection), not a 15.1
      or 15.4 defect.
