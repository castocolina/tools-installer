The main problem is that the writer scanner does not classify reliably. `guidance.py` turns its answer into a stated fact: "X adds it unconditionally… Opening a new terminal will not clear this one". The result is two kinds of error:
- **False positives:** a correctly guarded `if` line is reported as an unconditional writer.
- **False negatives:** some lines the Doctor's own comparator does treat as duplicate sources are missed. A trailing slash, a trailing comment, `;`, `&&` and zsh's `path=(...)` all fall back silently to the "usually transient" advice.

The second case is exactly the misdiagnosis `2eaae39` set out to fix. Neither Doctor route has a test for its wiring. The `$ZSH` fix works, but it was applied locally rather than in the autouse fixture `conftest.py` already uses for the same class of leak.

## Critical Issues

### CR-01: Presence-guarded `if` blocks are reported as "unconditional" writers, so Doctor tells the user to edit a correct line

**File:** `installer/rcclean.py:146-163` (consumed by `installer/guidance.py:96-120`)
**Issue:** `unguarded_path_writers` counts every indented `PATH=` line as a writer. It does this so Fedora's `if`-wrapped prepend is reported. But it never looks at the enclosing condition, so it also reports the most common idempotent guard idiom:

```sh
if [[ ":$PATH:" != *":$HOME/.local/bin:"* ]]; then
    export PATH="$HOME/.local/bin:$PATH"
fi
```

Reproduced: `unguarded_path_writers({rc: <above>}, {/home/u/.local/bin}, {"HOME": "/home/u"})` returns `{/home/u/.local/bin: (rc,)}`.

`doctor_guidance` then states as fact that the file "adds it unconditionally" and that "Opening a new terminal will not clear this one", and tells the user to edit or guard a line that is already guarded. The docstring's own contract says "Guarded forms are not writers … Flagging one would point the user at a correct line", and this violates it. The guarded forms the function does skip (single-line `case`, pnpm's `*) export PATH=…`) are skipped only because `_PATH_EXPORT` happens not to match lines that start with `case`/`*)`. That exclusion is a side effect of the regex, not a check. No test covers an `if`-guarded line, so the gap is invisible.

The same reasoning applies to the Fedora stock snippet that motivated the change. Its `if ! [[ "$PATH" =~ "$HOME/.local/bin:$HOME/bin:" ]]` is also a presence test. It skips the prepend whenever the pair is already contiguous, for example in a nested shell. So "unconditional" overstates even the motivating case.

**Fix:** Do not assert "unconditional" for indented lines. Either:
- Track the enclosing `if`/`case` header. If the header mentions `$PATH` together with the target directory, treat it as guarded:

```python
# while scanning: remember the most recent unclosed `if`/`case` header line
_GUARD_HEADER = re.compile(r'^\s*(if|case|\[\[|\[)\b.*\$\{?PATH')
...
if line[:1] in (" ", "\t") and open_header is not None and _GUARD_HEADER.match(open_header):
    continue  # presence-guarded: cannot re-add an already-present dir
```

- Or return a two-tier result (`unconditional` vs. `conditional`) and have `guidance.py` soften the wording to "may add it" for the conditional tier.

In both cases, add a test for the `if [[ ":$PATH:" != *":dir:"* ]]` idiom asserting `{}` (or the conditional tier).

## Warnings

### WR-01: Writer matching uses raw string equality, but the Doctor uses `Path` equality, so a writer behind a reported duplicate is silently missed

**File:** `installer/rcclean.py:147, 160-161`
**Issue:** `audit_path` (`installer/doctor.py:22`) counts entries as `Path(entry)`, which normalises trailing slashes and `//`. `unguarded_path_writers` instead looks up `targets.get(expanded)` with `targets` keyed by `str(directory)`. Reproduced:
- `audit_path([/home/u/.local/bin], "/home/u/.local/bin/:/home/u/.local/bin", …)` reports the directory as duplicated.
- `unguarded_path_writers` over `export PATH="$HOME/.local/bin/:$PATH"` returns `{}`. The same happens for `$HOME//.local/bin`.

The guidance then falls back to "Usually a nested shell … clears when you open a new shell". That is the never-working advice this commit was written to eliminate, now applied to a writer the Doctor itself counted.

**Fix:** Normalise the same way the Doctor does:

```python
targets = {Path(directory): directory for directory in managed_dirs}
...
directory = targets.get(Path(expanded)) if expanded else None
```

Add a trailing-slash test.

### WR-02: Common real-world PATH-line shapes are silently not recognised as writers

**File:** `installer/rcclean.py:16, 152-161`
**Issue:** `_PATH_EXPORT` (`^\s*(?:export\s+)?PATH=(.+?)\s*$`) treats the whole rest of the line as the value, and `_unquote` only strips a quote pair that spans the entire remainder. Reproduced, each of these returns `{}` for `/home/u/.local/bin`:
- `export PATH="$HOME/.local/bin:$PATH"  # added by uv` (trailing comment: first segment becomes `"/home/u/.local/bin` with a leading quote)
- `export PATH="$HOME/.local/bin:$PATH"; export X=1`
- `[ -d "$HOME/.local/bin" ] && export PATH="$HOME/.local/bin:$PATH"`. This is unconditional with respect to PATH and is a true writer.
- `path=("$HOME/.local/bin" $path)`, the idiomatic zsh form. `.zshrc` and `.zprofile` are in the scan set, so zsh users are directly affected.

Each miss downgrades a structural duplicate to the "transient" hypothesis. `find_duplicate_path_lines` has the same parser, and there a miss is the safe direction (nothing gets stripped). For a diagnostic that states a cause, it is not safe.

**Fix:**
- Strip an unquoted trailing `# …` comment and split on unquoted `;` before matching.
- Accept a `cmd && export PATH=` / `|| export PATH=` prefix.
- Add a zsh `path=(… $path)` matcher.

Cover each shape with a test.

### WR-03: The Doctor wiring is untested and bypasses `run_doctor`'s injected-seam contract

**File:** `installer/app.py:308-318, 374`
**Issue:** `run_doctor` injects every IO source: `path_value`, `exists`, `which`, `managed_globals`, `disk_pressure`, `competing`. `_duplicate_path_writers` instead hardwires `path_scan_rc_paths()` (real `Path.home()`) and `os.environ`. This has two effects:
1. **The wiring is untested.** No test in `tests/test_app.py` calls `run_doctor` with a duplicated report, and `grep duplicate_writers tests/` finds only `test_guidance.py` and `test_rcclean.py`. You can delete `_duplicate_path_writers(report)` from line 374, or the `duplicate_writers=` kwarg at `wizard_app.py:2390`, and the suite stays green. The commit message says the fix was "wired through both Doctor routes rather than left as an optional argument nothing passes", but nothing tests that claim.
2. **Future tests will be nondeterministic.** The first test that does pass a duplicated `path_value` will read the developer's real `~/.bashrc`/`~/.bash_profile`/`~/.profile` and get host-dependent output. This is the same class of leak `102c83e` just fixed for `$ZSH`.

Variable expansion also uses the live `os.environ`, while the PATH being audited is the injected `path_value`, so the two inputs can disagree.

**Fix:** Inject the scanner like the other seams, and add one test per route asserting the rc file name appears in the rendered output:

```python
def run_doctor(..., duplicate_writers: Callable[[DoctorReport], Mapping[Path, tuple[Path, ...]]] = _duplicate_path_writers, ...):
    ...
    render_doctor(report, console, duplicate_writers(report))
```

### WR-04: The duplicate-writer scoping rule is implemented twice

**File:** `installer/app.py:308-318` and `installer/wizard_app.py:2390-2394`
**Issue:** `wizard_app.py` already imports from `installer.app` (line 31), yet it re-implements `_duplicate_path_writers` inline: `scan_rc_path_writers(path_scan_rc_paths(), set(report.duplicated), os.environ) if report.duplicated else {}`. The scan set, the env source and the "only when duplicated" short-circuit now live in two places. Any fix to WR-01, WR-02 or WR-03 (for example injecting the env, or adding `~/.bashrc.d`) has to land in both, and the TUI and CLI Doctors can drift apart in what they report.
**Fix:** Rename `_duplicate_path_writers` to public `duplicate_path_writers` in `app.py`, then have `wizard_app.py` call `duplicate_path_writers(report)` and drop its `os`/`path_scan_rc_paths`/`scan_rc_path_writers` imports if they are otherwise unused.

### WR-05: The `$ZSH` isolation fix is local to one helper rather than in the autouse fixture that already exists for this class of leak

**File:** `tests/test_setup.py:439-443` (compare `tests/conftest.py`, `no_zdotdir`)
**Issue:** The fix is correct for `_sandbox`. I confirmed `$ZSH=/home/bazzite/.oh-my-zsh` on this host, which would make `test_build_app_wires_live_omz_availability_and_one_terminal_sync_closure`'s `missing_requirements() == ("oh-my-zsh",)` fail. But `conftest.py` already handles the sister leak, `$ZDOTDIR`, with an autouse `no_zdotdir` fixture, and its docstring describes exactly this problem.

Putting `$ZSH` only in `_sandbox` leaves other paths exposed:
- the hand-rolled sandbox at `tests/test_setup.py:1042-1049`, which also drives `_build_app`;
- any of the 18 other test files that `setenv("HOME", …)` without clearing `$ZSH`.

Through `setup.py:991` (`omz_present(Path.home(), os.environ)`) and `setup.py:729` (`sync_terminal_shells(environ=os.environ)`), these can still resolve the developer's real oh-my-zsh install the next time a test reaches them.

**Fix:** Move the clear into `conftest.py` next to `no_zdotdir`, and drop it from `_sandbox`:

```python
@pytest.fixture(autouse=True)
def no_zdotdir(monkeypatch: pytest.MonkeyPatch) -> None:
    monkeypatch.delenv("ZDOTDIR", raising=False)
    monkeypatch.delenv("ZSH", raising=False)  # omz_root falls back to $ZSH
```

Rename the fixture if you prefer, for example `no_shell_location_env`.

## Info

### IN-01: The writer-scan loop duplicates `find_duplicate_path_lines` nearly line for line

**File:** `installer/rcclean.py:146-168` vs. `installer/rcclean.py:72-102`
**Issue:** The two loops are about 20 near-identical lines: managed-block skip, local-env tracking, `$PATH` segment skip, `_expand`, and `_ASSIGN` propagation. They differ only in the indentation filter and the collection shape. The parser fixes in WR-01 and WR-02 would have to be made twice.
**Fix:** Extract a generator such as `_path_line_targets(lines, env) -> Iterator[tuple[int, str, list[str]]]` that yields `(index, line, expanded_segments)`, and build both functions on it.

### IN-02: The scan set omits common PATH-writer locations, so some structural duplicates stay unexplained

**File:** `installer/locations.py:111-132` (called from `installer/app.py:318`)
**Issue:**
- Fedora's stock `~/.bashrc` sources `~/.bashrc.d/*`, which is the distro-recommended place for user PATH edits, but it is not scanned.
- `~/.zshenv` and `~/.zlogin` are not scanned.
- `.zprofile` is read from `~/` even when `$ZDOTDIR` is set, although `_zshrc()` in the same list honours `$ZDOTDIR`.

A writer in any of these locations falls back to the "transient" advice.
**Fix:** Add `~/.bashrc.d/*` (sorted glob), `.zshenv` and `.zlogin`, and resolve all zsh files under `zshrc_path(...).parent`.

### IN-03: Function-local imports repeated in every new test

**File:** `tests/test_rcclean.py:317, 333, 351, 365, 380, 393, 405`
**Issue:** Each of the 7 new tests imports `unguarded_path_writers`/`scan_rc_path_writers` inside its body, while the module already imports `find_duplicate_path_lines` from the same module at line 5.
**Fix:** Add both names to the existing top-level import.
