<objective>
Wire D-04's consolidation into the one seam every PATH-wiring route already goes through,
guarantee that each rc file reaches `~/.myshellrc` by exactly one route, make a refusal impossible
to mistake for success, make the new path constant test-safe everywhere, and record this phase's
invariants in `.claude/architecture.md` so they survive as doctrine.

Purpose: D-04 — the consolidation has to actually RUN, on the same trigger D-01 names ("the next
time `apply`/`fix` runs on Doctor, or `make fix`"). D-01 — the migration of the managed block and
the consolidation of the generic file are triggered by the same four call sites, so wiring them
together keeps one user action from producing half a fix.

Output: a `shellrc_path` parameter and a structured return on `installer/app.py::configure_path`,
the single-route rule, a widened `run_live`, a `_SHELLRC` constant and four updated call sites in
`setup.py`, the test-isolation updates that make the new constant safe, and a new
`.claude/architecture.md` section.

**Why the consolidation runs BEFORE the PATH block is written.** The copy-forward must land while
the file's block layout is still whatever the previous run left; writing the managed PATH block
first would mean two consecutive read-modify-write cycles on `~/.myshellrc` in one call, with the
foreign content arriving second and the block order flipping depending on which ran first.
Consolidate, then write the managed block: the managed block ends up last, which is also the
order that makes the guarded exports the final word on PATH.

**Why each rc file must reach `~/.myshellrc` by exactly one route (review HIGH-02).** A generic
`~/.shellrc` is useful precisely because `.bashrc`/`.zshrc` commonly source it — that is the
normal reason such a file exists at all. After consolidation, that existing line still works,
because `~/.shellrc` is now a stub that sources `~/.myshellrc`. If `configure_path` ALSO runs
`ensure_source` on the same rc, the canonical file executes TWICE on every shell startup: every
unmanaged PATH export inside it duplicates, and every other side effect it carries runs twice.
The managed PATH block is immune (that is what plan 15.8-01 bought), but the user's own content
and the copied-forward foreign content are not. So: when an rc already live-sources `~/.shellrc`
and `~/.shellrc` is this project's stub, skip `ensure_source` for that rc and remove this
project's own source block if an earlier run left one. One route, chosen deterministically.

The earlier revision of this plan tested only by sourcing `~/.shellrc` or `~/.myshellrc`
directly, which is exactly the topology that hides this bug. Task 1 adds a real-shell test that
starts from a `.bashrc` sourcing `.shellrc` and counts executions with a variable inside the
copied content.

**Why split mode is skipped.** In split mode this project writes the managed block directly into
each rc file and deliberately maintains no `~/.myshellrc` indirection (`installer/app.py:207-212`).
Consolidating a foreign file into a file nothing sources would move the user's content somewhere
less reachable while reporting success. Skip it, silently, and record the reason in a comment —
this is a deliberate scope decision, not an oversight for a reviewer to flag.

**Why a refusal must be a typed raise and not only a printed line (review MEDIUM-04).** Doctor's
apply route (`setup.py:998-1012`) hands `configure_path` a `Console(file=io.StringIO())` — a
deliberate quiet console, so `configure_path`'s prints cannot corrupt the running TUI — and
discards the buffer. `installer/wizard_app.py:597-601` then does
`_, self.error = run_live(self._fix)` and `self.applied = self.error is None`. The RESULT of
`run_live` is discarded, so returning a refusal does not reach the screen either. A refusal
printed into that sink and returned as data would render as a green "PATH wired." — exactly the
outcome this phase says must never happen. So `_apply_fix` raises a typed `ShellrcRefusal` (plan
15.8-04 defines it) AFTER `configure_path` returns, and `run_live` is widened by one entry to
catch it. The PATH block has already been written at that point, which is correct: the wiring
succeeded, the consolidation did not, and the message says so.

**Host-safety rule, and why this plan carries the most of it.** This is the plan that introduces
a module-level constant derived from the REAL `Path.home()`. `~/.shellrc` does not exist on this
machine, so the production path is a no-op here — but that is luck, not isolation. Every test
that redirects `setup._MYSHELLRC` must redirect `setup._SHELLRC` in the same place, and Task 2
finds them all rather than assuming `_sandbox` is the only one. No task in this plan runs
`make setup`, `make fix` or `make uninstall` against this machine. `make doctor` is a read-only
report and is allowed.

`No tests collected` line on a green run. Re-run as `rtk proxy uv run pytest <args>` or
`.venv/bin/pytest <args>` to read the real result.

Add the single-route rule to the centralized/single branch. Replace the bare `ensure_source` loop
with one that, per rc path, first decides the route:

- When the consolidation outcome exists AND its status is consolidated or already — meaning
  `shellrc_path` now carries this project's stub — AND `shellrc.sources_file(<rc text>,
  shellrc_path)` answers `"yes"`, then this rc ALREADY reaches `~/.myshellrc` through the stub.
  Call `shellrc.remove_source_block(rc_path)` so a block left by an earlier run does not duplicate
  the route, and do NOT call `ensure_source` for this rc.
- When it answers `"unprovable"`, take the ORDINARY route — call `ensure_source` as today — and
  print one diagnostic line naming the rc file and saying it contains a source command this tool
  could not resolve, so if that line reaches `~/.myshellrc` the canonical file may run twice and
  the user should remove one of the two routes.
- Otherwise (`"no"`, or no consolidation outcome, or a status of absent/refused) call
  `ensure_source` exactly as today.

Handle all three answers explicitly — a `match` or an if/elif chain over the `Literal`, never a

not catch that; write the comparison against the literal values and let an unhandled member fail
the exhaustiveness check.

Read each rc file's text once for that decision (empty string when missing). Do not add a second
source detector — `sources_file` is the one predicate, deliberately broader than plan 15.8-05's
rewriter, and this is the caller its docstring names.

Put a comment at that branch stating the failure mode it prevents and the two it accepts. Without
it, a `.bashrc` that sources a generic `.shellrc` would execute the whole canonical file twice per
startup once the stub exists. Accepted residual one: because `sources_file` answers "is there a
live source command for this file" rather than "will it actually run", an rc that sources
`.shellrc` only inside a condition that never holds ends up with no route at all — judged far less
likely and far more visible than the duplicate execution it prevents, since Doctor's own audit

so an rc that reaches `~/.shellrc` through an unresolvable source command gets a second route —
and the diagnostic line is what makes that visible. Name the reason `unprovable` is NOT treated as

treating them as "already wired" would leave PATH unwired for most users, trading a risk for a
certainty.

Print one line when the single-route rule fires, naming the rc file and saying it reaches
`~/.myshellrc` through `~/.shellrc`. Silence here would make an unwired PATH undiagnosable.

Put a short comment at the split-mode condition recording WHY split is skipped: split mode
maintains no `~/.myshellrc`, so consolidating into it would relocate the user's content into a
file nothing sources while reporting success. A future reader must be able to tell this apart
from a missed case.

Do not catch `OSError` here. `installer/ui_common.py::run_live` (rule 3) is what surfaces IO
failures from screens, and the CLI paths already let them propagate — adding a local
`try/except` would make this the one PATH-wiring failure the user never hears about.

Update the docstring to state the new responsibilities in two sentences: the consolidation with
its split-mode carve-out, and the one-route-per-rc guarantee.
