<objective>
Turn 15.8-RESEARCH.md's live finding — that `installer/rcclean.py` needs no change once
`managed_block()` emits the guarded form — into a permanent, executable gate, and pin the
opposite direction at the same time so the cleanup path cannot silently degrade into a no-op.

Purpose: D-03's Claude's-Discretion clause requires that the new shape stays recognized as
self-deduping by this codebase's own duplicate-line scanner ("don't invent a shape `rcclean.py`
doesn't already know to skip"). Research verified this live by calling the real function; this
plan makes it a test so a future emitter change that collapses the guard into a leading
assignment fails the suite instead of quietly making `make fix` strip this project's own lines.

Output: new regression tests in `tests/test_rcclean.py`. No production code changes at all —
`installer/rcclean.py` must be byte-identical after this plan.

**Shape note (cross-AI review round 1).** Plan 15.8-01's emitted line changed during this
revision: the value now reaches PATH through a conditional expansion and the guard reads PATH
through a default-applying expansion (review MEDIUM-02 — a bare colon join left an empty PATH
component, which every POSIX shell resolves as the current working directory). That change was
re-checked against the real `find_duplicate_path_lines` this planning session — no findings for
the new line alone, none for the same line indented, and still exactly one finding for a plain
unguarded export of the same directory placed beneath it. Nothing in this plan needed to change
as a result, because every test here derives its rc text from the real emitter rather than from a
copied literal. That is precisely the property this plan exists to have: the shape moved and the
tests followed it for free.

**Why this is a plan and not a footnote.** The failure mode being prevented is not theoretical:
`find_duplicate_path_lines` feeds `strip_lines`, which DELETES lines from a user's `.bashrc` /
`.zshrc`. If a future shape change made this project's own guarded block match `_PATH_EXPORT`,
the cleanup path would start deleting the very lines this phase adds — an installer that removes
its own PATH wiring. One test is cheap; that outcome is not.

**RTK note (this host).** `uv run pytest ...` output is condensed here and can render as a false
`No tests collected` line even on a green run. Re-run as `rtk proxy uv run pytest <args>` or
`.venv/bin/pytest <args>` to read the real result. Never edit a test in response to that line.

**Host-safety rule.** No task here writes to the real `~/.myshellrc`, `~/.bashrc`, `~/.zshrc` or
`~/.shellrc`, and none runs `make setup`, `make fix` or `make uninstall`. All rc text in this
plan is an in-memory string or a `tmp_path` file.

**Concurrent-wave note.** Plan 15.8-03 runs in this same wave and is editing
`installer/shellrc.py` while this plan's tests import from it. If a run here fails on an IMPORT
or COLLECTION error inside `installer/shellrc.py` — rather than on an assertion — that is
15.8-03's in-flight edit, not a defect in this plan. Re-run once 15.8-03 reports done. Never
"fix" `installer/shellrc.py` from this plan: this plan changes no production file at all, and a
repair made from here would land on top of a half-applied deletion.
