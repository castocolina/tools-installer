# 15.8-05 — the conservative classifier, the narrow rewriter, and the loop proof

## What shipped

**Task 1 — the classifier.** One private line classifier produces all three
verdicts (`none` / `rewritable` / `ambiguous`), so detection and rewriting cannot
drift apart. Detection is deliberately much wider than the rewriter: the command
word is normalized before matching (so `sour\ce` and `'source'` are seen), the
`command`/`builtin` wrappers and their options are skipped, a dynamic command
word whose argument resolves to the target refuses, and both sides are compared
through `os.path.realpath` so a symlinked-home spelling is not copied forward
into a self-source. Three blanket file-level refusals close what no string rule
can judge: any here-document opener, any live `eval`, and any live `.`/`source`
whose argument is not statically resolvable.

**Task 2 — the rewriter and the two helpers plan 15.8-06 consumes.**
`consolidated_body` replaces the single certified-rewritable shape with a comment
carrying a reason plus the line's original text — disabled, never deleted (D-04)
— and alters nothing else. The rewrite applies to the COPY only; the backup is
still written from the step-4 snapshot, so one-`mv` reversibility is unchanged.
`sources_file` answers `yes` / `no` / `unprovable`, and `remove_source_block`
mirrors `remove_managed_block` exactly, atomic write included.

**Task 3 — real shells.** The 30s timeout is the assertion.

## Verification

**Differential check against real shells (orchestrator-run, beyond the plan).**
25 adversarial line shapes were classified and then actually sourced in bash, zsh
and `/bin/sh`. **Zero lines that a real shell sources are classified `none`** —
that is the loop-producing direction, and it is clean. Checked in the other
direction too, over 12 ordinary rc lines: the only non-`none` verdict is
`source "$ZDOTDIR/foo"`, which is the documented unresolvable-argument refusal,
not a false positive.

Two incidental facts the check turned up, both recorded in test comments:
`command source` executes under bash and `sh` but **not** zsh (zsh's `command`
does not run builtins), and `. "$HOME"/.myshellrc` — the split-quoted form —
is correctly caught as ambiguous.

**The loop is real, and worse than a hang.** Neutralizing `consolidated_body` so
content copies forward verbatim (what 15.8-04 did) and sourcing the result made
bash die with **SIGSEGV (`rc: -11`)** from stack exhaustion. Research A1 marked
this case `[ASSUMED]`; it is now demonstrated. A user hitting it would have their
shell crash at login, not merely hang. With the rewriter: exit 0, content runs
once, managed dir on PATH once.

`make validate` exit 0; `make test` 3088 passed, 5 skipped, 96.06% coverage.

## Deviations and issues

**The configured cross-AI backend went down mid-phase (ONESHOT-RULES.md Rule 12).**
`opencode run --model router-env/my-coding` failed on two dispatches of this plan
*and* on a one-line `PONG` health probe, all with `Service temporarily
unavailable due to resource pressure` — a backend outage, not a prompt problem.
This is the fourth transient cross-AI failure recorded in this phase. Rather than
drop straight to the direct executor, the orchestrator substituted the other
genuine cross-AI lane: **codex**, whose usage limit from the previous day had
reset. It ran sandboxed at `workspace-write`.

**Codex was stopped deliberately after Task 1.** Its sandbox runs `pyright`
outside the uv venv, so it saw phantom errors (`Import "pytest" could not be
resolved`, `Import "rich.console" could not be resolved`) that no code edit can
fix, and it had begun iterating against them; it then hit `Could not acquire
lock`. Since cross-AI could not run this project's type gate, it had
demonstrably failed for this plan, and Tasks 2 and 3 were completed directly.
Re-running the same gates properly through `uv` showed Task 1's work was in fact
**0 errors, 0 warnings** — every reported error was an artifact of the sandbox.

**A pre-existing gate bypass was retired.** `tests/test_shellrc.py` carried
`# pyright: ignore[reportUnusedFunction]` on `_source_n_times`, committed back in
plan 15.8-01 by the earlier cross-AI executor because nothing used the helper.
Task 3 is what uses it, so the suppression was removed by making the code honest
rather than by widening a gate. Worth noting that this slipped through four
plans' worth of green `make validate` runs — the gate cannot catch a suppression
that was committed with the code it silences.

**No host mutation.** Every shell in every test runs with `HOME` under
`tmp_path`. The real `~/.bashrc`, `~/.myshellrc`, `~/.zshrc` and `~/.profile`
were re-checked mid-plan and carry mtimes predating this session; no `~/.shellrc`
or `*.tools-installer.old` exists. `make setup` / `make fix` / `make uninstall`
were never run.
