<objective>
Close the half of D-02's "no site left behind" that lives in shell scripts rather than in Python:
convert the two plain PATH exports `scripts/container-e2e-verify.sh` writes into a container's rc
files to the same self-deduping guarded form this phase emits everywhere else, and install a
repo-level scan so a shell script cannot reintroduce the shape unseen.

Purpose: D-02 requires that no known site is left carrying the plain-export defect. D-03 fixes the
shape. Plan 15.8-03's invariant parses Python, so it is structurally incapable of seeing a `.sh`
file — and two live instances of exactly the defect this phase exists to kill were sitting in
`scripts/container-e2e-verify.sh:152,158` the whole time.

Output: a fixed `scripts/container-e2e-verify.sh`, and a new `tests/test_shell_scripts_path.py`
holding the shell-side invariant plus the real-shell proof.

**The defect, stated precisely.** `write_tester_path()` appends
`export PATH="$HOME/.local/bin:$PATH"` to the container user's `~/.bash_profile` AND `~/.bashrc`.
The surrounding `grep -q ".local/bin"` makes the FILE idempotent — the line is written once. It
does nothing for the RUNTIME effect: `su - tester` is a login shell that reads `.bash_profile`,
which on Fedora sources `.bashrc`, and any nested shell reads `.bashrc` again. Every re-source
prepends another copy. This is the same bug, with the same cause, in the same repository, one
directory away from the Python fix. The user verified it before forwarding the finding.

**What is NOT being converted, and why — read this before touching anything.** Three other
accumulating PATH lines exist in this repo's shell scripts and all three stay exactly as they are:

- `install.sh:60` — `PATH="$HOME/.local/bin:$PATH"` inside the curl|bash bootstrap, in the branch
  taken when uv's own `env` file is absent. It sets PATH for the remainder of THAT script's
  process. Nothing sources `install.sh`.
- `scripts/container-e2e-verify.sh:178` (`sync_workspace`) and `:239` (`run_setup_as_tester`) —
  `export PATH=...` inside a command string handed to `su - tester -c`. Each runs once, in a
  fresh process, to make `uv` reachable for the command that follows. Nothing sources them.

The property that puts all three outside the invariant is the same one that puts
`installer/executors.py::_path_prefix` outside plan 15.8-03's Python needle: a PATH assignment
evaluated once per process, in a script or command string no nested shell re-sources, cannot
accumulate across nesting levels. It may add one duplicate within its own short-lived process;
that costs nothing and is invisible. **The line between the two groups is "does a nested shell
re-source this file", not "does this line contain a prepend"** — and that is why the two container
rc appends ARE converted while the two container command prefixes are not. Record that reasoning
in the classification table, not only here.

**How the guarded line gets into the container script without an escaping nightmare.** The current
appends use `printf "%s\n" "…\"…\$…\""` inside a host-side single-quoted payload, so the guard's
quotes, `$`, `;;`, `|` and `*)` would each need escaping twice. Do not go down that road. Use a
here-document with a QUOTED delimiter instead, whose body is literal in every shell:

```
  if ! grep -q ".local/bin" ~/.bash_profile 2>/dev/null; then
    cat >> ~/.bash_profile <<"TI_PATH_GUARD"
  ...the guard line, verbatim, no escaping at all...
  TI_PATH_GUARD
  fi
```

The delimiter must be double-quoted (`<<"TI_PATH_GUARD"`), not single-quoted: the whole payload is
already inside a host-side single-quoted string, so an inner `'` would terminate it. A
double-quoted heredoc delimiter disables expansion identically. **Verified live this planning
session**: this exact construction, run three times against a `tmp_path` HOME, wrote the guard
line once; sourcing the result five times under bash 5.3.9, zsh 5.9.2 and this host's `/bin/sh`
left exactly one copy of the directory on PATH each time.

**RTK note (this host).** `uv run pytest ...` output is condensed here and can render as a false
`No tests collected` line on a green run. Re-run as `rtk proxy uv run pytest <args>` or
`.venv/bin/pytest <args>` to read the real result. Never edit a test in response to that line.

**Host-safety rule.** No task writes to the real `~/.myshellrc`, `~/.bashrc`, `~/.zshrc`,
`~/.bash_profile` or `~/.shellrc`, and none runs `make setup`, `make fix` or `make uninstall`.
Every shell this plan spawns gets `HOME` pointed at `tmp_path`. **No task in this plan runs
`scripts/container-e2e-verify.sh` itself** — its `bootstrap`/`pass1`/`pass2` commands create a
Fedora container, install packages and run the full installer. The proof here extracts the two
append STATEMENTS from the file and runs those, never the script.
