## Objective Complete ✓

Turned the live finding from 15.8-RESEARCH.md — that `installer/rcclean.py` needs no change once `managed_block()` emits the guarded form — into a permanent, executable gate, and pinned the opposite direction so the cleanup path cannot silently degrade.

## Tasks

### Task 1: Pin that this project's own guarded output is never flagged — COMPLETED
**Files**: `tests/test_rcclean.py`

#### Implementation
All new tests derive their rc text from the **real production emitter** (`managed_block()` and `path_export_guard()`), not from hand-copied fixtures. This ensures future shape changes are caught immediately.

#### Tests Added
- `test_managed_block_own_output_is_not_flagged()` — Real `managed_block()` output unflagged inside markers
- `test_guard_lines_are_not_flagged_outside_our_markers()` — Regex alone recognizes guard form (markers not required)
- `test_indented_guard_line_is_not_flagged()` — Guard line with leading whitespace stays safe
- `test_guard_line_for_an_unmanaged_dir_is_not_flagged()` — Self-deduping even for unmanaged directories
- `test_the_two_pattern_guard_form_is_not_flagged()` — Two-pattern aliased directory guard unflagged

**Key property**: Each test builds rc text by calling the real emitter, so the test follows the shape automatically if the emitter changes. A hand-copied fixture would pass after a breaking shape change and is exactly what this plan exists to prevent.

### Task 2: Pin the opposite direction — other tools' plain exports are still flagged — COMPLETED
**Files**: `tests/test_rcclean.py`

#### Tests Added
- `test_plain_export_for_a_managed_dir_is_still_flagged_alongside_our_guard()` — Critical: proves the two shapes are distinguished, not that everything stopped being flagged. File with both guarded and plain export flags only the plain export.
  - Builds rc text as a list and records the plain export line index dynamically (not hard-coded)
  - Verifies `result == [plain_export_line_index]`

- `test_pnpm_case_guard_and_our_guard_are_both_skipped_in_one_file()` — Two independent self-deduping guard forms coexist safely

**Key property**: The first test is the single most important assertion in the entire plan. It directly addresses the threat (T-15.8-05): if a future change to the emitter made this project's own guarded block match `_PATH_EXPORT`, the cleanup path would start deleting this project's own lines, creating an installer that removes its own PATH wiring. This test ensures that outcome fails the suite loudly instead of silently deleting user PATH entries.
