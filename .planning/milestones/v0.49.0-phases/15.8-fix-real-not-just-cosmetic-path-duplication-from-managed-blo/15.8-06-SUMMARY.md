# 15.8-06 — wiring, the single-route rule, and the phase's doctrine

## What shipped

**Task 1 — `configure_path` runs the consolidation.** It takes `shellrc_path` and
returns the outcome. Consolidation runs BEFORE the managed block is written, so
the copied content lands while the block layout is still whatever the previous
run left and the managed block ends up last. Split mode is skipped: it maintains
no `~/.myshellrc`, so consolidating into a file nothing sources would relocate
foreign content while reporting a false success.

The single-route rule: when an rc already reaches `~/.myshellrc` through this
project's `~/.shellrc` stub, its own source block is removed rather than left
duplicating the route. `unprovable` is deliberately NOT treated as `yes` — those
take the ordinary route and print a diagnostic.

**Task 2 — four call sites, and the isolation that makes them safe.** `_SHELLRC`
is passed at every `configure_path` call site. On the Doctor route the outcome is
inspected and a refusal raised as `ShellrcRefusal`, which `run_live` now catches
alongside `OSError` and `CommandError`.

**Task 3 — `.claude/architecture.md`** gained a Phase 15.8 section covering all
seven invariants in the file's existing prose voice.

## Verification

Every claim below was checked against the tree, not taken from the plan.

**The phase's premise, demonstrated.** Neutralizing the single-route rule
(`sources_file` forced to `no`) and sourcing a `.bashrc` that sources `.shellrc`
makes the copied content run **twice** (`__SHELLRC_RUNS = 2`); the committed test
asserts 1. The managed directory stays on PATH exactly once even in that broken
state — plan 15.8-01's guard doing its job. That is the division of labour the
plans claimed: the guard protects OUR block, the single-route rule protects the
USER's content.

**The refusal path, demonstrated.** Removing `ShellrcRefusal` from `run_live`'s
except tuple makes the wizard test fail with an uncaught exception rather than
pass quietly, so the widening is load-bearing.

**The home guard, demonstrated.** Pointing its fingerprint at a scratch
directory, it detects a dotfile mutation, a newly created `~/.shellrc`, and a
backup sibling appearing while every dotfile is otherwise unchanged.

**Task 3's factual claims, each verified before writing:** `grep -n
"write_text(" installer/shellrc.py` returns only `atomic_write_text` calls, so
the durability rule is written as the rule it now is; `PNPM_HOME` is only ever
READ (`installer/ownership.py:446`), so the gap is recorded as pre-existing and
still open; and the shell-script scan's classification table holds exactly three

## Deviations and issues

**Two defects found in the cross-AI draft of Task 1, fixed before committing.**

1. *`assert` used for control flow in production.* The draft narrowed the refusal
   message with `assert message is not None`. These were the only two asserts in
   `installer/`; bandit rates them Low and **exits 0**, so `make validate` does
   not catch them. Under `python -O` they vanish and a refusal would
   `console.print(None)` — printing the literal word "None" on the one path whose
   entire job is making a refusal impossible to mistake for success.
2. *The refusal message claimed the PATH block "was written" but printed before
   the write.* An exception in between would have told the user about a write
   that never happened. It now prints after the writes.

The draft also had not run the gates: ruff import order, an E501, an unnarrowed
`Path | None` into `sources_file`, and an untyped lambda. All fixed at the root,
nothing suppressed.

**H1 — test isolation was opt-in, and is now structural.** `setup.py` resolves
its path constants at IMPORT time, so `monkeypatch.setenv("HOME", ...)` does not
redirect them; each must be patched by name, and `tests/conftest.py` had no
autouse HOME sandbox. `_SHELLRC` is now redirected at all three sites that
redirect `_MYSHELLRC`, but patching-by-name is a guarantee a future test
eventually forgets — one un-redirected constant reaching `configure_path` would
consolidate the developer's own `~/.shellrc` and leave a backup behind. A
session-scoped autouse fixture now fingerprints the real home's shell files and
fails the run if any test changed one. This was raised by the orchestrator before
Task 2 ran, not found by an agent.

Worth recording plainly: this had not bitten only because this host has no
`~/.shellrc`, so `consolidate_shellrc` returns `absent`. That is luck, not
safety.
