<objective>
Make the Uninstall screen tell the truth about who owns each tool: surface the rich hint
`uninstall.py` already computes, and feed that hint from the shared ownership resolution the
catalog already ran, so pnpm/uv/dnf/apt/pacman/rpm-ostree/cask/OS-package/SDKMAN tools are
named instead of collapsing into one generic sentence.

Purpose: `_tool_entry` discards `ToolRow.hint` for a four-value enum lookup (D-03), and
`_manager_hint` only knows brew and cask, so every other manager falls through to
"managed outside this installer" (D-04). Both surfaces must stay fresh on the same trigger
Phase 15.1 established (D-05).
Output: one removal-hint vocabulary, one injected seam, one changed table cell — and the
verified package name kept alive from the probe that resolved it to the command the user
reads, so a split package like `ripgrep` or `git-core` is never rendered as the tool's own
command.
</objective>

  <action>
    Addresses Round-3 review HIGH. A removal phrase is only as truthful as the package name it
    is built from, and today that name is computed inside the native probes and then discarded,
    so the three layers below are one change: capture it, propagate it, and refuse to print a
    command without it.

    **Probe layer (`installer/install_ownership.py`) — capture what was verified.** Add a
    fourth field `package: str | None = None` to the `Ownership` dataclass, defaulting to
    `None` so `_UNKNOWN` and every existing construction stay valid and no unrelated probe has
    to change. Give each of the four native probes — `_dnf`, `_apt`, `_pacman`, `_rpm_ostree`
    — the matched package name in the record it returns. Each one already has that name in
    hand: it is the loop variable of the `_method_values` scan that just matched, and it is
    already interpolated into the detail string. Do not reconstruct it from the detail text.

    Write on the field why it exists: the detail string is prose for a human, and a removal
    COMMAND built by parsing prose is a command built on a formatting accident. A caller needs
    the name as data, and the probe is the only layer that knows which of several declared
    names the database actually answered for.

    Populate the field in the non-native probes only where it is trivially the value they
    already matched (`_brew`, `_pnpm`, `_sdkman`); leave `_managed_download` and `_host_setup`
    at `None`, and state in a comment that no downstream caller builds a native removal command
    from those two, so an absent name there is correct rather than a gap. Change no probe's
    manager, confidence, detail text or control flow — this task adds a field, it does not
    retune attribution.

    **Resolver layer (`installer/ownership.py`) — propagate it.** In `_native_owner`, replace
    the hard-coded `package=None` in the synthetic `OwnershipCandidate` (`ownership.py:479-483`)
    with the real name, resolved in this order:
    - when `active_path` is not None, prefer `path_owner_package(platform.os, str(active_path),
      probe)` — plan 15.4-01 T1's inverse query, which asks the manager's own database which
      package owns THIS file and needs no caller-supplied candidate. It is the authoritative
      answer for the binary the user actually runs, and it is already imported into this module
      by 15.4-01;
