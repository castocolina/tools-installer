<objective>
Make the doctor's per-tool status text distinguish a redirect from a hard block, and
state the volta security tradeoff where a user will actually read it — without changing
`guard_status()`'s return shape or any call site that assumes a plain bool.

Purpose: D-02 and ROADMAP SC#6. Plans 04-01 and 04-03 put the label text in
`installer/guards.py::guard_label`; this plan is where it reaches the two renderers.

Decisions implemented:
- D-02: the doctor UI's per-tool label text is what distinguishes a redirect from a block; `guard_status()`'s `{name: bool}` return shape is unchanged, no status enum is introduced, and no call site that assumed a plain bool has to change.
- D-07: the recorded Volta-shells-out-to-npm finding reaches the copy a user actually reads, stated as the verified mechanism rather than a vague caveat.

Output: a rewritten `guard_guidance` in `installer/guidance.py` plus the updated
assertions in the four test modules that pin its wording.
</objective>

    `status.get("pnpm", False)` is True.

    Why that predicate, and it must be stated in a comment: plan 04-03's
    `install_global_redirect_shims` writes the pnpm wrapper only when volta actually
    resolved, so a live pnpm shim is the one honest on-disk signal that global installs
    are being routed to volta rather than falling back to the hard block.

    `volta install` runs a real `npm install --global` subprocess with no flag that
    disables install scripts, so packages installed that way run their own

    allowlist since pnpm v10. This is the tradeoff accepted in exchange for pnpm's
    global-package loss on self-update. Severity is `Severity.OK`, not a warning: this is
    a standing property of an accepted design choice, and a permanent warning on every
    healthy machine would train the user to ignore the doctor.
