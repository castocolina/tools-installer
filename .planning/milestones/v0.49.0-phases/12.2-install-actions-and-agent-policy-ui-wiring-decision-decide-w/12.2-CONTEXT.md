<decisions>
## Implementation Decisions

### install_actions.py disposition
- **D-01:** Retire `installer/install_actions.py` and its test entirely —
  **Reversibility:** reversible — it's in git history if ever needed again.
  Origin's own `installer/omz.py` (Oh-My-Zsh plugin config) and
  `installer/daemon.py`/`executors.py` (pnpm/node managed setup) already
  cover, with more review cycles (12 GSD phases), the concrete cases this
  module used to serve in local's older UI. Keeping both would be two
  competing implementations of "managed setup" for the same problem.
- **D-01a:** Do NOT write a standing documentation entry (architecture.md,
  REQUIREMENTS.md, etc.) about the retired module — a clear commit message
  explaining why is sufficient. Documenting something that no longer exists
  in the codebase was explicitly rejected by the user ("documentar algo que
  ya no vale es como guardar el perfume de la ex").

### agent_policy.py disposition
- **D-02:** Leave `installer/agent_policy.py` (plus its dependencies
  `agent_env.py`, `agent_guidance.py`) dormant — valid, tested code, but not
  wired into origin's UI. **Reversibility:** reversible — no UI surface
  exists yet to design around, so nothing to unwind later.
  Unlike install_actions.py, origin has no equivalent mechanism for
  auditing/editing the `AGENTS-TOOLING.md` shared guidance block. But this
  project's own reconciliation PRD
  (`docs/prds/branch-reconciliation-tui-interaction-consistency-v1.0-prd.md`)
  already recorded a backlog item to retire that global file once its
  responsibility moves to `../ai-kit` — wiring it into the UI now risks
  throwaway work.
- **D-02a:** A brief inline note on the module is acceptable (it's not
  retired, just unused) but no separate architecture-doc section — same
  "don't document what has no home yet" principle as D-01a, applied more
  lightly since the code itself still exists and is real.

### UI wiring location
- **D-03:** Not applicable — neither module gets wired into the UI in this
  phase, so there's no "where in the Policies view vs. separate surface"
  decision to make. Explicitly skipped by the user.

### Phase scope
- **D-04:** The plan for this phase does exactly two things: (1) delete
  `installer/install_actions.py` and its test file, (2) run
  `make validate && make test` afterward to confirm no orphaned import,
  dead-code (vulture), or coverage-floor regression from the removal.
  `agent_policy.py` needs no code change — it already compiles clean as
  dormant code (confirmed during Phase 12.1's ported-but-unwired hygiene
  check). No UI code, no new tests beyond confirming the gate stays green.

### Claude's Discretion
- None outstanding — all four decisions are locked.

</decisions>
