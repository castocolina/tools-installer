<objective>
Plan 01 makes a buffering child stream where it can. Some children still will not: a statically
linked binary doing its own buffering, a host with no `stdbuf`, a step that is genuinely slow before
it prints anything. In all of those the user sees the same thing they see for a hung process — an
empty log — with no way to tell the two apart.

This plan removes that ambiguity. After 2 seconds with no new line from the in-flight tool's stream
(D-06), `ExecuteScreen` writes one clearly-marked transient line into that tool's own region of the
existing live log (D-07), attributed to that tool and not to the batch (D-08). It is superseded the
moment real output arrives, and it never enters the bounded tail that becomes a failure report.

Purpose: silence stops being ambiguous. A user watching a two-minute `pnpm add -g` knows the
installer is waiting on the child rather than wondering whether to press ctrl+c.

Output, symbol by symbol:
- `installer/execute_screen.py`: module constants `SILENCE_SECONDS`, `_WAITING_OUTPUT`,
  `_UPDATE_STARTED`; a `now: Callable[[], float]` field on `ExecuteInputs`; keyword-only `transient`
  and `generation` parameters on `InstallLogLine.__init__`; `ExecuteScreen` state `_in_flight`,
  `_last_output_at`, `_silence_noted`, `_silence_generation`, `_silence_timer`; methods
  `_note_output`, `_clear_in_flight`, `_arm_silence_timer`, `_check_output_silence`,
  `_transient_is_current`; one new `post_message` in `_run_updates`; and extensions to
  `action_start`, `on_install_log_line`, `on_install_tool_finished`, `on_update_tool_finished`,
  `on_prompt_open` and `on_install_run_finished`.

    no line and no status change. The indicator is posted asynchronously from the event loop while the

    Add `def _arm_silence_timer(self, delay: float) -> None` assigning
    `self._silence_timer = self.set_timer(delay, self._check_output_silence)`. One place creates the
    timer, so the callback and the delay cannot drift apart between call sites.

    Add `def _check_output_silence(self) -> None` shaped as a one-shot that re-arms itself, NOT as a
    poll body. Begin by setting `self._silence_timer = None` (the timer that just fired is spent).
    Then:

    - If `self.finished`: return without re-arming. The run is over; nothing should outlive it.
    - Read `self._in_flight` and `self._last_output_at` into locals. If either is None, or
      `self._waiting_prompt is not None`, or `self._silence_noted` is True: re-arm for
      `SILENCE_SECONDS` and return. Nothing is reportable NOW — nothing attributably in flight (D-08
      forbids naming anything), or the pause is a question the status line already explains, or this
      gap has already been reported — but the run continues, so the watch must continue. A bare
      return here is the bug that silently stops the indicator for the rest of the run.
    - Compute `elapsed = self._inputs.now() - last_output_at`. If `elapsed < SILENCE_SECONDS`: re-arm
      for `SILENCE_SECONDS - elapsed` and return. This is the branch that buys exactness — a line
      arrived after this timer was armed, so instead of waiting out another whole window the screen
      sleeps precisely the distance still to run and fires AT the threshold.
    - Otherwise set `self._silence_noted = True`, post
      `InstallLogLine(in_flight, _WAITING_OUTPUT, transient=True, generation=self._silence_generation)`,
      and re-arm for `SILENCE_SECONDS`.

    Reading `self._in_flight` into a local before the guards and posting that local is what lets
    pyright see a narrowed `str` with no `assert` and no cast.

    Note what this design does NOT do: it does not stop and recreate the timer on every real log line.
    Re-arming per line would be exact too, but a 500-line burst from a chatty installer would create
