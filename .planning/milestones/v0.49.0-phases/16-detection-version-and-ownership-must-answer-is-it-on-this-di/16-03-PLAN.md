Make `rcclean`'s writer diagnosis classify correctly before plan 16-08 builds a WRITE action on it.
This plan fixes 15.8-REVIEW.md findings CR-01 (critical), WR-01, WR-02, IN-01 and IN-03.

Purpose: D-21 offers to rewrite foreign PATH lines that `unguarded_path_writers` names. Today that
scanner has two failure modes:
- It names correctly guarded `if` lines as "unconditional", a reproduced false positive. Acting on
  it would rewrite a correct line.
- It misses trailing-slash, trailing-comment, `;`, `&&` and zsh `path=(...)` writers, a reproduced
  false negative.
Building a write path on a misclassifying scanner would turn a wrong diagnosis into a wrong edit.

Output: a quote-aware shared PATH-line generator, guard-context tracking, Path-normalized matching,
and the extra shapes, each pinned by a test. The strip set (`find_duplicate_path_lines`) stays
exactly as conservative as it is today.

Host-safety rule: no task may write to the real `~/.bashrc`, `~/.zshrc`, `~/.profile`,
`~/.bash_profile`, `~/.shellrc` or `~/.myshellrc`. Every test uses in-memory text or `tmp_path`.

Output harness note: if `uv run pytest` prints a false "No tests collected", re-run via `.venv/bin/pytest`.

It also keeps a block stack of frames `(closer, references_path)`, updated per line in this fixed order BEFORE the line's own PATH targets are judged:
