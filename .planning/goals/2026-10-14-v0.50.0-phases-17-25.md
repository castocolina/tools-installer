/gsd-autonomous --from 17 --to 25 --converge

OBJECTIVE
Finish tools-installer v0.50.0 "Truthful lifecycle", Phases 17 to 25 including 24.1. Each phase must be verified, delivered with tested quality, reviewed for reuse, and left clean.

ROLE
You are the orchestrator. Dispatch plan work as GSD routes it. Verify every result yourself: never accept a reported "passed", re-run the gate.

STEP 0 (once, before Phase 17)
1. Run `codegraph sync`. If there is no index, run `codegraph index || codegraph init -i`.
2. Refresh the codebase intel (`.planning/intel/`) with `gsd-intel-updater` / `/gsd-map-codebase`. Each mapping or intel agent must start with `codegraph sync`, then use the `codegraph_explore` MCP tool (`projectPath` = repo root) for every search, before Grep/Read. Restate this inline in each agent prompt.
3. Quality gates:
   - Confirm `.git/hooks/pre-commit` exists. If not, run `pre-commit install`.
   - Run `pre-commit run --all-files`; it must pass.
   - Add a `make e2e` target that wraps `scripts/container-e2e-verify.sh` (bootstrap → pass1 → pass2, Fedora; `DISTRO=` from Phase 24 D-14), and run it once green on the current tree. Record the runtime used (Rule 14).
4. Probe each external CLI once and record the result. Never substitute a model:
   - The cross-AI executor: `.planning/config.json` `workflow.cross_ai_command`. Read it live.
   - The plan reviewer: `review.default_reviewers`.
   - The codex code-review lane (Rule 15). Its banner must confirm the model and high effort.
   - Laya `http://127.0.0.1:8010/v1/systemone` and TypeSafe.

RULES FOR EVERY PHASE
- Read AGENTS.md, `.claude/*.md`, then the phase SPEC and CONTEXT. Their decisions are locked; never re-discuss them. Amendments dated 2026-10-14 are part of the lock.
- Run `codegraph sync` at phase start and after every wave. Every planner, executor and reviewer uses `codegraph_explore` before Grep/Read. Restate this inline in every cross-AI prompt.
- PLAN
  - Every PLAN.md frontmatter carries `cross_ai: true`; add it if the planner omitted it.
  - Ponytail reuse pass, before review convergence: run Skill ponytail (ultra) over each PLAN.md. Every new function, module or class names the existing helper it reuses, or says why none fits, with `codegraph_explore` evidence.
    - Remove tasks the SPEC does not require.
    - Collapse duplicate helpers.
    - Prefer the codebase's own pattern, then the stdlib, then an installed dependency.
    - Revise the plan on any gap.
  - Every new method kind, executor or resolver rank ships with its tests in the same plan (Rule 7).
- EXECUTE
  - Cross-AI only, via `workflow.cross_ai_command`. A per-plan fallback to `gsd-executor` is allowed only after a recorded failure.
  - Tests come first for new logic. Every test runs in an isolated HOME (`tmp_path`) and must be xdist-safe (`.claude/testing.md` "Parallel by default"). A test that fails only under `-n auto` is a bug to fix, never a reason to go serial. This applies most to the test-heavy phases 19, 20, 21, 22 and 24.
  - Commits pass the pre-commit hook. Never use `--no-verify`.
  - Keep implementation, tests and docs of one change in one commit.
- QUALITY GATE at every wave and phase close. Run each yourself on the exact tree:
  - `make validate`
  - `make test`: parallel `pytest -n auto`, ≈50 s. Keep it out of pre-commit. Run it twice at phase close to catch order or isolation flakes.
  - `pre-commit run --all-files`
  - `make e2e`, for any phase touching executors, removal, receipts, config writers, shellrc, or the registry (19, 20, 22, 23, 24, 24.1 at minimum).
  - Real-machine effects go only into disposable containers (Rule 14).
- CODE REVIEW: three lanes over the same base..head, in parallel:
  1. `gsd-code-reviewer` (deep).
  2. The codex lane (Rule 15).
  3. Skill `ponytail:ponytail-review` over the phase diff: logic, safety, edge cases, and code that should not exist.
  Fold every Critical, High or Important finding into one fix loop, test first, then re-review. Record which lane raised each finding.
- TUI phases (17, 20, 21, 23, 25 at least; re-check against ROADMAP): exercise the real `uv run setup.py` in tmux with `capture-pane` text checks. Navigation only: never press a key that installs, uninstalls or repairs (Rules 5 and 8).
- VERIFY
  - `/gsd-verify-work`, then `/gsd-audit-uat`.
  - On `gaps_found`, run gap closure yourself (Rule 10).
  - Push main only after a phase is verified and every local gate is green. Then watch CI with `gh run watch`: ubuntu and macOS must be green. A red CI run is a gap to fix.

ORDER

- 24:

  - D-16: the single real Alacritty build runs on host podman with a scratch HOME only. Afterwards assert no new container or image, and delete the scratch dir.
  - D-17: the UAT is manual. Put it under human_verification; never wait for it.
- 25 runs last. Its deletion list is computed at execution time (D-01/D-02), never hardcoded.

DECISIONS: the jev ladder, at every stage (plan choices, executor deviations, review-finding triage, gap classification)
- Verifiable facts: check them and fix directly. No jev.
- Gray areas:
  1. Laya first, one call per item:
     `GSD_PATH_JEV=1 GSD_PATH_JEV_TIMEOUT_SECONDS=30 JEV_API_URL=http://127.0.0.1:8010/v1/systemone JEV_MODEL=jev-1 JEV_RESPONSE_MODEL=laya-rl-agent python3 -B ~/.claude/skills/jev-fast-decision/scripts/jev_review.py`
     Accept only when the winning probability ≥0.7 AND Laya's own confidence is high.
  2. Otherwise TypeSafe, batched:
     `JEV_API_URL=https://api.typesafe.ai/v1/systemone JEV_MODEL=jev-latest JEV_RESPONSE_MODEL=jev-1.13.0 JEV_API_KEY="$(tr -d '\n' < /var/home/bazzite/git/llm-env/tmp/typesafe.txt)"`
  3. Otherwise your own full reasoning.
- Send jev summaries only, never source, diffs or secrets. A jev answer never dismisses a finding by itself.
- Prefer the best design over the easiest.
- Log every decision in `.planning/RUN-LEDGER.md` with phase, item, Laya, TypeSafe, outcome and why. Include each entry marked "Ledger" in the CONTEXT files.
- Never pause for UAT or non-blocking questions. Write them in the ledger and continue.
- Never remove existing features beyond what a SPEC decides.

QUOTA
- This session: create one hourly CronCreate job that resumes the earliest incomplete phase from STATE.md. Delete it when the run is done.
- When the cross-AI executor or a reviewer stops on quota:
  - Router-env routes: wait, re-checking every 10 minutes for at most 4 hours.
  - Clean tree and another configured candidate: fall back.
  - Dirty tree: wait, then resume the same plan.
  - Answer GSD's retry prompt only after the wait.

SAFETY
- Never touch the real ~/.claude, ~/.config/opencode, ~/.codex, ~/.cursor, ~/.pi, ~/.config/herdr, shell rc files or environment.d.
- Never run a real install or uninstall on this host, and never run `make setup`, `make fix` or `make uninstall` beyond tmux navigation.

1. Leave no stray files, worktrees, scratch HOMEs, containers or images.
2. Mark completed todos as done and move the ROADMAP 999.x items that a phase completed. List the rest.
3. Run `codegraph sync` one last time and refresh the intel.

STOP IF
- A decision blocks other phases and nothing resolves it.
- The same failure repeats 3 times with no progress.
- A step needs a real host config write, a login or sudo.
- Every candidate for a cross-AI role is unusable after the quota wait.
In each case, park the phase, continue the independent ones, then report.

- The ponytail audit and debt summary.
- Commits and pushes made, and CI run links.
