# Terminal and IDE defaults: the closed per-terminal table

Read at step 7 of `SKILL.md` when the entry is a terminal or editor. The four rules (a) to (d) it fills in are stated under "Terminal and IDE defaults" in step 7.

## Closed per-terminal table

One row per `terminal` or `editor` entry in `installer/registry.toml`; `tests/test_tool_onboarding_skill.py` fails when an entry has no row or a row has no entry, so a new terminal adds its row with its entry.

Each rule cell starts with one status word: `vendor` (the vendor default already meets the rule), `written` (the installer writes it today), `planned (phase N)` (that phase will write it), `gap (backlog 999.x)` (a platform gap: the installer cannot place or configure it yet, and the backlog item names the missing capability), `n/a` (the rule does not apply to this entry, or the part it needs is out of scope here, such as IDE keybindings (SKILL-07); the reason follows), `unverified` (not checked live yet; phases 30-31 settle the remaining terminal cells).

## Konsole

Konsole has no row: it is detected by code but is not a catalog entry. The owner decision is to verify it and leave it alone: `_sync_konsole` (`installer/terminal_shell.py`) keeps its zsh profile, and its stock Ctrl+Shift+K clear (Clear Scrollback and Reset) is checked and reported, never written; a user who removed it gets `konsole: partial: you removed Ctrl+Shift+K; kept yours` (29 D-09).
